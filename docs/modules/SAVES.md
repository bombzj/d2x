## 自动地图探索（2026-10-04）

角色文件继续使用原生 D2S v96，不增加私有字段或尾部。客户端探索保存在同目录、同角色名的 `.d2xmap`；例如 `Hero.d2s` 配套 `Hero.d2xmap`。分发或备份角色时应携带两者。原游戏的 `.map`／`.ma*` 二进制格式尚未核实，本项目不覆盖或冒充这些文件。[Grailward 的保存同步实现](https://github.com/Grailward/agent#map-exploration-sync)可交叉确认 D2R 的探索文件独立于 D2S；本地 D2MOO `PlrSave2` 没有探索格数据，不能据此宣称 `.d2xmap` 与原游戏互通。

- `client/automap_exploration.*` 唯一拥有区域探索掩码；角色权威记录、怪物、任务与 GPU 都不持有副本。`SceneView` 只推进观察者探索及绘制。
- `app/automap_save.*` 连接角色保存与客户端侧文件。F11、菜单／窗口退出保存和现有调试 `save` 均保存两者；启动选择角色、F11 读档及调试 `load` 恢复探索。
- 侧文件 JSON 格式为 `D2X automap`、版本 1，包含揭示规则标识 `d2x-visible-terrain-v2`、规范化 JSON 的 FNV 兼容校验值、角色姓名／职业，以及最多三个难度世界。每个难度保存一份地图种子、稳定原地图内容指纹和区域层。内容指纹为 FNV 输入版本 `d2x-automap-content-v1` 与固定顺序的 Automap、Levels、LvlTypes、LvlPrest、LvlMaze、LvlSub、Objects、MonStats2 原表名及原字节；不依赖本次先读角色或地形、当前区域或资源读取集合。每格一位，十六进制编码，低位对应先出现的格；尾部空位必须为零。区域层另存尺寸与原地形／房间几何指纹，首次加载时核对，不符则提示并清除该层，不向另一张地图套用记忆。
- 种子或内容不符时明确提示并不应用旧探索，保存时仅替换当前难度；另外两个难度保留。缺少侧文件的既有原生角色正常载入并开始积累探索。已知旧整房规则 `d2x-near-rooms-v1` 会提示旧记忆停用并开始重新探索，不转换旧格；下次保存将旧文件备份为 `.bak`、将三个难度的旧整房记忆替换为本轮重新积累的可见格。未知版本／规则、损坏、校验失败或角色不符会提示，保存时拒绝覆盖，不静默迁移；需人工保留／移走冲突文件。
- 文件读取限 16 MiB；单世界累计不超过 32 Mi 格，最多 512 层。两个文件各自用现有原子替换和 `.bak` 备份；两文件之间没有跨文件事务。若第二个文件写入失败，界面提示保存失败并保留游戏，D2S 可能已更新，可再次保存；不宣称两文件原子一致。

本轮不增加测试程序；按用户后续授权进行简单移动和保存重进冒烟，覆盖与未验收边界见自动地图文档。地图绘制与揭示证据边界见[自动地图](../gameplay/world/AUTOMAP.md)。

正常启动从 `saves/` 列出可读取的 `.d2s`，`quick.d2s` 是命令行快速档，不作为可选角色。创建七职业资料片普通角色后立即保存，正常退出自动保存，删除须确认。姓名仍限制为 1–15 个 ASCII 字母、数字或连字符；不提供普通版转换和专家模式。

- 第一幕罗格、第三幕铁狼及第五幕野蛮人佣兵原类型、名字偏移、种子、经验与死亡位；等级从原表和经验推导，存活佣兵进入新游戏时恢复基础生命。原档没有当前生命字段，不额外添加。
- 鼠标手持物品使用原 IMODE_ONCURSOR=4，只容纳一件，不受物品宽高影响。对应 D2MOO D2Items.h 的模式编号与 ItemMode.cpp::D2GAME_PickupItemEx_6FC42B80；读写仍为 v96，未增加私有字段或规则指纹。关闭背包不清除此物品，保存／重载可恢复手持位置。
- 地图种子、当前难度与当前幕；按原五幕编号在1／40／75／103／109城镇恢复。物品原生 start seed 在创建时由父流产生，佣兵 seed 保留候选生成的原值，不再写实体 ID／固定 1。项目内部角色／物品／容器 ID 在进入会话时重新分配，战斗／物品创建／商店等随机流重新初始化；运行时随机状态不进入 D2S。自选地图配置不是原格式字段，仍由启动参数决定。

重新进入会创建新的区域会话：怪物、怪物尸体、怪物 AI 阶段、召唤物、弹体、蛛网、地面掉落、区域击杀数、死亡结算、回城门、NPC 走动位置和商店本局售出状态都重置。野外物体的开启状态、井水余量和祭坛效果也重置。普通游戏过程中离开区域再返回，当前会话仍保留区域状态；只有载入存档才开始新的一局。角色冰冷、毒素、蛛网减速、施法／攻击动作及其他短时效果不会跨局保存。玩家未回收装备沿原 JM 尸体段保存，在城镇重建尸体；死亡时直接退出的角色按当前无装备属性恢复满生命、魔法和耐力，其他角色延续普通资源保存值。

任务状态在新的一局延续；凯恩石阵、任务物件和 NPC 出现状态根据记录恢复，普通区域敌人重新生成。凯恩获救致谢和安达利尔死后各 NPC 的待播放反应对齐 D2MOO 的本局 GUID 列表，保存在 GameSession，载入时清空；不与跨局保存的 NPC 初见记录混用。

这里的新局不是对 D2S 执行“战斗状态清理”：D2S 本来就没有冰甲、未完成施法或地狱之火引导等字段。解码构造 `CharacterRecord`／`HirelingRecord` 保存值，会话经 `runtime_record.cpp` 在幕城镇创建新的 `PlayerState`／佣兵运行态并推导属性，之后整体替换旧局；`CharacterSaveData` 的兼容成员 `player` 不再是完整运行人物。待施法参数、目标、倒计时及引导进度随旧人物状态销毁；`Simulation` 不另存这两类状态，读档不额外清空会话级施法槽。`CombatEffectSet` 的状态实例、来源、事件反应、句柄和绝对模拟帧只存在于本局；技能等级／选择仍使用原 Skills.Id，不使用内部 SkillBehavior 枚举。编码仍逐项写原 D2S 字段，格式／语义及运行规则指纹不变，没有旧档迁移。当前角色值映射与实际冒烟范围见 [角色基线](CHARACTER.md)。原地切换职业的调试功能已移除。

走／跑选择：本地 D2MOO `PlrSave2.h/.cpp`、`GAME/Clients.h::D2PackedClientSaveFlags` 与独立 `@dschu012/d2s` 的 v96 头部定义均没有已定义的走跑选择字段。`0x24` 一带的状态／进度位和武器切换位不可据此解释成跑步；未知位也不占用。本项目把走跑开关与 mini panel 开关保存到运行目录的 `client-settings.json`，跨角色、快速读档和客户端重启恢复；首次启动或配置不可读时两者默认关闭。该文件只含 `running`、`miniPanelOpen` 两个布尔值，不属于 D2S 或原版 ini 格式，不参与角色存档迁移。耐力仍按原属性字段保存在 D2S；原版客户端的具体偏好文件及字段尚未核实。

偏好 JSON 的缺省键或类型错误只回退对应开关，保留另一有效字段；整体 JSON 损坏时使用默认值。写入复用 `persistence/save_file.cpp::writeFileAtomically`：独占锁目录、临时文件写入及刷新／关闭检查、原子替换，失败不截断原配置。仅保存成功后清除待保存标记；游戏中失败重试至少间隔两秒，正常离开会话时再尝试一次。持续失败会记录错误，跨角色使用当前内存选择，但不能保证重启后恢复未成功写入的选择。该机制不改变 D2S 编码或其既有备份流程；偏好文件和锁目录均忽略 Git。

## 操作

- F11 保存角色，Ctrl+F11 从存档在城镇开始新的一局；默认路径 `saves/quick.d2s`。
- Esc 先关闭面板／对话，无面板时打开游戏菜单。选择 Save and Exit Game 才返回角色列表：角色来自列表、`--load` 或指定了 `--save` 时先保存到当前存档路径，失败则留在原会话和菜单并显示错误。Return to Game 或再次 Esc 恢复游戏，不触发保存；Options 暂不执行。`--class` 且没有 `--save` 的临时角色不自动落盘。返回列表后清除上一局的地图／存档启动选项，不把新选择的角色写回上一角色文件；关闭窗口／调试 quit 与返回列表分开处理。
- 普通图形启动先选择或创建资料片角色，所选角色在正常退出时自动保存。`--load <路径>` 直接启动载入；`--save <路径>` 设置存档路径，并在正常退出时保存。只指定 `--load` 时沿用该路径；命令行直进游戏而未指定 `--save` 不自动保存。
- `--class <MPQ 职业名>` 直接构造新的一级角色，不经过前端、不读取或自动创建 D2S；与 `--load` 互斥。测试场景可通过 `Play.cmd -Class Sorceress` 新建，或 `Play.cmd -Load <输入.d2s> -Save <输出.d2s>` 从已有场景开始并保留原档；只有显式保存才把临时角色写入磁盘。
- 覆盖前保留上一份 `<路径>.bak`。快速载入若地图种子或难度与当前进程不同会拒绝，改用 `--load` 重启。窗口关闭、调试 quit 和帧数退出均先保存有归属的角色；失败则显示错误并保留当前会话，不以抛出异常销毁未保存角色。系统强制终止、断电和进程崩溃不在此保护范围内。

## 编码和校验

- `gameplay/session/character_save.hpp::CharacterSaveData` 是角色存档值边界，不包含区域怪物、弹体、NPC 运动、地面掉落和怪物死亡结算；包含原格式可保存的一份玩家尸体及其物品容器。`characterSave()` 只收集角色和容器物品；`persistence/d2s_codec.cpp` 与 `d2s_header/fixed_sections/stats/skills/items/inventory` 逐项写入原字段，角色内存中的短时动作不被序列化。`session_restore.cpp` 校验新角色与装备、重建内部 ID 和空白新局，再提交状态。
- 原 `GameSession::snapshot()` 和整局世界校验已删除：现有测试及联机无调用，普通沉沦魔见尸记忆被误判为复活目标曾阻止保存。怪物 AI、商店售出、NPC 路径及战斗状态均不得作为角色保存的前置条件。库存值校验与 `LootState` 的小型状态接口仍有实际用途，不与整局快照混用。
