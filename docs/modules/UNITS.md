更新：2026-10-03。对应 P4 公共视图、周期伤害／恢复、第一项公共资源／效果、第二项公共动作／控制及第三项活角色组合。前三项已完成源码与调用方迁移，并按本轮授权通过 Windows Release 与简单冒烟。前一周期批次曾通过 Windows Release 与部分中毒现场，公共视图清理批次曾有三职业简单冒烟；准确的本轮范围见下方，旧证据不扩展本轮认证。当前包已包含该批改动；完整单位／区域所有权仍待实施，当前不实施多人联机。

毒素与白骨批已新增真实骨墙单位：保持 `Neutral` 关系，`canAttack` 对骨墙单独开放受攻击资格；不改普通中立单位的敌我关系。权威世界端口读取已准备的原骨墙属性与寿命、更新区域碰撞，根死亡清组，死亡不产生经验／掉落。白骨装甲定点物理吸收池属于公共效果，在物理抗性前结算；效果注册顺序决定与能量护盾的先后，耗尽移除。当前包已包含，范围及放置适配限制见 [死灵法师技能](../gameplay/skills/NECROMANCER.md#毒素与白骨技能)。

| `units/impairments.*` | 短期借用冰冷／冻结／眩晕／蛛网期限；调用方显式选择蛛网到期是否清元数据，不创造不存在的能力 |
| `units/movement.*` | 同步碰撞能力、路线到达处理、方向／距离执行及显式墙前截短；不查询设备输入、单位类别、会话或地图资源 |
| `units/actions.*` | 秒时钟、武器帧时钟、速率重算、取消与攻击意图清理；公共头仅前置声明武器／施法能力，不引入完整单位状态 |
| `player/control.*`、`player/movement.cpp` | 前者解释玩家方向／追击意图并经 `IPlayerControlWorld` 请求动作；后者仅绑定原人物能力、资源阶段及本地模拟器端口 |
| `npc/hireling_control.hpp`、`npc/hireling_controller.cpp` | 佣兵跟随、退避、空闲和攻击决策；仅借用位置／路线／决策状态，输入已解析移动规则，编入纯 gameplay |
| `npc/hireling_control.cpp`、`hireling_actions.cpp` | 前者绑定地图／目标／内容能力，后者处理佣兵原射箭结算，二者编入 session；`hireling.cpp` 保留生命周期与固定步编排 |
| `monsters/action_execution.cpp` | 怪物已接受攻击的执行适配，使用公共秒时钟并分派原事件；AI 主流程继续选择动作，不把原生怪物动作套成玩家施法 |
| `combat/damage_request.hpp` | `DamagePermission`、`DamageRequest`；只依赖 ID、伤害类型和数组，不引入单位布局或属性派生 |
| `simulation/unit_records.hpp` | 内部 `RuntimeCombatUnit` 扩展公共视图，`records` 保存具体人物／佣兵／怪物绑定；只供当前权威实现，不能从技能／客户端端口返回 |
| `simulation/unit_records.cpp` | 按原 ID 查询当前状态并构造绑定／属性，枚举顺序仍为玩家、有效佣兵、当前区怪物、随从；保留原装备、奔跑、词缀、转换和属性求值次序 |
| `combat/damage_resolution.*` | `rawResistance(attributes, type)` 是原六通道未封顶抗性取值；减伤继续在原入口处理不同单位规则及上限 |
| `simulation/skill_world.cpp` | 技能端口返回公共视图，自动剥离内部记录绑定；冷效果／具体动作仍在适配内按 ID 取得当前记录，保留调用方属性快照 |
| `skills/world_values.hpp` | 技能需要的尸体位置／资格和光环发射借用，不再定义另一份战斗单位 |

`PlayerState`／`HirelingState` 的身份字段直接包含身份头，世界另包含关系与属性值头；状态模型不再通过公共单位头引入战斗请求。技能武器端口仅前置声明能力值，完整装备、动作、效果容器定义留在使用它们的实现文件。

## 调用与所有权

```text
权威记录 → Simulation::combatUnit(id) → RuntimeCombatUnit
  ├─ 当前战斗／受击／死亡／AI 适配 → records 中的具体绑定
  └─ 技能端口／通用目标筛选 → CombatUnit 公共能力
显式属性快照 → rawResistance → 原冷／诅咒／减伤规则
```

公共视图和内部绑定都只在当前调用中借用，不持久保存，不创建第二份人物或怪物。单位扩容、删除、恢复和切区后重新按 ID 获取；公共视图中的指针仍是权威侧的短期能力，不是网络消息或客户端可写状态。

`player`／`hireling`／`monster` 记录原存储类别，`CombatIdentity.role` 继续独立表达玩家、怪物、佣兵和召唤物的归属。召唤怪物仍保留 monster 分类，以维持原冰冻、诅咒、转换及死亡分支；没有用角色类别替代存储类别而改变规则。分类与内部指针由同一绑定函数一起准备。

会话里的光环／诅咒资格和 ColdEffect 原表桥仍是权威内部适配，参数改为内部绑定；技能只向端口传单位 ID。抵抗率本来只读取传入快照，已移至纯函数，删除模拟器成员、技能代理和世界虚接口，不增加 MPQ 查询或改为重新读取活动属性。

## 公共周期伤害与恢复

`Simulation::tick` 在原活动／存活筛选后调用公共周期结算，仍先中毒再开放伤口，先扣期限、同步走 `dealDamage`，再在到期后清速率；不在两类伤害间增加存活检查。原玩家中毒不致死及安全区保护由调用方显式传入。武器附毒／开放伤口、清洁光环和蛛网写入改用公共能力，具体记录绑定集中于 `unit_records.cpp`。

人物先恢复生命、再法力，然后进入原人物更新；佣兵继续先计算自然恢复，再逐项累加药剂增量、封顶并清队列。共用算法保留各自浮点累加与封顶顺序，未移动状态所有权、改存档或新增原版规则。删除 `Simulation::updatePotions`、原 `Restoration`／`HirelingState::Healing` 重复类型和两处重复推进循环。后续自然资源／减速期限已迁移，分工见下一节；动作、死亡和特殊技能生命周期适配仍待后续拆分。

## 公共资源与效果推进

第一项已迁移的源码入口为 `units/resources.*`、`units/impairments.*` 和 `units/restoration.*`。公共头仅提供数值、活动条件、借用计时器和移除记录前置声明，不依赖完整角色、怪物、模拟器、会话或内容目录；新实现编入 `d2x_gameplay`，佣兵宿主调用同一规则模块。状态继续由原 `PlayerState`、`Enemy`、`HirelingState` 持有，没有创建第二份可变单位。

独立减速计时器合并到 `advanceImpairments`，期间不查询世界、触发回调或产生事件。冻结位仍在原减速推进阶段按期限重新赋值，包括零时长冻结位；玩家蛛网到期清比例和来源，怪物／召唤物／佣兵保留原元数据。没有把这几类单位的推进集中到循环开头，以免绕过击退和专用分支。

效果集合的帧到期与删除记录原本已在 `CombatEffectSet::expire`，继续复用，不增加重复效果容器或代理接口；玩家、自然怪物、召唤物和佣兵仍在各自原位置调用。删除资源计算旧内联段与无人调用的 `accumulateRestoration` 公共入口，队列累加留在恢复实现内部。AI 的 rethink／aiWait、专用生命周期和单位状态所有权不属于第一项。第二项动作推进的实际迁移见下一节；转换／Hydra 寿命／蛛网光环等专用规则仍保留原适配。

## 公共动作与控制策略

第二项分成“决策 → 已接受动作 → 具体结算”。`player/control.*` 读取借用的施法／武器／移动能力，通过窄端口选目标、查路线、请求普通攻击／武器技能／突进；不包含 `PlayerState`、`Enemy`、`HirelingState`、模拟器或会话。`npc/hireling_controller.cpp` 只解释跟随／退避／空闲／攻击策略，目标资格、地图与动态占用、原动作和内容查询留在 `hireling_control.cpp` 的本地适配。既有技能施法／引导和家族 AI 继续复用，未复制一套技能执行器。

`units/movement.*` 不决定目标或战术，调用方先选择方向和距离，再提供同步碰撞能力；通过后才修改原位置。玩家键盘方向保留 12 次墙前截短，路线移动不启用它。玩家／佣兵／NPC 到达阈值仍为 .01，普通召唤物 .05，怪物绕行／逃跑 .25；路线清理、重规划、NPC 原路径预算和静态／动态探测顺序保持。主移动、恐惧／微暗灵视移动、绕行／逃跑、佣兵跟随、普通召唤物、NPC 路径及突进／击退接入；传送、出生重定位和召唤物受阻后的专用侧向避让仍由各自规则控制。

`units/actions.*` 只推进既有动作能力。怪物仍使用秒时钟，玩家／佣兵仍使用原 25 Hz 武器帧；没有转换或重写持有状态。自然怪物完成截断 .00001／出手门槛 0，普通召唤物及 Hydra 出手门槛 .00001 保持；攻击速率变化按原比例同时缩放剩余／总时长／未释放事件。原怪物多事件重排、女伯爵火墙、复活、蛛网、巢、血鸟与安达利尔特殊释放仍在 `action_execution.cpp` 中按原分派执行，巢生成仍延迟汇总提交。

玩家武器与佣兵射箭共用帧推进；武器释放仍复验原装备版本／类型和目标，热诚回滚、重击、转换、消耗与随机顺序保留，佣兵仍无玩家法力消费。清理重复武器选择、攻击意图清理与时钟计算；停止移动不额外取消引导。死亡、受击、格挡、击退、诅咒／转换等资格继续由各自消费者判定，通过后复用适当取消能力，未强制统一所有中断规则。

```text
玩家方向／追击 → PlayerControl → 本地世界端口 → SkillRuntime／普通攻击
佣兵跟随／退避／空闲 → HirelingControl → 本地适配 → 原射箭执行
怪物家族 AI／诅咒策略 → 已接受动作 → 原事件执行适配
NPC 原路径决策 → 已选择路线
                         ↓
          公共移动执行／秒时钟／武器帧时钟
                         ↓
          原单位记录、原伤害／生成／表现事件
```

这些视图、接口和回调只在当前同步调用中借用，不跨单位扩容、删除、恢复或切区保存。技能／公共动作仍不读取 MPQ、设备输入或 GPU；本地适配保留具体记录和内容查询。完整单位拥有者、区域查找、怪物 AI 的全部能力接口、NPC 世界物件与投影及宿主瘦身仍未完成，不能据此宣称 P4 全部完成。前三项已通过本轮 Windows Release 与简单冒烟，覆盖范围见下方。

## 剩余范围与验证状态
