补全过程使用CRT _initterm登记、已恢复Hook／程序表回调，以及明确传给_atexit的指针作为入口种子。每次保留原文件摘要，只修改独立Ghidra工程；没有执行目标模块。82,290个纯E9别名按原字节单独归并，不强行创建为82,290份业务函数。种子处理报告保留每个现有／新增／重叠／失败状态；当前最后一轮无创建失败。

函数边界、调用流和自动名称是Ghidra的分析结果，no-return假设、共享代码、寄存器约定和间接调用仍会影响结果。已解析调用可包含CALL override；间接调用点完整列于[INDIRECT_CALLS.csv](INDIRECT_CALLS.csv)，不把缺少静态边当作不可达证明。公开BH名称只按模块与1.13c地址匹配，未认证为当前闭源核心原符号。

本目录已完整列出本轮识别出的函数体、登记跳板和剩余未归属指令范围；尚未逐一恢复每个业务函数的参数、结构和拒绝条件。语义待核实项保留明确分类，不以通用函数名替代理解。
