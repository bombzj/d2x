逐函数至少记录：实际入口与范围、执行侧／调用约定、输入和输出、前置条件、分支顺序、副作用、依赖与未决事项、D2X对应责任。结论用以下词区分：

- **已确认**：本函数指令或原始数据能直接支持的事实。
- **部分确认**：入口及主要分支明确，但被调函数、结构含义或运行条件未闭合。
- **未决**：不能据此实施的推断，以及能区分它的下一步证据。

## 必须纠正的读法

1. 查询地址不等于函数入口。旧物品查询`37E831→37E7F0`、`3A529C→3A4EB0`、`3ABCB5→3ABC30`、`375DAC→375C20`均由工具返回包含该地址的函数，箭头左侧不能登记为新函数。
2. 五字节跳板的伪代码可能展开整个解析器。`38F5B0`本体只有一条JMP，不能将展开后的缓存／版本解析也算作该接收函数新增算法。
3. 寄存器实参会丢失。`37FB80`的`309640(-1)`伪代码省略ECX=使用者、EDX=技能ID；`-1`不是技能ID。514分支调用`37EBE0`还传ECX／EDX，不能只抄栈参数。
4. `37A560`本次出现跳转表截断及读取无效地址警告。伪代码case编号不是线上类型号；必须恢复字节选择表和DWORD目标表才可实现。
5. `379E30`的字符串外观实际是60个四字节代码槽。原始`.rdata`确认29个非零地图代码、31个零槽；不能用字符串长度或NUL扫描代替60槽遍历。
6. 函数返回0不一定是失败。`37FB80`在执行514／513副作用后也统一返回0，不可直接映射为D2X命令Rejected。

## 属性文本

### 39E720：ABI包装

已确认：从EAX、ESI与调用者四个栈参数组装六实参，调用2ECFA0，再`ret 0x10`。未单独读MPQ、网络或库存。ESI对应输出缓冲；其余参数的最终业务名依被调函数约束，不采用反编译器猜测的void返回类型。

复刻边界：D2X不移植寄存器包装，只在所属物品提示入口调用等价纯值逻辑；不可把此包装器记为另一个描述算法。

### 2ECFA0：特殊文本选择

输入的静态含义：属性ID、UTF-16输出缓冲、物品指针、原分派透传参数、属性参数层、属性值。先调用378220取得属性定义；该getter的寄存器保存仍需单独核对，因此Ghidra的`extraout_ECX`不是新业务输入。

已确认分支顺序：

1. 属性定义存在，属性ID=191、参数=605、值=1时，清空输出，用字符串键`StrPhasingStatDesc`调用原格式化链，返回1。字符串由旧RVA44684C／新RVA449DE0定位；新版函数入口2EEC50同样比较BF／25D／1。
2. 否则，定义字节+36为30时，先清空输出。只有属性270再查物品扩展数据`item+14 → +28`参与的容器；找到记录且记录+4C非空，才经字符串解析／格式化输出。即使没找到也返回1，不回退普通描述。
3. 其余调用39E6F0转交原描述入口，返回其结果。

后续追踪确认：键为ItemData+28的fileIndex，2F2400→2F46A0查询全局5D54D8；容器由静态初始化CD980→2E6F90构造。两版23条文案索引已逐项一致：5条StrAnniversaryEdition、18条StrSpecialEdition。新版文案地址4496B0／4496D8，索引赋值位于CDEAA–CEC99。配置另含原贴图名及其他参数；2F01E0在属性270为正且品质7时选择外观贴图，Ormus索引166另按技能属性选择三种原图。这不是普通InvGfx变体；完整贴图配置的双版本核对尚未闭合，不能将stat270值直接作为颜色或TBL索引。查询保留在function-review-20261022/appearance。

D2X对应：`content/items/item_descriptions.cpp`已实现Phasing特例及特殊外观文案，属性描述接收真实物品记录索引，按上述23项选择当前TBL键并保留descpriority排序；未配置的descfunc30不输出猜测文本。22种静态库存原图在item_appearance集中配置，remote_ui_items在普通暗金图后应用；仅已鉴定暗金且自身服务器属性270／参数0为正时覆盖。旧CD980匿名图名44628C为inv8wsu_se；其余21种具名静态图在新版同样保留，全部22张均已在当前pd2assets.mpq目录核对。Ormus不返回静态图名，地面动画、特殊调色不由此覆盖。当前缺专用字符串时回退普通Phasing文案是D2X容错策略，不是已证明的native分支。BH腐化红星仅在显示属性范围开关／Ctrl条件下附加，不能不分设置作为核心必显属性移植。

### 39E760：显示数值ABI包装

### 2ED0C0：显示数值变换

物品指针为空时直接返回第一个输入，连原计算器也不调用。否则先经39E740调用原计算器取得result，再按属性ID分支：

- 488：返回`100 - result`，未见0–100钳制。
- 489：只有`item+14`、其`+5C`、再`+8`均非空才继续；调用306150读取该关联对象的属性184、参数0，乘result，按有符号比较只把大于40的结果截到40。没有除100，也没有下限钳制。任一指针缺失则返回result。
- 其余原样返回result。

旧入口2ED0C0／新版2EED70已分别指令核对。不能仅凭属性名字把184解释成即时缺血百分比，亦不能用客户端角色面板生命值替代关联对象的真实属性。乘法为32位IMUL，精确溢出语义须在实现时明确，不能默认使用无限精度。

D2X已接488提示补数；489在拥有明确物品主人及其已收到的属性184时，将显示值作32位无符号乘法回绕、按int32解释并取有符号上限40，不添加下限。内容接口只接收可选主人事实，不读取网络。地面／下落或位置未知物品不使用残留owner；未知主人属性保留原显示值，不从生命面板推算missing_hp。此项不复刻战斗效果，仍需真实物品核对属性184的同步覆盖。

### 2F9580：特殊版与染料调色

旧2F9580／新2FB450先按库存／地面选择Items的InvTrans／Transform组。特殊版属性270为正、品质7且有配置时，库存读取配置+54，地面读取+58，组覆盖取+51，零则保留基础组；颜色不是FF时取低五位并立即返回原调色查询结果，不回退普通暗金颜色。Ormus地面按关联技能元素取火8／雷13／冰5，库存固定FFFFFFFF。其余配置的库存值同为FFFFFFFF，低五位为31。

旧321940经模块11绑定D2CMP导出10091，当前原DLL入口RVA14EC0：组>=9、组0／3／4或颜色>=21返回空指针。基础d2data.mpq的invgreybrown.dat为5376字节，即21行，不存在第31行；因此特殊版库存是无染色，不应扩展调色表索引。D2X已据此取消普通暗金库存染色，并按配置及Ormus元素应用地面调色；原图动画仍沿现有路径。渲染器增加所选行字节边界检查。

未命中特殊版后，属性477（当前MPQ transform_dye）为正则进入染料分支；旧2F9570／新2FB440将值减1，结果在0–20内保留，否则取0。D2X在远端显示配置下用自身服务器属性及当前基础表调色组处理库存／地面染料，特殊版优先，原版不变。实际画面、所有属性列表组合仍待核对。

## 书卷与无限书

### 37E7F0：物品到技能身份

输入为物品单位指针，返回技能ID或`0xFFFFFFFF`。条件为非空、unitType=4、ItemData+45页字节属于0／2／3；函数不在此处校验ItemData指针，调用者必须满足初始化前置。

已确认：通过3055E0取得物品定义。记录+94的无符号DWORD大于2，且+80四字节代码为`rid `或`rtp `，直接返回+FA的WORD。此分支没有额外“返回值必须大于零”的检查。其他情况经307F90分别检查原类型18／22，再经378360取记录，前者取+0C，后者取+08，否则失败。

注意：+45是原ItemData页字段，不是S2C位置中的mode；不能把0／2／3套成D2X三种mode。它与网络page的转换、+94／+FA的表字段命名需结合目标记录结构，而非只看函数名称。已知目标Misc及已有专题把+FA关联到missiletype，但函数本身不读取TXT。

复刻用途：用于物品技能身份和可访问来源筛选的证据，不能证明拥有书就应本地增加技能等级或数量。

### 37FB80：无限书执行

ECX／EDX及栈上物品、三个透传参数、技能ID共同构成输入。game／actor的业务命名由调用链推定，不能当作已导出ABI。前三个对象非空后，先调用30B690(item,4,0)，再取定义；若传入技能ID为负且+FA非零，以该字段替换。

随后309640调用前明确有ECX=使用者、EDX=技能ID、栈参数=-1；3096A0再以使用者、所得技能对象、1求值。技能对象存在且结果为正才继续，技能ID=-1为额外放行分支。不能使用反编译器漏参后的`309640(-1)`解释权限。

514分支调用37EBE0，保留ECX／EDX及完整栈实参。513分支先经30B750要求正值，遍历使用者+60库存链，只处理ItemData+45为0或3且unitType=4、flag10检查为假的项，对每项调用371790；最后调用30BFD0(actor,47,0)。所有路径末尾返回0。

已确认有遍历、鉴定标志筛选及执行调用，不能把该函数作为客户端只读技能目录算法。30B690具体含义、30B750资格、371790完整鉴定副作用、37EBE0门户资格、47的属性命名仍须查原生绑定及调用者。此函数不提供C2S编码、客户端快捷槽持久化或物品技能源授予／撤销的完整证明。

## 核心计数

### 379E30：固定地图代码查找

ECX为四字节代码，零值立即失败；从RVA42F9F0扫描60个DWORD，返回首个相等槽的零基索引，未命中返回-1。无写入。

旧样本原始字节的前29项依次为：`t11 t21 t22 t24 t33 t34 t36 t26 t12 t25 t32 t37 t38 t14 t16 t3a t17 t13 t23 t31 t35 t39 t15 t28 t27 t3b t29 t18 t2a`，每项补一个空格成为四字节；其后31槽为零。它是固定容量代码表，不是60个有效物品，也不是以NUL结束的字符串。只证明磁盘初值和本函数读法，其他写者是否会改表需另查xref。

### 379E50：记录索引转地图子索引

ECX为有符号非负索引。依次要求全局5D8F28存在、其+154表指针存在、索引小于+158无符号条数；按`index * 0x1A8 + 0x80`读DWORD代码，尾跳379E30。失败返回-1。

指令明确恢复了反编译遗漏的索引乘法和字段读取；这是记录索引到代码的桥接，不是线上类型直接映射槽号。总表应与目标Items记录结构进一步确认，不能仅凭0x1A8就视作已核定所有字段。

### 37A560：计数地址选择

ECX为携带PlayerData的单位，EDX为索引；EDX=-1返回空。先调用379E50，返回非负时取`PlayerData + 0x51C + 2 * index`。相对85快照起点436，地图子区起始槽为115；本代码表静态非零项对应115–143。

未命中地图代码后，用`index - 7`的无符号范围检查限制到0–299，然后读字节选择表RVA37AD90，再索引DWORD跳转表RVA37AB70。各case返回PlayerData内不同WORD地址或空。不能把Ghidra的case序号当原索引。该函数本身不分配、加减计数或发包，也不验证单位是否玩家；调用者承担前置。

## 缓存与效果生命周期

以下四个函数由第三批只读查询取得。容器helper和原生库存函数仍存在寄存器实参恢复不完整，描述中的迁入／迁回是按实际页字段写入调用归纳，不等于全部原生库存副作用已恢复。

### 37E130：活动页迁入缓存

ECX为单位。单位及PlayerData存在、PlayerData+1C8为0才执行，否则返回0。先取库存首项，再调37E480获取一个最终按8字节释放的偏移对象。每次循环先取next再操作当前项，避免移除当前项后丢失遍历位置。

仅处理ItemData+45为4的项，读取路径对象+0C／+10坐标，加偏移对象的两个整数，经3080E0及308020进入目标页5，调用参数另含10／0。精确位置安置失败后调用308050自动安置到同页5；本函数不检查这次回退返回值。遍历结束无条件置PlayerData+1C8=1，释放偏移对象，返回1。

复刻风险：返回1不保证每件物品成功安置；不能据此提前宣布所有缓存完整。37E480坐标来源、3080E0移除返回契约、308020与308050具体容器常量需独立恢复。不能把原页4／5直接当D2X线上page编号。

### 37E220：缓存重放

ECX=单位、EDX=零基页、栈参数为模式。入口以有符号比较把目标页上限限制到9，未见单独负数下限钳制。单位／PlayerData存在且（模式为0或+1C8非零）才执行，否则返回0。

遍历同样先保存next，只处理ItemData+45为5的项。经37E530计算该项所属页，等于目标页才处理；从坐标减37E480得到的两个偏移，经3080E0及308020尝试放入页4，参数另含12／0。失败先308050自动安置页4，再失败才自动安置回页5（参数10／0）。结束时仅模式非零才清PlayerData+1C8，释放偏移对象并返回1。

**分层上限不能混淆：** 37E350接受到一基17，但这里重放钳到零基9。因此“内部选页字段”“缓存实际选页”“界面可选页”“线上服务页数”分别记录，不能将17宣布为可用仓库页数，也不能称所有核心函数都以十页为上限。CN mdll1共享链仍独立。
