## 自动地图探索（2026-10-04）

角色文件继续使用原生 D2S v96，不增加私有字段或尾部。客户端探索保存在同目录、同角色名的 `.d2xmap`；例如 `Hero.d2s` 配套 `Hero.d2xmap`。分发或备份角色时应携带两者。原游戏的 `.map`／`.ma*` 二进制格式尚未核实，本项目不覆盖或冒充这些文件。[Grailward 的保存同步实现](https://github.com/Grailward/agent#map-exploration-sync)可交叉确认 D2R 的探索文件独立于 D2S；本地 D2MOO `PlrSave2` 没有探索格数据，不能据此宣称 `.d2xmap` 与原游戏互通。

- `client/automap_exploration.*` 唯一拥有区域探索掩码；角色权威记录、怪物、任务与 GPU 都不持有副本。`SceneView` 只推进观察者探索及绘制。
- `app/automap_save.*` 连接角色保存与客户端侧文件。F11、菜单／窗口退出保存和现有调试 `save` 均保存两者；启动选择角色、F11 读档及调试 `load` 恢复探索。
- 侧文件 JSON 格式为 `D2X automap`、版本 1，包含揭示规则标识 `d2x-visible-terrain-v2`、规范化 JSON 的 FNV 兼容校验值、角色姓名／职业，以及最多三个难度世界。每个难度保存一份地图种子、稳定原地图内容指纹和区域层。内容指纹为 FNV 输入版本 `d2x-automap-content-v1` 与固定顺序的 Automap、Levels、LvlTypes、LvlPrest、LvlMaze、LvlSub、Objects、MonStats2 原表名及原字节；不依赖本次先读角色或地形、当前区域或资源读取集合。每格一位，十六进制编码，低位对应先出现的格；尾部空位必须为零。区域层另存尺寸与原地形／房间几何指纹，首次加载时核对，不符则提示并清除该层，不向另一张地图套用记忆。
- 种子或内容不符时明确提示并不应用旧探索，保存时仅替换当前难度；另外两个难度保留。缺少侧文件的既有原生角色正常载入并开始积累探索。已知旧整房规则 `d2x-near-rooms-v1` 会提示旧记忆停用并开始重新探索，不转换旧格；下次保存将旧文件备份为 `.bak`、将三个难度的旧整房记忆替换为本轮重新积累的可见格。未知版本／规则、损坏、校验失败或角色不符会提示，保存时拒绝覆盖，不静默迁移；需人工保留／移走冲突文件。
- 文件读取限 16 MiB；单世界累计不超过 32 Mi 格，最多 512 层。两个文件各自用现有原子替换和 `.bak` 备份；两文件之间没有跨文件事务。若第二个文件写入失败，界面提示保存失败并保留游戏，D2S 可能已更新，可再次保存；不宣称两文件原子一致。

本轮不增加测试程序；按用户后续授权进行简单移动和保存重进冒烟，覆盖与未验收边界见自动地图文档。地图绘制与揭示证据边界见[自动地图](AUTOMAP.md)。

## 操作

- F11 保存角色，Ctrl+F11 从存档在城镇开始新的一局；默认路径 `saves/quick.d2s`。
- Esc 先关闭面板／对话，无面板时打开游戏菜单。选择 Save and Exit Game 才返回角色列表：角色来自列表、`--load` 或指定了 `--save` 时先保存到当前存档路径，失败则留在原会话和菜单并显示错误。Return to Game 或再次 Esc 恢复游戏，不触发保存；Options 暂不执行。`--class` 且没有 `--save` 的临时角色不自动落盘。返回列表后清除上一局的地图／存档启动选项，不把新选择的角色写回上一角色文件；关闭窗口／调试 quit 与返回列表分开处理。
- 普通图形启动先选择或创建资料片角色，所选角色在正常退出时自动保存。`--load <路径>` 直接启动载入；`--save <路径>` 设置存档路径，并在正常退出时保存。只指定 `--load` 时沿用该路径；命令行直进游戏而未指定 `--save` 不自动保存。
- `--class <MPQ 职业名>` 直接构造新的一级角色，不经过前端、不读取或自动创建 D2S；与 `--load` 互斥。测试场景可通过 `Play.cmd -Class Sorceress` 新建，或 `Play.cmd -Load <输入.d2s> -Save <输出.d2s>` 从已有场景开始并保留原档；只有显式保存才把临时角色写入磁盘。
- 覆盖前保留上一份 `<路径>.bak`。快速载入若地图种子或难度与当前进程不同会拒绝，改用 `--load` 重启。窗口关闭、调试 quit 和帧数退出均先保存有归属的角色；失败则显示错误并保留当前会话，不以抛出异常销毁未保存角色。系统强制终止、断电和进程崩溃不在此保护范围内。

## 编码和校验

- `gameplay/session/character_save.hpp::CharacterSaveData` 是角色存档值边界，不包含区域怪物、弹体、NPC 运动、地面掉落和死亡结算。`characterSave()` 只收集角色和容器物品；`persistence/d2s_codec.cpp` 与 `d2s_header/fixed_sections/stats/skills/items/inventory` 逐项写入原字段，角色内存中的短时动作不被序列化。`session_restore.cpp` 校验新角色与装备、重建内部 ID 和空白新局，再提交状态。
- 原 `GameSession::snapshot()` 和整局世界校验已删除：现有测试及联机无调用，普通沉沦魔见尸记忆被误判为复活目标曾阻止保存。怪物 AI、商店售出、NPC 路径及战斗状态均不得作为角色保存的前置条件。库存值校验与 `LootState` 的小型状态接口仍有实际用途，不与整局快照混用。
- `AA55AA55`、原版本 96、长度、原循环移位累加校验和；小端低位优先位流，属性位宽来自 `ItemStatCost`。文件上限 16 MiB。保存先在内存编码并解码验证，再使用锁目录、同目录临时文件和备份原子替换。
- `CharStats/Experience/Skills/inventory` 及物品原表校验成长、技能、装备、箱子尺寸和属性；恢复时重算装备与角色派生值。磁盘不携带或检查本项目版本指纹。

## 支持边界

- 普通品质护身符的原生单词缀字段按 D2MOO 读写，允许其未鉴定状态，不将其转换成魔法品质；魔法护身符仍保留原前后缀、属性值和需求。原图案编号用于背包显示及往返。库存另按当前原表 `carry1` 拒绝同角色背包／方块／私人箱中重复的限带暗金，旧非法重复档明确报错，不静默删物品或迁移。2026-09-26 此批修改仅静态核对，未构建或运行往返；D2S 仍为 v96，无新私有字段和规则指纹。
- 不支持普通版、D2R、专家／死亡角色头、天梯、其他幕任务属性奖励或鲁高因以外的其他幕城镇。后续扩展支持仍使用同一原版格式。
- 尸体、铁魔、镶嵌物、符文之语、无形、个性化、耳朵、Crafted、自动词缀和 realm 数据目前拒绝。原档里的已知属性值可保留，但不代表全部技能触发或属性玩法已实现。
- 本项目生成物品若含未适配的 Properties 函数或没有真实掷值的随机套装附加属性，会拒绝保存并保留原文件，不少写属性。新角色的原版菜单装备外观字节目前使用空值；本项目角色列表按实际装备合成，原版客户端外观兼容尚未验收。
- 第一幕中间阶段会归并到原版持久任务位；进入新游戏后根据任务物件恢复进度，不保证本局动画／石阵／对白阶段逐项保留。生命、耐力等按原定点精度保存。
