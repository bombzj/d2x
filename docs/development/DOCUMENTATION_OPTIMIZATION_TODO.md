## 实施约束

- 优先去重、改善导航、明确归属，再考虑新增文件；不机械按固定行数截断，不把一个完整函数契约或生命周期拆到多页。
- 叙述页建议以一个主要职责为中心，尽量控制在约200至300行、40至60 KiB内；这是软目标，完整证据、必要表格及既有兼容入口可例外。新增页面不得只是将原来一个大页换成另一个大页。
- 索引保留全量可检索入口。现有CSV适合机器查询，但不能只删Markdown、要求读者依赖忽略目录或重新运行逆向工具。结构化事实与人工结论分开；确需调整生成流程时另行确定源码归属，不在本轮新增脚本。
- 每项迁移前登记旧路径／锚点到新位置的映射；相对链接按新目录重新计算。已知仓内引用同步修改，外部引用无法穷举的入口保留旧页及锚点跳转。只有旧页标题仍在并不能保住所有`rva-*`逐行锚点，需单独评估兼容壳的体积代价。
- 版本、模块／RVA、MPQ表字段、例外和待核实项随正文迁移；共享免责声明可集中，单项限制不可省略。保留规则分析、D2X消费者和未验证边界的区别。
- 不将用户尚未提交的并行修改当作重复内容回退；迁移前重新读取受影响页并明确文件归属。默认不构建、运行游戏、打包或新增测试脚本，遵循[验证指南](TESTING.md)。

## 执行顺序与完成条件

建议先做D01小范围试点和D03高频模块入口；确认导航与链接维护成本后扩展D02，再推进D04至D07，最后处理P2。涉及同一份正文或PD2领域归属的工作顺序执行，避免多个任务同时移动同段内容。

- [ ] **内容守恒**：迁移前后逐项核对有效规则、函数／补丁记录、版本和未知项；索引按身份键核对，不只比总行数。重复记录是否有顺序意义先确认，不随意去重。
- [ ] **单一归属**：每个主题仅一处维护完整正文，旧页只保留必要摘要、兼容入口及链接；目录、基线和其他专题不新增第二套状态表。
- [ ] **链接完整**：静态核对新相对路径、标题锚点及显式HTML锚点；同步检查根目录文档、docs与源码中的引用。既有断链与本次引入的问题分开记录。
- [ ] **查找可用**：人工抽查从目录查模块所有权、从RVA查函数、从F编号查审查结论、从规则查版本与证据，均能直达目标，不依赖临时产物。
- [ ] **规模复核**：刷新候选表，确认正文阅读负担实际下降；超过建议值但保留单页的条目写明理由，不通过缩成超长行来降低行数。
- [ ] **待办收敛**：完成后在原待办勾选或改写剩余项，删除失效建议，不按会话追加过程日志。全部完成后本页只留必要维护结论或从目录撤下，不成为第二份长期架构文档。
