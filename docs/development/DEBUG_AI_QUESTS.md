# 调试AI任务配方

本页维护自动玩家的任务编排、完成判据与部分进度恢复，不定义权威玩法。命令与策略参数见[使用入口](DEBUG_AI.md)，公共动作见[执行契约](DEBUG_AI_RUNTIME.md)，原版规则见[任务系统](../gameplay/quests/SYSTEM.md)。

## 条件图与恢复

五幕27项任务共用事实条件图。节点先核对自身是否满足，满足则剪去整段依赖；就绪动作按当前区域、实际目标位置及旅行估价选择，保留已提交操作和有效接近。队列顺序来自[默认配置](../../config/debug-ai.json)，不是任务面板编号；`questNumber`始终为`QuestDefinition.displaySlot + 1`。

事实来自个人原任务位、实际库存、当前场景、个人传送点及本局观察。尸体可证明目标已死，不能证明个人击杀归功；共享物件模式不能代替个人资格。已领取目标跳过；本局明确COMPLETEDNOW／状态12且无个人奖励、待奖或主目标资格时标为`skipped`，保留原因，不能把导航失败当成不可完成。

同局保留实际消费、阅读和见证的不可逆结果，补给后重新核对条件再选目的地。新游戏不恢复旧GUID、尸体、波次或未决请求；真墓线索须重新取得本局消息。后幕可通过正常旅行补办前幕任务，无通行资格明确失败。

任务计划先收妥实际Cursor，并通过正常容器操作取回可访问材料；玩家交易中拒绝启动。合成节点指定本幕城镇，先旅行后交给库存工作流，这是AI策略，不限制玩家野外合成。收纳、清理权限与结果确认只维护在[物品工作流](../modules/INVENTORY.md#客户端物品工作流)。

默认保留恰西灌注、拉苏克镶孔和安雅个性化次数。启动或单个quest显式设置`useServiceRewards:true`才继续服务；不改变REWARDPENDING的原意。仅选择背包内合格备用`cap`，不使用当前装备、不生成材料；灌注要求normal且无孔，镶孔／署名另验服务资格。产物与Cursor收妥后才完成，未知结果不重放。

NPC配方只声明所需对白，不插入欢迎前置。自动台词沿普通客户端入口结束；可选menu2仅选配方列出的主题，缺席可让出，但不证明任务推进。必要交物／领奖／通行须等各自结果；关窗后可正常查询私人位，不能靠任意修订或非零日志状态结案。任务完成后的Q日志预览属于界面操作，见[事件参数](DEBUG_AI.md#事件参数)。

`questPlan`显示根依赖、满足状态、就绪动作和选择原因；`questProgress.mode=conditions`时`step`是节点索引，不是递增进度。诊断字段见[现场读取](DEBUG_AI_DIAGNOSTICS.md#状态与事件)。
