# 客户端调试任务AI

本功能把一次高层目标或目标队列转为正常客户端操作。它属于app/debug，默认不启动；只在图形客户端调度，headless入口不执行该AI，不构造另一套战斗、掉落、任务或存档规则。现有单目标行走仍见[调试管道](DEBUG_PIPE.md#客户端自主行走)。

单机专项调试可加`--no-pause-on-focus-loss`，AI完成或取消后也不会因窗口失焦停住已提交请求；ESC菜单及显式暂停保留，见[启动参数](BUILD_AND_RUN.md)。

五幕共27项任务配方。固定81762E77版已用99级女巫在原版Host普通难度，从空任务档单进程、单次计划自主完成27项及39个传送点，真实终局、正常保存和重入通过；三项服务奖励保留。特殊恢复组合、低等级及其他职业／难度不随之认证。[测试条件与结果](AI_TEST_REC.md)

文档分工见[AI文档导航](../README.md#调试任务ai文档)：本页维护指令、策略、任务配方、复用边界和实现入口；[AI测试记录](AI_TEST_REC.md)维护角色准备、测试条件、结果与取证补充；[调试管道](DEBUG_PIPE.md)维护命令传输及现场读取；[构建运行](BUILD_AND_RUN.md)维护启动；[原版缺口](ORIGINAL_GAPS.md#待验收调试导航)维护当前阻塞及待验收项。权威任务规则仍归各幕玩法文档。

## 全链路问题的共用恢复

公共恢复契约如下；对应问题及新增路径的验收边界见[测试记录](AI_TEST_REC.md#本次修复与仍未解决的问题)。

- **动作恢复与药剂分开调度**：RemoteScene读取当前MPQ动画及普通人物投影的FHR／FBR／FCR，观察施法、攻击、受击、格挡和击退的实际动画结束；伤害回包本身不等于进入受击动作。AI恢复期继续观察死亡、换区、任务／库存／药剂结果及生命变化，并允许普通药剂Use入口；暂缓新的独立施法、交互、换装、目标选择和重寻路。持续技能续按保留原输入语义。动画解除阻塞的首次前端观察帧直接唤醒决策，不再加固定思考间隔；这不是对异步Host恢复帧的保证。缺原动画时保留未知并沿已有施法信号，不编造时长。诊断为`actions.actionRecoveryBusy`。药剂Use按MPQ类型准备独立能力，会话不再因施法回包未到而拒绝已确认的生命／法力／回复药剂；仍等待已有物品消费结果，不并发买药或重放消费。子导航同时暂停输入与无进展计时，已提交操作的现实期限不变。
- **交互恢复**。客户端和 Host 仍在接近目标时保留打开请求。停在范围外且没有进展时，按单位身份和当前碰撞重新选择接近点。只有实际菜单或物件回包才能确认结果。详见[公共操作与部分进度恢复](#公共操作与部分进度恢复)。
- **整数指针与移动技能**：行走输入复验沿原`nativeMovementTarget`进入格碰撞，允许离开被后来占用的起始格；首个折点量化失败时继续检查真实后续路径节点，不扩大通行规则。暂时没有路径的child保留已有15秒无进展及总预算，让父级职业移动有机会接管。传送优先选择实际单位的合法交互周边站位，并核对已加载邻房、碰撞、距离和危险，不要求先找到通向不可站立物件中心的步行路线。
- **旅行恢复**：只为实际提交的门户／出口记录源区域、单位指派、请求修订和本人位移代次。原等待到期后，只有新本人位置仍属于源区域、未发生位置不连续、门户仍为同一指派，才允许至多两次重新接近／点击；无新证据继续明确失败。普通跨区、任务门户、自有返城门和补给回程共用，不重放开门施法、卷轴消耗、购买、领奖或同层传送台。历史type5在3秒时仅凭本地位置再点的特殊分支已删除。
- **传送点记忆**：AI仅保留`knownWaypointAreas`这一份决策用解锁记忆，激活判断、旅行候选、任务Waypoint条件和preferWaypoint均消费它；删除旧的独立激活抑制集合。尚未收到个人总表时在城镇正常查询一次63；本人中立传送点点击后的实际激活回执直接增量加入，不为刷新总表额外开菜单。正常跨幕到达的城镇沿原SUnitNpc／ObjMode自动解锁规则加入旅行记忆，数据索引取MPQ Levels。实际使用传送点时收到的新63一次性校正记忆；旧63快照不能在下一帧覆盖后来的激活。记忆跨同房间计划重启保留，新游戏清空，诊断为`waypointMemory`。该记忆只用于决策，不写协议副本／D2S；最终旅行仍由真实菜单和Host裁决。
- **机关阶段**：Operate34／66的激活请求与旅行请求分开；OPERATING不满足OPENED。静默ENDANIM使用RemoteTown和显示／碰撞共用的MPQ期限投影，既不等待原版不会额外发送的模式回包，也不写回副本或提前判定旅行成功。

## 场景记忆的归属

探索回溯将最终待探房间与图搜索选中的中转坐标分开保存。分段移动保持该中转目标，抵达后从新位置重算房间路线；已知路段不以新增开图作为唯一进展。单次中转在无新增观察时记录经过位置，检测返回旧位置并暂缓该目的房间，沿已有重试／新覆盖条件恢复。日志为exploration-backtrack-relay-reached与exploration-backtrack-cycle；新修复尚未构建、实测。

当前计划的待拾物品见调试状态 `rememberedDrops`。任务步骤切换、战斗和临时离区都保留已见目标物品的区域、坐标与单位号。启动新计划时清空记录。返回后以当前指派发起拾取，以实际持有结案；已回到来源房间且短等后仍未见物品时，撤销这条位置记录，恢复任务原有的寻找流程。

位置与地形继续复用RemoteTown现有导航记忆：已见NPC／目标位置、入口连接、传送点坐标和房间探索记录按地图配置、各幕种子与布局匹配，跨区保留；坐标只引导重新接近，当前交互仍需真实指派。多只同类怪物不能靠按类型保存的单个坐标代表整个群体。

动态清场记录统一由`populationMemory`维护，替换原QuestRun内的房间／剩余敌人集合。按游戏、区域及幕种子保留真实房间订阅、各GUID最后位置与指派身份，跨任务步骤、补给和同房间计划重启保留；新游戏或该区域种子改变清空。死亡模式删除敌人线索，身份替换／已知阵营变化复验；退订不当成死亡。重新订阅同一房间也重新等待250毫秒单位消息，之后清场只失效已重新订阅且不再指派的旧线索。当前单位优先于历史位置，旧位置不能授权攻击、任务完成或断言房间永远无怪；新指派／复活可再次进入记录。记录在AI观察运行期间更新，不持久化动态GUID到导航存档，不推测服务器从未发送的怪物。

旅行先找本层当前指派的传送点，再使用已见坐标。到达记忆位置后仍无可用指派且有普通路线时，这趟旅行暂缓使用该来源。实际指派可以重新启用它，目标解锁记录保留。同一趟旅行连续两次无法接近同一方向的徒步边界时，把折返成本计入路线比较，可经其他相邻层或已解锁的传送点绕行。诊断`populationMemory`给出当前区域的房间与敌人线索数，`waypointMemory`给出决策用解锁区域及最近完整63修订。静态导航持久化沿原格式，本次不改变存档语义。

跨幕旅行若当前层无传送点且无已知直接路线，先用普通回城流程取得实际来源。新进程尚未物化目标幕连接、无法估算任何完整路线时，可先到本人已解锁的目标幕传送点观察，再从实际到达区域重新规划；诊断为`observe-destination-act-via-unlocked-waypoint`。有可估算的合法路线时优先按原成本比较，同幕不使用此观察中转，目的地资格仍由实际菜单和Host校验。

毁灭前夕在新局先按已有资格尝试山顶门。547 中立门拒绝本次开门并对本人发出声音 19 后，AI 使用真实祭坛、阅读 20002、确认三名古人的死亡，再尝试进入要塞。离开山顶或试炼重置后重新观察。王座的实际 563 门可作为普通旅行入口，565 终局门由终局任务单独使用。复现现场与验收状态见[验收记录](AI_TEST_REC.md)。

赶路已具备 Teleport 能力时跳过沿途可选战斗，法力不足仍先走药剂／补给策略；任务必杀、清场及指定掉落搜索不受此策略跳过；多区域掉落搜索按当前已配置搜索目的地派生leaf区域，不能因step.area为空误判成普通赶路。冰甲按当前 MPQ 技能与真实 aurastate 维护，危险避让优先于补甲。飞弹躲避只保留首领／已核高危来源，或预计交汇至少3枚、低血、近期明显掉血时的威胁；这是 AI 策略，不是原版伤害计算。

第二幕读日志后先使用现场红门并确认峡谷传送点，再回城做后续评论。庇护所仍有待探房间、当前分支已无可达落点，或绕回中心更短时，可用蓝门回城并从已解锁的中心点继续原任务。保留已探房间，同一来源房间在没有新增庇护所探索格时不重复消耗蓝门。已获本局真墓符号时，按共享的原版固定峡谷预设及当前 MPQ 的 DS1／Warp 坐标引导正确墓口；提示不暴露真墓答案、不解锁地图，也不代替入口实际指派。

室外探索在常规房间采样把脚下房间判为孤立时，检查其已加载邻房中实际位于一跳范围的可站格（诊断 `directNeighborLandings`）。仍有待探房间却没有可用观察路线时，允许回城并从本区已知、已解锁的传送点换起点；同一步骤须有新增本区覆盖才可再次使用。普通房间回溯先于回城，现场等待任务结果或固定战斗时保留原任务位置。

## 输入与组合

任务默认只完成目标、交付并取得奖励资格，保留恰西灌注、拉苏克镶孔和安雅个性化次数；不为完成任务购买材料或自动消耗这些服务。原版REWARDPENDING／可用资格保持原值，不改成已消费。只有明确测试服务时，在启动请求或该quest目标写`"useServiceRewards":true`，才继续原Take／QuestService／Place并检查实际产物；status.goals显示该选项。它不属于运行中策略重载项。

`debug-ai-start` 的 `"activateAllWaypoints":true` 按 MPQ Levels 标记有传送点的区域。当前区域的任务可继续，准备走出口、用门户、返城或跨幕时须先确认本区传送点已解锁。完整五幕计划把未途经的支线点分幕安排在各幕最终任务前，已确认的目标直接跳过。短计划同样要求全部点，仍须满足实际通行条件。此策略默认关闭，只在启动时设置。

### 文件配置与运行中重载

`config/debug-ai.json`提供七职业技能、战斗距离／后撤／无进展恢复、远程施法后换位、可见弹体避让、职业移动距离及补给数量的示例策略。启动时显式传`configFile`；绝对路径直接使用，相对路径优先拼接EXE所在目录，那里不存在才按进程工作目录查找。找到的EXE旁文件读取／解析失败时直接报告错误，不改读另一个同名文件。限制64KiB UTF-8 JSON对象；命令中显式参数递归覆盖文件默认值。文件也可提供已有高层goals／scenario等计划字段，仍走同一校验和正常客户端输入，不保存新的任务真值。

`combat.byClass` 支持 `amazon`、`sorceress`、`necromancer`、`paladin`、`barbarian`、`druid`、`assassin`，每组可配置 `skill`、`fallbackSkills`、`aura`。启动时按本人实际单位职业选组：文件公共配置 → 文件当前职业组 → 命令显式覆盖；命令也可提供职业组，其组内项覆盖命令公共项。未配置当前职业组时保留公共配置；职业未知时拒绝分组配置，不猜职业。`configuration.characterClass` 显示本次选择。

主／备用攻击均接受技能名、ID或 `{"skill":"Frozen Orb","minLevel":5}`；`minLevel` 默认1、范围1–255，比较正常客户端已观察到的有效技能等级（含装备／状态加成），先天普通攻击按至少1级处理。例如女巫组可写：

```json
"sorceress": {
  "skill": {"skill": "Frozen Orb", "minLevel": 5},
  "fallbackSkills": [{"skill": "Ice Blast", "minLevel": 3}, "Fire Bolt", "Attack"]
}
```

出城前按主／备用顺序选择首个满足有效等级和手别的主动技能，整次出城锁定；冷却、状态、缺蓝及目标变化不触发备用。回城后重新选择，野外启动时初始化一次。实际施放仍检查资源与目标资格。未知技能、被动、攻击列表中的光环及冲突门槛拒绝；普通攻击仅在明确列入时作为备用。七职业示例不代表召唤管理、陷阱数量、蓄气连招或完整通关均已验证。

```powershell
& scripts/Send-D2XCommand.ps1 -Command debug-ai-start -Arguments @{
    configFile = 'config/debug-ai.json'
    goals = @(@{action='quest';quest='eve-of-destruction'})
    combat = @{skill='Frozen Orb';fallbackSkills=@('Ice Blast','Fire Bolt')}
    mobility = @{mode='teleport'}
}
# 编辑策略文件后，作用于下一次正常决策；无需编译或重开计划。
& scripts/Send-D2XCommand.ps1 -Command debug-ai-reload-config
```

显式重载沿用最近成功加载的文件，也可另传`configFile`或数值覆盖。仅接受combat的数值策略及rangedKite、mobility.distance、supplies的数值阈值／数量及下文events策略；重载忽略文件中的 `combat.byClass`，保留当前计划技能顺序与最低等级。更换职业组、技能／门槛、目标、移动模式及补给开关须重新下发计划，显式请求修改这些项仍拒绝。包含goals等计划字段的campaign文件仍不能作为运行中数值重载文件。解析／边界错误不会部分应用；实际学习技能、计划进度、已提交的交互／采购／施放及其结果期限保持原契约。`configuration.file`记录成功加载的绝对路径，后续不带路径重载仍读这个文件；各策略快照可核对本次配置。原版规则／资源、协议与任务条件图不由该文件改写，文件不自动轮询；事件策略增量尚待运行验收。

不需要逐步给坐标、GUID、施法目标、门或NPC消息编号。入口通过游戏内聊天或现有Send-D2XCommand.ps1发送，任务在游戏主循环中持续执行；命令返回只表示计划已接收。当前位置、目标、进度和失败原因通过status观察。当前支持原版1.13c客户端配置，不将零售任务配方套用到PD2。

### 一条聊天命令安排五幕

独立配置[debug-ai-campaign.json](../../config/debug-ai-campaign.json)包含按顺序的27项完整任务、七职业主／备用技能、自动职业移动、正常补给及每任务3600秒预算；女巫组仍优先Frozen Orb，移动能力允许时使用Teleport。不依赖artifacts测试目录，也不自动合并debug-ai.json的后续编辑。七职业配置不扩大既有强力女巫运行验收范围。入局后输入：

```text
/debug-ai-start {"configFile":"debug-ai-campaign.json"}
```

可将JSON直接放在d2x.exe旁，命令只写文件名；相对路径先从EXE所在目录找，不存在才查工作目录。链接d2x后会自动补齐EXE旁缺少的debug-ai.json与debug-ai-campaign.json，不覆盖已有同名文件，以保留用户修改；更新源码默认配置后如需采用新默认值，应自行替换运行副本。原项目目录下config/debug-ai-campaign.json的相对写法仍可在Play.cmd设置的项目工作目录中回退找到，也可显式给绝对路径。Windows路径可用正斜杠。命令在255字节聊天限制内，一次性接收27目标，不需要在前幕瞬间跳过之前追加后幕。运行中查看、暂停、继续分别为`/debug-ai-status`、`/debug-ai-pause`、`/debug-ai-resume`；已有活动计划不能再start，先按实际需要cancel，且须等待已提交物品／门户结果。

重跑任务使用独立工作存档，保留原始基准；角色准备与初始资源限制见[测试记录](AI_TEST_REC.md#角色与取证约定)。

已有部分进度也可用同一命令：第一至第五幕均按实际条件选择剩余工作。已完成目标按个人记录跳过；本局明确COMPLETEDNOW且无奖励／待奖／主目标资格的目标记为skipped，保留原因并继续，不写任务位或声称领奖。Cain已不可再救同样明确跳过。任务在其他幕时使用正常城镇传送点及实际个人63资格返回该幕，不再要求手动把人物停在最早任务所在幕；无合法通行资格仍明确失败，不能把导航失败／超时当作本局不可完成。退出重开后，真墓线索、怪物、门及波次按当前房间重建；私人材料／奖励资格保留。需要的个人材料可正常从私人箱／方块取回，任务计划启动时会先收妥真实Cursor；未知形状、满包或未知操作结果保留现场。实现与本批验收范围见[缺口清单](ORIGINAL_GAPS.md#本批验收清单)。

### 游戏内聊天入口

图形客户端入局后按Enter输入，可用Ctrl+V将复制的命令粘贴到当前光标，再按Enter提交；粘贴的换行／制表符转为空格，每条命令分别复制提交，仍受255原生字节上限约束。无需启用调试管道。剪贴板、编码边界和输入法组合的验证范围见[测试记录](AI_TEST_REC.md#下一轮重点)。

```text
/debug-ai-start act1
/debug-ai-start act2
/debug-ai-start quest search-for-cain
/debug-ai-start act1 {"mobility":{"mode":"teleport"},"combat":{"skill":"Frozen Orb"}}
/debug-ai-status
/debug-ai-pause
/debug-ai-resume
/debug-ai-cancel
/debug-help
```

上例的start是不同计划的用法示例，不能在已有活动计划时连续替换；结束后再start，或先cancel。任务前置、金币、技能资格和验收边界与管道一致；可保留的服务奖励默认不消费。

`/debug-ai-start <scenario> [JSON options]`与`/debug-ai-append <scenario> [JSON options]`接受原scenario简写。`quest <任务名>`显式生成单项quest；`/debug-ai-start quest tools-of-the-trade`与兼容入口`/debug-ai-start tools-of-the-trade`默认均交回马勒斯并保留灌注资格，仅显式useServiceRewards=true才继续使用服务。复杂目标直接传JSON对象，字段与管道Arguments相同，不传command；例如：

```text
/debug-ai-start {"goals":[{"action":"restock"}]}
/debug-ai-append quest sisters-to-the-slaughter
/debug-ai-start {"goals":[{"action":"hunt","monster":"smith"},{"action":"acquire","item":"hdm"},{"action":"return-town"},{"action":"deliver","quest":"tools-of-the-trade"}]}
/debug-walk waypoint
/debug-walk exit {"level":2,"interact":false}
/debug-walk-status
/debug-walk-cancel
```

JSON须用双引号，保留聊天原生编码后255字节的输入上限；更长目标队列继续用管道。append继承当前计划的策略，不接受新的combat／mobility／supplies。无参数的status／pause／resume／cancel不接受附加内容。名称不区分ASCII大小写；未知`/debug-*`与格式错误在本地报告，不发房间广播或BNCS命令。

应用在`app/debug/chat_command`解析后共用原DebugAi／DebugAutoWalk入口；聊天只显示状态、目标、阶段、任务内部步骤及原因摘要，完整快照继续用管道。反馈以`[Debug]`标记进入本地顶部消息和M日志，另持最多64条，不写世界／账号聊天副本，不作为服务端完成回执。失败保留输入草稿。打开聊天、消息日志及其编辑／关闭帧保留AI计划并阻止新输入，关闭后继续；显式pause须resume。已有动作和宿主时钟不会因查看聊天而暂停，死亡仍会停止计划。

一次安排第一幕全部六个任务，优先使用角色已有的传送和固定战斗技能：

```powershell
.\scripts\Send-D2XCommand.ps1 -Command debug-ai-start -Arguments @{
    scenario = 'act1'
    mobility = @{ mode = 'teleport' }
    combat = @{ skill = 'Frozen Orb' }
}
```

这会按任务日志顺序执行六个高层目标，最后经瓦瑞夫的正常Go East服务到达鲁高因。使用下文独立女巫配方准备全新任务、正常补给资金；不需要灌注材料。已有存档按实际条件跳过已完成目标，保留服务奖励。仅做某项时使用`goals=@(@{action='quest'; quest='search-for-cain'})`；六个名称与完整完成条件见[第一幕任务配方](#第一幕任务配方)。

原有仅交还马勒斯、保留灌注奖励的入口继续保留：

```powershell
.\scripts\Send-D2XCommand.ps1 -Command debug-ai-start -Arguments @{
    scenario = 'tools-of-the-trade'
    combat = @{ skill = 'Frozen Orb' }
}
```

也可组合高层目标；已知铁匠、恰西和马勒斯的位置／来源提示会自动补全：

```powershell
.\scripts\Send-D2XCommand.ps1 -Command debug-ai-start -Arguments @{
    goals = @(
        @{ action='hunt'; monster='smith' }
        @{ action='acquire'; item='hdm' }
        @{ action='return-town' }
        @{ action='deliver'; quest='tools-of-the-trade' }
    )
    combat = @{ skill='Frozen Orb' }
    goalTimeoutSeconds = 600
}
```

区域使用当前MPQ的Levels.Name（可省略“Act 1 - ”一类前缀），单位使用MonStats.Id、物件使用Objects.Name，`superunique`使用SuperUniques.Superunique／hcIdx并核对其Class和实际分配包身份，物品使用原代码，技能使用Skills.skill；匹配不区分ASCII大小写，歧义与未知资源明确拒绝。也接受已存在的数值身份。没有位置提示的目标可给`area='Barracks'`等粗粒度区域；不要求调用方指定路径。这里是结构化目标接口，不解析自由文本自然语言。

| action | 目标及参数 | 实际完成条件 |
| --- | --- | --- |
| travel | 必填area | 目标区域的原生场景已就绪 |
| find | monster／npc／object／superunique四选一；可给area；NPC可interact=true | 真实单位已指派并接近；要求交谈时观察到该NPC对话 |
| hunt | monster或superunique；可给area | 指定真实身份出现死亡模式；已存在的尸体可满足“目标已死”，不声称个人击杀归因 |
| acquire | item；可给area及source物件名 | 对应物品实际归本人所有，包含原任务查询允许的根库存／cursor范围 |
| return-town | 无必填参数 | 本幕真实城镇场景已到达 |
| deliver | quest语义配方；当前只有tools-of-the-trade | 对应物品已被消费，且真实角色任务奖励位已更新 |
| restock | 无必填参数；使用supplies配置 | 正常回到本幕城镇，实际可用红／蓝药数量达到储备目标；显式目标完成后留在城镇 |
| quest | 已登记的第一至第五幕quest名；自动解析区域，不接受area | 完整执行该任务配方并观察原角色奖励位；前四幕幕末另要求实际抵达下一幕及原跨幕完成位，第五幕要求实际终局结果 |

整个计划最多32项目标，quest默认每项1800秒，其余每项600秒，可用goalTimeoutSeconds或各goal.timeoutSeconds设置10–3600秒。没有完成当前目标不会执行后续目标。一次请求先完整解析／校验，再接收计划；append同样先校验整批，不部分插入。

| 命令 | 行为 |
| --- | --- |
| debug-ai-start | 接收scenario或goals；接管独立debug-walk；已有活动计划须先cancel或使用append |
| debug-ai-append | 给现有running／paused计划追加goals；继承原战斗／移动／药剂策略，不接受新的combat／mobility／supplies配置 |
| debug-ai-status | 只读状态、当前 goalIndex、完整队列、phase／reason、questProgress、决策及请求计数、目标和最近 128 条事件。behaviorLog.file 给出本计划日志的绝对路径，behaviorLog.error 给出写盘错误。navigationDiagnostics 保留最近的候选诊断。 |
| debug-ai-pause | 停止本AI输入及技能动作，保留队列／已发请求的观察状态；不暂停宿主 |
| debug-ai-resume | 同一游戏、区域及区域代次内恢复；暂停时间不计入本步期限；暂停中换区须取消并建立新计划 |
| debug-ai-cancel | 终止计划并沿正常客户端Stop停动作；不撤销已经发生的拾取、死亡或交付 |

### 事后查看行为日志

启动计划时自动创建 UTF-8 制表符分隔的 `events.log`，游戏内输入 `/debug-ai-status` 可看绝对路径。默认在工作目录的 `logs/ai-<启动毫秒>/`。启用 `--game-packet-log` 时，计划目录放在客户端抓包文件旁。追加目标、暂停和继续沿用同一文件，新计划另建目录。写盘失败会在状态中显示原因，AI 仍可运行。

每行依次为计划内经过毫秒、历史序号、目标索引（从 0 起）、区域、本地脚点、最近 Host 脚点、事件、详情。缺失值用 `-`，详情中的换行和制表符转义。文件头记录启动 Unix 毫秒。带序号的事件可对照状态快照中的 history，额外的阶段与导航记录没有历史序号。

排查停顿可先找 `failed` 或 `walk-failed`，向上看最近的 `goal-started`、`quest-condition-selected` 和 `walk-goal`。`phase+` 记录本次决策留下的阶段及原因，同一阶段和原因不会逐帧重复。`phase-` 给出持续毫秒。导航失败另记移动请求数、搜索续算次数及最后目标。同一行的两个脚点是当时可见的采样，Host 坐标可能滞后。各行写完即刷新，正常退出时仍活动的计划记作 `session-ended`。

人工移动／施法点击、技能与装备切换、饮药、观察面板关闭之外的ESC、显式独立debug-walk、修改客户端状态的online-*请求（online-chat-input按实际本地命令分流）、退出或换游戏接管控制。Tab、小地图平移／显示及只读观察不取消计划；人物、包裹、任务、聊天和消息日志等观察面板保留计划并暂停AI输入，关闭后继续。Q面板内点击切换任务及Escape关闭均保留计划，面板外的世界操作仍接管控制。管道ui-input同样按实际意图判断。最小化、表现暂停及游戏菜单阻止AI输入。计划只在内存中保存，不写D2S，不在新游戏恢复旧GUID、目标或请求。死亡停止任务，不添加自动复活。

| 层级 | 职责 | 实现入口 |
| --- | --- | --- |
| 目标队列与任务依赖 | 选择当前目标，根据角色任务位、库存和场景重算仍缺的步骤 | `DebugAi`、`ai_quest_graph.cpp` |
| 动作执行与恢复 | 接近、开门、拾取等动作分别记录目标和预期结果。恢复时先核对实际状态，再决定继续接近、等待回包或结束动作 | `DebugAutoWalk`、`QuestPending`、`WorldWait`、`rememberedDrops` |

等待世界结果与回收已知掉落共用 `resumeAction`。任务图选择步骤，执行层保留当前要等或要取的目标，即时反应可临时接管移动和战斗。恢复时重新执行当前步骤的状态判断。切换任务步骤会结束旧动作，同局掉落记录可供后续步骤使用。状态中的 `actions.continuation` 显示恢复类型。

| --- | --- | --- |

| 回收已知掉落 | 记住物品身份、区域和位置。战斗结束后重新接近，回到原房间时等待重新指派 | 提交拾取后独立观察请求序号与本人库存。房间已重新订阅而物品持续缺席时撤销该线索。未确认归属的请求超时会停止 |

### 自适应决策节奏

[decision_cadence.hpp](../../src/app/debug/decision_cadence.hpp)分离决策、输入重试与玩法时钟。危险／接近路径末端约40ms复核，交战或近身敌对威胁约80ms，稳定导航约160ms，空闲规划约250ms，被动等待／暂停观察最多500ms。实际生命下降、区域变化、库存／任务／对话／技能／交互结果、当前敌人的生命及动作变化可提前唤醒；通常合并40ms内的观察，紧急变化可缩至20ms。关键期限可提前唤醒，后台寻路未就绪时在下一显示帧观察结果。网络到达与显示帧仍决定实际响应延迟，以上不是硬实时保证。

子导航另观察停止／移动、目标移动、当前碰撞修订及距段尾距离，路径结束附近及时续接，稳定长段不因每次人物位置采样重做完整求路。输入受理前重试及无原技能延迟时的调试攻击间隔仍独立使用200ms；不加快原版动画、冷却或服务端25Hz规则。status的`decisionIntervalMs`表示当前模式周期上限，`scheduler`另列唤醒原因、eventWakeups、timerWakeups及searchContinuations，不能把它当作每条C2S的发包间隔。

### 事件观察与现场保持

等待门切换模式、任务入口出现或祭坛召怪时，AI 可处理身边的威胁，沿用正常战斗的换位、拉开距离和避险。需要角色留在触发区域的事件保留原有活动范围。每次继续等待前先核对事件结果，开门后即可通行。需要击杀指定敌人的遭遇仍按自身条件推进。

[ai_events.cpp](../../src/app/debug/ai_events.cpp)共用处理实际门户／入口可用、NPC指派、首领出生／恢复可攻击、遭遇结束及终局通知。`QuestRun.worldWait`是可中断的被动观察，独立于`QuestPending`中已经提交的物品／剧情操作。配方声明实际完成条件、见证者、可选等待时间及已核实的相对偏移；例如都瑞尔入口的(-13,+3)由第二幕配方提供，公共等待器不硬编码幕／怪物／物件ID。未观察到的出生位置不推测，未收到通知不当作成功。

等待以开始时的执行时间预算计时，面板／暂停停计，结果仍在暂停期间观察。遭遇等待按现场的新敌对指派、已跟踪敌人的死亡或净生命新低续期。王座步骤另外识别当前见证者的 S→C 2C 事件 16，并在首次被动等待两秒后或收到该事件时检查仍在本层已加载房间的残怪。补查按 Fn134 的 64 单位界限和见证者的 MPQ SizeX 计算距离。阶段声音只触发观察，入殿仍需真实状态与门户；同一敌人一直存在、离开指派范围、无关怪物／状态包和玩家移动均不续期。不把“出现敌人”记成“门户已开”。最多跟踪256个指派身份，达到上限仍受原等待及高层目标预算约束。`worldWait`诊断包含实际区域／锚点、expected、progress、lastProgress、trackedEnemies与剩余时间；受理回执仍由各操作自己的现实期限处理。

见证者第一次实际位置固定为当前遭遇锚点，NPC离场移动不拖动锚点。观察站位按多个半径、当前碰撞、射线、危险和真实可达路径选择，并保留选中的接近目标；未到位不标记已锚定。必清范围以锚点为中心，远处无关敌人不自动升级为必杀。战斗换位／撤退／避险落点限定在当前已加载区域，遭遇期间保留现场范围；已被打散时允许向现场返回。待事件及已锚定阶段不插入可选传送点激活。补给可以中断被动观察，回来重新观察；已提交剧情／库存操作仍须先消费真实结果。

配置文件及显式重载接受`events`数值策略，append继承原策略。`waitSeconds`默认90（15–300），`encounterRadius`默认32（12–64），`standoffMin`默认8（4–20），`standoffMax`默认24（8–40）；要求min < max且max + 3 ≤ encounterRadius。距离是客户端原生格单位，只决定调试输入，不修改玩法触发距离。配方的`resultWaitSeconds`覆盖默认等待；已开始等待冻结自身秒数，热重载不延长现有期限。这些策略不允许配置私人任务位、原物件资格或未观察的位置。

任务门户的“等待出现／可交互”和“点击后等待换场”共用上述预算，首次已知事件等待或实际点击开始计时，重试／热重载不续期；搜索尚未知的门不消耗此事件预算。点击后保护移动／技能输入，避免冰甲打断服务端接近；仍在同一已加载源场景、同一指派可交互、显示脚点已在交互范围且停稳时，每3秒经普通交互入口重试，不要求额外位置纠正包。实际换场优先结束等待；到期明确失败。第四幕配方增加原版泰瑞尔X+5出生见证点；城镇间任务门户先跨幕，补给留到下一次出城，避免开门后绕访商人。补给启动日志以heal／hp／mp／tp标明治疗、红药、蓝药、回城书不足的具体触发项。上述修复为源码逻辑，events.waitSeconds仅控制预算，默认90秒；未构建／运行。

条件图在已提交请求等待和暂停期间仍观察明确允许保留的事实；尸体事实核对来源区域。保留观察不代表可重复领奖，也不替代实际交互时的新指派。缺少任务旗标、最终结果或可执行分支时仍检查高层目标总期限，不再因准备阶段提前返回而无限等待；准备未就绪时允许正常饮药、避险和防御。新事件机制不负责修复缺少的宿主任务消息。

显式暂停保留已提交职业位移的目标及现实期限；前端对暂停计划继续提供只读资源／技能投影。治疗结果在观察阶段记录，暂停中看到真实生命回满后，不因恢复输入前上限变化或再次掉血而否认这次结果；NPC关闭与下一项补给仍等待输入恢复。没有实际治疗观察时仍按原期限失败。

战斗站位按射程和威胁评分；步行验证接近路线，传送验证落点。狭窄地形中的近距离合法射击位可以成为后备，不再被首选远程距离硬排除；步行路径检查采样段上的已知危险，缺蓝／装备状态明确不可用的Teleport不作为可执行移动能力。技能射线掩码按已选出城技能从当前MPQ预备索引读取；普通接近也登记已选站位，近战站位要求实际靠近到一格内。效果观察从该策略首次受理施放开始，技能选择等待不凭空算作已经攻击无效；总战斗无进展预算保留。

自动成长目前仍只具备任务、战斗、真实取物及补给的操作底座，没有自动练级路线、属性／技能分配或通用装备估值／换装策略。后续消费者应以实际等级、技能、库存及资金作为事实，通过相同正常命令与结果确认推进，不能靠此轮策略参数补造掉落、装备属性或通关能力。

### 导航与动作执行

战斗区分必要击杀与可绕行交战：明确Hunt目标、真正Clear步骤及已到场的Encounter清场才将击杀作为必要条件；SearchDrop允许搜寻掉落时交战，但不把每个遭遇者升级成必杀。拾取连枷／熔炉锤及救囚不再要求清空周边区域；默认defensive仍按近身威胁与实际任务目标附近的敌人决定介入，沿途无效交战可暂避。零售客户端已观察到的Submerge起手按当前MPQ的srvstfunc51排除活体攻击资格，Emerge不排除；该判断共用正常目标入口，不根据无伤害猜测免疫，也不按地图或怪物ID加黑名单。

元数据在第一次start／append时按当前挂载惰性读取，未启动AI不额外加载这些表。房间、碰撞、单位、库存、技能和任务状态均来自正常客户端副本／重建；不读取GameHost、server-snapshot、服务端隐藏位置或本地存档，不调用管理旅行、生成、伤害、授予技能、回血或解锁。

同一旅行目标保留选定的区域序列，按真实换区推进，避免局部估值在相邻区域之间反复改选回头路。目标变化、实际偏离、解析连接否定下一段或接近明确失败才重规划；补给／新目标重置旅程。已有普通路线时，传送点捷径不返回本次旅程已访问前缀；没有普通路线时仍允许全部合法传送点恢复。`travel.route/visitedAreas`及规划／失效／偏离事件用于定位，不写任何原版旅行资格。

旅行按本幕已解析的Vis连接、实际指派出口／门户及合法传送点规划路线，包含崔斯特瑞姆红门回程。步行先到真实开口再正常跨界，warp使用实际单位；区域改变后重算连接，已提交的warp／传送点先等真实结果。传送点资格统一消费[解锁记忆](#全链路问题的共用恢复)。跨幕使用瓦瑞夫／马席夫服务、HellGate及Harrogath门户；第五幕入口仍由真实机关与任务资格裁决。

门户旅行收到提交之后的本人0x15，若仍在原场景已加载房间、原门户指派未变且纠正后已停在交互范围外，可提前恢复正常接近，不空等15秒。普通旅行、任务入口、自有蓝门及补给返程共用此恢复，每个来源／指派最多两次；游戏／区域代次、来源身份、存活、可交互性仍逐项复验。换区、换门及同层传送台不据此重放；实际到达仍须目的场景确认。

门、NPC、物件、拾取及门户共用原交互几何和动态碰撞。开门接近固定当前目标，按GUID／指派代次等待实际模式；同一门持续关闭12秒明确失败。身边已有可交互目标时先完成，不被远处开门抢占；门操作不充当物品或旅行结果。

单位接近先选可达交互周边，再调用正常RemoteControl完成最后跟随和点击，持续移动期间不逐段覆盖。城镇远距接近已指派单位时，沿已知路线寻找进入逐轴 50 子格点击范围的站位。NPC／传送点首击通常在 32 子格内；更远时要求本地和最近 Host 脚点均在原点击范围内，并通过相应行走射线。传送点向中心作行走碰撞射线，最近可走到的终点已在有效操作区时就点击已指派单位，由普通客户端走近；激活及开菜单分别等待服务端确认。局部停住但直线无碰撞时保留最多5秒无进展窗口；碰撞或窗口耗尽后再绕路。NPC打开请求以原会话期限为界，Host仍接近时保留意图；确认无进展才换交互站位，至多两轮，已在范围内可原地有界重点击。结果仍须真实对话／换区，未知服务结果不重放。

子导航消费RemoteControl真实提交时的源位置及代次记录，沿前端本地DynamicPath绑定场景；区域／生成代次更新后重新绑定，旧child取消不代表旅行成功。Jerhyn 与 Alkor 的跟随、点击和 Host 回包现场见[测试记录](AI_TEST_REC.md#本次修复与仍未解决的问题)，最终钥匙、资格和碰撞由服务端裁决。

已探索地图记忆不受屏幕、小地图窗口或缩放裁切；它与当前活跃房间的碰撞快照、以及本任务已搜索覆盖分开记录。RemoteTown复用原AutomapExploration层及NativeMap，按游戏／区域／地形修订和新增探索更新只读房间／连接索引，并按const引用复用。AI不另建地图生成器，不每次重构地图。普通探索按真实观察掩码与已重建DT1选取已知／未知交界，从当前世界视口的x-y／x+y投影范围估计能揭开的边界格数，再结合实际路径长度评分；每次最多详细检查24个空间分散的观察位置。进入房间不等于已经观察完边界，已完全观察过的区域不重复搜索。失败的局部接近点随碰撞修订、出发点推进或 5 秒期限重新评估。已抵达的开图中继点保留 30 秒，实际观察覆盖另行持久记录。已知目标落在已释放碰撞房间时，按已有RoomEx.near连接返回已探索的可达接点，再接近同一目标，不把已知目的地降级为全图未知搜索。

地形探索的优先级由实际目标决定。找普通步行连接使用已解析 Vis／Warp=-1 接缝，提高能看到目标接缝的观察位优先级，兼容第四幕平原及旋转后的第五幕矩形室外区域；未知洞口／楼梯继续覆盖扫描。取消把接缝最近投影当作必须抵达的地面目标。树、传送点等按尚未稳定订阅的房间扫描，纯地图覆盖按实际未观察瓦片扫描，候选按世界视口大小分块，每块保留两个不同接近位置，总详细寻路上限24；步行评分累计途中视口并集，最多采样64处及终点，传送只计落点观察。已知纯实心地形不吸引补扫，未知碰撞仍保留。预测收益仅用于排序，只有实际观察更新覆盖。

庇护所从已观察的中心传送点划分四臂，优先沿当前臂向外探索，再由已有回溯／回城流程换臂；合法落点、步行通道和原局部传送装置仍逐段验证。依据 D2MOO `DrlgMaze::DRLGMAZE_PlaceArcaneSanctuary`，四臂每臂按15次房间放置构建；`LVLTYPE_ACT2_ARCANE` 分支另抽取随机方向替换召唤者预设，当前没有已核实的入口预测规则。第五幕边缘布局依据 `DrlgOutSiege::DRLGOUTSIEGE_PlaceBarricadeEntrancesAndExits`。第四幕仅普通室外步行连接沿边；`DrlgOutdoors` 对诅咒之城的 `LVLPREST_ACT4_MESA_WARP` 使用内部区块放置函数，因此到火焰之河的楼梯仍须内部扫描。

第一幕入口／定向策略（已构建，行为待验收）：冰冷之原是含营地点的第二个传送点。D2MOO `DRLGOUTDOORS_SpawnAct12Waypoint` 优先把它预留在鲜血荒地连接旁、向内钳制的8瓦片区块；该分支失败仍有随机后备，不能认定为绝对坐标。AI收到本区真实传送点指派即优先接近，不再限于50子格发现距离；尚未指派时，只在实际跨入入口附近观察入口区块及两侧邻块，最多3处／20秒，每次抵达留250ms观察正常指派。失败恢复原流程，已开点跳过，门户到远处不触发返入口。日志为 `cold-plains-entry-waypoint`／`cold-plains-waypoint-fallback`。

泰摩高地→修道院大门，以及大门→高地／外侧回廊，按已重建的唯一目标接缝定向接近，再交给正常跨区；依据 `DrlgOutPlace::sub_6FD81AD0` 固定连接及MPQ `Act 1 - Mon Front` 的原门面。只用于这段旅行，找地穴和其他任务仍按其目标探索；接近失败保留5秒普通恢复，不把逻辑接缝当可穿越地面。`navigationDiagnostics.travel.terrainStrategy=monastery-connection`。已有可用Teleport时不主动开普通门；若接近门途中恢复传送能力，取消尚未提交实际操作的接近，记录 `door-approach-skipped`。缺蓝／不能传送时仍可开门，城镇和任务机关保留原流程。

瓦特之厅采用[壁画定向](../../src/app/debug/ai_terrain_clues.cpp)（578F99D3实见-X，其余组合待验收）。原版 `LvlPrest` 864／区域124的四张 `Nihl{E,N,S,W}.ds1` 中，中央 `interior.dt1` main=0、sub=1/2成对壁画对应 +X、-Y、+Y、-X 分支（地图坐标）。首次使用从当前MPQ解析四模板，校验唯一中央组合、四方向及 `Objects.InitFn=69` 出生标记的同臂关系；依据 D2MOO `OBJECTS_InitFunction69_NihlathakStartOutsideTown`，不按本局种子选择模板、不读取本局隐藏单位。模板仅保留小量墙面签名、观察位和由地板范围推导的分支末端。

仅寻找尼拉塞克时启用：先接近中央分岔，必要时依次到四个附近观察位；`RemoteTown::observedNavigationWalls` 只提供当前地形快照内真实视口回调确认过的墙面，房间加载、地面探索和全图覆盖不算证据。完整两块组合确认后立即撤销其他探索，沿该臂向末端大厅推进；传送仍按合法落点接续、步行仍沿真实通道，到达大厅不代表找到或杀死目标，真实指派优先接管。仅一块／未见不推断；组合冲突、模板异常或观察位耗尽恢复普通探索，局部路径失败让原恢复流程运行5秒再重试。观察位在途中固定，避免因距离变化反复换目标。八个候选墙面证据按本局／地图种子／区域原点记忆，换区返回保留，新局或种子变化清理，不写存档。诊断为 `navigationDiagnostics.terrainClue`，日志包括 `terrain-clue-confirmed`、`terrain-clue-conflict`、`terrain-clue-route-recovery`。

单位搜索使用实际服务器房间订阅和250ms稳定窗口，同局保留已稳定房间，退订不清除搜索记录，尚未稳定就退订仍须补查；覆盖范围可超出屏幕，不为已经订阅的城镇房间补扫墙角。这不保证延迟生成的单位已经存在，任务出生标记另行等待。看见目标仍立即转原交互，动态召唤／任务结果沿原等待流程。诊断新增 `focus`、`boundarySegments`、`scanBlocks`、`solidTilesSkipped`、`subscribedRooms`、`newTravelTiles`；途中覆盖取消记录 `exploration-view-covered`。方向权重和扫描预算属于AI策略，速度收益尚待同条件实测。

探索接近保留原观察目标；多段观察位记录当时预期揭开的瓦片，途中实际覆盖后立即撤销剩余接近。回溯房间也先检查是否已看清或已完成单位指派，再决定是否继续到房间中心。已知目标的局部接近固定本次前沿，完成或明确失败后记录已探查点。完成中间点后从新位置继续评估同一个实际目标，不把它误当作恢复无关房间探索的条件；只有更远的新前沿或可达真实目标才再次接近。NPC、物件及出口的位置线索只从实际客户端单位分配记住，撤出当前兴趣范围后仍可作为最后已知位置接近；重新收到实际单位才交互或判断完成。已指派但中间地形尚未物化的warp先接近已知可达前沿，再精确交互。新游戏和同幕地图种子改变清相应线索。不读取NPC预设、未见NPC的位置或宿主隐藏状态。

探索只对当前已物化碰撞提交正常移动，未知边界以视野能覆盖的位置接近；预测收益只用于选择输入，实际观察仍唯一由可见瓦片回调更新，不从靠近／进入房间推断已探索。不以房间中心或贴墙为默认目标；清场仍可精确扫查房间以等待真实剩余怪物条件。普通探索耗尽时，用已经重建的RoomEx.near图寻找未访问分支，通过仍有碰撞的旧房间回走；中心被河岸／墙体占据时检查房间四分位的九个候选位置。每段仍须实际寻路可达，不能把逻辑邻接当可穿越的边；回走使用精确子导航并等其结果。原版已实际观察的永久红门和Operate34宫殿门保留有向位置记忆；后者按D2MOO的54↔74规则解释目的地，不从地图种子补门户。离开指派范围后先按旧位置找回实际门户再交互，不缓存会被替换的角色蓝门为永久路线。门、拾取和实际关卡连接保留必要的精确接近。普通移动带来后续房间消息；正常跨区替换子导航时重新绑定，不把取消当旅行成功。不调用完整地图生成、房间激活或revealAll接口。无可达新房间或回走点时等待正常更新并保留原因，最后受目标期限约束。

物件中心路径被截停在矩形角外时，子导航在物件周边查找通过同一interactionReady且实际可达的候选位置，不把到达截断点当成交互完成；步行边界的另一侧已重建时，同时检查跨界段，避免选中本侧可达但对侧为墙角的伪开口。连续门交互被客户端限流且尚未入队时保留目标等待，仍受已有15秒无进展及总期限约束；不重试已提交的操作。地面物品受阻在原版也可出现，不能单凭此现象认定拾取协议或落地规则错误。AI复用普通客户端nativePickupReach的原单位距离／射线检查，在物品周围选择能站立且可拾取的接近点；同一位置走到后仍不满足条件或子路径失败时，排除该落点及近邻后换侧接近，最多尝试8个不同位置，失败明确保留原因。物品当前格可合法站立且角色已有可用Teleport时，允许正常传送到该格；否则选择周边合法落点。普通acquire和Cain掉落在地上的奖励戒指共用此策略，status的pickupApproachesTried观察本步已排除落点数。发出拾取请求后仍只等待真实归属，未知结果不自动重发。

移动／战斗按状态与事件自适应调度，不要求角色先停下。任务被战斗打断后重新开始必要的接近，不重复已经提交的物品／剧情操作；已提交传送点或warp交互时先等真实区域结果；已提交蓝门创建时也保留施法输入，避免战斗切换技能打断开门。蓝门创建超时且未实际使用门户时只记录未确认结果，不重发开门或假定卷轴已消费，回退正常步行／已解锁传送点；其他超时仍明确失败。死亡、拾取、回城及交付分别使用实际死亡模式、归属、城镇场景和任务位作完成依据；accepted、Updated或acknowledged都不单独表示成功。目标消失不能当作死亡。

NPC开窗子任务完成只证明当次会话曾打开。原版自动对白最后一条确认会沿31→30结束会话；采购及任务服务随后需要新会话时，先失效已完成子任务，再走正常交互开窗。`npc-service-open`／`npc-service-speech`表示当前阶段，不能用旧child或phase推断服务已开始；已提交交易仍只观察原结果。

事件接近与等待共用`WorldWait／waitAtWorldEvent`：记录实际已见位置、接近距离和超时，允许现场防御／换位后继续；已提交操作不重放，缺少mapTarget或接近受阻不转全层探索。石柱／日志／插杖入口、三古人门、墨菲斯托红门及安雅出生等待复用此流程；巴尔五波仍要求原任务status3，563初始mode1不替代资格，旅行以实际换区完成。步行升桥使用当前MPQ Init45身份／SizeX及原版同房间D2Common_10399<18条件，选择已知可达岸边等待服务端mode2；可传送时跳过升桥等待。该批源码未构建、未实测。

动作调度由[ai_execution.cpp](../../src/app/debug/ai_execution.cpp)统一派生轻量契约，各领域仍保存自己的真实pending及确认条件，不再以一个等待分支的提前返回阻止其他结果观察。每轮先观察子导航、药剂、门、传送点、职业移动、任务／库存和旅行结果，再按输入占用允许新的动作。门／传送点等待可让防御／饮药中断输入，已提交职业位移保留移动／技能输入；药剂请求只占库存输入。合成方块已打开、灌注已取材料、插杖已取得租约以及实际任务库存请求才进入事务保护，赶往这些目标本身不因步骤名称屏蔽战斗。补给保留原高层目标及自己的执行预算；普通任务、技能、物品和NPC请求继续通过原客户端门禁裁决。

输入受理前共用`submitInput`及`submitItem`／`submitCombat`适配，已接采购／饮药、普通与任务拾取、任务库存／灌注／卷轴、技能选择／攻击／职业移动及蓝门施放。等待记录按动作所有者保存操作键、所需输入、原因、尝试数、200毫秒重试间隔和执行预算；每次尝试先检查现有输入占用。未受理不建立服务端pending，也不把一次输入节流记作已提交；受理立即退出该等待，转由已有领域pending观察实际结果，不能用受理前通用重试重放已提交购买、饮药、合成；门户旅行另有基于源场景的有界重试。默认受理前预算12秒，蓝门2秒后可转正常旅行；库存超时明确失败，战斗／职业移动仍按原策略恢复。观察面板和显式暂停补偿受理前执行预算及任务门户事件预算，其他已提交请求的现实等待不补偿。`actions.submissions`分别列这些未受理等待；它们不额外独占输入，下一次尝试仍由现有契约裁决。

拾取／装备等库存输入优先观察正常客户端施法动画结束、移动技能结果及技能请求完成，并等待本人最近动作回包稳定600毫秒，避免晚到受击后立即提交库存请求；仅在没有动画投影时保留最后施法后1500毫秒的后备等待。它只控制debug输入节奏，不代替服务器动作资格判定，也不重放未知结果的库存操作。

[action_state.hpp](../../src/app/debug/action_state.hpp)区分执行预算和现实等待：观察面板、最小化、表现暂停、地图输入不可用和显式AI暂停只停计父目标／补给执行预算及子导航总预算／15秒移动无进展；已提交门、传送点、位移、药剂、库存／任务和区域旅行的期限继续按steady_clock推进。暂停期间仍观察原回包，已到达的事实先于超时判定；只在恢复输入后关闭本人传送点菜单或执行下一步。尚需正常阅读／私人查询输入的任务继续点按执行时间计，实际发出查询后重新使用现实等待期限；不延长已经在等回复的请求，不重放合成、插杖、饮药或服务。

`debug-ai-status.actions`列inputBlocked、executionSuspendedMs、逐动作owner／action、inputs／interruptors、waitingFor、clock、waitRemainingMs、resultObserved、recovery及各输入分支的allowed。输入位为移动1、技能2、库存4、交互8、菜单16；中断位按goal／navigation／door／waypoint／mobility／potion／supply／combat的0–7索引。契约来自现有动作状态，不是第二份世界事实，也不是向服务端发送的新协议。`goalExecutionRemainingMs`及子导航的executionRemainingMs／suspendedExecutionMs可核对阻塞前后预算。

零售调试导航使用RemoteTown临时只读查询，按当前MPQ单位尺寸加入已指派存活单位的原cross／square占位，自身及当前交互目标不作障碍，已知佣兵使用pet模式；不向NativeMap或世界副本写碰撞。父级探索、接近、开门和子导航使用同一查询。原版沙虫潜地、秃鹰飞行及蛙魔潜水的无技能空闲S1不加入实体占位；原始怪物分配包即使未带0x0E标记，也沿同一原模式／MPQ AI身份排除不可攻击目标。依据为既有显示消费者、D2MOO MaggotDown／Submerge及对应AI，修正仅扩展零售lod113c分配包，PD2分支不据此认证。步行边界需到达选定原生格，再复验当前已知的对侧开口；普通跨界移动被占位挡停时重新规划，不重发物品／剧情服务。输入起点始终来自正常DynamicPath，停下后也不切到稀疏0x96旧坐标，避免把已到达的短段反复当作新目标；type5瓦片使用停住的正常本地路径及公共交互几何提交，等待真实换区，NPC仍以实际会话确认；物件沿正常控制器提交操作，由原版物件路径继续靠近，不用稀疏资源坐标阻止其正常输入。不修改人物位置，位移校验沿客户端已有消费者。

拾取及任务库存操作沿上述动画与实际动作回包稳定窗口等待，不将1.5秒后备窗口当作固定技能冷却：当前D2X在技能执行期间拦截非Use库存操作，飞弹已发出或传送已同步不等于其门控已释放。D2MOO ItemMode的PLAYER_IsBusy检查交互、Cursor和剧情忙碌，不能据此把所有技能执行都视作同一原版门控；这项宿主一致性边界仍需单独核对。已经发送的库存请求只观察实际结果，不以等待窗口为由重试。技能书正常Use不套用该库存等待；其实际消耗和永久技能点分别核实。

较远的已指派物件、门户和出口先沿已重建地图接近，再发起单位交互；已指派NPC直接使用正常单位接近，按实际交互距离停下，不把NPC中心作普通落脚点；接近路线保持到完成，避免目标分配随房间切换而在探索与接近之间反复取消。开门先判断当前位置的实际交互资格，门中心路径无效时也检查真实周边接近点。临时单位占路保留已有无进展期限，邻格抖动不刷新进展；步行出口受阻只换同一连接的其他候选，不转去无关房间。正常赶路只处理邻近已指派门；探索没有可用前沿时，可接近一扇实际可达的关闭门以观察门后区域。未知位置的传送点不抢占旅行任务；位置已由真实指派记住且原表路径可能缩短路线时，可正常打开该点读取63历史，再只选择实际解锁的捷径，不为查询去搜索未知房间。

赶路／任务期间记住本区横纵各50子格内经过的真实传送点，等当前动作允许时接近。旧坐标用于找回指派，重新走到仍无指派时继续探索。危险避让、任务服务及已提交旅行结果等待优先。已解锁判断统一消费`knownWaypointAreas`；世界模式1／2不能代替个人资格。中性点点击后的实际激活回执增量加入记忆，实际使用菜单时由新63校正；个人历史未知且外观已打开时不宣称本人解锁。只处理已见传送点，不从隐藏预设或城镇拼图猜位置。

地图覆盖只统计当前视口实际呈现的客户端瓦片，排除城镇全显和reveal叠层；换区域／任务保留同局观察。寻找NPC、任务物件、怪物和传送点另用实际07房间订阅：持续稳定250ms后记入同局searchedRooms，08退订不抹除；过早退订不算已查。地图seen／visited不代替单位指派，地下未观察的独立地形也保留扫描候选。实际指派留下的目标／连接位置及观察记录可由独立.d2xnav侧文件恢复，不保存活GUID或授予解锁；跨profile／轮换及损坏缓存组合仍待验收。

探索和已知目标接近的子导航结束只记录短期落点尝试，不把completed／failed当作观察覆盖。`exploration.frontierAttempts`最多256项，逐项列落点、结束时实际客户端位置、reached、outcome、失败原因、地形／静态碰撞revision及剩余重试毫秒；地形修订、位置移动至少8子格或5秒冷却到期解除排除。动态单位撤开即使未改静态revision也可在冷却后重试。实际覆盖仍只由正常渲染视口写入navigationObservation，失败不写seen，也不永久排除附近前沿；到达但仍有新增覆盖价值的落点同样不永久禁用。

回走到已知连接房间另记录所服务的未观察目标房间及出发时真实覆盖计数：到达／失败后仍未增加覆盖时，该分支让出30秒供其他分支尝试，新真实覆盖可提前解除；单纯移开八格或活动碰撞窗口变化不清除这份无发现记录。它不写seen，不断言目标房间不可达；换区／步骤重置清除，最多保留256个分支。此限制防止两个已知观察位之间的回走反复抢占其他分支。

城外传送选路及落点确认见[职业移动策略](#职业移动策略)。观察点的 `directTeleport` 标记表示这一跳已有候选落点；是否到达仍看本人位置回包。

同层传送台只取实际单位指派。普通前沿／回走无可用方案时，可接近已看到的TeleportPad；步行模式按可达性交互，传送模式按已知落点接近。接近预算30秒按执行时间计，实际交互后等待20秒现实时间的本人位置不连续通知，不重放已提交操作或猜测服务端配对。`localTravel`列实际源／落点和使用次数，连续16次未增加观察覆盖／目标记忆则明确阻塞，保留现场。原版Operate27及自研宿主未实现边界见[物件](../gameplay/world/OBJECTS.md#同层传送台边界)。

旅行统一比较当前已解析的普通连接／已观察门户路线和当前位置已知传送点的合法候选。普通路线为空不否决传送点；仅为缩短已知普通路线而打开传送点超时时，保留诊断并暂缓该开窗，继续合法普通路线，不伪造解锁或目的地。路径保留复验同时承认当前实际分配的门户边，不把规划时使用的蓝门／红门边又判成无效；个人解锁历史未知时，正常打开实际传送点读取63，选择目的地仍要求真实个人解锁。如果普通路线不存在、当前表明确本关卡有传送点且仍有潜在合法目的地，可沿真实观察边界寻找未知位置的当前传送点；此最后回退不抢占已有普通路线，不读预设坐标或城镇拼图。区域路线使用加权搜索，估价包含步行地形距离或传送直线距离、已观察连接位置、未知出口的搜索成本和交互成本，不再仅按区域跳数。未加载段使用已观察房间尺度或缺省尺度估计，代价是debug策略而非原版玩法参数，不保证全局最短或未知碰撞可通行。没有任何合法候选仍明确失败，不自造跨幕旅行或授予解锁。

导航诊断由`debug-ai-status.navigationDiagnostics`返回：`search`记录房间／观察位置候选的已加载／探索状态、路径端点、新增边界格数、排除理由和分数；`approach`记录目标来源、端点及是否截断；`mobility`记录传送选定的落点；冲锋另记地面路线的总长、进度及候选位置；`travel`记录普通路线及估价、传送点接近成本、实际已解锁候选及最终选择，无普通路线的成本为null。只保留最近一次对应规划；`debug-walk-status.excludedOpenings`另列当前连接已停止的接近点。需要连续证据时把状态快照保存到忽略目录，同时保留完整原包，不把本地规划判断当作服务端结果。

清场与寻找地标分别使用对应证据。清场依据原版`GAME/Level.cpp::LEVEL_AddClient`的07房间订阅及随后单位指派，不以画面覆盖判断有没有怪物；优先处理全部实际存活敌怪，保留撤出订阅范围的最后位置并在重新订阅后复验。已取得单位数据的空房间无需走到中心，探索只为取得尚未订阅区域的单位数据；新订阅有250毫秒接收缓冲，这不是清场成功证明。探索耗尽后查询真实任务状态，不再每两秒清空房间记忆重扫；最终仍需原任务状态确认。`questProgress`提供订阅房间数、存活位置提示数和状态查询数。

MPQ 标为 Outdoor 的区域按可见地形覆盖选点。同一个视野内，新揭示的内部空带和外缘格都计入收益；分数比较预计新增格数、传送次数或步行距离及离墙间距。只以实际视野更新探索记录。当前视野无收益时，沿已观察房间连接分段接近尚未探完的位置。已知跨区边界优先找真实开口，远处投影只引导接近。迷宫继续按已见／未见地形交界选点。

普通移动目标与交互目标同样可从当前已加载邻房的合法空地选择直接／分段传送落点，不要求绕墙步行路线。探索按新增可见瓦片、路线长度及离墙间距选择观察点。一跳可达时直接传送；需要中继时按已加载房间的可落脚地形选择下一跳，允许先往侧面或远离目标的方向传送。没有完整路线时，利用已观察房间连接或合法中继寻找侧路。

开图偏好与已知静态障碍保持 6 个子格的间距。步行中途和绕路传送可横移到能接回原路线的点；窄道仍可用原路，空旷处按视野收益选方向。分段观察保留目标和走过的脚点，寻路预算让出后继续；未新增观察而折返、失败或耗尽 8 段时暂缓目标附近的候选，目标房间新增覆盖或 30 秒后可重试。AI 快照的 `exploration.stagedViewpoint` 和 `navigationDiagnostics.mobility.wallClearance` 可用于对照；离墙读数上限为 9 子格。

城镇自动行走优先给转弯留4个子格余量，桥口兼顾两侧，窄路保留原可走点。靠障碍急转保留已提交步段；同区域最近本人路径验证可用于约束转弯，不要求它晚于每条频繁更新的移动指令。短等0.6–2秒后优先找本地脚点与已收Host脚点都可直达的前方中继；没有共同可达点就保留原弯，不再无条件提交会切墙的下一段或交出单位接近。原无进展期限仍有效，不回走到旧样本位置；本人0x15清掉旧弯。手动点击不变。待验桥头双向、绕帐篷点传送点、窄门及直路；观察请求、两端脚点与校正包，单机同样需验。

“只传送”（`mobility.mode=teleport`）让赶路优先使用传送，途中跳过无关普通怪。出城先按 Host 在已订阅野外房间的位置确认能否施法。若位置仍在城内，短等后沿可走路线越界，确认后恢复传送。短距离直达、传送不可用或没有合法落点时可朝同一目标步行；已选定的施法和已提交的位移会等实际结果。任务必杀目标和必要防御保留。受理前预算耗尽与已受理后无位移分别记录。子导航只在静态路径确实通向目标而动态路径受阻时等待占位，不把走向墙边的部分路径当作静态可达。仅能传送到达的已知落点在选技能／受理前短等待期间由移动技能持有接近过程，步行子导航不得先判失败；未到达的候选暂缓后重新规划，不终止整个任务。新建单位接近可直接读取实际指派位置，无需先走一帧；已指派门户和换区入口在普通点击范围内可按 GUID 接近；跟随停步后由单位导航寻找可交互站位。野外激活传送点及已生成的自有蓝门接近同样可用正常传送，到原交互范围后直接点击。生成门户的技能等待与使用门户后的换区等待分别持有输入，已生成、尚未点击的门户不再禁用接近技能。

石柱全激活后的Tristram红门及阅读日志后的峡谷红门配置已观察的事件见证物；未指派门户时靠近该现场进入WorldWait，不退回全图探索。门户仍必须实际指派且可操作；防御换位保留等待现场的范围。

交易面板与AI提交共用实际NPC状态：补给先确认服务器提供的自动对白，再打开普通交易；收到货架后显示商店，关闭会话后收起商店及其背包。仅本商人的开店待定且无购买未决时，货架超时允许重新交谈一次。每次购买（含 Shift 批量）等待交易结果和实际库存增长，数量按配置补足，不把面板显示当成交证据。物件对白沿真实单位类型投影，不生成NPC服务菜单，避免AI已确认古书后才绘制的空Cancel菜单阻塞子导航。

### 共享寻路预算

回走图保留当前原生near列表，并补入有实际观察记录的房间及其几何相接前沿；未观察且未加载的房间只作为前沿，不能继续展开成假想通路。释放房间的near为空不等于过去走过的路线消失。中间落点须位于所选房间内，重建地图中仅含移除／空白DT1的房间不作为观察目标；这些候选记录不写入实际探索掩码。无新增观察的重试记录按对应房间的覆盖变化失效，不因别处新增几个格子就全部清空。客户端已有区域布局的Vis／warp=-1接边可提供换区候选，实际开口仍按当前碰撞验证，再经普通移动触发指派。

[navigation_search.cpp](../../src/app/debug/navigation_search.cpp)由父 AI 和自动行走共享。近距离直线在客户端检查，步行A*、连通范围、传送落点图与图上A*在独立工作线程执行。工作线程只读带一格边缘的碰撞掩码快照。步行查询按游戏、区域和地形域失效；传送的目的地路线可跨普通地形修订保留，使用时复验接入段，地图坐标原点或游戏／区域变化则清除。动态查询另区分实际单位占位、脚点、目标和移动规则。决策、技能选择、动作回执与实际输入留在主线程。

跨区先检查直接可走的入口，再用静态连通搜索筛选同一侧的入口和有探索价值的边缘。连通边按原生移动线段验证，最多保留四个已查区域；同一区域内移动或返回已缓存区域不重复洪泛。地形可达查询复用区域成员关系，不能把这一证明用于实时单位占位。探索优先选能揭开边界的安全直达传送点；需要比较步行路线时，可连续派发最多四个尚未返回的候选，已有可用路线即可继续。部分路径查找按环的周长检查阻挡目标附近的脚点。

野外持续等待路线且角色已停下时，可以对附近威胁施法、避险走位或传送。恢复时保留同一目的地的长路线，先从当前脚点接入能直达的后续路段，必要时单独求一段回到原起点的短路，女巫也可尝试传回合法起点。实际走跑和施法仍复验当前碰撞、动作和技能条件。暂存的行动只恢复同一任务步骤的移动，不重放交互。长路线起点最多保留64个，60秒未使用或地形域变化时失效。

探索观察点和已知目标的候选批次按当前已知静态地形规划，避免附近怪物／佣兵移动使每帧的候选前缀重新计算；子导航与实际移动仍按当前动态占位及原射线复验。RoomEx的near包含相隔最多五tile的可见房间，步行回走只将几何相接且没有已知静态封墙的边当作候选；未知接缝仍须实际接近验证。具备传送能力时，可另使用两侧当前已知合法站立点在配置距离内的连接，不把所有near或空白河道房间当作传送链。跨多段传送接近观察点、或经中间房间回走时保留同一最终目标；中间点到达不冒充远端房间已到达，未产生新观察且无法继续的目标只暂缓重试，不写入探索覆盖。寻找步行边界时，按目标接缝附近的未观察区域选中继，视口已覆盖后重选观察目标。已到达的中继对同一已知目标短时避重，接近边界后按实际开口选路。已知目标的恢复路线保留至完整路径出现；传送规划同时返回合法落点和completeRoute；战斗选位消费落点坐标，局部可达落点不能解除接近绕行，部分落点沿用同目标避重。接近与移动先分别保存落点和默认false的完整路线标记，再生成诊断，未选中落点时完整标记保持false。接近／移动诊断的completeTeleportRoute区分路线是否真正到达目标；战斗中断不丢弃绕路选择。两侧房间均已重建时记录静态接缝／合法传送候选的判定，Room1释放后仍保留已观察结果，重新加载后重查；该缓存不来自导航失败，不写探索覆盖，实际输入仍复验当前碰撞。

子导航继续沿用仍然有效的移动段。`navigationSearch` 的 `componentSearches` 和 `routeJoins` 分别统计跨区连通搜索和步行接回次数。`budgetYields` 保留旧字段名，现表示本帧遇到后台结果尚未就绪。`framePathUs` 是这一帧取回的步行A*计算耗时，不含传送图搜索；主线程实际耗时见帧日志的 `ai` 和 `navigation`。探索候选排序、快照准备和最终输入检查仍在主线程；传送落点枚举及两房间落脚单元的距离查询在后台。

## 药剂与自动补给

`supplies`是整条计划的输入策略，默认启用，不需要逐瓶指定GUID或购买步骤。例如：

```powershell
.\scripts\Send-D2XCommand.ps1 -Command debug-ai-start -Arguments @{
    scenario='tools-of-the-trade'
    supplies=@{lifePercent=60; manaPercent=35; criticalLifePercent=25; healthCount=4; manaCount=4}
}
```

| 参数 | 默认 | 行为 |
| --- | --- | --- |
| enabled | true | 自动喝药及补给总开关 |
| lifePercent／manaPercent | 60／35 | 当前生命／法力严格低于该百分比时考虑饮药，范围1–99 |
| criticalLifePercent | 25，最多为lifePercent | 危急生命线，优先本人已有回复药水；允许正常红药追加 |
| intervalMs | 1500 | 两次已确认饮药之间的调试策略间隔，范围600–10000；不是新增玩法冷却 |
| buy | true | 在城镇自动补齐储备；false时仍可喝已有药剂 |
| healthCount／manaCount | 4／4 | 红／蓝药各自的储备瓶数，范围0–16，0表示不购买该类 |
| returnWhenEmpty | true | 野外资源已低且对应药及回复药均用尽时，安全插入回城补给并返回原区域 |
| fillPortalBook | true | 无书或余量不超过总容量一半时触发城镇自动采购。因其他短缺已进店或显式 restock 时按 Misc.maxstack 补满 |

当前生命／法力读取正常原包，最大值借用同一人物HUD／人物面板的已知投影，未知最大值不猜阈值。`debug-ai-status.supplies.vitals`分别显示原包当前值及`displayMaxLife`／`displayMaxMana`，不将显示上限作为宿主权威真值；既有法力上限投影差异见基准档段落。

只选本人腰带或背包里的已解码药剂，直接通过RemoteInventory.Use使用；不从关闭的箱子／方块取物，不替佣兵喝药。分类读取当前Misc、ItemTypes、pSpell、state与States，先区分rpot，再区分继承的hpot／mpot，避免把回复药当普通红／蓝药。已观察到普通恢复状态时暂不叠喝该类，危急生命例外；没有普通药时才以回复药后备。相同类别按当前表的恢复量常量选强瓶，这只是选择提示，不在客户端计算、应用恢复或职业随机倍率。

使用提交后冻结本次物品／请求序号，等待原件实际消费；普通库存Updated不单独代表成功。`lastPotion.consumed`和`recoveryObserved`分别记录消耗及其后12秒内观察到的恢复状态／对应资源增长，不能把瓶子消失直接写成已恢复；观察期结束仍未见结果会保留未确认标记，不把后来无关的资源变化当作该瓶证据。结果未知、被替换或超时不盲目重用；等待期间不继续发子导航输入。正常Pending、Cursor、死亡、门户及物品资格仍由现有客户端入口裁决。

补给按本幕寻找Akara／Lysander／Ormus／Jamella／Malah，第二幕回城书／卷轴另找Drognan；身份从当前MonStats编译记录解析，并核对Npc及Misc的原商店供应字段。只通过真实NPC交谈、TradeOpen、实际货架及Buy执行。报价复用RemoteUiClients.itemQuote；价格未知不传零价。按实际资金选择能负担的强瓶。对常备且可自动入腰带的药水，根据已装备腰带格数、底排药剂家族和空列计算 Shift 购买可填数量。可填两瓶以上、总价可负担且不会超过该种药水配额时，一次发原 0x32 multibuy。必须等成交回包与本人库存达到本次预期增量才提交下一笔，其他情况单买。回城书缺失时先正常购买一本，再对实际货架卷轴提交原Shift购买，按已解码书本页数增长确认；容量读取当前Misc.maxstack，不写死20或购买数量。只检查背包中可用的书，箱子／方块中的书不算出门资源；已有多本时补齐其实际容量。药剂不使用Shift补满，不出售装备筹钱、不生成药剂或授金币。缺金币、满背包、拒绝、缺货及未知结果均明确失败，保留现场原因。

这套准备在各幕城镇共用，先通过正常治疗NPC交谈等待实际生命回满，再满足配置的红蓝药储备及回城书，最后继续原任务／出城；满药／满书不跳过带伤治疗。治疗资格复用原NPC服务表，第二幕Lysander不治疗，改找Fara／已指派Atma；未知生命上限不伪造治疗完成。已提交会话只等待真实生命变化，12秒无回执明确停止，不重复点击。不会每喝一瓶就在野外返城。野外已观察到原表boss、处于接敌距离、治疗药及回复药均耗尽，且生命低于70%或近期掉血达到combat.lifeDropPercent时，也会请求补给。进入回城阶段后优先正常蓝门／脱离路线，不被主动攻击反复打断；危险飞弹避让和已有药剂使用仍可执行。首领身份本身不算危险证据。`supplies.vitals`提供portalBooks／portalPages／portalCapacity／portalStockKnown及红蓝药数量，历史区分请求和实际成交。

自动补给仅在没有待确认的开门、拾取、物品来源、任务交付、选点／跨区或门户操作时插入；保留原目标索引，补给期间单独有600秒上限，完成后补回原目标的剩余执行时间。回程优先使用实际存在、归本人所有且目的地为原区域的蓝门，没有则普通旅行；若当前目标本来就是回城或去本幕城镇，则补给后留在城镇继续该目标，避免无意义往返。回城／补给途中没有可用药剂、且缺蓝或生命危急时优先继续正常脱离路线，避免站在原地反复施放不可用的固定技能；原怪物碰撞及伤害照常生效。已经提交但未确认的原操作不因缺药重新执行。显式`@{action='restock'}`可单独排入队列，回城购买后留在城镇，方便组合新的目标；它要求enabled与buy都开启。暂停保留已提交药剂／购买的观察状态，换游戏取消旧意图。

原依据为D2MOO `SKILLS/SkillItem.cpp::SKILLITEM_pSpell03_Potion`／`SKILLITEM_pSpell05_RejuvPotion`、`ITEMS/ItemMode.cpp`及`UNIT/SUnitProxy.cpp`原NPC／幕与交易准备；正常0x20／0x26使用、0x38开店、0x32购买和0x2A结果复用现有协议入口。原玩法细节见[腰带与消耗品](../gameplay/items/BELT_AND_CONSUMABLES.md)、[NPC交易](../gameplay/npc/TRADE.md)、[商店经济](../gameplay/items/ECONOMY.md)。已有蓝药实际消费／恢复及正常货架购买／回城补给往返记录，阈值与失败组合仍待验收；默认开启购买要求角色实际有金币，基准角色的准备不等于AI可以无偿购买。

实际饮药、治疗、采购和回城书往返见[测试记录](AI_TEST_REC.md#下一轮重点)。各幕商人切换、未知资源、资金／容量／拒绝、首领压力脱离及暂停组合仍待验收，详见[补给缺口](ORIGINAL_GAPS.md#待验收调试导航)。

## 公共操作与部分进度恢复

材料消耗与世界机关阶段分开判断：熔炉真实非中立状态即可证明已放入灵魂石，保留的放置观察可满足材料前置条件；敲击另等开启，不要求消耗后的材料仍在背包。通用缺话题恢复在短等后关闭交谈、刷新私人快照并重评条件，再至多重开一次；失败时尝试关闭AI当前单位动作的NPC会话，保留原失败原因，不伪造任务完成。移动自动关闭交谈仍沿客户端公共输入链；上述新增恢复待实测。

任务目标完成后，AI通过界面功能入口打开正常Q任务日志以消除New Entry；无提示时不额外开窗，NPC／库存操作占用时延后并合并请求。两秒计时归AI独立调度，届时调用关闭入口，不阻塞行走、传送、战斗，也不直接处理已阅位或发送已阅消息。正常任务面板动画／回执继续由原客户端流程处理；玩家手动接管面板后不被自动关闭。AI控制期间隐藏普通鼠标手形，暂停、结束或手动查看面板时恢复；手持物品原图保留。

受限传送复用RemoteCombat的MPQ资格查询：Levels.Teleport=0禁止、=2要求起终点之间的原0x0804（门／飞弹屏障）射线通过，其余非零模式不加此射线。当前MPQ都瑞尔房间73为2；图搜索逐跳检查该射线，不因最终目标直线受阻直接否定多跳绕路，无合法传送段时保留步行child。不硬编码坐标或把怪物当成射线障碍。落点、图搜索跳跃、避险及实际提交分别复验；新源码未运行回归。

AI只读客户端副本，操作经RemoteControl／RemoteInventory／RemoteCombat，不直接调用RealmSession发送命令。对白确认、关闭、问候、跨幕旅行和传送点选择与UI共用RemoteControl入口，复验当前对白／服务／已解锁菜单；插杖交付共用RemoteInventory入口。任务数据仍归OnlineQuestState；Q面板与AI共用refreshQuests，按私人快照的独立接收修订判断是否比调用方观察更新，普通状态通知不冒充私人快照。缺少更新时由客户端查询，同局未返回请求合并，交谈确认／关闭后允许重新刷新；受理不代表任务完成。显式协议诊断命令不属于自主AI。

玩家输入从 `app/input.cpp` 的按键映射和鼠标命中转换为动作；AI 从计划选择世界坐标、单位、物品或已提供的对白。两者移动／交互共用 RemoteControl，物品的拿起、放置、装备和使用经过 RemoteInventory::submit 的身份、修订和位置校验。自动收进背包共用 firstBackpackSpace；腰带列指令用 useBeltColumnCommand 解析该列最下方物品，点名使用上层或背包里的特定药剂则保留它自己的物品身份。UI 测试管道可注入 FrameInput，任务 AI 与自动寻路没有调用该入口。

RealmSession::acknowledge_npc_message 是交谈完成命令。NPC 的自动台词按当前27列表顺序确认，最后一条在同一会话中依次发31和30；可选话题与物件阅读沿各自处理。AI 的购买、灌注、第五幕物品奖励和 NPC 跨幕服务先处理已提供的自动台词，确需服务才重新交互。移动及转向另一 NPC 通过目标动作结束先前交互；明确退出商店、任务需要 NPCDEACTIVATE 的收尾和有界重试仍可主动结束会话。AI 以实际物品、任务或旅行回包确认结果。

已见证的世界事件共用独立的`WorldWait`，实现、参数和诊断见[事件观察与现场保持](#事件观察与现场保持)。迪亚波罗出生、王座波次、Baal退场开门、击杀后的NPC指派及电影通知分别观察真实结果；新波次只算相关进展，不等同开门成功。见证退指派保留本步骤的位置，观察站位使用可配置半径和实际路径验证；`questProgress.encounterAnchor/encounterAnchored`提供现场诊断。

跨幕NPC旅行沿公共RealmSession按原1.13c先30结束交谈、再38旅行；宿主按同幕真实来源和原每轴50范围复验，不能要求刚关闭的会话继续存在。顺路Waypoint无模式／个人解锁结果时保留waypointDeferral诊断并暂缓，30秒且离开原接近位置16格后才重试；显式旅行仍要求真实菜单／目的地，不据暂缓推断已解锁。

单位跟随的 02／04 负责接近，13 发起交互。任务交谈到达有效距离后，若该 NPC 的 0x8A 尚未到达，AI 按往返延迟等 0.6–2 秒再开口。实际菜单缺少所需主题时允许重开一次。NPC 和传送点都观察本地及服务端的接近进度，停在范围外时优先选择双方可达的位置，直线受阻则沿最近服务端位置的可行路径取转角。传送点首次激活与旅行菜单分别确认，选择目的地后等待实际换区。

原版 27／28 对话及具体奖励各自确认。旅行／传送点菜单与激活由ai_navigation共用，NPC接近和主题由ai_quest_actions共用，药剂／书本补货由ai_supplies沿正常商店报价、购买及回执执行。任务配方调用客户端功能层，由功能层经RealmSession提交协议；不直接修改服务器坐标、物品或任务位。动作受理后的等待见统一执行契约，不能把accepted当作操作完成。

第二至五幕使用条件图重算尚缺条件，已完成任务按个人完成位跳过；部分完成按实际材料、奖励标记、当前场景及已激活传送点续办。第五幕的123／129实际传送点及后续区域可证明对应入口已通过，不强制重走安雅红门或山顶。冰中对白是本局观察，持有ice才可跨进程作为材料证据；563门初始mode1不代表五波完成，必须收到A5Q6状态3后再尝试进入大殿。恢复观测与尚未认证的中断组合见[测试记录](AI_TEST_REC.md#下一轮重点)。

重新建局不恢复世界波次、囚犯路径或怪物尸体；原版要求在新世界重新执行的部分不能伪装已完成。已有私人奖励／任务材料仍须保留，不从第一任务重跑。未知或未确认请求不盲目重放；开始时存在玩家交易会明确拒绝；任务计划可正常收妥Cursor，其他目标仍要求事先收妥。尚未认证所有中断点自动恢复。

## 战斗策略

远程射线按当前Skills的原飞弹链接及Missiles.CollideType使用公共`nativeMissileContactMask`的地形位：普通投射类型1／2／3／5／6检查MISSILE_BARRIER4，类型8另含WALL1；近战仍保留墙检查。不能将可供飞行怪悬停、但不挡普通飞弹的高台当作所有技能的墙。依据D2MOO MissMode碰撞表及当前MPQ，服务端已有相同碰撞定义，本项只纠正调试AI的过严判断。

普通远程施法后可按`rangedKite`沿已观察敌群外侧换位，保持射线和射程，避开近身敌人、不可攻击的敌对危险来源及已见弹体。`kiteIntervalMs`、`kiteDistance`、`kiteMinDistance`、`hazardLookaheadMs`与`hazardPadding`可通过策略文件重载。等真实施法动作门禁结束后再用正常步行／Teleport输入；近战及仍占用原动作的持续引导不强行套独立射击。换位不重置无伤害恢复计时，无安全已知位置时继续重评而不伪造落点；多个落点先廉价评分，仅最多四个步行候选提交后台路径查询。

威胁预测只读正常客户端已重建的敌对弹体：除已核实的四种持续首领效果外，按当前Missiles.ClientCol／Size纳入普通碰撞弹体，沿可见速度及短时间窗口评估；非NPC、可死亡且原表isAtt=0的敌对来源（如九头蛇）另保持距离。普通敌怪暂时潜地、离地或附着导致不可攻击，不据此生成持续危险区，也不计入传送落点拥挤；其真实敌对弹体仍独立判断。它不是服务端伤害预判或免疫结论。抵达安全点后立即重评攻击，不额外固定停两秒；必要避险优先于普通换位和已见证的世界结果等待。`hazardFeedback.unitThreats`列危险来源的[classId,x,y]，回避事件另列弹体／单位数。

战斗候选、必杀目标及持续交战恢复共用RemoteCombat的原表攻击资格；MonStats.killable不足以说明可攻击，还必须满足所链接MonStats2.isAtt。九头蛇不可成为攻击／清场目标，仍保留敌对弹体威胁识别，不通过无伤害超时猜测其免疫。

未指定combat.skill时仍按实际掌握的Frozen Orb、Fire Ball、Zeal、Attack选择候选主技能。城镇中按主技能→fallbackSkills顺序，只检查原表主动技能、有效等级／minLevel及左右手资格；忽略冷却、临时状态、法力及目标。离城后固定选中的一个攻击技能，换目标、换野外区域和任务步骤不重新选；回城再准备，野外启动计划时按同样规则初始化。备用仅用于出发时主技能不合格，不用于战斗中无伤害或暂不可用时切换。传送、冰甲、光环与静电场仍是独立特殊能力；静电场仅在主攻冷却期间穿插，不改变出城主攻选择。combatPolicy.departureSkill及combat-excursion-skill日志显示实际选择。实际施放仍由普通RemoteCombat校验目标、资源、状态及冷却，不绕过客户端或服务端资格。

例如角色确实已掌握这些技能时，可把下面的combat配置用于原有scenario／goals：

```powershell
combat = @{
    skill = 'Frozen Orb'
    fallbackSkills = @('Fire Ball', 'Lightning')
    noProgressSeconds = 6
    stallTimeoutSeconds = 90
}
```

探索／赶路默认只处理贴身威胁，接近hunt目标后处理其附近敌人，清场沿实际步骤保留全部必杀目标。单次指派的效果观察只将规范化原生命比例的**新低值**计为净进展；生命回升、原命中标志位、受理次数及独立命中通知不充当净伤害。记录生命回升与命中反馈，但不据此确定当前技能的伤害归因；没有生命反馈时明确保持未知，不判定免疫。

持续无净进展时复查射线／距离、门与实际技能资格／资源，尝试不同攻击角度，再观察同一出城技能的效果；仍无进展按原局部预算报告阻塞或暂避非必杀目标，不换备用、不推定免疫。已观察的共享冷却与本次正延迟等待不计入局部无进展时间；技能到期后继续使用。缺蓝／装备或临时资格不足时保留选择，沿既有补给／等待／有界失败处理。单次接近／换位最多8秒，移动本身不算伤害进展；目标策略随真实GUID／指派变化重置，出城技能选择独立保留。

| crowdRadius／crowdCount | 6／4 | 拥挤判断；不再是唯一后撤条件 |
| retreatDistance | 8 | 已知可达地形中的撤退距离 |

已取得的同一指派目标在engage半径内继续交战，战术换位或另一个怪短暂更近不会清空恢复阶段；实际必杀目标仍优先。目标短暂不合法／不相关时释放攻击输入并允许继续任务，保留同GUID／指派代次的策略进度；重新交战时补偿这段非交战时间。单位移除、指派变化、死亡或阵营失效才清理该记录。该补偿只作用于局部效果判断，已提交请求的现实等待期限仍独立计时。

非必杀沿途目标用尽策略后暂避，不再仅10秒到期就原地重新打同一目标；到期后还须本人移动至少8格且已离开该目标的接敌半径加撤退距离，或该指派目标移动至少4格，才允许再尝试。实际单位撤出／重新指派／死亡会清旧记录。任务必杀、真实清场和取物清敌不使用该暂避排除，以免把沿途失败误当成任务完成；这些是debug选择策略，不新增玩法免疫或攻击规则。

单个首领／必杀目标也会结合低生命、近期掉血与剩余红药／回复药触发后撤，远程威胁不要求进入贴身半径；药剂仍由既有补给动作消费，资源不足不会变成免费恢复。后撤从16个方向的完整已知路径中选择更安全位置，保持最多2秒、至少4秒间隔；生命危急、无药且无安全路线时具体报阻塞。普通怪／中立／伙伴身份沿RemoteCombat，不自造威胁或修改原碰撞。

静电场沿当前Skills.aurarangecalc求有效等级半径，沿DifficultyLevels.StaticFieldMin读取资料片难度下限，经典版不使用该下限；依据D2MOO SkillSor::SrvDo020／AuraCallback_StaticField。保留原首领、已学技能、当前安全射程条件，不为静电场额外贴近。先施放一次出城主攻，冷却期间用普通自施法输入穿插；每轮重新判断主攻是否就绪，不设固定三次上限、不重置主攻nextCast，主攻优先于可选绕圈，实际动作恢复门禁仍有效。血量比例达到原难度下限便停止，不再增加25%／50%等任意策略下限。

**绝对HP限制**：原版普通怪物同步及当前OnlineUnit只有血量比例，不能用MonStats基础生命冒充现场生命，也不读取宿主隐藏数据。本次未实现绝对HP停用条件，不能宣称已满足该项；未知HP时仅使用原难度比例下限。诊断targetAbsoluteLife=null／staticFieldAbsoluteStop明确说明，staticFieldCasts记录特殊施放；日志static-field-between-primary便于核对穿插。比例存在原包量化误差，接近难度下限时保守停止。

飞弹躲避借用正常RemoteScene的只读显示缓存：世界位置、当前速度、敌我及剩余寿命，沿实际轨迹作0.35秒规划；危险尺寸取当前Missiles.Size，另加debug余量。纳入正常客户端已重建、当前ClientCol／Size表明可碰撞的敌方飞弹，并保留diablight／diabfire／diabwall／vampirefirewall专门验证，友方、尚未出现或已过期的效果不算危险；不读取服务端隐藏技能／未来轨迹。每轮复验选定落点，优先正常Teleport，落点须为当前已加载／近房间的可站地面；步行后备需完整已知路径且避免继续穿过危险段。躲避释放攻击输入、保留战斗记忆，不能绕过施法动作／资源／原输入门禁。挂起的战斗记忆不再独占职业移动；明确的接近／换位／后撤阶段释放攻击后，也可通过同一正常职业移动入口执行，持续攻击仍不抢占。`hazardFeedback`报告观察数、间距与落点，`combatFeedback`列出城技能与静电场等级／半径；普通online快照也列飞弹速度及敌我。此处是基于可见表现的避险策略，未认证全部攻击预兆、视觉缺失、延迟和所有怪物技能。

施放不再固定为600毫秒独立点击。首次使用正常点击，保持相同技能／目标时沿普通控制器的repeat请求；非持续技能等待与正常鼠标输入相同的本地动画忙碌信号，持续技能沿原客户端channel分类保持输入。延迟通过中间层`RemoteCombat::skillDelayFrames／skillDelayActive`查询有效等级公式及当前零售skilldelay状态，与提交入口共用；已知正延迟按25Hz换算本地最早再次施放时间并使用独立点击，无法求值时保留未知。正常冷却不视为技能失败，不因usableNow=false降级备用或判无伤害；到期再复验真实资源／装备资格。该等待不替代原动画、费用、目标／装备和服务端截止帧。

策略全部无效或局部预算耗尽时，必杀／清场目标明确失败并保留角色现场、任务及`combatFeedback`诊断，不跳过目标或宣称击杀；沿途非必杀威胁可暂避该次指派10秒。诊断列目标身份／位置、当前／最低生命、回升／命中反馈、射线、玩家生命趋势、红蓝补给、技能序列／阶段、输入拒绝与尝试原因。无净进展始终保留遮挡、未命中、回复和反馈不足等解释，不自动标记免疫，也不自动配置破免装备。

资源可用性复用已有角色投影，不在debug重算另一份法力费用；原技能费用与延迟依据见[技能公共机制](../gameplay/skills/COMMON.md)。持续输入／动画门控复用`SceneController::handleWorld`、`RemoteScene::Impl::channelSkill`和RealmSession的原单次／重复技能请求。效果窗口、撤退阈值、候选与预算是debug策略。实际战斗观测见[测试记录](AI_TEST_REC.md#下一轮重点)，持续无进展后的备用技能切换、策略耗尽及全部单体撤退仍待验收。

## 职业移动策略

默认`mobility.mode='auto'`按当前已学技能选择：女巫优先Teleport；有Charge的圣骑士使用左手Charge，并在右手选择已学Vigor；只有Vigor时保持普通行走。配置`mode='walk'`关闭传送／冲锋，`vigor=false`可同时关闭移动光环。也可选`teleport`或`charge`，城镇和不能使用移动技能的区域按地面规则行进。`distance`默认24、范围8–50，为单次调试输入距离。

城外步行按地形和物件规划长路线，下一段输入再复验当前单位占位。普通怪堵住眼前路段时允许防御。传送单独按落脚地形、原生房间邻域、射程及特殊屏障建图，不套步行连通性。已加载房间按小块扫描，混合块细分到子格，开阔块用角点／中心压缩；未变房间复用落点样本，同一图的跳跃连接按需缓存。该采样图不保证连续地形上的全局最优。

传送A*优先减少跳数，再比较路程；最多保留32个目的地的完整多跳路线，临时子目标及小范围战斗位移不抹去后续路线。实际脚点到达才推进游标，执行时优先接入更靠后的合法点，允许绕路暂时远离最终目标。新增房间后优先走完有效的已选路段，静态接入失效才重规划；实时占位／危险聚集只调整当前落点，不改变长期连通图。本次算法重构未构建、未实测，验收见[测试记录](AI_TEST_REC.md#第三幕往返与导航路线复用算法重构待验)。

传送和冲锋均使用正常技能选择及施放流程。传送以本人位置不连续通知和实际落点确认进展；同一目标与落点的未确认尝试上限为两次。冲锋按地面路线取目标，并检查当前位置到目标的原生碰撞射线。跨区仍以真实区域变化为准。

Do27落点还须属于当前Room1或其活动邻房间；缓存中其他房间的合法地面不能替代原生查找资格。超出该邻域的观察目标按合法落点分段接近。依据`SUNIT::sub_6FCBDFE0`及`DUNGEON_GetRoomAtPosition`，不改变普通施法或搬移规则。共用RemoteCombat接收UI的displayOrigin或AI的正常路径坐标，校验本地射程时使用该输入原点，并保持同一地图绑定；稀疏资源位置样本不再覆盖当前输入位置。无可用投影时使用服务器样本，最终坐标、费用和施法由服务器裁决。

进入战斗范围后停止移动策略；右手由Vigor切换到战斗光环，再用左手攻击；敌群清除后恢复移动策略。调用示例仍是一条完整任务，而不是逐技能指令：
