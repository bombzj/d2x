# 客户端调试任务AI

本功能把一次高层目标或目标队列转为正常客户端操作。它属于app/debug，默认不启动；只在图形客户端调度，headless入口不执行该AI，不构造另一套战斗、掉落、任务或存档规则。现有单目标行走仍见[调试管道](DEBUG_PIPE.md#客户端自主行走)。Windows Release已构建并执行有限实机检查，实际覆盖与未验收范围见文末，不沿用早期debug-walk桥头往返及39传送点结果。

第一至第三幕各六任务及第四幕三任务配方、200毫秒决策、药剂使用／购买和自动补给已通过Windows Release构建并进入实机回归；完成条件与实际覆盖见各幕条目及文末，源码支持不等于全部组合已验收。

## 输入与组合

不需要逐步给坐标、GUID、施法目标、门或NPC消息编号。入口通过游戏内聊天或现有Send-D2XCommand.ps1发送，任务在游戏主循环中持续执行；命令返回只表示计划已接收。当前位置、目标、进度和失败原因通过status观察。当前支持原版1.13c客户端配置，不将零售任务配方套用到PD2。

### 游戏内聊天入口

图形客户端入局后按Enter输入，可用Ctrl+V将复制的命令粘贴到当前光标，再按Enter提交；粘贴的换行／制表符转为空格，每条命令分别复制提交，仍受255原生字节上限约束。无需启用调试管道。聊天入口及粘贴增量已通过Windows Release构建。本轮单机已验证/debug-help、状态查询、聊天启动seven-tombs、未知命令本地拒绝、普通广播，以及聊天框实际输入／提交状态命令后保留AI计划；原包中调试命令不作为聊天广播。Ctrl+V剪贴板、粘贴换行、255字节边界及输入法组合仍待专门验证。

```text
/debug-ai-start act1
/debug-ai-start act2
/debug-ai-start quest search-for-cain
/debug-ai-start act1 {"mobility":{"mode":"teleport"},"combat":{"skill":"Frozen Orb"}}
/debug-ai-status
/debug-ai-pause
/debug-ai-resume
/debug-ai-cancel
/debug-help
```

上例的start是不同计划的用法示例，不能在已有活动计划时连续替换；结束后再start，或先cancel。前四幕任务前置、普通帽子／灌注消费、金币、技能资格和验收边界与管道一致。

`/debug-ai-start <scenario> [JSON options]`与`/debug-ai-append <scenario> [JSON options]`接受原scenario简写。`quest <任务名>`显式生成单项完整quest；因此`/debug-ai-start quest tools-of-the-trade`会消费灌注奖励，而兼容入口`/debug-ai-start tools-of-the-trade`只交回马勒斯。复杂目标直接传JSON对象，字段与管道Arguments相同，不传command；例如：

```text
/debug-ai-start {"goals":[{"action":"restock"}]}
/debug-ai-append quest sisters-to-the-slaughter
/debug-ai-start {"goals":[{"action":"hunt","monster":"smith"},{"action":"acquire","item":"hdm"},{"action":"return-town"},{"action":"deliver","quest":"tools-of-the-trade"}]}
/debug-walk waypoint
/debug-walk exit {"level":2,"interact":false}
/debug-walk-status
/debug-walk-cancel
```

JSON须用双引号，保留聊天原生编码后255字节的输入上限；更长目标队列继续用管道。append继承当前计划的策略，不接受新的combat／mobility／supplies。无参数的status／pause／resume／cancel不接受附加内容。名称不区分ASCII大小写；未知`/debug-*`与格式错误在本地报告，不发房间广播或BNCS命令。

应用在`app/debug/chat_command`解析后共用原DebugAi／DebugAutoWalk入口；聊天只显示状态、目标、阶段、任务内部步骤及原因摘要，完整快照继续用管道。反馈以`[Debug]`标记进入本地顶部消息和M日志，另持最多64条，不写世界／账号聊天副本，不作为服务端完成回执。失败保留输入草稿。打开聊天、消息日志及其编辑／关闭帧保留AI计划并阻止新输入，关闭后继续；显式pause须resume。已有动作和宿主时钟不会因查看聊天而暂停，死亡仍会停止计划。

一次安排第一幕全部六个任务，优先使用角色已有的传送和固定战斗技能：

```powershell
.\scripts\Send-D2XCommand.ps1 -Command debug-ai-start -Arguments @{
    scenario = 'act1'
    mobility = @{ mode = 'teleport' }
    combat = @{ skill = 'Frozen Orb' }
}
```

这会按任务日志顺序执行六个高层目标，最后经瓦瑞夫的正常Go East服务到达鲁高因。使用下文独立女巫配方准备全新任务、购买资金和灌注用普通帽子；已有存档跳过已领取奖励的任务，保留尚未完成的实际资格。仅做某项时使用`goals=@(@{action='quest'; quest='search-for-cain'})`；六个名称与完整完成条件见[第一幕任务配方](#第一幕任务配方)。

原有仅交还马勒斯、保留灌注奖励的入口继续保留：

```powershell
.\scripts\Send-D2XCommand.ps1 -Command debug-ai-start -Arguments @{
    scenario = 'tools-of-the-trade'
    combat = @{ skill = 'Frozen Orb' }
}
```

也可组合高层目标；已知铁匠、恰西和马勒斯的位置／来源提示会自动补全：

```powershell
.\scripts\Send-D2XCommand.ps1 -Command debug-ai-start -Arguments @{
    goals = @(
        @{ action='hunt'; monster='smith' }
        @{ action='acquire'; item='hdm' }
        @{ action='return-town' }
        @{ action='deliver'; quest='tools-of-the-trade' }
    )
    combat = @{ skill='Frozen Orb' }
    goalTimeoutSeconds = 600
}
```

区域使用当前MPQ的Levels.Name（可省略“Act 1 - ”一类前缀），单位使用MonStats.Id、物件使用Objects.Name，`superunique`使用SuperUniques.Superunique／hcIdx并核对其Class和实际分配包身份，物品使用原代码，技能使用Skills.skill；匹配不区分ASCII大小写，歧义与未知资源明确拒绝。也接受已存在的数值身份。没有位置提示的目标可给`area='Barracks'`等粗粒度区域；不要求调用方指定路径。这里是结构化目标接口，不解析自由文本自然语言。

| action | 目标及参数 | 实际完成条件 |
| --- | --- | --- |
| travel | 必填area | 目标区域的原生场景已就绪 |
| find | monster／npc／object／superunique四选一；可给area；NPC可interact=true | 真实单位已指派并接近；要求交谈时观察到该NPC对话 |
| hunt | monster或superunique；可给area | 指定真实身份出现死亡模式；已存在的尸体可满足“目标已死”，不声称个人击杀归因 |
| acquire | item；可给area及source物件名 | 对应物品实际归本人所有，包含原任务查询允许的根库存／cursor范围 |
| return-town | 无必填参数 | 本幕真实城镇场景已到达 |
| deliver | quest语义配方；当前只有tools-of-the-trade | 对应物品已被消费，且真实角色任务奖励位已更新 |
| restock | 无必填参数；使用supplies配置 | 正常回到本幕城镇，实际可用红／蓝药数量达到储备目标；显式目标完成后留在城镇 |
| quest | 已登记的第一至第四幕quest名；自动解析区域，不接受area | 完整执行该任务配方并观察原角色奖励位；幕末另要求实际抵达下一幕及原跨幕完成位 |

整个计划最多32项目标，quest默认每项1800秒，其余每项600秒，可用goalTimeoutSeconds或各goal.timeoutSeconds设置10–3600秒。没有完成当前目标不会执行后续目标。一次请求先完整解析／校验，再接收计划；append同样先校验整批，不部分插入。

| 命令 | 行为 |
| --- | --- |
| debug-ai-start | 接收scenario或goals；接管独立debug-walk；已有活动计划须先cancel或使用append |
| debug-ai-append | 给现有running／paused计划追加goals；继承原战斗／移动／药剂策略，不接受新的combat／mobility／supplies配置 |
| debug-ai-status | 只读状态、当前goalIndex、完整队列、phase／reason、questProgress内部步骤／待确认操作／灌注阶段、决策及请求计数、实际目标和最近128条事件；navigationDiagnostics保留最近一次搜索、接近和移动技能的候选诊断 |
| debug-ai-pause | 停止本AI输入及技能动作，保留队列／已发请求的观察状态；不暂停宿主 |
| debug-ai-resume | 同一游戏、区域及区域代次内恢复；暂停时间不计入本步期限；暂停中换区须取消并建立新计划 |
| debug-ai-cancel | 终止计划并沿正常客户端Stop停动作；不撤销已经发生的拾取、死亡或交付 |

人工移动／施法点击、技能与装备切换、饮药、观察面板关闭之外的ESC、显式独立debug-walk、修改客户端状态的online-*请求（online-chat-input按实际本地命令分流）、退出或换游戏接管控制。Tab、小地图平移／显示及只读观察不取消计划；人物、包裹、任务、聊天和消息日志等观察面板保留计划并暂停AI输入，关闭后继续。Q面板内点击切换任务及Escape关闭均保留计划，面板外的世界操作仍接管控制；原版Host实机已核对暂停／运行计划下的任务图标点击和运行计划的Escape关闭均不取消计划。管道ui-input同样按实际意图判断，不因观察帧取消。最小化、表现暂停及游戏菜单阻止AI输入。计划只在内存中保存，不写D2S，不在新游戏恢复旧GUID、目标或请求。死亡停止任务，不添加自动复活。

## 执行分层

`DebugAi`负责队列、目标完成条件、旅行／探索阶段、战斗优先级与有界观察记录；`DebugAutoWalk`负责单次接近。两者共用200毫秒决策间隔，行走过程中也重新判断；均在app主循环运行，和正常输入共用RemoteControl、RemoteCombat、RemoteInventory、RealmSession原操作入口，不直接编码另外一套游戏消息。

元数据在第一次start／append时按当前挂载惰性读取，未启动AI不额外加载这些表。房间、碰撞、单位、库存、技能和任务状态均来自正常客户端副本／重建；不读取GameHost、server-snapshot、服务端隐藏位置或本地存档，不调用管理旅行、生成、伤害、授予技能、回血或解锁。

旅行按本幕已解析的Vis连接及当前实际指派的出口／门户规划区域路线（包含崔斯特瑞姆红门回程），允许使用角色实际已解锁且能缩短路线的传送点；尚未收到0x63历史时先正常打开当前可用传送点。步行连接先到真实开口，再提交普通跨界移动；warp用当前实际指派单位交互。区域实际改变后重算普通步行连接，不继续使用上一层出口；已提交的warp／传送点保留结果等待。公共接近流程会处理附近可接近的已指派关闭门，候选路径末点须通过同一原物件交互几何检查，包含探索、战斗接近、地面物品、NPC、架子、门户和传送点；开门接近保留当前目标直到子导航完成或明确失败，避免移动中在两扇门之间反复改选；门按GUID及指派代次记录待确认操作，等待实际模式变化后才记为已操作；同一指派持续关闭12秒则明确失败，不把accepted当作开门成功，也不盲目重复切换。门操作不能误记成物品来源或传送成功。NPC开窗和type5楼梯／洞口交互前同时等待本地路径停稳、正常原包位置进入原交互范围；同一真实type5与目的地仍在、本人停稳且服务器确认在范围内时，首次进入未生效最多再正常点击一次，不重放物品／NPC服务，也不把请求受理当作到达；仅开窗超时可正常重开至多两次，已发任务主题／物品请求不重放。服务端继续校验钥匙、任务及碰撞。已在身边的门户／物品／NPC交互先完成，不被远处开门抢占。子导航沿前端已按本地DynamicPath选择的场景绑定，不再无位置重选到服务器稀疏采样所在的另一侧。区域与生成代次更新后重新绑定，不将旧child导航的取消误当成旅行成功。已登记第一幕瓦瑞夫及第二幕马席夫的正常跨幕服务；第三幕以真实HellGate门户跨至第四幕；第四幕经泰瑞尔真实Harrogath门户到第五幕；第五幕完整交通编排尚未登记，不补造未解锁通道。

已探索地图记忆不受屏幕、小地图窗口或缩放裁切；它与当前活跃房间的碰撞快照、以及本任务已搜索覆盖分开记录。RemoteTown复用原AutomapExploration层及NativeMap，按游戏／区域／地形修订和新增探索更新只读房间／连接索引，并按const引用复用。AI不另建地图生成器，不每次重构地图。普通探索按真实观察掩码与已重建DT1选取已知／未知交界，从当前世界视口的x-y／x+y投影范围估计能揭开的边界格数，再结合实际路径长度评分；每次最多详细检查24个空间分散的观察位置。进入房间不等于已经观察完边界，已完全观察过的区域不重复搜索。失败候选随碰撞修订、出发点推进及5秒期限重新评估；观察过的接近点持续保留。已知目标落在已释放碰撞房间时，按已有RoomEx.near连接返回已探索的可达接点，再接近同一目标，不把已知目的地降级为全图未知搜索。

已开始的探索接近保留到子路径完成；已知目标的局部接近也固定本次前沿，完成或明确失败后记录已探查点。完成中间点后从新位置继续评估同一个实际目标，不把它误当作恢复无关房间探索的条件；只有更远的新前沿或可达真实目标才再次接近。NPC、物件及出口的位置线索只从实际客户端单位分配记住，撤出当前兴趣范围后仍可作为最后已知位置接近；重新收到实际单位才交互或判断完成。已指派但中间地形尚未物化的warp先接近已知可达前沿，再精确交互。新游戏和同幕地图种子改变清相应线索。不读取NPC预设、未见NPC的位置或宿主隐藏状态。

探索只对当前已物化碰撞提交正常移动，未知边界以视野能覆盖的位置接近；预测收益只用于选择输入，实际观察仍唯一由可见瓦片回调更新，不从靠近／进入房间推断已探索。不以房间中心或贴墙为默认目标；清场仍可精确扫查房间以等待真实剩余怪物条件。普通探索耗尽时，用已经重建的RoomEx.near图寻找未访问分支，通过仍有碰撞的旧房间回走；中心被河岸／墙体占据时检查房间四分位的九个候选位置。每段仍须实际寻路可达，不能把逻辑邻接当可穿越的边；回走使用精确子导航并等其结果。原版已实际观察的永久红门和Operate34宫殿门保留有向位置记忆；后者按D2MOO的54↔74规则解释目的地，不从地图种子补门户。离开指派范围后先按旧位置找回实际门户再交互，不缓存会被替换的角色蓝门为永久路线。门、拾取和实际关卡连接保留必要的精确接近。普通移动带来后续房间消息；正常跨区替换子导航时重新绑定，不把取消当旅行成功。不调用完整地图生成、房间激活或revealAll接口。无可达新房间或回走点时等待正常更新并保留原因，最后受目标期限约束。

物件中心路径被截停在矩形角外时，子导航在物件周边查找通过同一interactionReady且实际可达的候选位置，不把到达截断点当成交互完成；步行边界的另一侧已重建时，同时检查跨界段，避免选中本侧可达但对侧为墙角的伪开口。连续门交互被客户端限流且尚未入队时保留目标等待，仍受已有15秒无进展及总期限约束；不重试已提交的操作。地面物品受阻在原版也可出现，不能单凭此现象认定拾取协议或落地规则错误。AI复用普通客户端nativePickupReach的原单位距离／射线检查，在物品周围选择能站立且可拾取的接近点；同一位置走到后仍不满足条件或子路径失败时，排除该落点及近邻后换侧接近，最多尝试8个不同位置，失败明确保留原因。物品当前格可合法站立且角色已有可用Teleport时，允许正常传送到该格；否则选择周边合法落点。普通acquire和Cain掉落在地上的奖励戒指共用此策略，status的pickupApproachesTried观察本步已排除落点数。发出拾取请求后仍只等待真实归属，未知结果不自动重发。

移动／战斗每0.2秒判断，不要求角色先停下。任务被战斗打断后重新开始必要的接近，不重复已经提交的物品／剧情操作；已提交传送点或warp交互时先等真实区域结果；已提交蓝门创建时也保留施法输入，避免战斗切换技能打断开门。蓝门创建超时且未实际使用门户时只记录未确认结果，不重发开门或假定卷轴已消费，回退正常步行／已解锁传送点；其他超时仍明确失败。死亡、拾取、回城及交付分别使用实际死亡模式、归属、城镇场景和任务位作完成依据；accepted、Updated或acknowledged都不单独表示成功。目标消失不能当作死亡。

动作调度由[ai_execution.cpp](../../src/app/debug/ai_execution.cpp)统一派生轻量契约，各领域仍保存自己的真实pending及确认条件，不再以一个等待分支的提前返回阻止其他结果观察。每轮先观察子导航、药剂、门、传送点、职业移动、任务／库存和旅行结果，再按输入占用允许新的动作。门／传送点等待可让防御／饮药中断输入，已提交职业位移保留移动／技能输入；药剂请求只占库存输入。合成方块已打开、灌注已取材料、插杖已取得租约以及实际任务库存请求才进入事务保护，赶往这些目标本身不因步骤名称屏蔽战斗。补给保留原高层目标及自己的执行预算；普通任务、技能、物品和NPC请求继续通过原客户端门禁裁决。

输入受理前共用`submitInput`及`submitItem`／`submitCombat`适配，已接采购／饮药、普通与任务拾取、任务库存／灌注／卷轴、技能选择／攻击／职业移动及蓝门施放。等待记录按动作所有者保存操作键、所需输入、原因、尝试数、200毫秒重试间隔和执行预算；每次尝试先检查现有输入占用。未受理不建立服务端pending，也不把一次输入节流记作已提交；受理立即退出该等待，转由已有领域pending观察实际结果，不能用通用重试重放已提交购买、饮药、合成或门户。默认受理前预算12秒，蓝门2秒后可转正常旅行；库存超时明确失败，战斗／职业移动仍按原策略恢复。观察面板和显式暂停补偿受理前执行预算，已提交请求的现实等待不补偿。`actions.submissions`分别列这些未受理等待；它们不额外独占输入，下一次尝试仍由现有契约裁决。

拾取／装备等库存输入前除最后施法后1500毫秒的静候，还等待本人最近正常动作回包稳定600毫秒，避免受击发生在最后施法之后仍立即提交库存请求。该静候只控制debug输入节奏，不代替服务器的动作资格判定，也不重放未知结果的库存操作。

[action_state.hpp](../../src/app/debug/action_state.hpp)区分执行预算和现实等待：观察面板、最小化、表现暂停、地图输入不可用和显式AI暂停只停计父目标／补给执行预算及子导航总预算／15秒移动无进展；已提交门、传送点、位移、药剂、库存／任务和区域旅行的期限继续按steady_clock推进。暂停期间仍观察原回包，已到达的事实先于超时判定；只在恢复输入后关闭本人传送点菜单或执行下一步。尚需正常阅读／私人查询输入的任务继续点按执行时间计，实际发出查询后重新使用现实等待期限；不延长已经在等回复的请求，不重放合成、插杖、饮药或服务。

`debug-ai-status.actions`列inputBlocked、executionSuspendedMs、逐动作owner／action、inputs／interruptors、waitingFor、clock、waitRemainingMs、resultObserved、recovery及各输入分支的allowed。输入位为移动1、技能2、库存4、交互8、菜单16；中断位按goal／navigation／door／waypoint／mobility／potion／supply／combat的0–7索引。契约来自现有动作状态，不是第二份世界事实，也不是向服务端发送的新协议。`goalExecutionRemainingMs`及子导航的executionRemainingMs／suspendedExecutionMs可核对阻塞前后预算。

零售调试导航使用RemoteTown临时只读查询，按当前MPQ单位尺寸加入已指派存活单位的原cross／square占位，自身及当前交互目标不作障碍，已知佣兵使用pet模式；不向NativeMap或世界副本写碰撞。父级探索、接近、开门和子导航使用同一查询。原版沙虫潜地、秃鹰飞行及蛙魔潜水的无技能空闲S1不加入实体占位；原始怪物分配包即使未带0x0E标记，也沿同一原模式／MPQ AI身份排除不可攻击目标。依据为既有显示消费者、D2MOO MaggotDown／Submerge及对应AI，修正仅扩展零售lod113c分配包，PD2分支不据此认证。步行边界需到达选定原生格，再复验当前已知的对侧开口；普通跨界移动被占位挡停时重新规划，不重发物品／剧情服务。输入起点始终来自正常DynamicPath，停下后也不切到稀疏0x96旧坐标，避免把已到达的短段反复当作新目标；type5瓦片另等待位置回包进入实际范围，NPC使用正常本地交互距离并以实际会话确认；物件沿正常控制器提交操作，由原版物件路径继续靠近，不用稀疏资源坐标阻止其正常输入。不修改人物位置，位移校验沿客户端已有消费者。

拾取及任务库存操作在最近一次正常攻击／移动技能输入后保留1.5秒静默窗口，仍每200毫秒判断。该数值是调试输入节奏，不是原版技能冷却：当前D2X在技能执行期间拦截非Use库存操作，飞弹已发出或传送已同步不等于其门控已释放。D2MOO ItemMode的PLAYER_IsBusy检查交互、Cursor和剧情忙碌，不能据此把所有技能执行都视作同一原版门控；这项宿主一致性边界仍需单独核对。已经发送的库存请求只观察实际结果，不以等待窗口为由重试。技能书正常Use不套用该库存等待；其实际消耗和永久技能点分别核实。

较远的已指派物件、门户和出口先沿已重建地图接近，再发起单位交互；已指派NPC直接使用正常单位接近，按实际交互距离停下，不把NPC中心作普通落脚点；接近路线保持到完成，避免目标分配随房间切换而在探索与接近之间反复取消。开门先判断当前位置的实际交互资格，门中心路径无效时也检查真实周边接近点。临时单位占路保留已有无进展期限，邻格抖动不刷新进展；步行出口受阻只换同一连接的其他候选，不转去无关房间。正常赶路只处理邻近已指派门；探索没有可用前沿时，可接近一扇实际可达的关闭门以观察门后区域。未知位置的传送点不抢占旅行任务；位置已由真实指派记住且原表路径可能缩短路线时，可正常打开该点读取63历史，再只选择实际解锁的捷径，不为查询去搜索未知房间。

赶路／任务期间遇到正常50子格输入范围内已指派的传送点，近身战斗、任务服务与旅行结果等待优先。真实0x63记录已确认本关卡解锁则跳过；世界模式1／2并不代表这个人物已解锁，63明确未解锁时仍可正常操作该点，并等待新63确认后关闭菜单。中性点首次操作按原Operate23先激活本人WS再播开启动画，AI等真实模式变化并记住本计划已操作的关卡以避免立即再点，不向客户端／磁盘伪造解锁；之后实际菜单可推翻该临时防重记录。个人历史未知且外观已打开时不宣称本人解锁。该策略只处理客户端已见的传送点，不从隐藏预设定位野外点。导航不解析城镇拼图来猜位置。搜索覆盖只统计当前视口实际呈现的客户端瓦片，排除城镇全显和reveal叠层；换区域／任务不清除同局观察记录，完全观察过的房间不再因任务步骤重置而被重复搜寻。实际单位指派留下的目标／连接记忆用于回到已知目标；这些观察和实际位置提示由独立.d2xnav侧文件恢复，同seed正常退出／新进程已验证；恢复不保存活GUID或授予解锁，跨profile／轮换及损坏缓存组合仍待验收。

探索和已知目标接近的子导航结束只记录短期落点尝试，不把completed／failed当作观察覆盖。`exploration.frontierAttempts`最多256项，逐项列落点、结束时实际客户端位置、reached、outcome、失败原因、地形／静态碰撞revision及剩余重试毫秒；地形修订、位置移动至少8子格或5秒冷却到期解除排除。动态单位撤开即使未改静态revision也可在冷却后重试。实际覆盖仍只由正常渲染视口写入navigationObservation，失败不写seen，也不永久排除附近前沿；到达但仍有新增覆盖价值的落点同样不永久禁用。

回走到已知连接房间另记录所服务的未观察目标房间及出发时真实覆盖计数：到达／失败后仍未增加覆盖时，该分支让出30秒供其他分支尝试，新真实覆盖可提前解除；单纯移开八格或活动碰撞窗口变化不清除这份无发现记录。它不写seen，不断言目标房间不可达；换区／步骤重置清除，最多保留256个分支。此限制防止两个已知观察位之间的回走反复抢占其他分支。

已知连接房间也允许在无完整步行路线时以Teleport接近，远目标保持不变，每次仅选择策略距离内、严格推进且当前真实碰撞可站立的落点，实际本人跳转后继续下一段；不把未知房间中心直接作为传送落点。`directTeleport`只标记这类已核实落点的debug意图。

同层传送台只取实际单位指派。普通前沿／回走无可用方案时，可接近已看到的TeleportPad；没有完整步行路线只降低候选优先级，仍可沿已知合法落点施放正常Teleport。接近预算30秒按执行时间计，实际交互后等待20秒现实时间的本人位置不连续通知，不重放已提交操作或猜测服务端配对。`localTravel`列实际源／落点和使用次数，连续16次未增加观察覆盖／目标记忆则明确阻塞，保留现场。原版Operate27及自研宿主未实现边界见[物件](../gameplay/world/OBJECTS.md#同层传送台边界)。

旅行统一比较当前已解析的普通连接／已观察门户路线和当前位置已知传送点的合法候选。普通路线为空不否决传送点；个人解锁历史未知时，正常打开实际传送点读取63，选择目的地仍要求真实个人解锁。如果普通路线不存在、当前表明确本关卡有传送点且仍有潜在合法目的地，可沿真实观察边界寻找未知位置的当前传送点；此最后回退不抢占已有普通路线，不读预设坐标或城镇拼图。区域路线使用加权搜索，估价包含当前已知地形路径距离、已观察连接位置、未知出口的搜索成本和交互成本，不再仅按区域跳数。未加载段使用已观察房间尺度或缺省尺度估计，代价是debug策略而非原版玩法参数，不保证全局最短或未知碰撞可通行。没有任何合法候选仍明确失败，不自造跨幕旅行或授予解锁。

导航诊断由`debug-ai-status.navigationDiagnostics`返回：`search`记录房间／观察位置候选的已加载／探索状态、路径端点、新增边界格数、排除理由和分数；`approach`记录目标来源、端点及是否截断；`mobility`记录固定已知路线的总长、已确认进度、最多15个候选的路线位置及最终落点；`travel`记录普通路线及估价、传送点接近成本、实际已解锁候选及最终选择，无普通路线的成本为null。只保留最近一次对应规划；`debug-walk-status.excludedOpenings`另列当前连接已停止的接近点。需要连续证据时把状态快照保存到忽略目录，同时保留完整原包，不把本地规划判断当作服务端结果。

### 共享寻路预算

回走图保留当前原生near列表，并补入有实际观察记录的房间及其几何相接前沿；未观察且未加载的房间只作为前沿，不能继续展开成假想通路。释放房间的near为空不等于过去走过的路线消失。中间落点须位于所选房间内，重建地图中仅含移除／空白DT1的房间不作为观察目标；这些候选记录不写入实际探索掩码。无新增观察的重试记录按对应房间的覆盖变化失效，不因别处新增几个格子就全部清空。客户端已有区域布局的Vis／warp=-1接边可提供换区候选，实际开口仍按当前碰撞验证，再经普通移动触发指派。

[navigation_search.cpp](../../src/app/debug/navigation_search.cpp)由`DebugAutoWalk`持有，父AI通过同一实例查询。图形帧在父／子调度前统一重置配额，路线估价、探索及回走、门、拾取、物件接近、职业移动和战斗换位合计最多启动8次新`Grid::path()`；两次查询之间另检查2毫秒软预算。这是debug调度参数，不是原版路径或移动规则。预算不足抛出独立的协作让出信号，只由父／子决策边界消费；下一图形帧续算，同起点、目标、碰撞域和参数的已完成查询复用，包含确实求得的空结果。候选重放不再重复执行前缀搜索，不把尚未计算的候选写成不可达、探索覆盖或策略耗尽。普通决策仍为200毫秒，只有尚未完成的查询批次可在下一帧继续；所有真实请求和进展期限保留原时钟。

缓存按游戏／区域代次及地形修订失效，键还包含实际起点、尺寸、移动mask／size、部分路径及原射线选项。动态视图以客户端实际派生的占位格及静态修订形成碰撞指纹，交互目标的忽略占位也体现在该域；不跨域复用空结果。只保存路径值，不保存借用Grid／地图指针或回调。多个候选同起点同碰撞时可复用已有路径前缀的可达证明；这种证明仅服务布尔可达查询，路线长度估价仍求自己的路径，不宣称另一条前缀最短。缓存上限4096个查询、262144个路径点及16384个证明，连续120个图形帧未使用的条目淘汰；容量不足明确报告诊断，不通过逐帧清除活动前缀制造反复计算。

探索观察点和已知目标的候选批次按当前已知静态地形规划，避免附近怪物／佣兵移动使每帧的候选前缀重新计算；子导航与实际移动仍按当前动态占位及原射线复验。第三幕单机曾观察到动态候选批次持续让出而没有子导航，单次原子查询达51245.3微秒；这证明同步长调用仍存在，不能声称严格2毫秒上限或给出未测得的提速比例。RoomEx的near包含相隔最多五tile的可见房间，步行回走只将几何相接且没有已知静态封墙的边当作候选；未知接缝仍须实际接近验证。具备传送能力时，可另使用两侧当前已知合法站立点在配置距离内的连接，不把所有near或空白河道房间当作传送链。跨多段传送接近观察点、或经中间房间回走时保留同一最终目标；中间点到达不冒充远端房间已到达，未产生新观察且无法继续的目标只暂缓重试，不写入探索覆盖。已知目标的恢复路线保留至完整路径出现，不能在每个中间落点重新贪心接近河岸；战斗中断也不丢弃该绕路选择。两侧房间均已重建时记录静态接缝／合法传送候选的判定，Room1释放后仍保留已观察结果，重新加载后重查；该缓存不来自导航失败，不写探索覆盖，实际输入仍复验当前碰撞。

子导航先观察目标、交互和当前进展，再检查正在移动的原指针段：目标没移动、离段末尚远且当前动态碰撞与原整数射线仍可通时直接沿用；接近段末、单位移动或阻挡变化立即进入重规划，不要求先停下。每个新移动请求仍按当前碰撞复验。状态中的`navigationSearch`记录新查询、命中、可达证明命中、预算让出、移动段沿用及单次／累计微秒，`lastQuery`和`slowestQuery`还列实际调用文件／行号与最慢查询的局部坐标；`online-status.performance`同样提供该诊断，并将原帧计时拆出`ai`和`navigation`阶段，以区分候选处理、实际求路及其他客户端工作。

共享预算已通过Windows Release全部目标构建，并在原版1.13c Host第二幕运行中实见预算让出、缓存命中及移动段沿用，采样帧新查询数不超过8；同起点跨候选的可达证明复用尚未实见。单次求路曾达30498.9微秒，来自物件接近的观察位置查询，因此2毫秒不是严格帧上限；没有同条件旧／新性能对照，不宣称提速幅度。公共`Grid::path()`算法保持原实现，单次调用仍同步执行，内部AStar及整网格初始化没有可暂停继续点，候选生成和碰撞视图准备也不受该求路配额约束。当前只恢复候选查询批次，不保存AStar内部堆；残余长调用仍须按实际计时定位。

## 药剂与自动补给

`supplies`是整条计划的输入策略，默认启用，不需要逐瓶指定GUID或购买步骤。例如：

```powershell
.\scripts\Send-D2XCommand.ps1 -Command debug-ai-start -Arguments @{
    scenario='tools-of-the-trade'
    supplies=@{lifePercent=60; manaPercent=35; criticalLifePercent=25; healthCount=4; manaCount=4}
}
```

| 参数 | 默认 | 行为 |
| --- | --- | --- |
| enabled | true | 自动喝药及补给总开关 |
| lifePercent／manaPercent | 60／35 | 当前生命／法力严格低于该百分比时考虑饮药，范围1–99 |
| criticalLifePercent | 25，最多为lifePercent | 危急生命线，优先本人已有回复药水；允许正常红药追加 |
| intervalMs | 1500 | 两次已确认饮药之间的调试策略间隔，范围600–10000；不是新增玩法冷却 |
| buy | true | 在城镇自动补齐储备；false时仍可喝已有药剂 |
| healthCount／manaCount | 4／4 | 红／蓝药各自的储备瓶数，范围0–16，0表示不购买该类 |
| returnWhenEmpty | true | 野外资源已低且对应药及回复药均用尽时，安全插入回城补给并返回原区域 |
| fillPortalBook | true | 在本幕城镇采购可用回城书，并按当前Misc.maxstack补满背包书本；也适用于显式restock |

当前生命／法力读取正常原包，最大值借用同一人物HUD／人物面板的已知投影，未知最大值不猜阈值。`debug-ai-status.supplies.vitals`分别显示原包当前值及`displayMaxLife`／`displayMaxMana`，不将显示上限作为宿主权威真值；既有法力上限投影差异见基准档段落。

只选本人腰带或背包里的已解码药剂，直接通过RemoteInventory.Use使用；不从关闭的箱子／方块取物，不替佣兵喝药。分类读取当前Misc、ItemTypes、pSpell、state与States，先区分rpot，再区分继承的hpot／mpot，避免把回复药当普通红／蓝药。已观察到普通恢复状态时暂不叠喝该类，危急生命例外；没有普通药时才以回复药后备。相同类别按当前表的恢复量常量选强瓶，这只是选择提示，不在客户端计算、应用恢复或职业随机倍率。

使用提交后冻结本次物品／请求序号，等待原件实际消费；普通库存Updated不单独代表成功。`lastPotion.consumed`和`recoveryObserved`分别记录消耗及其后12秒内观察到的恢复状态／对应资源增长，不能把瓶子消失直接写成已恢复；观察期结束仍未见结果会保留未确认标记，不把后来无关的资源变化当作该瓶证据。结果未知、被替换或超时不盲目重用；等待期间不继续发子导航输入。正常Pending、Cursor、死亡、门户及物品资格仍由现有客户端入口裁决。

补给按本幕寻找Akara／Lysander／Ormus／Jamella／Malah，第二幕回城书／卷轴另找Drognan；身份从当前MonStats编译记录解析，并核对Npc及Misc的原商店供应字段。只通过真实NPC交谈、TradeOpen、实际货架及Buy执行。报价复用RemoteUiClients.itemQuote；价格未知不传零价。按实际资金选择能负担的强瓶，逐瓶等待新0x2A成交结果与本人药剂数量增长，再购买下一瓶。回城书缺失时先正常购买一本，再对实际货架卷轴提交原Shift购买，按已解码书本页数增长确认；容量读取当前Misc.maxstack，不写死20或购买数量。只检查背包中可用的书，箱子／方块中的书不算出门资源；已有多本时补齐其实际容量。药剂不使用Shift补满，不出售装备筹钱、不生成药剂或授金币。缺金币、满背包、拒绝、缺货及未知结果均明确失败，保留现场原因。

这套准备在各幕城镇共用，先满足配置的红蓝药储备及回城书，再继续原任务／出城；不会每喝一瓶就在野外返城。野外已观察到原表boss、处于接敌距离、治疗药及回复药均耗尽，且生命低于70%或近期掉血达到combat.lifeDropPercent时，也会请求补给。进入回城阶段后优先正常蓝门／脱离路线，不被主动攻击反复打断；危险飞弹避让和已有药剂使用仍可执行。首领身份本身不算危险证据。`supplies.vitals`提供portalBooks／portalPages／portalCapacity／portalStockKnown及红蓝药数量，历史区分请求和实际成交。

自动补给仅在没有待确认的开门、拾取、物品来源、任务交付、选点／跨区或门户操作时插入；保留原目标索引，补给期间单独有600秒上限，完成后补回原目标的剩余执行时间。回程优先使用实际存在、归本人所有且目的地为原区域的蓝门，没有则普通旅行；若当前目标本来就是回城或去本幕城镇，则补给后留在城镇继续该目标，避免无意义往返。回城／补给途中没有可用药剂、且缺蓝或生命危急时优先继续正常脱离路线，避免站在原地反复施放不可用的固定技能；原怪物碰撞及伤害照常生效。已经提交但未确认的原操作不因缺药重新执行。显式`@{action='restock'}`可单独排入队列，回城购买后留在城镇，方便组合新的目标；它要求enabled与buy都开启。暂停保留已提交药剂／购买的观察状态，换游戏取消旧意图。

原依据为D2MOO `SKILLS/SkillItem.cpp::SKILLITEM_pSpell03_Potion`／`SKILLITEM_pSpell05_RejuvPotion`、`ITEMS/ItemMode.cpp`及`UNIT/SUnitProxy.cpp`原NPC／幕与交易准备；正常0x20／0x26使用、0x38开店、0x32购买和0x2A结果复用现有协议入口。原玩法细节见[腰带与消耗品](../gameplay/items/BELT_AND_CONSUMABLES.md)、[NPC交易](../gameplay/npc/TRADE.md)、[商店经济](../gameplay/items/ECONOMY.md)。已有蓝药实际消费／恢复及正常货架购买／回城补给往返记录，阈值与失败组合仍待验收；默认开启购买要求角色实际有金币，基准角色的准备不等于AI可以无偿购买。

通用受理等待及回城书收尾使用Windows Release全部目标构建，EXE SHA-256为`C4093C198C71E2BD041FBB244FEA089B678016D081B23F0F4FD3A7B8E80F8F62`。忽略目录`artifacts/debug-ai-act4-20261031-063527/single-21-shared-wait/`从原正常存档基准出发，正常购买书／Shift补满和8红8蓝，旅行104、蓝门返城103、补回20页全部完成，11笔成交、online.error为空、server.failures=0；重复restock为零购买。`native-10-shared-wait/`以同一程序加入现有原版1.13c Host:4000，从无书基准直接安排旅行／返城／补给，出城前自动插入采购，完成相同往返及11笔成交。实际C2S选择220，原0x22数量20→19→20，未改任务位／授金／生成资源；完整原包和portal-skill-quantity-index保留。此前native-09在220数量20时错误选了旧219技能且未创建蓝门；共用RemoteControl现优先明确数量通知，不让旧技能资格遮住可用书。受理前的暂时拒绝经共用入口等待，已提交请求不重发。

## 战斗策略

未指定combat.skill时仍按实际掌握的Frozen Orb、Fire Ball、Zeal、Attack选择主技能；`fallbackSkills`显式列出已掌握的备用主动攻击，最多8项，不自动加点、装备、授予法力或猜测抗性。主技能与备选都在接收计划时核对实际技能；运行时继续复核等级、左右手、原目标资格和普通角色投影的usableNow。战斗光环占右手，攻击及备选须支持左手；切换／施放／停止共用正常RemoteCombat。未知资源或资格不伪装成已知可用，原服务端仍裁决实际资源和命中。

例如角色确实已掌握这些技能时，可把下面的combat配置用于原有scenario／goals：

```powershell
combat = @{
    skill = 'Frozen Orb'
    fallbackSkills = @('Fire Ball', 'Lightning')
    noProgressSeconds = 6
    stallTimeoutSeconds = 90
}
```

探索／赶路默认只处理贴身威胁，接近hunt目标后处理其附近敌人，清场沿实际步骤保留全部必杀目标。单次指派的效果观察只将规范化原生命比例的**新低值**计为净进展；生命回升、原命中标志位、受理次数及独立命中通知不充当净伤害。记录生命回升与命中反馈，但不据此确定当前技能的伤害归因；没有生命反馈时明确保持未知，不判定免疫。

持续无净进展时先复查当前射线／距离、门与实际技能资格／资源，沿完整已知碰撞路径尝试一个不同的攻击角度，再留一个效果窗口；仍不能推进则按配置顺序切换备选，每个技能重新核对资格。单次接近／换位最多8秒，移动并不直接算战斗进展。门与正常技能选择等待延后效果窗口；攻击动画和原延迟期间不抢占输入，时间仍累计，在可输入的空挡判断效果，连续无伤害施放不会重置窗口。整个战斗仍有局部停滞预算。资源／资格暂时不可用时保留一个观察窗口并重查，恢复后可重新选择可用攻击。尝试原因最多64项、换位记录最多128点，绑定真实GUID及assignment；换区、换目标／指派或任务步骤变化清理策略状态。

已取得的同一指派目标在engage半径内继续交战，战术换位或另一个怪短暂更近不会清空恢复阶段；实际必杀目标仍优先。目标短暂不合法／不相关时释放攻击输入并允许继续任务，保留同GUID／指派代次的策略进度；重新交战时补偿这段非交战时间。单位移除、指派变化、死亡或阵营失效才清理该记录。该补偿只作用于局部效果判断，已提交请求的现实等待期限仍独立计时。

非必杀沿途目标用尽策略后暂避，不再仅10秒到期就原地重新打同一目标；到期后还须本人移动至少8格且已离开该目标的接敌半径加撤退距离，或该指派目标移动至少4格，才允许再尝试。实际单位撤出／重新指派／死亡会清旧记录。任务必杀、真实清场和取物清敌不使用该暂避排除，以免把沿途失败误当成任务完成；这些是debug选择策略，不新增玩法免疫或攻击规则。

单个首领／必杀目标也会结合低生命、近期掉血与剩余红药／回复药触发后撤，远程威胁不要求进入贴身半径；药剂仍由既有补给动作消费，资源不足不会变成免费恢复。后撤从16个方向的完整已知路径中选择更安全位置，保持最多2秒、至少4秒间隔；生命危急、无药且无安全路线时具体报阻塞。普通怪／中立／伙伴身份沿RemoteCombat，不自造威胁或修改原碰撞。

静电场读取当前Skills的aurarangecalc及参数，用公共公式求有效作用半径；读取DifficultyLevels.StaticFieldMin，不在客户端施加百分比伤害。原MonStats.boss且生命反馈至少60%时才自动插入，正常难度观察至25%，其他难度采用至少25%及原下限加5%的较高值，再切回配置的伤害技能；这些是debug策略阈值。实际无进展仍沿原换位／备用恢复，不判为免疫。依据D2MOO SkillSor::SrvDo020／AuraCallback，客户端用普通自施法输入，最终效果由服务器裁决。当前测试女巫基础等级1，正常装备可提供有效等级10，无需改档／授级；零售初始94仅发基础清单，客户端有效等级由已观察装备／状态沿公共原生等级函数派生，不能把缺少21当成没有装备加成。

飞弹躲避借用正常RemoteScene的只读显示缓存：世界位置、当前速度、敌我及剩余寿命，沿实际轨迹作0.35秒规划；危险尺寸取当前Missiles.Size，另加debug余量。只纳入正常客户端已重建的diablight／diabfire／diabwall／vampirefirewall，友方、尚未出现或已过期的效果不算危险；不读取服务端隐藏技能／未来轨迹。每轮复验选定落点，优先正常Teleport，落点须为当前已加载／近房间的可站地面；步行后备需完整已知路径且避免继续穿过危险段。躲避释放攻击输入、保留战斗记忆，不能绕过施法动作／资源／原输入门禁。挂起的战斗记忆不再独占职业移动；明确的接近／换位／后撤阶段释放攻击后，也可通过同一正常职业移动入口执行，持续攻击仍不抢占。`hazardFeedback`报告观察数、间距与落点，`combatFeedback`列静电场等级／半径／停用阈值；普通online快照也列飞弹速度及敌我。此处是基于可见表现的避险策略，未认证全部攻击预兆、视觉缺失、延迟和所有怪物技能。

施放不再固定为600毫秒独立点击。首次使用正常点击，保持相同技能／目标时沿普通控制器的repeat请求；非持续技能等待与正常鼠标输入相同的本地动画忙碌信号，持续技能沿原客户端channel分类保持输入。原表数值delay按25Hz换算最早再次施放时间，正延迟使用独立点击并观察原skilldelay状态；非数值公式的延迟保持未知，仅沿实际状态与普通输入门控，不把它假定为零。仍每200毫秒判断，不替代原动画、费用、目标／装备、冷却及请求限流。

策略全部无效或局部预算耗尽时，必杀／清场目标明确失败并保留角色现场、任务及`combatFeedback`诊断，不跳过目标或宣称击杀；沿途非必杀威胁可暂避该次指派10秒。诊断列目标身份／位置、当前／最低生命、回升／命中反馈、射线、玩家生命趋势、红蓝补给、技能序列／阶段、输入拒绝与尝试原因。无净进展始终保留遮挡、未命中、回复和反馈不足等解释，不自动标记免疫，也不自动配置破免装备。

依据及边界：本地D2MOO `D2Common/src/D2Skills.cpp::SKILLS_GetManaCosts`、`D2Common_SKILLMANA_CheckStat_6FDB0F50`及`SKILLS_CheckSkillDelay`，`D2Game/src/SKILLS/Skills.cpp`的原delay状态；资源可用性复用已有角色投影，不在debug重算另一份法力费用。持续输入／动画门控复用现有`SceneController::handleWorld`、`RemoteScene::Impl::channelSkill`和RealmSession的原单次／重复技能请求。效果窗口、撤退阈值、候选与预算是debug策略，不是原版玩法参数。战斗闭环已通过Windows Release全部目标构建并进入原版1.13c Host第二幕回归，实见净生命进展、沿途防御及拥挤后撤。一次复活／生命回升观察中bestLife保持原低值，没有把回升当作伤害进展；当前高等级角色与佣兵常在恢复窗口前击杀目标，尚不能认证持续无进展后的备用技能切换、策略耗尽及全部单体撤退组合。未掌握的配置技能在计划启动时已拒绝，不能把该入口检查当作运行期切换已通过。

## 职业移动策略

默认`mobility.mode='auto'`按当前已学技能选择：女巫优先Teleport；有Charge的圣骑士使用左手Charge，并在右手选择已学Vigor；只有Vigor时保持普通行走。配置`mode='walk'`关闭传送／冲锋，`vigor=false`可同时关闭移动光环。也可选`teleport`或`charge`，技能未知、城镇禁用、落点不合适或正常请求不允许时仍回退步行，不授予技能和法力。`distance`默认24、范围8–50，为单次调试输入距离。

同一子导航目标先缓存一条到实际目标的完整已知步行路线，再沿固定路线选择更后面的整数落点；不把活动碰撞窗口的截断点当成目标，也不在每次传送后重新选择相反绕行路线。路线只来自已观察地形，当前落点仍须通过实际客户端碰撞及8–50格策略距离检查，未知或失效位置不能凭缓存施放。收到本人原0x15位置不连续通知且实际落点接近所选位置后才推进已确认路线进度；受理、普通行走或无关位置纠正不算传送到达。新目标、换区或任务步骤变化清除旧路线。无法建立完整路线时交回普通探索，不重置子路径的无进展期限。

同一步对同一目标／落点最多尝试两次。候选沿路线采样，检查与发送使用同一个整数格；2／4／6子格碰撞余量只作同方向候选的次要偏好，不能把后退当作收益。对于客户端已观察到的实际目标／入口，即使步行路径被墙截断，也可选择配置策略范围内、向同一目标严格推进的已知合法整数落点；探索也可用当前已重建、可站立的观察落点跨墙，须在策略距离内、确实能展开未知边界且等待真实传送反馈；有价值的已重建观察位置超出一次施放距离时，可先选择向该位置推进的已知合法中途落点，保持该段完成后再评估；不把这一例外用于未知房间中心。允许Teleport跨墙，但不生成隐藏地图；读取当前Levels.Teleport并由服务端裁决技能、资源、落点及费用。Charge另要求从当前原生位置到落点的普通碰撞与原整数射线均畅通。两种施放期间暂停子行走输入，技能选择等待正常确认，请求保留Pending及节流；3秒无位移反馈后暂退普通行走。短距离门／NPC仍正常接近；拾取专用目标允许8子格以内的正常Teleport，须另通过当前可站立及实际拾取距离／射线检查。原版技能依据为D2MOO `SkillSor::SKILLS_SrvDo027_Teleport`；这些均为调试输入策略，不修改玩法或客户端位移规则。
