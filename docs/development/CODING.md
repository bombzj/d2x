# 简明编码规范

适用于项目源码；具体文件沿用邻近风格，不为统一格式改写无关代码。模块职责见[架构速览](../architecture/OVERVIEW.md#agent速览)，当前实现与限制见[基线](../../BASELINE.md)。

## 代码与接口

- 使用C++20、标准库和现有项目工具；Windows／Linux共用玩法代码，平台API留外围适配层。
- 命名说明业务含义，优先沿用模块的类型、函数和文件命名；新增代码避免单字母变量、魔法数字和布尔参数堆叠。
- 函数围绕一个职责组织；先复用已有领域入口和纯计算，不引入万能管理器、服务定位器或每技能虚类。
- 资源／规则从当前MPQ准备为纯值；原协议常量、算法常量与资源参数区别对待，缺依据不编造默认成功行为。
- 生命周期用RAII表达；所有权唯一，借用只读，裸指针不跨可能失效的提交／异步边界保存。运行实体使用真实ID及必要代次，不用容器下标代替身份。

## 依赖与编译

- 公共头只暴露必要契约，能前置声明就不包含完整系统定义；每个文件直接包含自己需要的类型，不能依赖偶然的传递包含。
- 非模板、非必要内联的实现放入`.cpp`；私有复杂运行态放模块内部，确有依赖收益时才采用PImpl，不为所有小类型增加堆分配。
- 改技能实现不应迫使无关模块重新编译；参考`skills/evaluation.cpp`和私有`skills/runtime.hpp`，模块外不包含后者。
- 跨领域使用显式窄Ports和类型化请求，不向玩法传入GameSystems、MPQ句柄、网络连接或UI对象。
- 新增编译单元登记到现有CMake目标；依赖尽量使用PRIVATE，只有公共契约确实需要时才传播PUBLIC依赖，不用聚合头掩盖缺失包含。

## 状态与提交

- UI／客户端读副本并提交原请求；服务端决定目标资格、命中、资源、奖励和保存结果。
- 派生索引／缓存不成为第二份可写真值；说明更新时点、失效条件和稳定遍历顺序，优化不能暗改目标优先级或随机顺序。
- 准备与提交分开；提交复验身份、区域／控制代次、revision和资格。背压保留阶段，不能重复扣费、掷数、命中或发奖。
- 随机流和发生标识有明确所有者；不得失败后回写过期全局随机，也不得从客户端重试次数推导奖励身份。
- 未实现、输入无效、过期和容量不足明确区分；不吞错误，不把stub当成功，不用普通攻击替代未实现技能。

## 修改与交付

- 先读基线和对应模块，做最小相关修改；保留用户改动，不顺手清理无关文件或改变公共API。
- 修改规则／存档语义时同步规则指纹、格式边界与负责文档；旧档不静默迁移。原版证据和未核实项明确记录。
- 遵守[验证指南](TESTING.md)的授权边界。说明改了什么、实际检查了什么、哪些仍未验证；编辑器无错误不等于构建或运行通过。
- 资源、参考仓库、构建产物、日志、截图和用户存档不纳入源码提交；文档只在负责页维护事实，不复制过程流水。
