# 简明测试与验证指南

本页说明验证方法，不自动授权执行。默认只修改源码／文档并说明静态核对结果，等待用户查看；不新增测试脚本、测试用例或专用测试程序。构建、运行检查、测试和打包按当轮明确授权执行，不能从“实现功能”推断已获授权。

## 验证顺序

1. **确定范围**：阅读[基线](../../BASELINE.md)和负责模块，写清复现条件、期望结果及最小受影响路径。先区分当前源码、已有EXE和历史证据。
2. **静态核对**：检查调用点、类型／头文件依赖、CMake登记、身份／代次、失败和重试分支；可查看编辑器诊断。只改文档时核对路径、链接和约定一致性即可。
3. **构建（获授权后）**：在VS Code使用CMake Tools，先确认配置和目标。客户端为`d2x`，独立服务端为`d2x_pvpgn`；`d2x_server`是内核库。失败先查构建诊断，只处理相关问题；不隐式切换Debug／Release或打包。
4. **现有测试（获授权后）**：通过CMake Tools列出并运行当前已注册测试；不要因存在`tests/`或旧构建目录就认定测试仍有效。没有适合入口则明确说明，不新建专用程序凑覆盖。
5. **运行与回归（获授权后）**：复用现有游戏、资源工具和调试管道，先验证最小行为，再验证受影响边界；保存功能必须正常退局并在新进程恢复。打包属于另一步授权。

## 运行选择

| 改动 | 最小观察与回归边界 |
| --- | --- |
| UI／客户端表现 | 实际操作、原包副本及截图；两种服务端共用路径，不能仅凭权威快照证明画面正确 |
| 战斗／技能／物品 | 正常请求、伤害／资源／物品事实；无效目标、死亡、换区、中断、容量背压及重复提交 |
| 多人／组队 | 至少双客户端真实TCP；加入／离开／断线、私有事实隔离及同队资格；单机通过不等于多人通过 |
| 存档／规则 | 隔离角色和备份，保存→正常退出→新进程重入，核对持久值与明确拒绝条件 |
| 性能／依赖 | 固定配置、地图、种子、人数和负载；记录耗时与候选／队列量，区分冷热缓存。增量编译范围以实际编译日志为证据 |

使用独立角色、存档目录、管道名和空闲端口，不覆盖用户存档、不停止已有服务。只关闭本轮启动的进程；失败后先保留日志和可恢复状态。管理生成／补资源仅用于准备条件，不能作为自然通关或真实掉落概率的证据。

## 结果记录

记录源码版本／未提交改动、实际EXE及配置、MPQ、角色条件、连接方式、步骤、预期／实际结果和证据路径。临时证据放忽略目录`artifacts/`，不提交资源、日志、截图或存档。

结论分开写“源码核对”“构建成功”“列出路径有限运行通过”“未验证／失败”；旧包成功不能认证新源码，Windows结果不能认证Linux，调试准备不能认证原版一致性。更新负责专题和基线，不在多个页面复制同一运行台账。
