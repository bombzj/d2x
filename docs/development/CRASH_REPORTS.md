# 崩溃记录

Windows EXE 在 `main` 安装 `app/crash_report.cpp` 的未处理异常过滤器。可写的运行目录下，报告路径为 `artifacts/crashes/<UTC时间-进程ID-线程ID>/`，每次使用独立目录：

- `crash.txt`：异常码、异常地址、EXE 加载基址，以及故障线程最多 64 层调用栈。符号缺失时仍记录模块名和模块内偏移。
- `crash.dmp`：包含异常上下文及线程信息的 minidump，先于符号解析尝试写入。可用 WinDbg 加载；它不是存档，也不能恢复未落盘进度。
- `d2x.exe`：尽力复制当时的程序；同目录存在 `d2x.pdb` 时一并复制，避免之后重编译导致地址与符号不匹配。MinGW 的符号未必能被 DbgHelp 解析，可依据报告基址与偏移分析保留的 EXE。

报告只保存在本机、不自动上传，dump 可能包含进程内存中的角色数据和本机路径，分享前须检查。使用进程内 DbgHelp，严重堆破坏、栈耗尽、fail-fast、强制终止、磁盘不可写、断电或其他处理器覆盖可能导致报告缺失／不完整／卡住，不保证任何崩溃都能记录。挂着调试器时由调试器先处理异常。非 Windows 当前为空实现。

顶层捕获的 C++ 异常和 `std::terminate` 也尽力生成报告，但日志使用 `0xE000D2A0` 标记合成上下文，文本栈是报告处理器所在位置，不冒充原始 throw 调用栈。主线程预留了异常栈空间；不宣称覆盖其他线程的栈溢出。新增记录器目前仅通过 Windows Release 编译，未实际触发崩溃验证。
