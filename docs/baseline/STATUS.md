目标：基于经典 Diablo II MPQ 的 C++ 引擎；当前为单机 MVP，不是完整原版重实现。

连续主线：

`罗格营地 → 血腥荒地 → 冰冷之原 → 石块旷野 → 地下通道一层 → 黑暗森林 → 黑色荒地 → 泰摩高地 → 修道院大门 → 外侧回廊 → 兵营 → 监牢三层 → 内侧回廊 → 大教堂 → 地下墓穴四层`

支线：邪恶洞窟、洞窟一／二层、地下通道二层、地洞一／二层、深坑一／二层、埋骨之地及两座墓穴、遗忘之塔入口及五层。外侧回廊／大教堂按原表 Depend／Offset 连接依赖关卡，兵营按原朝向及坐标偏移接入回廊。崔斯特瑞姆地形可独立查看，任务传送门尚未实现。

兵营：采用原版 10×14 房间、四房起始环、主题房、定向回廊连接房、监牢楼梯及铁匠房。入口跟随外侧回廊变体；普通入口为 `--level 28`，回廊方向可通过 `--level 27 --variant 0..2` 选择。资源检查与打包共用迷宫家族元数据；缺某家族资源不禁用其他家族。三个回廊朝向均已有短帧启动记录。

监牢：12×12 房间与四房起始环；一层放传送点房，二层放 Pitspawn 特殊房，三层楼梯接内侧回廊。地下墓穴：一层使用四向固定入口房，二／三层使用横向或纵向固定入口房；二层放传送点房，下楼梯接原版第四层预设。门状态、传送点功能、首领行为、任务及键鼠往返不因地形加载通过而视为完成。

牛场：独立 80×80 地形，原悬崖、中间、转角、边缘四类 LvlSub 模板按分组匹配和变体替换，放置原营地、池塘、围栏、沼泽及石块预设。牛王原身份已识别，行为仍使用敌对替身。通过 `--level 39` 查看；没有伪造洞口或无条件红门，任务开启／返回规则尚未实现。

主线野外：洞口先于中间、转角、边缘替换，跨区接边和原预设占用受保护；空白宏格不再铺基础草地或创建刷怪房间。按已核实方向查表接入河岸和桥变体，道路使用原两格宽栅格化及 256 项 DT1 地板转换表。宏格路径沿用项目 Grid 寻路与平滑，是适配实现，不保证原版道路形状或随机流一致；未加入原营地专用道路端点。石阵、艾尼弗斯树与塔入口放置失败会明确拒绝地图，不再静默遗漏。

主线悬崖：按相邻关卡接触区拆分边界，保护连接段，选择原悬崖转角与直段；优先扫描悬崖洞口，未找到时保留普通洞口分支。营地过渡按原方向查表选择固定文件槽位，种子 1 已实际触发并加载 TownSTrans2。二者仍是当前矩形区域布局上的适配，非原版逐随机流一致实现。

通用 LvlSub 主题阻塞：当前挂载源的 `data/global/tiles/act1/outdoors/trees.ds1` 为 v12、6960 字节，偏移 6744 声明 14 个分组，余下只有 13 个完整的 16 字节分组及 4 字节，无法读取第 14 组完整边界。资源查询明确拒绝截断数据；未删减分组、未修改原 MPQ。需核对合法完整资源或有依据的版本解释后再接主题执行器。

仍待逐项补齐：道路原路径选择及端点、通用 LvlSub 地形主题／神殿／传送点、崔斯特瑞姆与牛场任务传送门，以及更广泛种子下的原布局一致性。39/39 只表示目录地形覆盖，不表示这些规则已完成；本阶段按最新指令提交源码，保留这些缺口。

## 掉落实行顺序

当前主任务已由装备切换为怪物掉落；逐项实现和验证，不写测试脚本／用例，不补造概率。按最新指令先提交装备基础与 TC 选择阶段为 `dfa9029`，再继续死亡入口；提交不代表装备或掉落已完整实现。

1. TC 选择：已实现 LoD 单人正 Picks 权重抽样、原 NoDrop、负 Picks 顺序展开、递归及四项品质修正取较高值。按原 ItemTypes.TreasureClass、物品等级区间、可生成／任务限制、类型 rarity 和物品表顺序生成 160 个自动类别；根 TC 沿原相邻 group/level 升级，子 TC 不自动升级。提供循环、深度及工作量保护。纯 treasure 查询不创建物品；游戏批次在每个叶子执行品质回调并在六件支持候选后停止，不保证与完整原版实例生成随机流一致。
2. 死亡入口：已接 `resolveMonsterLoot`，按真实身份选择普通 TC1、冠军 TC2、独特 TC3、超级独特的难度 TC；普通难度取 MonStats 等级，噩梦／地狱非 boss、非 noRatio 怪物取区域等级并允许根 TC 升级。基础冠军加 2 级，独特／超级独特加 3 级；超级独特另有改变等级的修正时暂缓。任务 TC4 缺击杀者任务状态时暂缓，当前 Minion 同时表示普通及精英随从，缺归属修正时不猜等级。重复死亡 ID 在解析前跳过；支持入口执行批次规划，暂缓原因通过日志与现有 UI 通知显示。实际击杀路径尚待定向验收。
3. 品质与实例：原 ItemRatio 选行、品质顺序及非负 MF／TC 修正已实现，品质请求不等于成功创建暗金／套装或词缀。当前生成强制普通、非任务、无耐久的药水／卷轴、箭袋和金币，保留等级；箭袋 minstack/maxstack、其他已支持堆叠消耗品 minstack/spawnstack、金币等级随机数与 gld,mul=N 倍率按原规则。金币钱包上限等级乘 10000，正常拾取，不占格；超上限余额留地面。当前金币堆超过原 maxstack 时明确暂缓，装备金币加成、银行、死亡掉金、投掷武器、负 MF、其他 token 和品质实例未实现。未知实例仍整批清空候选、不重抽，保留已消费随机状态并通知，已结算死亡不会补发。
4. 游戏闭环：格式 v8／规则 v26；旧档拒绝。新增显式启用的 Windows 调试管道与 PowerShell 客户端，通过正常移动、屏幕内指定 ID 击杀和正常拾取，验证四个普通怪物死亡只结算四次，箭袋数量 196／等级 2 入包、金币 5 入钱包且地面实例消失，重复击杀拒绝。保存恢复后数量、钱包、已结算数和随机状态保持。位移找空位是项目网格适配；六件上限、钱包满额部分拾取、跨用户 ACL 拒绝及 Linux 构建仍未实际验证。接口见 DEBUG_PIPE，不作为普通攻击命中和伤害验证。

已验证：默认种子下 `Act 1 H2H A` 命中 NoDrop；`Act 1 Champ A` 展开为 `buc、hp2、hp2`，重复查询结果与随机状态相同；`weap3` 展开为 `dgr`；指定等级 30 的 `Act 1 H2H A` 升级为 `Act 4 H2H B`。这是原表选择证据，不是实际击杀掉落验收。

1. 原装备数据：部位、类型继承、职业、双手、箭袋配对及需求。已完成 LoD 只读导入，现有资源查询验证双手剑、弓、盾、戒指、法杖和野蛮人专属头盔；旧数字类型格式仍暂缓。
2. 穿脱事务：预览与提交共用私有库存快照；替换和冲突装备退包，容量或版本失败不提交；腰带保留原缩容事务且共用需求检查。普通装备提交前验证派生属性。当前原初始斧盾穿戴、v7 保存恢复通过；满包回滚、双手／双持、过期版本、死亡拒绝等定向交互待验收，不标为全项通过。
3. 面板与初始装备：十个原 Inventory 部位坐标，背包拖入指定部位、右键选择空的合法槽位／卸下；原 CharStats 初始斧盾实际创建并穿戴，真实库存按需加载原美术。已接装备拖出到空背包格、直接丢弃和已打开私人箱，仍执行原访问／距离／空间规则；目标格已有物品时拒绝，不支持装备与包内物品直接互换。面板显示基础伤害、防御与格挡；完整键鼠流程待验收。
4. 属性与战斗：普通近战按武器原伤害、力量／敏捷系数、单双手状态计算定点伤害，双持轮流使用武器；不再使用固定 34 点范围普攻。防具创建时在原最小／最大防御间掷骰一次并保存，派生防御含敏捷四分之一；盾牌格挡使用原 BlockFactor、敏捷和等级，跑动格挡降至三分之一。普通难度普通怪物 A1 从 MonStats／MonLvl 导入准确率，静止／行走时执行防御命中公式，跑动绕过命中检定；其他难度、精英和首领仍保留原行为。玩家攻击命中率、武器速度、需求加成循环、生命法力及抗性尚未接入；远程武器不伪装成近战，技能仍是原 MVP 参数。
5. 完整实例效果：非堆叠普通武器命中后按 4% 损耗耐久，受击防具按原部位权重选择后按 10% 损耗；损坏装备保留部位但不参与属性派生，提示 Broken。投掷堆叠损耗、弹药、修理、品质／鉴定、词缀、套装／暗金、宝石／符文／符文之语及插槽效果未实现，事务仍只接受普通品质。实际耐久损耗尚无定向运行证据，不以编译或存档通过代替验收。
