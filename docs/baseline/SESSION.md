# 会话与权威宿主基线

更新：2026-10-04。记录当前源码事实；后续阶段见 [技术改造方案](../TECHNICAL_REFACTOR_PLAN.md)。

## 当前边界（P0）

- [`GameSession`](../../src/gameplay/session/session.hpp) 是不透明、不可复制的兼容外观，唯一拥有 `unique_ptr<GameSessionImpl>`；构造、析构和查询转发在 [`session_facade.cpp`](../../src/gameplay/session/session_facade.cpp)。公开成员不再内联读取私有世界／内容状态。
- [`GameSessionImpl`](../../src/gameplay/session/session_impl.hpp) 拥有 ID／随机流、内容目录、模拟、库存、掉落与临时请求，并组装区域资源管理器和休眠状态仓储。只由会话／NPC 实现和外观转发包含，不作为 UI 入口。
- `session.cpp`、各 `session_*.cpp` 及 NPC 会话成员实现迁到 `GameSessionImpl`，函数逻辑、成员顺序、构造初始化、固定步与随机消费顺序保持。模拟／库存原有朋友访问暂时由该私有实现承担。
- [`session_views.hpp`](../../src/gameplay/session/session_views.hpp) 保存旧接口使用的祭坛、NPC 对话、佣兵属性和传送门值类型；传送门仍可通过 `GameSession::PortalView` 使用。它不是新的网络协议。
- `d2x_session` 增加外观转发源文件，库依赖方向不变。消费者需要完整内容、区域、库存或角色保存值时，在实现中显式包含对应头，不再依赖会话传递包含。

## 状态与生命周期

玩家死亡新增独立 `session_player_corpses.cpp`：接收 `PlayerDied`，连接库存脱装、普通单机损失、原动画结束后的宠物清理／幕城镇复活及回收路径；宿主按 MPQ 时序通知模拟器一次性完成 `DT → DEAD`，无需等待 Esc，也不写死延迟。模拟器按归属杀死所有已注册本人召唤物并保留死亡佣兵；死亡动画期间不因脱装后的技能等级下降重算召唤数量限制。尸体集合属于会话，跨区域保留，回城复活不调用重置区域。公开尸体查询为只读 span，客户端提交 `RespawnPlayer`／`RecoverPlayerCorpse`，存档只选择原单机可保存的最早非空尸体。依赖与原版限制见 [玩家死亡](../PLAYER_DEATH.md)，该源码批次尚未构建、运行或打包。

`app → GameSession → GameSessionImpl → Simulation / InventoryService / 区域`。外观与私有实现同时存在，不能复制或替换私有实现；已注入的回调仍指向稳定的实现对象。区域与模拟的借用关系、销毁顺序、存档恢复和死亡结算继续沿用现有实现。

第六项区域资源缓存已归 `RegionStore`，固定槽位只填充／不扩容；`AreaRepository` 移交休眠战斗状态。加载／切换和人口准备从 `session.cpp` 移到 `session_regions.cpp`，原 NPC／任务／库存协调留宿主。`Map` 组合 `MapTerrain` 与活导航；地图显示／手势与地形图形准备分别经 `IMapClient`／`IMapAssetSource`。单玩家当前区索引与兼容查询保留，完整并行活区尚未实现。第六／七项已一起构建并做有限交谈／卷轴／交易接触和地图显示冒烟，见[地图基线](MAP.md)。

公开 `state()`、`content()`、`inventory()`、区域查询和旧命令仍保留，返回同一权威对象的只读引用。这是迁移中的兼容边界；P1 已开始通过本地适配投影移动／受控人物显示，具体范围见 [客户端基线](CLIENT.md)，不能据此宣称多人或独立服务端已经实现；已实现技能的通用执行边界另见 [技能基线](SKILL_RUNTIME.md)。

P0 降低私有布局与函数声明变化向消费者传播；共享命令／事件／值类型及完整内容查询仍有编译依赖。未测量增量编译耗时，不报告性能提升百分比。

## 技能来源服务切片（P5 S2）

`GameSessionImpl` 拥有 `UnitSkillSources`，在 [`session_skill_sources.cpp`](../../src/gameplay/session/session_skill_sources.cpp) 配置本地玩家提供函数与模拟器求值回调。玩家起手及 `resolveUnitSkill_` 的后续／反应求值按单位 ID 走同一服务；提供函数每次读取当前记录及原加成，不缓存起手数值或长期借用人物状态。服务公共头不包含会话、模拟器、人物或怪物。

现有玩家与会话同寿命，恢复替换记录仍使用本局 ID；独立来源移除必须先注销绑定。怪物特殊飞弹保留显式输入；火专精查询改为显式单位 ID，未知单位拒绝。会话准备当前玩家资格／来源后调用独立技能运行器；动作／资源能力由模拟器适配短期借用原状态，技能不读完整会话。装备充能及多玩家所有权仍未实现；此前技能迁移通过 Windows Release 与代表性冒烟。本批光环／诅咒资格和 ColdEffect 桥改用内部 `RuntimeCombatUnit`，具体记录不进入技能端口；本批已通过 Windows Release 与简单冒烟，准确边界见 [通用技能基线](SKILL_RUNTIME.md)和[单位基线](UNITS.md)。

## 本地宿主与固定步收口（第九项）

最后一项基础切片已接源码，完整 P8 尚未完成；多人继续暂缓。本轮构建与冒烟结果见下方联合收尾，不复用第七项二进制认证。

| 入口 | 分工 |
| --- | --- |
| `session.cpp` | 保留本局组装、内容回调与兼容查询／库存通知；不再包含完整命令分发和步进循环 |
| `session_commands.cpp` | 顺序消费原命令批次，按领域服务分发；保持跨区后的旧批次截断和每命令光环同步 |
| `session_tick.cpp` | 本地连续输入绑定复验、固定步宿主协调，仍唯一连接原模拟／区域／库存与任务服务 |
| `simulation/simulation_tick.cpp` | 有序调用时钟／人物、公共持续伤害、移动恢复、词缀、技能、怪物、召唤、弹体、死亡及效果收尾 |
| `player/frame.cpp` | 人物动作／资源计时、移动恢复和死亡清理；原技能运行器与公共单位算法继续复用 |
| `simulation/simulation_effects.cpp` | 公共单位持续伤害与视觉效果期限／清区提示，保持活区过滤及原先后顺序 |
| `simulation/simulation_commands.cpp` | 模拟器原移动／攻击／调试击杀等窄执行分发 |
| `simulation/fixed_step.hpp` | 无设备依赖的 25 Hz 常量和累积器；应用决定暂停、加时间和步后消耗 |
| `player/frame_input.hpp`、`IActorClient::control` | 显式玩家 ID、方向、临时跑步输入；UI 只提交方向／跑步意图，由本地客户端绑定 ID |

正式连续输入路径：`Controller → IActorClient::control → LocalActorClient → setPlayerInput → GameSession::advance → Simulation::tick`。宿主拒绝空 ID／非绑定玩家；恢复成功后清输入。输入是本地同线程最新状态，正常应用在每步前提交；没有网络序号、重放或任意玩家权限。原 `tick(dt, direction, forceRun)` 保留为宿主／调试兼容，一次调用默认中立，不读取已保持的输入。

宿主顺序为：清本步事件→物件碰撞／仓库复验→命令→连续输入取消旧请求→召唤上限／光环→模拟→本人死亡结算／动画结束处理→库存补充→佣兵→物件／任务／碰撞→NPC→死亡奖励→邪恶洞窟／拾取／尸体回收／任务物品／交互→碰撞／门户／出口→仓库复验→视图版本。模拟顺序仍为：帧及动作／效果时钟→施法／武器释放→持续伤害→本人恢复／移动／火径／人口激活→词缀／光环／雷云→怪物／召唤／弹体→本人死亡起始清理→清区提示／临时效果到期。

`tick(0)` 仍消费命令并运行原宿主协调，不增加模拟时间／帧；应用继续在绘制前交付该步事件。正时间只由应用累积器按 1/25 秒推进并在每步后刷新表现；暂停／读档清累积时间，帧时间上限保持原值。没有改变运行节拍、随机消耗、人物恢复方式或 D2S v96。

CMake 的表现目标公开依赖客户端与 raylib，会话依赖收为 PRIVATE；残余世界显示仍在实现中使用本地会话，不能称已经能单独构建联网客户端。完整内容查询、初始化回调和 friend 写入、多区域／操作者所有权及若干具体怪物执行仍保留兼容入口。以上九项基础切片完成不等于完整 P1–P8 或原版行为认证。
