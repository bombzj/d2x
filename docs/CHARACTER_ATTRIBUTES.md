# 角色与战斗属性实施计划

当前代码边界：成长与加点规则在 `gameplay/character/progression.*`，角色面板／HUD 读取本人 `CharacterView`，显示计算使用显式上下文。保存仍为原 D2S v96；下方私有版本及早期验证为历史记录，当前实施和冒烟范围见 [角色基线](baseline/CHARACTER.md)。

所有职业共用属性分配和派生计算。可用职业、起点、成长及经验阈值在启动时从原 MPQ 的 `CharStats.txt`、`Experience.txt` 读取；物品属性定义从 `Properties.txt`、`ItemStatCost.txt` 与原物品表读取。职业代码和人物图形 token 是原引擎资源身份映射，不包含成长数值。玩法层只接收类型化定义，不读 MPQ。未核实的属性效果保留原展示值，不猜测公式。现行战斗结算与限时效果入口见 [战斗数值](COMBAT_NUMBERS.md)。

命中率、无装备防御、每级五点及基础法力恢复周期参考 Blizzard 原 [Arreat Summit 角色说明](https://classic.battle.net/diablo2exp/basics/characters.shtml)；本项目仍须以当前挂载 MPQ 的字段值决定职业起点和成长。低法力下的定点恢复舍入及技能／装备修正尚未逐帧核实。

移动属性现从当前 MPQ `CharStats.WalkVelocity`／`RunVelocity`／`RunDrain` 与有效装备的 `item_fastermovevelocity`、防具 `speed`、`item_staminadrainpct` 和 `staminarecoverybonus` 共同派生。快速移动词缀按 D2MOO 的 150 基数递减公式处理，护甲惩罚与跑步加成进入同一最终速度；移动、人物步行动画和脚步节奏读取该结果。角色默认步行，R 切换走跑，按住 Ctrl 临时跑步，Ctrl+R 保留开发用区域重开；默认步行、R 和 Ctrl 控制依据 [Blizzard 操作说明](https://classic.battle.net/diablo2exp/basics/controls.shtml)。未经本轮构建和交互验收；旋风等技能自身的运动规则仍按现有实现。

## 最终属性边界

- 持久基础状态：角色等级、经验、未分配属性点、四维已分配点、未分配技能点。基础值及每级点数来自 `CharStats`；已分配总点数必须与升级所得相符。重置属性只归还已分配点，不修改等级或经验。
- 派生快照：四维、生命／法力／耐力上限与恢复、攻击准确率、普通攻击伤害、攻击速度、命中回避／防御／格挡、抗性与上限、物理伤害修正。派生值只从基础状态、有效装备和将来的临时效果源重算，不入存档；生命等当前值入存档并在上限变化时裁剪。
- 装备来源：普通装备原基础值、耐久／穿戴要求；已生成实例的品质、词缀、暗金／套装基础属性。先支持可明确映射的直接加值、武器伤害／防御、攻击准确率和抗性；百分比、按等级、条件、套装件数、技能、触发和光环等分别核实后接入，不把展示字符串直接相加。破损和未鉴定状态按规则决定有效性。
- 战斗入口：玩家普通攻击命中、物理伤害、怪物命中玩家后的防御／格挡／减伤／抗性，以及上限和恢复。女巫已接 12 项主动和四项被动，旧演示参数与攻击替代已删除；技能和状态扩展边界见 [技能](SKILLS.md)。怪物自身完整属性和 AI 是另一条主线。
- UI：原 MPQ 角色面板图、四维与派生数值、未用点数和逐点加号；按键／按钮只提交命令。背包仍负责穿脱，人物外观从穿戴状态重建。
- 存档：新增持久字段时提升格式及规则指纹，同步快照边界校验；旧版明确拒绝，不静默迁移。

派生顺序固定为：`CharStats` 起点与升级／已分配点 → 装备需求闭包 → 已生成实例的无条件词缀 → 角色资源与战斗派生 → 当前值裁剪 → 命中与伤害执行。后续套装条件、技能、光环和 Buff 作为额外来源进入同一派生入口；不能另建一个与角色面板不同步的战斗属性副本。来源记录保留原 `Properties`／`ItemStatCost` 身份和参数；需要新随机值的效果先改实例生成与存档，之后才执行。

最终属性清单按此结构扩展：四维与资源、移动／攻击／施法／受击速度；物理与元素伤害、准确率、暴击、压碎性打击、撕裂伤口和吸取；防御、格挡、四抗与抗性上限、物理／魔法减伤；金币与魔法物品获取、等级与技能加成；条件、触发、套装、插槽与符文规则。当前角色面板只显示已派生的字段，尚未核实的类别不显示伪数值。原 `ItemStatCost` 的编码／操作语义和原引擎公式要逐类核对，不能仅因字段存在就宣称效果已实现。

## 逐项实施

1. **角色成长与存档。已完成并通过 Windows 冒烟。** 类型化导入 MPQ 当前提供的职业起点、每级／每点增长、基础命中和各职业经验阈值；所有职业走同一个加点及派生入口。增设已分配四维及未用点数；等级提升逐级发点并调整生命／法力／耐力上限；命令分配及调试重置；需求校验改用实际四维。存档 v18 保存职业身份，恢复时按该职业校验及重算。重置后不满足需求的装备留在原槽但暂不提供派生属性。玩家击杀经验使用 MPQ `MonStats`／`MonLvl`／`Experience` 和原引擎等级差规则；升级、加点、资源变化及存读档已用现有管道核对；完整交互仍待验收。
2. **装备效果。已完成首批源码并通过 Windows 构建。** `content/items/equipment_modifiers.*` 从实例原行和掷值识别 `Properties` 的单个 `func1=1` 直接属性，汇总四维、资源上限、准确率、防御与四种抗性。按基础属性起步反复激活满足需求的装备，装备本身不能满足自己的需求；损坏装备停用，未鉴定装备仍可生效。套装条件加成与其他属性函数仍只展示，待原规则与实例随机值完整支持后再执行。直接属性已通过构建，装备组合的定向交互仍待验收。
3. **战斗派生与执行。已完成首批源码并通过 Windows 构建。** 角色准确率、四维、生命／法力／耐力上限和防御集中派生；普通难度普通怪物从 `MonStats.AC` 与 `MonLvl.L-AC` 导入防御，玩家普通近战执行等级、准确率与防御命中公式。怪物打玩家复用相同命中函数。普通伤害仍按武器原基础值及四维系数，技能当前范围以 [技能](SKILLS.md) 为准，未实现技能不执行替代伤害。抗性已有派生快照；当前怪物普通攻击只有物理 MVP 伤害，抗性尚无可作用的伤害类型。派生数值已在升级与加点冒烟中核对；完整战斗交互仍待验收。
4. **角色面板。已完成并通过早期 Windows 冒烟。** `A`／`C` 打开原 MPQ `invchar.dc6` 左半面板，显示当前职业的四维、生命／法力／耐力、左右当前技能各自的伤害／准确率、防御、抗性和经验；有未用点数时底栏 MPQ 红色按钮也可打开面板，面板内按钮提交单点加值命令。底栏经验条及悬停提示使用当前职业 MPQ 经验阈值。`Ctrl+Alt+A` 调试重置；命名管道提供 `allocate-attribute` 和 `reset-attributes`。运行中原地切换职业的调试功能已移除，不同职业通过正常创建／选择角色或加载 D2S 进入。视图只读本人角色投影，读档时关闭面板。面板已按原图框格重排并完成截图核对；本轮键鼠改动待统一冒烟。
5. **统一验收。部分完成。** Windows 构建、七职业外观、升级／加点、存读档、角色面板截图已核对；键鼠点击、长期战斗及 Linux 运行仍待验收。未编写测试脚本／用例，运行目录直接读取原始 MPQ。

七职业技能树、点数及当前角色已学技能选择见 [技能树实施](SKILLS.md)；女巫五项优先技能以外的新增效果仍待实现。药水治疗倍率仍是原先野蛮人规则，需另行核实职业差异。限时效果的统一类型与重算生命周期已接，具体施加条件按 [战斗数值](COMBAT_NUMBERS.md) 逐项补齐。

面板布局依据原 `invchar.dc6` 图框、用户提供的 800×600 截图和 [OpenDiablo2 角色面板坐标](https://github.com/OpenDiablo2/OpenDiablo2/blob/master/d2game/d2player/hero_stats_panel.go) 交叉核对；`inventory.txt` 只给右侧装备／背包格，不含角色文字位置。红色加点按钮和剩余点数字段运行时读取原 MPQ 的 `level.dc6`、`skillpoints.dc6`。截图保存在忽略的 `artifacts/character-skill-layout-reference-cn.png`，本轮截图为 `artifacts/character-panel-final.png`。技能面板后续可依据同一参考截图和 MPQ 的 `data/global/ui/spells/skltree_*_back.dc6`；`artifacts/skill-panel-sorceress-mpq.png` 是本地原图预览。
