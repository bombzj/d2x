# 角色与战斗属性实施计划

所有职业共用属性分配和派生计算。可用职业、起点、成长及经验阈值在启动时从原 MPQ 的 `CharStats.txt`、`Experience.txt` 读取；物品属性定义从 `Properties.txt`、`ItemStatCost.txt` 与原物品表读取。职业代码和人物图形 token 是原引擎资源身份映射，不包含成长数值。玩法层只接收类型化定义，不读 MPQ。未核实的属性效果保留原展示值，不猜测公式。Buff／减益效果只保留后续接入口，本轮不执行。

命中率、无装备防御、每级五点及基础法力恢复周期参考 Blizzard 原 [Arreat Summit 角色说明](https://classic.battle.net/diablo2exp/basics/characters.shtml)；本项目仍须以当前挂载 MPQ 的字段值决定职业起点和成长。低法力下的定点恢复舍入及技能／装备修正尚未逐帧核实。

## 最终属性边界

- 持久基础状态：角色等级、经验、未分配属性点、四维已分配点、未分配技能点。基础值及每级点数来自 `CharStats`；已分配总点数必须与升级所得相符。重置属性只归还已分配点，不修改等级或经验。
- 派生快照：四维、生命／法力／耐力上限与恢复、攻击准确率、普通攻击伤害、攻击速度、命中回避／防御／格挡、抗性与上限、物理伤害修正。派生值只从基础状态、有效装备和将来的临时效果源重算，不入存档；生命等当前值入存档并在上限变化时裁剪。
- 装备来源：普通装备原基础值、耐久／穿戴要求；已生成实例的品质、词缀、暗金／套装基础属性。先支持可明确映射的直接加值、武器伤害／防御、攻击准确率和抗性；百分比、按等级、条件、套装件数、技能、触发和光环等分别核实后接入，不把展示字符串直接相加。破损和未鉴定状态按规则决定有效性。
- 战斗入口：玩家普通攻击命中、物理伤害、怪物命中玩家后的防御／格挡／减伤／抗性，以及上限和恢复。现有技能仍使用项目 MVP 技能数值；技能伤害、施法速度、状态效果与 Buff 留给技能系统。怪物自身完整属性和 AI 是另一条主线。
- UI：原 MPQ 角色面板图、四维与派生数值、未用点数和逐点加号；按键／按钮只提交命令。背包仍负责穿脱，人物外观从穿戴状态重建。
- 存档：新增持久字段时提升格式及规则指纹，同步快照边界校验；旧版明确拒绝，不静默迁移。

派生顺序固定为：`CharStats` 起点与升级／已分配点 → 装备需求闭包 → 已生成实例的无条件词缀 → 角色资源与战斗派生 → 当前值裁剪 → 命中与伤害执行。后续套装条件、技能、光环和 Buff 作为额外来源进入同一派生入口；不能另建一个与角色面板不同步的战斗属性副本。来源记录保留原 `Properties`／`ItemStatCost` 身份和参数；需要新随机值的效果先改实例生成与存档，之后才执行。

最终属性清单按此结构扩展：四维与资源、移动／攻击／施法／受击速度；物理与元素伤害、准确率、暴击、压碎性打击、撕裂伤口和吸取；防御、格挡、四抗与抗性上限、物理／魔法减伤；金币与魔法物品获取、等级与技能加成；条件、触发、套装、插槽与符文规则。当前角色面板只显示已派生的字段，尚未核实的类别不显示伪数值。原 `ItemStatCost` 的编码／操作语义和原引擎公式要逐类核对，不能仅因字段存在就宣称效果已实现。

## 逐项实施

1. **角色成长与存档。已完成并通过 Windows 冒烟。** 类型化导入 MPQ 当前提供的职业起点、每级／每点增长、基础命中和各职业经验阈值；所有职业走同一个加点及派生入口。增设已分配四维及未用点数；等级提升逐级发点并调整生命／法力／耐力上限；命令分配及调试重置；需求校验改用实际四维。存档 v18 保存职业身份，恢复时按该职业校验及重算。重置后不满足需求的装备留在原槽但暂不提供派生属性。玩家击杀经验使用 MPQ `MonStats`／`MonLvl`／`Experience` 和原引擎等级差规则；升级、加点、资源变化及存读档已用现有管道核对；完整交互仍待验收。
2. **装备效果。已完成首批源码并通过 Windows 构建。** `content/equipment_modifiers.*` 从实例原行和掷值识别 `Properties` 的单个 `func1=1` 直接属性，汇总四维、资源上限、准确率、防御与四种抗性。按基础属性起步反复激活满足需求的装备，装备本身不能满足自己的需求；损坏装备停用，未鉴定装备仍可生效。套装条件加成与其他属性函数仍只展示，待原规则与实例随机值完整支持后再执行。直接属性已通过构建，装备组合的定向交互仍待验收。
3. **战斗派生与执行。已完成首批源码并通过 Windows 构建。** 角色准确率、四维、生命／法力／耐力上限和防御集中派生；普通难度普通怪物从 `MonStats.AC` 与 `MonLvl.L-AC` 导入防御，玩家普通近战执行等级、准确率与防御命中公式。怪物打玩家复用相同命中函数。普通伤害仍按武器原基础值及四维系数，技能与怪物完整伤害规则保留原有 MVP 行为。抗性已有派生快照；当前怪物普通攻击只有物理 MVP 伤害，抗性尚无可作用的伤害类型。派生数值已在升级与加点冒烟中核对；完整战斗交互仍待验收。
4. **角色面板。已完成并通过 Windows 冒烟。** `C` 打开原 MPQ `invchar.dc6` 左半面板，显示当前职业的四维、生命／法力／耐力、普通伤害／准确率／防御、抗性和经验；有未用点数时按钮提交单点加值命令。`Ctrl+Alt+A` 调试重置；`Ctrl+Alt+C` 在角色存活时循环切换当前 MPQ 的职业。命名管道提供 `allocate-attribute`、`reset-attributes` 和 `switch-character`。切换为调试操作：等级、经验和属性点归零，生命等资源回满，背包和装备保留；金币超过一级携带上限时裁剪。视图只读会话派生快照，读档时关闭面板。面板已按原图框格重排并完成截图核对；鼠标点击仍待人工验收。
5. **统一验收。部分完成。** Windows 构建、七职业外观、升级／加点、存读档、角色面板截图已核对；键鼠点击、长期战斗及 Linux 运行仍待验收。未编写测试脚本／用例，运行目录直接读取原始 MPQ。

每项实现完成后更新本页及既有基线，再进入下一项。原技能仍为 MVP 通用快捷栏，不代表其他职业技能树已经实现；药水治疗倍率仍是原先野蛮人规则，需另行核实职业差异。Buff 接口预留类型及重算位置，不建立空的运行系统。

面板布局依据原 `invchar.dc6` 图框、用户提供的 800×600 截图和 [OpenDiablo2 角色面板坐标](https://github.com/OpenDiablo2/OpenDiablo2/blob/master/d2game/d2player/hero_stats_panel.go) 交叉核对；`inventory.txt` 只给右侧装备／背包格，不含角色文字位置。红色加点按钮和剩余点数字段运行时读取原 MPQ 的 `level.dc6`、`skillpoints.dc6`。截图保存在忽略的 `artifacts/character-skill-layout-reference-cn.png`，本轮截图为 `artifacts/character-panel-final.png`。技能面板后续可依据同一参考截图和 MPQ 的 `data/global/ui/spells/skltree_*_back.dc6`；`artifacts/skill-panel-sorceress-mpq.png` 是本地原图预览。
