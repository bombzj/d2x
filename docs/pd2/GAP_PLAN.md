# PD2差异补齐步骤与优先级

本页负责从[逐函数审查](FUNCTION_PARITY.md)和现有领域基线导出的执行步骤，不复制原算法或另建功能完成台账。总体PvE目标与产品范围沿[兼容设计](../architecture/PD2_COMPATIBILITY.md#当前模块覆盖与自有宿主优先级)，公共内核依赖沿[战斗总计划](../architecture/MULTIPLAYER.md#23-战斗重构实际阶段与剩余步骤)。规则版本见[BUILDS](BUILDS.md)。

代码应如何分离、如何合法复用公共及非公共函数，统一见[PD2代码分离计划](../architecture/PD2_CODE_ISOLATION.md)。该设计承接本页业务优先级，不要求先完成大规模重构才修复P0，也不把文件迁移作为行为等价的证明。

## 范围与证据

本页基于当前源码，包含资源／profile组装、数值修正、地图消耗及Leoric／Guardian专用路径。已按明确授权完成Windows Release构建及有限互通验证，范围与结果见[协议与保存](PROTOCOL_AND_SAVES.md#当前互通验证范围)；没有新增测试脚本、用例或专用程序。自研PD2当前支持／验收限单机和TCP/IP，不测试独立GS接PvPGN；本机原生及正式CN均沿既有CN客户端接入。构建和基础互通不关闭下列玩法缺口。

用户目标拆为三项，作为任务映射而非新功能规格：R1对比现有项目并确定缺口；R2给出依赖有序的补齐步骤；R3逐函数人工分析公共／专用实现且每完成一项立即落盘。当前R3已覆盖FUNCTION_PARITY中的F01–F17；未完成全库审查，不能将这十七项推广到所有技能、地图、AI、协议或存档。

缺口采用三种证据标签：**确定差异**为指令与源码能明确区分；**未闭合**为缺调用者、数据或生命周期证据；**明确缺程序**为当前源码显式拒绝或缺少相应执行链。未闭合不等于必须重写，观察未覆盖不等于实现不存在。

## 优先级原则

- **P0：已开放路径的基础正确性。** 会污染大量伤害、随机轨迹、物品或保存的差异优先；当前确定项是F02浮点缩放。公共事件与事务时序按可达依赖推进，不等待所有特殊内容恢复。
- **P1：现有功能的调用链与单机／TCP/IP闭环。** 处理手位、运行属性、充能、吸血、伙伴以及协议／保存组装。先确认依赖再修复，不能以增加技能数代替闭合。
- **P2：普通PvE及地图循环。** 在公共能力成立后补实际会遭遇的怪物、连续技能、地图来源和玩家／伙伴跨区；每条链包含失败与恢复。
- **P3：特殊控制器与完整首领场景。** 一次完成入口、控制器、AI、阶段、死亡、奖励及结束释放，不单独放开入口。
- **P4：非阻塞表现与扩展覆盖。** 剩余提示、计时、文字容量、声音与部署范围；会误导战斗或损坏存档的项目提升P0／P1。
- **P5：另行定范围的独立系统。** PvP／BR、公会等；本地共享／材料仓库仍不在授权范围。CN附加模块不自动算作核心待移植功能。
