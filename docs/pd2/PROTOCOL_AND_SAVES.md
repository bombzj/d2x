# PD2协议与原生存档边界

本页区分客户端能接收、宿主能执行和存档能保留的能力，详细字段由已有格式负责页维护。共同版本见[版本与证据](BUILDS.md)，产品组装与隔离见[兼容设计](../architecture/PD2_COMPATIBILITY.md)。

## 三种不同的范围

| 范围 | 权威及当前边界 |
| --- | --- |
| PD2／CN远端 | 远端服务决定玩法、物品、存储和保存；D2X按固定目标原包接收状态并提交请求。CN附加模块能力不能直接归为ProjectDiablo核心规则 |
| 自有PD2宿主 | 当前支持与验收范围为Single Player／TCP/IP，使用EmbeddedRealm和Pd2Local方言；图形与无窗口入口共用PD2内容／codec。PvpgnServer的PD2实验组装不在当前支持／运行验收范围；具体玩法覆盖见各分册 |
| 原版 | 保持默认原版资源、规则与格式；不按收到的未知包或目录名动态切换为PD2 |

“远端可显示”“宿主可生成”“原生档可读写”互不代替。共享／材料仓库属于先前明确排除的本地宿主范围；CN独立协议的接收实现不构成本地功能。

本机原生Realm加载真实D2Game／ProjectDiablo核心，属于远端权威的本地部署；D2X的server-snapshot／管理命令不适用于它。客户端收发、角色／物品／状态副本及原生GS／D2DBS保存回执分别取证；发送accepted、单个未知包计数或自研内核快照均不能单独证明原服已执行。当前对照环境的旧核心与当前MPQ组合见[版本基线](BUILDS.md#本地原生战网对照环境)，与自有宿主的目标版本分开。

## 当前互通验证范围

Windows Release的`d2x`及`d2x_pvpgn`已完成编译／链接，最后的增量构建未出现编译或链接警告；独立GS只构建，没有启动或接入PvPGN测试。运行使用现有调试管道、游戏入口及headless配置，没有新增测试脚本、用例或专用程序。下表是已有连接／保存观察，不能用于认证其后新增的全部玩法修正。

普通地图实例、子飞弹、公开速率／MonProp、位移续办、连续触发和铁魔材料再生的新源码也已纳入双端构建。最新自研单机观察中，合格地狱角色及权威区域可载入，但客户端场景因隐藏ItemEffect的通用图标索引不匹配而停在Loading，错误为`Missing original common skill icon: 冰尖柱`。该回归尚未修复，不能宣称最新源码已重跑通过下表全部路径；修复入口及范围见[F22](FUNCTION_PARITY.md#f22-充能技能源d2common_10954与隐藏itemeffect)。

## 统一入口与连接生命周期

`PlayPD2.cmd`只选择固定PD2资源配置，默认进入与原版共用的主菜单。Single Player、TCP/IP的Host／Join、Battle.net的账号／Realm／角色／房间均使用既有前端流程；本地角色默认`saves/pd2`，战网角色继续由远端保存。旧`-Local`／`--pd2-local`仅保留参数兼容，不再形成独立启动模式。

`RealmSession`在显式本地接入和账号认证入口选择Pd2Local／Pd2CnNormal20261020。当前连接的方言固定；跨方言仅在Idle且会话内没有待交付TCP/IP回传时重建协议状态及网络worker，保留已准备仓库几何、默认技能与诊断观察器，递增连接／游戏代次以拒绝旧意图。未断开时不切换，也不依据收到的包动态猜方言。资源构建仍在启动时固定。

CN专属库存限制和自动地图周期报告根据当前会话启用，不由启动脚本决定；本地操作不因此落入CN存储控制。代码入口为`src/app/{frontend,frontend_commands,client_setup}.cpp`、`src/network/realm_session.cpp`及各Remote客户端适配器。

## 物品与扩展消息

Pd2Local为自有地图属性启用原55的210字节布局；其余包继续使用该本地方言的既有帧长。宿主以类型化地图事实编码，客户端复用已取证的地图属性接收；Lod113c的55保持原解释，不开放整套CN服务扩展。具体地图范围及未验证边界见[地图物品与词缀](MAP_PROPERTIES.md)。

完整物品按逐件format选择字段，网络物品、磁盘JM记录、独立增量和compact分支分别解释；不能全局扩大属性ID位宽。当前ItemStatCost最大ID为510，也不意味着完整新格式仍使用9位ID。连读组、保存列和参数位数均以目标表和真实入口为依据。

详细位流见[完整物品位流](../resources/PD2_CN_DLL_ANALYSIS.md#完整物品位流版本与字段)，D2X格式选择入口为`src/content/pd2/item_encoding.hpp`。客户端9D扩展action、分片、状态／材料计数、地图属性广播与周期报告归[状态扩展接收链](../resources/PD2_CN_DLL_ANALYSIS.md#状态扩展接收链)和[周期报告](../resources/PD2_CN_DLL_ANALYSIS.md#原客户端抓包确认的周期上报与候选修复)。这些章节保留各自版本，不把旧核心地址移植到当前目标。

触发技能通知只提供表现事实，不重新裁定技能、覆盖当前动作或猜测伤害。本人技能等级、装备、状态和主人事实不完整时，客户端公式／动态提示保留未知，不能从动画反推权威数值。

## 属性分配控制边界

属性分配的 CN 边界来自固定 mdll1（SHA-256 `6d6b8bf38e1a47a172b18715b5d4d89542332b4f61264efc3e61602e9d43e90a`）：RVA `0x1E670` 对低字节先减 `0x10`，范围外返回0；`0x20520–0x20540` 在返回0时继续原属性分派，提取低字节 stat 和高字节 count−1。因此属性0–3不属于仓库控制；`0x12AB0 → 0x6A00` 的三字节构造也没有改变普通3A布局。D2X开放1–100点的原请求，发送前要求属性及 statpts 已知且余点足够，仍由服务端裁决并等待绝对属性增加与余点减少；不开放0x10以上的任意控制码。原数量语义另见D2MOO `D2GAME_PACKETCALLBACK_Rcv0x3A_AddStatPoint_6FC86E80`。

## 原生PD2存档

唯一格式与校验负责页为[PD2原生存档格式](SAVE_FORMAT.md)。当前沿用原生D2S v96正文、逐件物品format及目标扩展段；新物品采用104，已有旧物品保留原format。未知原生扩展元数据保留，不引入私有头、不静默迁移旧试验格式。

当前核心保存RVA `0x39A510`、读取`0x39AD40`及扩展段顺序／长度边界见该负责页。共享文件不导入；原版与PD2角色目录隔离。属性系数、实际充能、腐化与物品技能按原生属性保存；战斗列表、蓄气、定时器、传播与触发游标不写成新私有段。

特殊死亡掉落的当前核心`0x36D410`向原生物品创建结构写itemLevel=0x83（131）。配套Common的七位物品等级写出按127饱和，不能取低七位变成3。PD2选定生成接受1–131的运行时等级，覆盖当前36D410的130／131；原版生成边界仍为1–127；`exportD2sItem`写127，读入边界仍为1–127，其他非法等级明确拒绝。它不增加存档字段，也不静默修改旧格式；131的生成属性仍须先按运行时等级准备。特殊掉落实例的完整原生读写／传档组合尚未认证。

## 待核实与未完成

新旧完整格式、全部品质／镶嵌／符文之语、扩展热键与复杂库存组合、原生客户端传档及持续多人会话未全部认证。TCP/IP断线恢复现只在恢复副本成功原子落盘并关闭权威绑定后标记清理完成；失败保留会话并按宿主时钟重试，首次可导出的有效D2S冻结供后续写盘，成功后不重复生成恢复档。B3入队仍不等同客端落盘确认；恢复档不受网络小于8192字节的限制，超限角色保留在宿主供人工恢复，不能截断发送。传输聚合拒绝空中间片；原上传恰为255倍数的终止空片仍由完成分支处理。已统一构建并实测：单机写盘锁失败保留原档后重试成功；TCP/IP恢复目录被文件占用时保留关闭中的绑定，移除占用后自动写出唯一恢复档并释放；恢复档、正常回传档及交易所得104物品均可在新进程载入。原版单机保存／退局也已回归。这些观察不覆盖全部复杂库存和长度边界。格式通过不证明地图程序、隐藏技能、权限或全部玩法可执行；未经核实的版本组合明确拒绝。
