# PD2协议与原生存档边界

本页区分客户端能接收、宿主能执行和存档能保留的能力，详细字段由已有格式负责页维护。共同版本见[版本与证据](BUILDS.md)，产品组装与隔离见[兼容设计](../architecture/PD2_COMPATIBILITY.md)。

## 三种不同的范围

| 范围 | 权威及当前边界 |
| --- | --- |
| PD2／CN远端 | 远端服务决定玩法、物品、存储和保存；D2X按固定目标原包接收状态并提交请求。CN附加模块能力不能直接归为ProjectDiablo核心规则 |
| 自有PD2宿主 | `--pd2-local`组装既有EmbeddedRealm和权威内核，按PD2内容准备差异；单机与TCP/IP复用原协议和原生角色生命周期，具体玩法覆盖见各分册 |
| 原版 | 保持默认原版资源、规则与格式；不按收到的未知包或目录名动态切换为PD2 |

“远端可显示”“宿主可生成”“原生档可读写”互不代替。共享／材料仓库属于先前明确排除的本地宿主范围；CN独立协议的接收实现不构成本地功能。

## 物品与扩展消息

完整物品按逐件format选择字段，网络物品、磁盘JM记录、独立增量和compact分支分别解释；不能全局扩大属性ID位宽。当前ItemStatCost最大ID为510，也不意味着完整新格式仍使用9位ID。连读组、保存列和参数位数均以目标表和真实入口为依据。

详细位流见[完整物品位流](../resources/PD2_CN_DLL_ANALYSIS.md#完整物品位流版本与字段)，D2X格式选择入口为`src/content/pd2/item_encoding.hpp`。客户端9D扩展action、分片、状态／材料计数、地图属性广播与周期报告归[状态扩展接收链](../resources/PD2_CN_DLL_ANALYSIS.md#状态扩展接收链)和[周期报告](../resources/PD2_CN_DLL_ANALYSIS.md#原客户端抓包确认的周期上报与候选修复)。这些章节保留各自版本，不把旧核心地址移植到当前目标。

触发技能通知只提供表现事实，不重新裁定技能、覆盖当前动作或猜测伤害。本人技能等级、装备、状态和主人事实不完整时，客户端公式／动态提示保留未知，不能从动画反推权威数值。

## 属性分配控制边界

属性分配的 CN 边界来自固定 mdll1（SHA-256 `6d6b8bf38e1a47a172b18715b5d4d89542332b4f61264efc3e61602e9d43e90a`）：RVA `0x1E670` 对低字节先减 `0x10`，范围外返回0；`0x20520–0x20540` 在返回0时继续原属性分派，提取低字节 stat 和高字节 count−1。因此属性0–3不属于仓库控制；`0x12AB0 → 0x6A00` 的三字节构造也没有改变普通3A布局。D2X开放1–100点的原请求，发送前要求属性及 statpts 已知且余点足够，仍由服务端裁决并等待绝对属性增加与余点减少；不开放0x10以上的任意控制码。原数量语义另见D2MOO `D2GAME_PACKETCALLBACK_Rcv0x3A_AddStatPoint_6FC86E80`。

## 原生PD2存档

唯一格式与校验负责页为[存档模块的PD2边界](../modules/SAVES.md#d2x-pd2本地存档)。当前沿用原生D2S v96正文、逐件物品format及目标扩展段；新物品采用104，已有旧物品保留原format。未知原生扩展元数据保留，不引入私有头、不静默迁移旧试验格式。

当前核心保存RVA `0x39A510`、读取`0x39AD40`及扩展段顺序／长度边界见该负责页。共享文件不导入；原版与PD2角色目录隔离。属性系数、实际充能、腐化与物品技能按原生属性保存；战斗列表、蓄气、定时器、传播与触发游标不写成新私有段。

## 待核实与未完成

新旧完整格式、全部品质／镶嵌／符文之语、扩展热键与复杂库存组合、原生客户端传档及持续多人会话未全部认证。TCP/IP仍受既有传档上限约束。格式通过不证明地图程序、隐藏技能、权限或全部玩法可执行；未经核实的版本组合明确拒绝。
