# 原生存档

PD2本地角色的原生格式、隔离目录、读写校验与拒绝边界。原版D2S及公共保存生命周期见[存档模块](../modules/SAVES.md)。 目标身份与证据口径见[版本与证据](BUILDS.md)。

本地角色租约及原子写盘共用资源层的操作系统文件锁，名册按实际租约判断占用；锁侧文件留存不表示角色仍在使用。原生PD2 D2S与独立角色目录不变，旧版锁目录的恢复条件沿公共存档说明；本次公共锁修改未运行PD2回归。CN远端角色仍由其服务端保存，不使用本地角色租约。

## 原生存档：格式与边界

JM编解码主体位于`gameplay/items/native_save`，内容层准备不可变基底／位宽规则，persistence保留原接口包装；PD2格式选择与饱和helper位于`gameplay/items/pd2/save_encoding`，旧content头转发同一实现。世界休眠显式允许地面坐标和金币，角色存档默认仍拒绝地面物品，不改变v96布局或旧档迁移策略。地面休眠中字段截断后的属性由宿主重新准备，不沿用截断前缓存；具体生命周期见[人口恢复](../gameplay/monsters/POPULATION.md#公共出生压缩与特殊恢复)。

来源：[docs/modules/SAVES.md](../modules/SAVES.md)。

自有PD2城镇宿主沿用原生PD2 D2S：v96头、固定段、校验和、Skills最大职业行数及原JM／jf／kf结构，默认目录`saves/pd2`。不写D2X私有标记，也不把原生档转成私有格式；此前带`D2XPD2`头标记的试验档明确拒绝，须使用原生角色副本或重新建角，不静默迁移。原版与PD2目录、资源配置保持隔离，载入仍须通过完整内容与边界校验。

完整物品逐件保留原format；format<102使用9位属性ID，102及以后使用10位，终止符分别为511／1023。format<103使用MPQ的S12列，103使用S13列，104及以后使用当前Save列；compact仍用当前列。新物品采用104，旧101与新104可以同档共存。磁盘读写、宿主网络投影与客户端读取共用`content/pd2/item_encoding.hpp`的格式选择；独立网络ItemStat增量仍为9位。职业库存／个人仓库／方块尺寸取当前Inventory表。公共death生成的死亡金币与PvP耳朵同样按固定PD2规则选择新format104；耳朵的真实死者身份、HC NAMED位及DT／DEAD阶段沿[玩家死亡](../gameplay/characters/PLAYER_DEATH.md#自研宿主pvp死亡)。导出时7位耳朵等级按Common写位饱和到127，不提前截断运行身份，也不扩展v96布局。该公共消费者已更新；当前运行对照只覆盖LoD 1.13c耳朵，PD2高等级／HC耳朵仍未实机认证，不能由format支持推断完整PD2 PvP等价。

当前41d49完整物品写出为385DC0。属性值经385D40读取对应版本的SaveAdd，以x86有符号加法求和，再在位宽小于32时饱和到0..(2^bits−1)；385C60对参数层使用同一饱和规则，32位保持原位型。D2X的PD2写出沿`pd2ItemSavedValue`复刻这一步，不更改运行时原属性或物品format。当前MPQ的地图溅射427可生成150、SaveBits却为7，写出应为127，不能拒绝整件合法地图或修改原表扩大位宽。原版编码及结构／身份／重复记录校验保持各自边界；这不是旧档迁移，重入仍读取实际保存值；地图属性427的150→127写出及新进程恢复已有自研观察，其余属性位宽／复合物品组合仍待覆盖。

当前核心SHA256 `17d5fb1b049d8076226d27295487b49c8b5f2629553c193a01aa1e3d8afaba57`的保存RVA `0x39A510`、读取`0x39AD40`确认：kf之后可有`70 64 82 0A`扩展头，依次为su（3+count×2，count≤128）、bk（6）、st（64）、ht（3）、xp（3）、hc（130字节）。解析检查完整顺序、版本、长度及尾部；内容作为原生元数据保留在`nativeSaveSections`固定段之后，保存时保留未知字节，不把未知含义的字段重置或伪造。无扩展的旧格式正文也由原生读取入口接受，新建角色可使用该正文。共享文件不导入；当前39B730确定的st段+10起17个WORD另由CharacterRecord持有，写出时只覆盖这34字节；其余已存在段字节保持原样。地图死亡程序通过transactions共同增加对应持久项与PlayerState当局项；当局项不落盘。无扩展的正文在实际产生新统计后写出当前原生扩展头及完整段，旧私有格式仍拒绝。此修改完整场景仍待原版对照；bk的DWORD现由pd2BossKills持有，写出只覆盖该DWORD；39D980／39D9E0是41d49的实际bk入口，旧39A510／39AD40不得当当前地址。41–45死亡与统计同一事务置位，原380A10成就选择仍为当局掩码，不额外写入D2S。额外热键的物品来源与复杂库存变更组合尚未完整认证。

`--load`、名册、租约、备份和正常退局保存复用既有流程；使用原档副本验证，未支持字段、版本或内容明确拒绝，不回退重读。TCP/IP仍受既有小于8192字节的传输上限约束；全部品质、扩展热键、复杂装备及原生客户端网络传档兼容仍需覆盖。


运行态PD2技能、佣兵攻击和地图程序不因存档可读而获得实现；技能宿主已接入普通五幕区域及七职业差异程序，完整技能组合仍待验收，详见[PD2宿主边界](../architecture/PD2_COMPATIBILITY.md#自有pd2城镇宿主)。[存档模块](../modules/SAVES.md)未明确标注PD2的原格式说明仍指原版LoD路径。

物品的nativePropertyRandom仅保存当前进程内实际构造／属性执行后的随机流，供后续自动腐化与献祭继续使用；原生D2S仍只写原种子／实际属性，不添加私有随机扩展。读档物品没有该运行值时沿原nativeSeed初始化，实际属性不重掷。
