# PD2地图物品与词缀程序

本页负责地图物品→实例→人口／单位属性→掉落的调用链。目标身份沿用[版本与证据](BUILDS.md)，布局及区域索引见[地图](MAPS.md)。下文“接入”指存在对应的内容准备、权威执行或协议消费者；普通开图路径不代表全部地图程序已完成。

## 内容与实例

`src/content/pd2/map_data.cpp`从当前Misc.pSpell12准备全部物品的len、missiletype及原物品记录索引，路由来自ItemStatCost.Divide，状态来自States.map／198。玩法只接收`gameplay/maps/pd2`的纯值，不读取MPQ或执行DLL。

`src/server/systems/travel/pd2/maps.cpp`的普通入口检查Harrogath、地狱、等级80及古代人任务完成资格；资格例外、PvP和专属控制器仍拒绝。当前核心`0x3810A0`读取任务槽0x27的bit0：包装器`0x30A800`链接配套Common ordinal10174／RVA0x2D0F0，直接读取`quest*16+bit`，不执行编号加一；该槽是RiteOfPassage／39，不是EveOfDestruction／40。先冻结物品实际原生属性及revision，再用公共World异步准备区域；准备或程序不满足时不消耗地图。成功才提交消耗、真实门户规则和两端房间保留，并用55广播最多24项**原始**属性及门户GUID／类型、区域、品质、原物品索引，不能广播转换后的清单。已进入第五幕的玩家随开门事务接收报告；中途加入／随后来到第五幕的玩家由Travel补发，接收凭据只在可靠事实接受后发布。

当前一个游戏保留一份成功开图上下文，目标及后续原出口的区域准备共享该不可变实例。已有管理旅行区域不能直接重新绑定。Travel持有异步开图待办，加载期间自动续办同一物品revision及原玩家／区域代次，不要求客户端再次使用；提交前重新检查归属、资格和物品版本，失效不扣物品。带未提交地图的AreaState标为provisionalPd2Map，允许碰撞／门户落点准备，但不进入人口房间序列，也不能被无实例的旅行请求使用。物品事务成功才解除标记；其后的子区按已提交实例安装。

失效请求撤销匹配实例的World待办及失败记录；已安装但未发布的区域先复验无玩家、单位链与房间引用，再卸载活动房间／碰撞、解除房间身份及区域租约，删除权威AreaState。同幕共享DRLG保留不含地图属性的解码输入，不重建其他区域或回退其随机；再次安装会重建该区的活动房间状态。宿主按权威区域存在性清除旧地形，并取消失去待办的后台票据。暂不可安全释放时Travel保留取消阶段继续清理，不接受另一张地图覆盖它。已提交实例不进入这一撤销路径。门户落点和预留GUID在背压期间保留，重试提交时合并当前门户集合，避免重选落点或覆写期间的其他门户变化。实例和临时来源不写入D2S，物品仍使用原PD2格式，不迁移旧档；此项源码补齐已统一构建，普通旅行已回归；现有符合地狱Ancients资格且携带t11的隔离角色已载入，但客户端场景受F22图标错误阻塞；已安装地图的取消／背压与成功往返尚未实测，不能以管理旅行认证开图。

成功消耗按`0x3810A0`末尾分支：仅普通品质2且数量大于1时减一；其他品质／数量返回1，由物品使用调用者删除整个物品。D2X已修正为相同分支，不对所有品质一律减一。当前核心在成功路径末尾才把零控制值写为10；自研异步准备因此不能在物品事务前发布人口或把失败上下文当作已开图。准备失败／版本失效不扣物品，清理权威区域后才清Travel指针，不能让另一张图复用旧区域属性。

DRLG的邻房预载也必须传递实例：`world/rooms.cpp`从已准备区域或实际邻房取得同一上下文，再准备扩展子区域。`world::request`统一按当前核心`37A740`的无符号`level-137<74`界定实例范围；出口命令、预载和返回原五幕均经过同一边界，原五幕及城镇不继承地图实例。原出口请求无条件传递实例、预载单独限区域的差异已收拢；该修正已构建，完整开图／子区／回城往返尚待实测。出口命令与提前预载不能各自产生一份地图身份，否则第二层会因上下文冲突拒绝进入。子层重新使用原物品属性，地图状态不重复叠加；范围判据不授予特殊地图资格。

当前核心`0x3810A0`首先检查Game+0x1DF4，正数且不为0x28即拒绝；普通开图在末尾至少写为10。对当前核心该字段直接写入及普通开图链的核对，仅见开图自身及方块`0x365790`设置40的入口，没有普通地图完成／回城后清零的消费者。因此普通模式同局只开一张图，原门户可往返；第二张拒绝且不消耗。新游戏重新建立实例，结束游戏释放实例。不将同局回收后重开列为待实现功能；特殊事件的40分支及结束规则仍另核实。

## 路由和单位属性

依据当前核心RVA `0x3810A0`、`0x388FD0`、`0x389040`、`0x388A40`；消费者为`property_program.cpp`、`attributes/pd2/map_values.cpp`、`effects/pd2/map_state.cpp`。

| Divide | 执行 |
| --- | --- |
| 0 | 不进入单位列表；500的存在单独表示强制事件 |
| 1024 | 原ID及参数进入怪物列表，不能当作24 |
| 其他小于1000 | 余数为怪物属性ID |
| 1000–1999 | 余数为玩家属性ID |
| 2000–2999 | 余数为全局程序号，保留参数及值 |
| 3000–3999 | 暂存原属性，最后追加怪物列表；432–436在单位上采样物理伤害 |

普通怪物属性仅给MonStats.Align为零的单位；独立的破免分支仍检查全部怪物。数值与装备、技能共用原生StatList及事件注册。怪物与玩家均使用CombatEffectSet的真实状态198；先填满原列表，再一次合并入单位，不能先发布空列表再逐项模拟装备。

怪物出生候选同时携带待发布效果，ActorPublication与Effects共同复验／提交；带物品光环的混合出生也继承该初始清单。当前States.map的plrstaydeath、monstaydeath、bossstaydeath均空白，按公共死亡流程撤销数值及状态位，不保留常驻尸体词缀。`stageDamageStates`在撤销前冻结PD2死亡掉落所需的FullStats；后续异步掉落读取此快照，不能为获得额外TC而将效果继续挂在尸体上。休眠重建从实例重新准备状态，压缩记录仍不增加存档字段。状态／掉落与原DLL的完整逐帧顺序仍待核对。

受控伙伴的首次出生也经`monsters/controlled.cpp`准备独立状态198，合并已有初始效果，不覆盖光环／技能状态，也不将受伤佣兵恢复满血。友方Align不接普通敌对词缀，独立破免仍按原怪物分支处理。当前`0x388FD0`在137–210内按MonStats.Align选择普通列表或空列表，入口来自`0x370490`出生包装及`0x36FDF0`技能安装后缺198的检查。`0x389040`在原房间更新后明确限定UnitType=0，只在区域变化时处理玩家；离开137–210撤销198及相关地图技能状态，不能把这个回调移植给伙伴，或每次伙伴warp都重贴状态。现有伙伴跨区沿原单位保留其列表，死亡按States死亡位撤销；休眠重建和技能重装的全部交错仍待闭合。上述身份依据为当前核心对应函数的指令，不以自动反编译漏失的ECX／EDX参数推导调用签名。

432–436分别生成闪电、冰冷、火焰、毒、魔法最小／最大伤害。百分比采用有符号float转换，物理基数采用无符号转换，先除100再乘。最小值零写1；最大值及长度最后写回。冰冷／毒长度为非零低WORD参数，否则25／125。同键写入覆盖，不能重复相加。

怪物目标76按无符号`maxhp + (maxhp / 100) * value`直接改基础最大生命，超过INT32_MAX封顶，并写432=1标记；玩家76仍走正常属性求值。其余普通输入零按原程序写1。369虽名map_defense，当前描述是StrCorruptNum且无StatOp；保留原ID，不能据名称添加防御百分比。

玩家进入／离开、出口、门户／传送点、管理旅行、跨区传送及复活，在人物事务中准备地图来源与资源上限，再发布位置。离图撤销来源；同一实例不重复叠加。

普通循环的源码入口已逐段核对：Travel持有开图及不可变实例；World统一请求主区／原出口子区，人物事务同步198与位置；普通／永久门户沿Travel原入口往返，55报告在同游戏跨区时保留、第五幕后加入时补发；玩家死亡撤销状态，复活重新取目的区来源。怪物压缩明确拒绝有owner或死亡奖励未完成的单位，恢复先按实例准备出生来源，再以休眠记录恢复生命／等级／阵营，不能再次乘地图生命倍率；未完成的掉落不以尸体压缩绕过。离局存档不保存地图实例／198，最后玩家离开后实例随GameInstance释放。这些入口构成已开放普通地图的源码闭环，最终运行需覆盖开图、子层、回城、重入、死亡／复活、保存及新游戏；逐随机等价与特殊事件控制器不由该闭环推定。

## 地图掉落

依据`0x378660→0x377DE0`。`MapLootRules`以原生MonStats类967（当前TCStartDontUseOrChange）的正常TC为锚，按原代码偏移链接当前TreasureClassEx；候选、权重及参数仍读MPQ。地图首领资格来自六组原核心身份集合，不等同于MonStats.boss或Unique等级。

| --- | --- |
| 494／495／496／497 | +982／983／984／985：首饰、武器、护甲、合成材料 |
| 502／506 | +986／988：护身符、珠宝 |

小弟标记排除上述额外掉落。494–497及502／506无属性也掷数；职业物品仅正数时掷数。152／153、164／165、171／172、186／187及197–199另有本体TC调用。额外TC与后继抽取交错使用同一怪物随机；内容侧合并各次唯一物品占用，权威只提交一次结果。

自动腐化和无形／孔数另用CRT及物品随机。掉落准备捕获期望CRT，安装时复验并连同候选结果更新，背压不再次掷数。`applyPd2AutomaticCorruption`也供方块破坏产生的新稀有物品使用：扫描当前CubeMain阈值并忽略属性chance，保持当前物品身份；它不是带材料的手动WSS操作。

### 独立材料与暗金地图来源

`0x377DE0`前置`0x3744F0`独立抽取先于小弟排除及额外TC，不受上述六件TC容量合并限制。锚点仍为类967的首个正常TC。概率读取对应TCExShort的WORD Unique（+0x20）与Set（+0x1E），不是执行该TC的品质权重；0／65535不抽，Set为2–65534时作倍率，否则为1。玩家2–8分别按125／123／121／119／117／115／113除127缩放分母；使用PD2单位随机取模后与1比较，Skirmish的非地图首领在137–210区域阈值为2。Unique=75000在原WORD编译后是9464，不能保留TXT整数75000。当前宿主以实际已入局人数准备，完整原生人数／虚拟人数交互仍待对照。

暗金地图的当前区域／UniqueItems原生记录对为176／432、181／433、183／436、180／453、192／452、195／472、197／478、200／482。`0x37F550`先清该记录的本局暗金占用，再强制指定品质及记录；rarity0不禁用这个入口，记录号必须排除Expansion分隔行。内容准备动态链接Misc目的区域及底材并核对UniqueItems.code，不能只把t51等底材交给随机暗金选择。创建等级131及原生保存127边界见[协议与存档](PROTOCOL_AND_SAVES.md#原生pd2存档)。

### 地图信息显示

当前55接收入口`0x391930→0x36C9B0`格式化原始属性，过滤360／361／458，再追加当前区域名；品质4／6／7分别用蓝／橙／金色。`0x36C800`消费该说明作为物件名称链。D2X的`remote_scene_pd2.cpp::pd2MapDescription`调用独立`content/pd2/map_description.cpp::describeMap`，名称及描述仍读当前Levels.LevelName／ItemStatCost／TBL；`remote_scene_draw`仅在原报告GUID／类型匹配的门户悬浮时显示。

当前指令补核：最多保留15条，遇到相同非零dgrp且数值相同的后续条目，标记首条为分组并忽略后条，不要求全组齐全，也不累加相同属性或按层区分。满15条后仍能合并，遇到下一条新记录才停止。`0x373CB0→0x373D80`在该容量走稳定插入排序，比较器`0x36A210`按无符号WORD加载的descpriority升序；不是普通物品的降序／ID排序。

专用`0x37AF70`未分组始终选descstrpos，分组数值负时选dgrpstrpos、非负时选dgrpstrneg；不能按普通物品修正其方向。函数5无百分号，19在descval0时将文案作为一个整数格式，否则与20一样取负值加百分号；未知非零函数走固定`+%d`，因此负值也保留`+-`。描述函数0不输出但仍占候选容量。D2X已按这些分支分离实现；TBL不作为宿主printf格式执行。构造区1000个UTF16单元的secure格式调用溢出时清空当前追加片段，最后保留507单元尾部；发生截断则用`ÿc3[...]`覆盖尾部前8单元。D2X按UTF16计数并将边界孤立代理项转换为U+FFFD，输出UTF8且逐行保持颜色；该非法代理项保护与原内存表示不同。已构建／未进行原生界面对照，不宣称像素完全一致。
