# 区域判定逐函数说明

默认核心SHA-256为`17d5fb1b049d8076226d27295487b49c8b5f2629553c193a01aa1e3d8afaba57`，ImageBase=0x10000000，地址为RVA。依据为当前核心反汇编中对应入口的完整指令，保存于reference/pd2-cn-analysis/core-catalog/kick-decision/updated-core/ProjectDiablo.disasm.txt。区域布局与玩法归[地图分册](../MAPS.md)。

## 37A9C0 三个特殊区域编号判定

**范围与用途。** 37A9C0–37A9E0。供物品再生等调用者判断一个区域编号是否为157、159或166；不是城镇、碰撞、敌意或任意PvP区域检测。

**ABI与算法。** ECX为区域编号；依次比较0x9D、0x9F、0xA6，任一相同返回EAX=1，其余返回0；无栈参数，RET。没有符号范围运算，因此负值及其他编号自然不匹配。

**副作用。** 无全局读取、表查找、写入或随机，不验证该区域当前已加载。编号的含义来自对应版本Levels，不能把相同数字套到其他资源版本。

**调用意义。** 3451E0命中时将除法所得间隔商逻辑右移1；它只是条件，不包含减半算法。37AA30也尾跳至本函数。是否允许进入区域、是否处于安全矩形均需其他函数，返回1不能作为开图或战斗授权。

## 37A9F0 单一区域166判定

**范围与用途。** 37A9F0–37A9FB，仅回答输入区域是否等于166。当前资源中166为BR Arena；本函数没有读取区域名称或控制器。

**ABI与算法。** ECX输入；XOR EAX,EAX后CMP ECX,0xA6，再SETE AL，返回严格0或1；无栈参数。与37A9C0相比，157和159在这里均返回0。

**副作用与重点。** 无内存读取、写入或随机。37AA60将路径取出的区域ID尾跳到这里；不能用同属特殊区域的三编号谓词替换，否则会扩大下游分支适用范围。它也不检查BR是否正在进行、队伍或玩家资格。

## 37AA30 由单位路径判断三个特殊区域

**范围与用途。** 37AA30–37AA5D。将单位当前路径／房间关联转换为区域编号，再复用37A9C0，返回是否属于157／159／166。

**ABI与指针链。** ECX为单位指针；依次检查单位非空、`[unit+2C]`非空、`[前项+1C]`非空、`[前项+10]`非空、`[前项+58]`非空；最后从`[前项+1D0]`取DWORD区域ID到ECX，JMP 37A9C0。任一指针检查失败，XOR EAX,EAX并RET。各偏移是原结构地址链，不是D2X模型偏移。

**重点。** 没有unitType检查，没有坐标计算，也不读取地图安全区或Flags；不能传任意不同布局的实体。返回0既可表示普通区域，也可表示中间关联缺失，调用者无法仅凭该值区分。D2X不应从当前观察者区域补齐缺失单位房间后宣称同义。

**副作用与依赖。** 纯读取后尾跳，不分配、不改房间、不消耗随机。精确结构类型可由原版结构继续校验，本条已确认的是全部解引用偏移、空检查和最终谓词，不把相邻函数的区域集合混入。

## 37AA60 由单位路径判断区域166

**范围与用途。** 37AA60–37AA8D。读取单位关联区域，只判断166；不是37AA30的别名。

**输入输出与流程。** ECX输入单位，按`unit+2C → +1C → +10 → +58`逐层读取并检查非空，末端+1D0读区域ID到ECX，尾跳37A9F0。任意关联为空返回EAX=0；否则由37A9F0返回严格0／1。无栈参数，也未检查unitType。

**重点与副作用。** 与37AA30的决定性区别只有最终谓词，但这直接影响157／159上的分支行为；不得为去重改为同一个三区域判断。两函数可共用经过核实的取区域基础能力，仍保留两个明确条件。无写入、随机、房间创建或控制器检查，不能由返回1判定所有BR玩法状态。
