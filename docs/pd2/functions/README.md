# ProjectDiablo逐函数分析

本目录按模块维护**单一函数**的用途与核心实现。每读完一个函数即写入负责分册，后续发现修订原条目；不按日期追加会话日志，不用自动命名或批量反编译代替人工分析。当前有13个独立核心入口条目，数量只说明本目录覆盖，不代表全库完成。

默认目标为ProjectDiablo.dll SHA-256 `17d5fb1b049d8076226d27295487b49c8b5f2629553c193a01aa1e3d8afaba57`，ImageBase=0x10000000。全部地址使用RVA，其他模块与旧构建必须单独注明。[版本表](../BUILDS.md)是身份依据。[旧全量目录](../../resources/pd2-core/README.md)仍限定9c2b…，不能把其入口数量套作当前版本分析进度。

## 每个函数必须说明什么

实际入口与函数体范围；用途及执行侧证据；寄存器／栈输入与返回；早退、分支和顺序；重要字段、表项、运算宽度／符号；写入、随机、分配、事件或原包等副作用；真实调用者和直接依赖；反编译误读及仍未闭合部分。说明名不是PDB名，缺少业务身份时使用字段或编号描述，不强行命名。

桥接、getter、包装器和业务函数分别记录。只有知道实际目标还不够，必须阅读目标实现才可解释下游算法。查询内部地址只登记工具返回的实际函数入口，不能重复计算；尾跳函数的ABI也不能直接采用伪代码的void签名。
