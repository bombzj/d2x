## 如何理解PD2对原版的修改

PD2不是只换一套TXT数值，也不是所有新增函数都代表新玩法。原版模块继续承担大量基础工作，核心通过代码改写、分派表替换及包装调用改变部分流程；MPQ又决定这些程序的实际调用者、数据和图形。需要同时回答“原版入口是什么、PD2替换了什么、当前表如何触发、最终状态在哪里变化”。

| 改动层 | 原版与PD2应如何比较 | 负责说明与阅读重点 |
| --- | --- | --- |
| 安装与桥接 | 原模块磁盘代码不等于安装后的内存代码；地址解析器也不等于业务算法 | [启动逐函数契约](../resources/pd2-core/BOOTSTRAP_FUNCTION_REVIEW.md)、[挂接记录](../resources/pd2-core/HOOKS.md)、[程序表](../resources/pd2-core/PROGRAM_TABLES.md)；旧核心静态范围，不套当前地址 |
| 表数据与记录身份 | 同名记录可能换字段或程序；新增记录不等于新增敌人；TXT行号不一定是编译ID | [技能树与客户端程序](SKILLS.md#角色技能树与客户端程序)、[怪物身份](MONSTERS.md#monstats与预设身份)、[Levels编译](MAPS.md#levels与leveldef链接)；先确认链接、宽度、空白与默认值 |
| 伤害与属性计算 | 不只改倍率，还可能改变掷数顺序、属性来源、符号和截断点 | [暴击](ITEMS.md#暴击与致命攻击)、[动态主人属性](ITEMS.md#动态主人属性)、[伤口与压碎](ITEMS.md#open-wounds与crushing-blow)；条件查询结果不写回原系数 |
| 技能与飞弹程序 | 同一程序号可被多技能使用；客户端创建图形与服务端裁定伤害是两条链 | [技能分册](SKILLS.md)、[近战溅射](SKILLS.md#do163实际手位分配伤害与独立防御)；继续追子体、接触和状态，不能以发射成功算技能完整 |
| 状态与帧事件 | 原版既有事件被PD2复用或扩展，触发时与执行时可能采样不同状态 | [装备触发](ITEMS.md#装备触发与装备自带技能)、[充能回调](ITEMS.md#3452d0充能事件回调契约)、[命中间隔](ITEMS.md#飞弹命中间隔)；明确谁拥有时钟、何时取消及是否持久化 |
| 地图与区域程序 | 原版房间／预设结构仍被使用，地图物品另引入资格、门户、属性路由和事件控制 | [开图分派](MAPS.md#开图程序与属性分派)、[地图词缀全链](MAP_PROPERTIES.md)；能加载地形不等于开图和首领流程完成 |
| AI与伙伴 | AI名称相同仍可被替换回调加入身份分支；原版回退只在指定条件成立 | [AI程序与回退](MONSTERS.md#ai程序与原版回退)、[召唤与伙伴](MONSTERS.md#召唤实体与伙伴)；不将普通分支等同特殊首领 |
| 物品加工与经济 | 原表配方与价格输入保留，但匹配、循环、重建、资格及收费可被改写 | [方块与重掷](ITEMS.md#方块链与重掷)、[城镇经济](TOWN.md)；生成、报价、权威扣费分开 |
| 客户端表现 | 原图、物品外观、提示公式及效果回调可独立修改，不授予权威属性 | [物品函数复核](../resources/pd2-core/ITEM_FUNCTION_REVIEW.md)、[客户端技能](SKILLS.md#角色技能树与客户端程序)；未知主人／状态输入不能当0 |
| 协议与持久化 | 原包入口可能换长度与含义；逐件物品格式、磁盘容器、运行状态互不等价 | [协议与存档](PROTOCOL_AND_SAVES.md)、[字段取证](../resources/PD2_CN_DLL_ANALYSIS.md)；CN附加模块单独注明，不归为核心通用规则 |

这张表是阅读导航，不重复负责分册的数值规则。所谓“相对原版”也须指定原生模块版本；D2MOO用于理解原调用链，当前配套DLL／MPQ用于消除版本和字段差异。某一函数委托原版只证明那条分支，不证明其所有调用者、输入和上下游均未改变。

## 全库分析的未完成范围

旧核心已编目20,196个分析器函数体和82,290个独立CRT跳板，仍有未归属代码，详见[覆盖边界](../resources/pd2-core/COVERAGE.md)。当前核心只有多批定点分析，没有与旧版等量、逐项对应且语义闭合的全库契约。已存在的领域文档混合了详细算法、部分分支和只定位入口；未统一审完的内容不作整体准确性背书。

后续分析按依赖推进，结果直接回填负责条目，不建立第二份实现计划或会话日志：

1. 固定当前核心的函数边界与挂接清单，逐项建立旧／新对应；独立归类CRT、容器、解析跳板，不能用地址平移或名字匹配代替对应证据。
2. 先闭合被多个玩法复用的原生绑定、随机、百分比、属性与事件helper，再核对依赖这些helper的现有结论。错误的公共函数身份会同时污染多个分册。
3. 按功能从真实Hook／程序表／MPQ调用者向下走，补齐每个业务函数的ABI、前置条件、早退、分支、状态写入、释放和调用顺序；没有普通callers不判为不可达。
4. 补特殊地图控制器、首领AI、存储容器、客户端专用表现等尚未闭合链；同名原版回退和敌对替身不能算原规则恢复。
5. 对已有D2X消费者做独立源码映射，记录匹配、差异与输入可达范围。规则分析完成、代码已接入、原生对照通过分别描述，未经授权不自动构建或运行。

“每个函数用途和核心都已解释”的完成条件不仅是给每个地址一行名称：所有识别入口须有可追溯的分类或契约，业务挂接须闭合到实际规则，跨版本身份须明确，剩余无法恢复处须逐项列明。当前交付尚未达到这个全库完成条件。

## 条目的内容与证据口径

每条规则在负责分册的稳定标题下维护以下信息；短条目可用一段话或一行表格，不强制展开模板：

1. **范围与规则**：原版怎样、目标PD2怎样；触发条件、输入、输出、副作用、执行顺序及适用例外。只确认了一部分就写清该部分。
2. **定位依据**：引用[版本标识](BUILDS.md#目标版本)，注明模块／RVA、真实调用点或表项；资源注明表名、记录身份、字段、TXT／BIN语义。地址表、推断和实机观察分别说明。
3. **当前消费者**：列出内容准备、权威执行、客户端表现／协议和保存中实际相关的代码入口；仅解析、仅显示、已接入执行和已覆盖组合不得混为一谈。
4. **边界与未知**：保留未恢复分支、证据冲突、版本差异及未覆盖组合；没有消费者的字段不能写成已经实现。

“已确认规则”指有可定位的原表、指令／调用链或限定条件下的原生观察支持；“代码已接入”只说明当前D2X有对应路径；“待核实”保留候选解释及缺失依据。三者分别描述，不按构建成功或自研冒烟给规则升级。

同一规则只维护一次：装备触发归物品，触发的技能程序归技能；地图词缀来源及区域生命周期归地图，怪物接收属性和行为归怪物；保存字段归存档负责页。跨领域用链接连接，不复制数值与状态清单。

## 持续维护

分析或修改PD2功能前，先读版本与负责分册。确认新行为、修正旧结论、增加消费者或发现限制时，在同一工作中更新原条目；被新证据推翻的结论直接修正，必要时保留仍有兼容意义的版本分支及差异原因。新增领域先在此登记归属。

未知项没有核实前明确暂缓，不用原版行为或假参数补齐。代码改动仍遵守[协作约定](../../AGENTS.md)；本目录不扩大构建、运行或提交授权。开发过程、冒烟台账、截图、日志、存档、DLL／MPQ和整批反编译留在当次交付或忽略目录；修改历史由Git追溯。
