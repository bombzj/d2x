# 战斗单位与阵营

战斗实现入口在 `gameplay/combat/unit.cpp`，当前绑定／属性准备在 `gameplay/simulation/unit_records.*`。身份、关系与伤害请求分别在 `combat/identity.hpp`、`relations.hpp`、`damage_request.hpp`；公共 `CombatUnit` 不携带具体人物／佣兵／怪物指针，内部 `RuntimeCombatUnit.records` 承担原具体适配。`CombatUnit` 是短生命周期的访问视图，连接玩家、佣兵、怪物和召唤物各自的状态；不得跨实体容器增删或换区保存视图。动画、背包和服务仍由各自模块持有。

## 身份与关系

`CombatIdentity` 分别记录任意编号的 faction、owner、party、角色类别和可受攻击标志。怪物身份 `MonsterIdentity` 不代表敌我关系。默认玩家阵营 1 与敌对怪物阵营 2 互相敌对；未配置关系为中立。相同主人始终为盟友；随后依次查询单位关系、主人关系、同队关系和阵营关系，支持定向敌对。相同非零阵营默认友好，未知的不同阵营默认中立。所有权循环或缺失不会产生攻击许可或玩家收益。

`canAttack` 是近战、弹体、范围伤害、毒云、敌对光环、诅咒和自动选敌的共同过滤器；辅助光环使用 Allied 关系。AI 保存实际目标 ID，表现层也按该目标朝向。种族与群组条件仍用于沉沦魔指挥和巫师复活，但额外要求盟友关系。

## 计算与归属

`DamagePermission` 明确区分敌对攻击、已生效的持续伤害、环境伤害和调试命令。环境物体无需伪装成敌对角色；爆炸木桶遍历公共单位并执行原 ObjEval 的命中／固定点伤害，再统一减伤。火焰祭坛的原直接生命扣减也遍历公共单位。

`resolveIncoming` 处理攻击双方的原版倍率和目标减伤规则；`dealDamage` 处理实际生命变化、受击及死亡。可同时提交多个元素通道，避免同一次范围伤害产生多次死亡。`recoverUnit` 集中处理受击，普通怪物命中的物理与附加元素结算完成后只触发一次，保留佣兵命中类别／生命阈值；毒和撕裂的持续扣血不触发受击动作。玩家/佣兵抗性上限与普通怪物免疫规则仍有区别，PvP、佣兵对首领、首领对宠物倍率依据本地 D2MOO SUnitDmg，不以阵营编号推断。

箭矢和持续伤害保留实际攻击者 ID。吸血、击杀恢复作用于攻击者；死亡事件单独携带控制玩家、实际攻击者及死亡时的 MF/GF 快照。第八项将 `EnemyDied` 独立到 `rewards/death.hpp` 并补原 NOTC 快照，奖励协调通过显式受益者与宿主端口执行，本轮已联合构建／有限冒烟，见[奖励基线](../../modules/REWARDS.md)。无玩家主人的怪物击杀不借用当前玩家的属性或授予其经验。`UnitDied` 是无收益的通用死亡通知；只有可结算怪物死亡才发出带收益信息的 `EnemyDied`，骷髅死亡不会生成掉落。玩家属性和装备派生快照现归 `PlayerState` 所有，不再是模拟器的唯一全局战斗缓存。

参考：`reference/d2moo/source/D2Game/src/UNIT/SUnit.cpp::SUNIT_AreUnitsAligned`、`SUnitDmg.cpp::SUNITDMG_CalculateTotalDamage`、`SUNITDMG_DistributeExperience`。原参数仍由当前 MPQ 内容层读取，参考代码不进入源码提交。

召唤骷髅作为首个新增参与方使用上述公共接口，数据、行为及原图边界见 [死灵法师召唤](../skills/NECROMANCER.md)。后续阵营无需增加“怪物打某类友军”的成对伤害函数；新单位需适配身份、状态、属性和本身的动作／死亡处理。

## 边界

当前实际世界仍只有一个可操控玩家，命令、库存、区域激活和网络同步未改成联机系统。通用战斗算法通过单位访问视图工作；接入其他玩家需要注册其实体状态、属性与可信命令来源，不能复用本地玩家的库存或技能回调。现有区域休眠和寻路范围仍然保留。阵营和临时战斗状态不写入角色 D2S v96，不改变磁盘格式或静默迁移旧档。

本轮公共单位与冗余清理未构建或运行，不新增测试程序；当前源码状态见 [单位基线](../../modules/UNITS.md)。此前构建与交付结果在 `BUILD_AND_SHARE.md`，不能认证本轮改动。
