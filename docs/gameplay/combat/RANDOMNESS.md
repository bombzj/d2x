# 随机机制

正常创建新游戏时由应用层取得新 32 位种子，不再固定使用 210／0xd2。`--seed <uint32>` 固定整局初始随机源（包括 0），`--map-seed`、`--population-seed` 可分别覆盖地图和人口计划；参数顺序不影响覆盖关系。启动日志记录根、地图、人口和会话种子。相同种子、同一资源和代码版本、同样的玩法操作／单位创建顺序可复现；不承诺跨版本或与零售版逐掷值相同。

## 共用规则

`core/random.hpp` 对照本地 D2MOO `D2Common/D2Seed.h/.cpp`：低位为传入种子，高位初始化为 666；下一状态为 `uint64(low) * 0x6ac690c5 + high`，返回新的低 32 位。限界取样按原版取模，界限为 0 时返回 0 且不推进状态。666 和乘数是原算法常量，不是固定的新局种子。`childRandom` 参考 `D2Game/UNIT/SUnit.cpp::SUNIT_InitSeed`，推进父流后用结果初始化子流。

应用层的 `core/random_seed.hpp` 使用标准 C++ `random_device` 取边界熵，失败直接报告，不退回固定值。D2MOO `GAME/Game.cpp` 的建局入口使用动态时间／计数器并支持 `GAME_SetInitSeed`；此处用跨平台熵接口替代 Win32 时间接口。玩法与存档编码没有新增 Win32 依赖。

| 随机源 | 当前消费者和依据 |
| --- | --- |
| 地图 | 原 DRLG 递推与父流掷值加关卡 ID 派生；地图几何规则仍见 ACT1_MAPS。DT1 图块依 DrlgRoomTile.cpp 的 GetTileCache 按原 rarity 加权选择，加载时固定结果，碰撞和绘制共用；去掉仅按坐标散列的选择。 |
| 人口／世界物体 | 移除人口 SplitMix64、路径 FNV 和物体 ID／坐标异或种子；房间、物体按父流分配子流，概率与范围仍来自原表及既有参考规则。房间划分、创建顺序和流分配层次仍为本项目适配。 |
| 单位／战斗／掉落 | 玩家、怪物、佣兵与弹体在创建或读档时得到本局随机状态。怪物死亡事件携带该单位的种子供 TC 结算；宝箱沿自己的种子，未混入公共物体掉落流。参考 SUnit.cpp、Items.cpp、Objects.cpp；普通物体仍使用本局公共流。 |
| 物品／商店／佣兵 | 新物品 start seed 从父流产生，原图案／基础防御使用其子流；商店和候选不再按实体 ID 固定。佣兵保存候选生成的 seed，新物品保存真实 start seed，不再写固定 1 或内部实体 ID。词缀／品质规划和实例创建仍是分阶段的项目流程，不承诺完整原版消费顺序。 |
| 任务／祭坛 | 凯恩石阵使用本局任务流，按 A1Q4.cpp 把顺序编号填进随机空槽，冲突重抽；同局查看不改变顺序。祭坛使用对象流选择效果，实际效果另用本局玩法流。 |
| 客户端效果 | 使用本局分出的独立视觉流，碎片随机不改变伤害、掉落或单位 ID。当前毒烟节拍等未完成效果不因此被视为已修复，见 COMMON_ATTACKS。 |

充能弹路径的 `index + path X` 种子保留：这是 `SkillSor.cpp::SKILLS_MissileInit_ChargedBolt` 的明确规则，配套 `PathMisc.cpp::PATH_ComputePathChargedBolt_6FDAB4A0`，不能当成错误的固定游戏种子删除。

## 保存与适配边界

D2S 仍为原生 v96，不添加规则指纹、运行时 RNG 快照或私有尾段。载入保留原地图种子和物品／佣兵原生身份种子；物品创建、战斗、商店、任务、客户端效果等重新进入本局随机流，人口配置不再意外落回默认值。在同进程快速重载时，宝箱锁／陷阱／掉落种子也通过同一初始化函数重建。地图图块变体的消费顺序按本项目装配后的地图遍历，尚未复刻零售版的房间分配时序。

可选资源查询命令也不再默认固定 210，提供种子时沿其已有参数执行；接受原始 64 位随机状态的底层查询仍保留原协议。程序未通过本轮游戏运行或多种子统计验证；构建与交付状态见 BUILD_AND_SHARE。
