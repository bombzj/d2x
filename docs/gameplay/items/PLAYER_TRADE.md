# 玩家交易

更新：2026-10-27。服务端入口为 `server/systems/trade`，两人的真实库存始终由 PlayerStore 持有；客户端共用原 D2GS 协议。验证范围见[基线](../../../BASELINE.md)。

同城镇、同区域、存活且已入场的两名玩家通过原 13/type0 邀请；双方没有 Cursor、NPC 对话、仓库／方块或其他交易。邀请双方停下移动及待执行交互；4F/button3 仅受邀者接受，button2 取消。77/6／78 打开面板并给出伙伴身份；双方报价初始为零，79 按实际金币报价请求回传。

接受时按当前 MPQ `Inventory.Trade Page 2-2` 创建运行态 Trade 容器。原18/page2、19、1F复用库存规划器，只允许本人 Backpack／Cursor／报价格间取放和交换。本人报价为page3，对方收到page2只读镜像；每次重新报价分配新的镜像及socket子项GUID，不进入真实库存。镜像保留复制时的物品标志；沿D2MOO `ITEMS_Duplicate` 给原件设置IFLAG_ITEM（0x08000000），取回背包后仍保留该位；生成物品与读档物品的保存路径都保留该32位原标志。撤回镜像使用9D/action5、Cursor模式、原格地址、page2及IFLAG_QUANTITY（0x20），不以0A替代。回包从事务冻结的物品原值编码，不查询后续活库存。

4F/button8 报金币，报价不扣钱；按原 PlrTrade 的接收者当前随身金币上限截断。只向报价者回79/side1、对方回79/side0，不附带77/6，也不重发另一侧的金币。重复相同报价不撤销确认；任一方已确认时，改变金币须先用button7撤销双方确认。button7只回双方77/6，不改变金币报价和现有锁期限。

取回已报价物品时，原77/14锁定双方确认框十秒，77/15解锁；新增报价不启动、不延长也不提前解除已有锁。报价变化撤销已有确认，已确认者不能修改物品。固定1.13c实包要求已有确认时先77/6、再77/14，随后才发送本人及镜像的移物回执，金币报价保留；不套用D2MOO另一版本分支中的金币清零顺序。消息与期限只在库存事务成功后生效。button4要求空Cursor、已解锁且本人尚未确认；关闭后的再邀请冷却五秒。客户端用77/14／15维护锁、77/6撤销确认、79/side1结束GoldSent等待。

两人都确认时，先为双方计算任务／carry1资格、背包空间、金币上限及属性规则。沿 `PlrTrade::sub_6FC92A90` 复制报价物品和socket子项，接收者获得新GUID；使用既有 `Draft::space` 对应 `D2GAME_PlaceItem_6FC44410 → INVENTORY_GetFreePosition` 的加权找格，一行物品从右下扫描，较高物品从左上扫描，按占用边缘与边界评分。尺寸取当前MPQ。金币双向净额结算；`transactions::commitInventories` 同时复验两名玩家及区域版本，先保留完整不可变事实，再交换双方库存／人物。资格或空间不足不移物、不扣钱，6／9／10撤销确认并保留报价。成交先以带QUANTITY的9D/action5撤销原件及镜像，再77/13关闭，随后发布收件物品。

取消沿 `PlrTrade::sub_6FC90AE0/sub_6FC90BE0` 重建接受时的个人库存及原位置，根物品和socket子项均获得新GUID；同步重映射注册武器、选中技能来源及快捷键来源。尸体和佣兵属于独立库存链，保留各自当前单位及属性。双方92/type0/玩家GUID先发给已入局观察者，然后各自77/12及完整私有物品回包；公开装备由既有复制器在事实排空后重建，不泄露背包。客户端按92的真实所有者清理旧根物品、关联子项、公开装备及本人挂起移物／物品目标，不能只在77/12清空界面。离场、断线、移动／旅行和死亡须先取消；输出背压保留原交易／人物。交易期间普通消耗、装备、NPC、合成及其他库存写入被拒绝；普通数量／耐久再生沿既有交易限制，PD2充能见[专用契约](../../pd2/ITEMS.md#3452d0充能事件回调契约)。报价金币未扣除，取消不另加退款。

自动保存／停服保存导出接受时的个人库存快照，保留当前人物记录、尸体及佣兵库存，不把报价格或镜像写入磁盘。编码器拒绝未归一化的Trade容器。D2S v96及原物品格式不变；运行态GUID、邀请、报价、确认、冷却及镜像映射不保存，物品技能来源继续按原库存索引保存和重绑。

成交原子性属于局内权威及可靠事实提交。PvPGN D2DBS 仍按原协议逐角色保存，两份磁盘记录没有跨角色持久事务；后端失败或进程崩溃恰落在两次保存之间的恢复尚未认证，不能据此承诺持久层同时提交。

## 原版参考与缺口

依据为本地D2MOO `PlrTrade` 的邀请、复制、恢复、确认锁，`ItemMode::D2GAME_PlaceItem_6FC44410` 及D2Common `INVENTORY_GetFreePosition`；实际顺序以固定1.13c实包为准。D2Game.dll MD5为 `978f6f74cd031bce6ecee602cd5988cc`，D2Client.dll MD5为 `f5860c629d309b8fc1f96174babcf633`。参考仓库不纳入源码。

2026-10-27用相同90级／1级女巫D2S输入，分别连接D2X Host和原版Host：邀请／拒绝、反向接受、双向金币、重复报价、钱包余量截断、确认撤销、取回和锁内重新报价、取消均完成。取消恢复16／8件根物品及既有镶孔关系，旧GUID与镜像不残留。每种宿主同一游戏、同一连接连续成交两次：RVS与HP1互换，500／200报价后钱包为199516／1300，再以200／500换回后恢复199816／1000；均为新收件GUID，落点分别为(4,0)与(9,3)，光标与镜像为空。两次成交之间无68重连或69退出；正常返回档在新进程中与退出前物品属性、位置、镶孔和金币一致。
