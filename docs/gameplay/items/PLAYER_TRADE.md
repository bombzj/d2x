# 玩家交易

更新：2026-10-10。服务端入口为 `server/systems/trade`，两人的真实库存始终由 PlayerStore 持有；客户端共用原 D2GS 协议。验证范围见[基线](../../../BASELINE.md)。

同城镇、同区域、存活且已入场的两名玩家通过原 13/type0 邀请；双方没有 Cursor、NPC 对话、仓库／方块或其他交易。邀请双方停下移动及待执行交互；4F/button3 仅受邀者接受，button2 取消。6／78／79 原包打开面板、给出伙伴身份及双方金币。

接受时按当前 MPQ `Inventory.Trade Page 2-2` 创建运行态 Trade 容器。原 18/page2、19、1F 复用库存规划器，只允许本人 Backpack／Cursor／报价格间取放和交换。对方只收到独立 GUID 的 page2 只读镜像，本人报价为 page3；镜像及 socket 子项不进入真实库存，也不能从镜像发起取物。物品及属性使用既有原 9C／9D 位流，不新增网络或存档格式。

4F/button8 报金币，报价不扣钱；按原 PlrTrade 的接收者当前随身金币上限截断。button7 撤销双方确认。物品报价变化后，原 77/14 锁定双方确认框十秒，77/15 解锁；关闭后的再邀请冷却五秒。button4 只允许空 Cursor、解锁且尚未确认的本人提交。报价变化撤销双方确认，已确认者不能修改物品。

两人都确认时，先为双方计算收件人任务／carry1资格、背包空格、金币上限及全部属性规则。保持物品实体及 socket 身份，自动放入对方 Backpack；金币双向净额结算。`transactions::commitInventories` 同时复验两个玩家及区域版本，先发布完整不可变事实，再以不抛异常的交换更新双方库存／人物。任一资格或空间不足均不移物、不扣钱，6／9／10 撤销确认并保持报价；成功以77/13结束。

取消恢复接受时的完整库存与原位置，提升移动物品版本，清除双方镜像并发77/12。离场、断线、移动／旅行和死亡须先取消；取消输出背压时保留交易／人物，等待输出可用。交易期间普通消耗、装备、NPC、合成及其他库存写入被拒绝；自恢复库存等待交易结束。报价金币未扣除，取消不另加退款。

自动保存／停服保存导出接受时的原库存，保留当前人物记录，不把报价格或镜像写入磁盘。编码器显式拒绝未归一化 Trade 容器。D2S v96 不变；准入规则 v30，运行态邀请、报价、确认、冷却及镜像映射不保存，旧规则不静默迁移。

成交原子性属于局内权威及可靠事实提交。PvPGN D2DBS 仍按原协议逐角色保存，两份磁盘记录没有跨角色持久事务；后端失败或进程崩溃恰落在两次保存之间的恢复尚未认证，不能据此承诺持久层同时提交。

依据：本地 D2MOO `PLAYER/PlrTrade.cpp` 的邀请、恢复、按钮、收件资格与确认锁；`PLAYER/PlrMsg.cpp` 的原 13／18／4F；`ITEMS/ItemMode.cpp` 收件资格；当前 MPQ Inventory 格尺寸。参考仓库只作规则证据，不纳入源码。队伍／敌意、跨机器、原版 Game.exe 的整套交互及长期／故障恢复不由本页宣称完成。
