## 状态与登记口径

客户端C、服务端S和证据V独立记录，统一定义见[总计划](../../architecture/MULTIPLAYER.md#21-统一状态口径)。定义导入、网络解码、服务端生成／使用、D2S保存和运行证据是不同能力；空入口、可见属性或管理生成不算完整实现。V0是源码依据，V1是对应构建，V2只覆盖列出的有限路径，V3须列声明范围及排除项；新增分支不能继承旧包的V2。

后续具体条目的登记至少包含当前MPQ稳定键／表行、实际代码入口、客户端已知字段与表现、服务端来源／资格／消费者、公共函数与状态所有者、保存边界、原版依据、证据与缺口。不维护另一套静态物品参数或概率表，变动表行须回到当前MPQ核对。

## 类型与机制的交叉引用

| 物品类别 | 主要归属与当前边界 |
| --- | --- |
| 武器／弓弩／投掷／职业武器 | EQUIPMENT＋DURABILITY；技能／弹药执行归技能／战斗，不因基底可生成标全武器效果完成 |
| 防具／盾／腰带／靴／手套／头盔 | EQUIPMENT，腰带操作归INVENTORY与消耗品；格挡／踢击等专属消费者另有依赖 |
| 戒指／项链／护符／职业专属物品 | EQUIPMENT＋AFFIXES；护符位置资格与特殊技能消费者单独核对 |
| 宝石／符文／珠宝 | SOCKETS＋GENERATION；每条原表／宿主差异待逐项登记 |
| 药水／投掷药瓶／卷轴／书本／弹药／钥匙 | 消耗品、GENERAL技能、INVENTORY与SPECIAL分别负责，不能将全部物品使用视为药水 |
| 方块／任务物品／永久奖励／Token／扩展材料 | CUBE＋QUEST_ITEMS；任务／地图／首领依赖不是配方匹配的替代品 |
| 金币／耳朵／身体部件／Realm／特殊品质 | GOLD或SPECIAL／SAVES；编码成功不证明来源已实现 |

品质、基底、属性、生成来源、存放位置和使用者是独立维度，不能按一个成功样本批量标完成。每件物品应有当前Armor／Weapons／Misc代码与类型归属，每个属性／配方／来源登记消费者、Clt支持、自研执行、保存、原版依据与有限证据；未知用途先归SPECIAL，未核实规则不造参数、概率或替代品。

## 维护规范与待补范围

COMMON写公共边界，GENERATION／AFFIXES写准备值，EQUIPMENT写贡献，INVENTORY／GROUND／GOLD写移动与事务，CUBE／QUEST_ITEMS／ECONOMY写各自资格与提交。UI和原包分别写INVENTORY_UI／PRESENTATION；物品技能仍归skills目录，任务阶段、佣兵服务、尸体和D2S仍链接原专题，不复制实现与历史流水。

完整逐基底、Properties／ItemStatCost消费者、全部词缀／特殊品质、Gems／Runes、CubeMain与来源组合台账尚未完成；已实现的保留入口，未做类别明确预留。当前证据只覆盖列出路径，三难度、多人、全随机、音频／像素与原服精确认证仍有限；完整后续顺序见[总计划](../../architecture/MULTIPLAYER.md)，当前包只见[基线](../../../BASELINE.md)。
