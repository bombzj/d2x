# 腰带与物品使用

更新：2026-10-04。以当前 LoD 源码与 MPQ 为准；职业药剂倍率本批按本地 D2MOO 修正，已随镶嵌通过 Windows Release 构建；药剂倍率尚未逐职业运行验收，未打包。

## 操作

| 输入 | 行为 |
| --- | --- |
| `1`～`4` | 饮用对应腰带列中最下方的物品；无物品或尚未实现使用效果时提示 |
| `Shift+1`～`4`／`Shift` 右击腰带药剂 | 给存活佣兵使用对应药剂，适用类型见 [佣兵](../characters/HIRELINGS.md) |
| `B` | 展开／收起腰带；打开包裹时自动显示全部可用行 |
| 右键点击包裹／腰带中的药水 | 饮用该瓶；拖动或拆分过程中右键仍是取消 |
| `Shift` 点击包裹药水／卷轴 | 优先填充同类腰带列，再找空列；不改变其他列 |
| `Shift` 点击腰带物品 | 自动移入包裹 |
| 在包裹与腰带格间拖动 | 移动或交换；双方都必须适配目标容器 |
| 右键／`Shift` 点击包裹里的腰带装备 | 穿戴或替换腰带；也可拖到原版装备栏中央的腰带槽 |
| 右键／`Shift` 点击已穿戴腰带 | 脱下，放入包裹 |
| `F1`～`F8` | 悬停技能菜单图标绑定左右鼠标技能；之后按键切换技能，数字键留给腰带 |

帮助、传送点菜单、死亡状态下不能饮药。鼠标位于包裹／腰带上时，右键不会穿透到世界施法；拖动期间不会使用腰带快捷键。

## 容量、拾取与补位

基础腰带有 4 格；当前普通 Sash、Light Belt 为 8 格，Belt、Heavy Belt 为 12 格，Girdle 为 16 格。普通、扩展、精华腰带均由 Armor.belt 索引当前 Belts.numboxes，除以四得行数；没有仅五种普通腰带的硬编码目录／掉落池。原 TC、品质、等级、需求与可用美术共同决定是否生成和装备；词缀效果仍受 [物品支持](SUPPORT.md) 的共同限制。

腰带是四列、从下往上存放的容器，逻辑 `y=0` 为准备行。自动放入优先查找同类列：生命药水各等级为一类、法力药水各等级为一类、两种回复药水为一类，其他物品按定义代码匹配。满列不会挤出原物品。手动拖放允许混合列。

拾取生命／法力药水时可自动占用空列；其他腰带适用物品只自动进入已有同类列。不能自动入带就使用原有包裹拾取事务；两处都不能容纳时留在地面。`Shift` 点击是明确的整理操作，允许为回复药水、卷轴等使用空列。

饮用后删除实例，同一列其余物品向下补齐，其他列保持原样；也可直接右键饮用展开行中的药水。手动整理产生的空洞不会使快捷键失效，快捷键始终选择该列最低的物品。

换小腰带或脱下腰带时，超出新容量的物品自动尝试放入包裹。预先在库存快照上规划装备交换、溢出物品位置和版本变化，全部成功才提交；包裹没有足够的完整空格时拒绝整笔操作。不会删除溢出物品，也不会自动扔到地面。界面显示的容量始终读取真实容器。

## 药剂效果及复刻边界

LoD 运行时从原 MPQ `misc.txt` 识别五级生命、五级法力、回复、全面回复、耐力、解毒和解冻药剂。物品美术按实际实例的 `invfile`／`flippyfile` 路径载入；掉落走原 TC。试玩／经典资源只保留历史材料，没有运行入口。

当前 LoD 表的基础生命恢复量为 30／60／100／180／320，基础法力为 20／40／80／150／250。内容层保存原 calc 基础值，在实际消费时由纯玩法 `potionRestorationAmount` 应用原引擎职业倍率；修正旧内容层生命预乘二导致全部职业使用野蛮人数值的问题。倍率来自本地 D2MOO `Items.cpp::ITEMS_GetBonusLifeBasedOnClass/ITEMS_GetBonusManaBasedOnClass`，不是 MPQ 药剂参数，不反写原表。

| 使用者 | 生命倍率 | 法力倍率 |
| --- | ---: | ---: |
| 亚马逊／圣骑士／刺客 | 1.5 | 1.5 |
| 野蛮人 | 2 | 1 |
| 女巫／死灵法师／德鲁伊 | 1 | 2 |
| 非玩家单位 | 2 | 1（当前佣兵喂药仍拒绝法力药） |

回复药剂的 35%／100% 与耐力、解毒、解冻药剂的各 750 帧持续时间来自 `misc.txt`，回复比例不受上述职业倍率改变。职业倍率修正没有补齐玩家活力／精力药剂暴击、原恢复叠加平均与全部 8.8 舍入；这些仍未完成／未验收。佣兵治疗继续走其已实现的暴击与固定点恢复分支，不受玩家职业影响。

生命和法力在固定 25 Hz 玩法更新中恢复。同一种资源的连续药剂当前排队生效，不叠加恢复速度；达到上限会丢弃未使用的恢复量，满值时仍可饮用并消耗药水。持续时间按 LoD `misc.txt` 各物品的 `len` 帧换算。D2MOO `SkillItem.cpp` 原 pSpell03 会合并剩余恢复量／时长并求新速率，当前玩家队列不是该完整规则，不能称逐帧等价。

初始物品从当前角色的 MPQ `charstats.txt` 行读取，旅行保留药效、库存和装备。临时状态不写入 D2S；死亡按原 States 的保留位移除，当前三种药剂均不保留。治疗入口补满资源并清除现有毒／冷计时器，不再清空全部 Item 来源状态；因此阿卡拉治疗和调试恢复不会错误移除耐力、解毒、解冻加成。依据 `SUnitNpc.cpp::D2GAME_NPC_HealPlayer_6FCCB080`，有益药剂状态未带原 curable 位。

背包中的回城卷轴和有页数的回城书可使用；鉴定卷轴／书通过右键选择未鉴定物品。耐力 vps 的 pSpell=9 读取 staminapot、staminarecoverybonus=5000、750 帧并立刻补满耐力；States.stambarblue 控制蓝条。解毒 yps／解冻 wms 的 pSpell=6 与 pSpell=9 共用三组 stat/calc 导入，分别获得原 50 毒／冰抗、10 对应最大抗性、750 帧；按 cstate1/2 的 poison／freeze,cold 清除状态，旧毒／冷计时器也由这些原表列转换的标志清除，不按物品代码判断。未知属性／公式拒绝整瓶的效果适配，不能只执行已知的一半。临时加成进入统一 CombatEffectSet，整数帧延时、不叠加属性；没有待解异常也可饮用。依据本地 D2MOO `SkillItem.cpp::SKILLITEM_pSpell09_StaminaPotion`／`SKILLITEM_pSpell09_AntidoteThawingPotion`。`PlrModes.cpp::sub_6FC7F780` 的奔跑消耗与 `EVENTS_StaminaRegen` 分开计算，恢复加成达到 1000 才允许非站立／步行时恢复，不能据此直接禁用消耗；恢复使用原 8.8 舍入，步行减半，城外不足 1 点耐力时步行不恢复。当前统一浮点资源与模拟调度仍不是原引擎逐帧等价。

耐力条颜色：普通／低耐力使用 OpenDiablo2 hud.go 的 AF8848C8／FF0000C8 及 25% 阈值，蓝条使用该项目 color_tokens.go 的通用 UI 蓝 6969FF，沿用 HUD alpha C8。蓝条优先于低耐力颜色，过期后恢复普通判定；这替代了无来源的 70/130/220/205 选色，但通用 UI 蓝用于耐力条仍属参考适配，不能称为 1.13c 原条的精确蓝色。

投掷药瓶按 ItemTypes 装备手位，Throw 发射并消耗堆叠；饮用和未实现的物品效果明确拒绝，数量不变。腰带穿戴校验原表需求并改变容量，属性消费者见 [物品支持](SUPPORT.md)。佣兵已有治疗、回复、解毒和解冻喂药入口，类型与限制见 [佣兵](../characters/HIRELINGS.md)。私人储物箱和赫拉迪克方块的存取已实现；合成支持法杖、克林姆两项任务与孔相关配方，详见 [方块](CUBE_AND_GOLD.md)。

- 容量、自动入带及初始物品元数据从当前挂载原表在运行时准备，不依赖历史精简 MPQ 或试玩命名映射。

本轮未下载另一套 UI、人物或物品素材。总体 HUD 布局、提示框、部分技能图形和粒子仍是项目的表现代码，不声称整个界面已逐像素复刻。

## 扩展入口与验证范围

`items/belt.cpp` 负责列选择、容量事务和饮用后的库存补位；`consumables/potions.hpp/.cpp` 定义药效、职业倍率及应用；`session_consumables.cpp` 负责访问校验、消耗与应用效果；固定步资源更新在玩家／单位资源模块。穿戴容器 `BeltEquipment` 仍使用唯一物品位置，普通移动／交换接口不能绕过装备事务修改它。

`EquipBelt`、`UseItem`、`UseBeltColumn` 是意图命令，权限由会话生成；`ItemUsed` 和 `BeltEquipped` 驱动音效。药效状态属于 `PlayerState`，MPQ 纹理属于 `SceneAssets`；D2S 保存角色与库存，不保存这些临时效果或 GPU 对象。

此前已有 Windows 构建和有限腰带／饮用手势证据，实际范围见 [库存模块](../../modules/INVENTORY.md#构建与冒烟)；不认证全部药效和职业数值。本次职业倍率源码修正已随镶嵌构建通过，未逐职业运行验收，规则指纹增加 `potion-class-rules-v1-native-restoration`，临时药效仍不入 D2S。未编写测试脚本、用例或专用程序；Linux 保持标准 C++20／CMake 接口，但本机未实际编译运行 Linux 版本。
