# 物品公共规范与事务边界

更新：2026-10-09。本页维护物品迁入、权威所有权、事务与公共计算规范；分类及当前范围见[目录](README.md)，代码入口见[库存模块](../../modules/INVENTORY.md)，实例调度见[内核](../../modules/SERVER_SYSTEMS.md)。

## 权威与分层

原服和自研宿主共用RealmSession／RemoteInventory／RemoteUiClients、原1.13c物品包及公共UI。客户端只读已收到的身份／属性、预览并发送原请求；真实物品、金币、容器、装备贡献、材料、货架与交易结果由连接的服务端持有。禁止为自研宿主增加客户端玩法分支或私有协议。

PlayerStore唯一持有人物库存，items持地面物品，merchant持NPC货架和个人赌博准备，crafting持加工请求；attributes计算提交后的总值，transactions提交人物／库存／世界草稿，hosting准备当前MPQ规则和冻结掷值。GameInstance只组装领域，不拥有第二套物品／商店规则；内核不访问MPQ、GPU、输入、文件或Win32。

准备结果绑定请求token、种子、库存／人物revision；提交前复验所有权、交互、区域代次与容量。失败不消费材料；Outbox背压保留准备身份，不重新抽奖。库存、人物与必要世界事实成组接收后才提交状态。

定义、品质与实际属性分别建模；生成时冻结词缀、孔内和条件套装值，不能在装备、显示、报价或保存重入时重新抽取。ItemHandle／库存revision、区域／交互代次和地面落地generation用途不同，不能把可变属性版本当作一次落地身份，详见[模型](MODEL.md)及[地面](GROUND.md)。

## 公共计算与原包

gameplay/items与gameplay/loot提供显式输入的品质、需求、装备贡献、数量／恢复、配方匹配与随机计算。部分content/items函数仍使用ClassicData，由内容适配层调用；不能因为名字叫纯函数就把ClassicData传进server或把整个生成器放到客户端。客户端只用原包完整已知值计算显示／报价，不推算隐藏掷值或重建未知孔内属性。

原请求和回包使用同一消费者；Pending／Updated／SentNoAck与完成分别记录，超时为未知，不自动重发非幂等操作。客户端必须复验连接／游戏／区域／交互代次与物品来源，组合步骤按真实Cursor和回包推进。原包／位流／成功条件归[PRESENTATION](PRESENTATION.md)，D2S独立归[存档](../../modules/SAVES.md)。

## 迁入与登记流程

1. 先读master已有物品、掉落、商店、配方及装备规则，再查当前领域与公共函数；只迁可用规则，不恢复旧GameSession或本地库存执行器。
2. 以当前MPQ的物品代码、类型／品质、属性／词缀、配方或来源为稳定主键，核对当前表；本地reference和原DLL只补规则依据，参考参数不覆盖MPQ。
3. 提取真正相同的纯计算，明确等级／品质、实际属性、来源、取整、位宽、随机流与状态所有者；客户端缺数据保持未知，服务端缺规则明确暂缓，不生成少属性替代品。
4. 生成／报价／地图准备绑定请求与版本，先确认全部输入、材料、落点、输出容量及事实容量，再一次提交；迟到、争用、失败、背压不重复扣费、掷值或发奖。
5. 更新所属专题的客户端／自研执行／证据与明确缺口，保存语义变化同步格式、规则指纹及文档；旧档不静默迁移。
6. 构建／打包／运行仅按有效授权，不编写测试脚本、测试用例或专用程序；静态依据、构建、有限冒烟与完整原版验收分开记录。

当前分类入口已齐，全部MPQ物品／属性／配方及所有组合仍未逐行审计。管理生成验证准备条件，不替代自然掉落概率、任务来源、实际战斗触发或多人争用验收；历史证据统一见[EVIDENCE](EVIDENCE.md)。
