# 金币、钱包与仓库存取

更新：2026-10-20。本页维护金币作为人物余额和地面金堆的区别。所有金额、上限、扣费与最终余额由服务端决定；商店扣款归[ECONOMY](ECONOMY.md)，死亡惩罚的自研执行归[死亡领域](../../modules/SERVER_SYSTEMS.md#死亡与尸体)、原服显示见[人物死亡](../characters/PLAYER_DEATH.md)，地面寿命归[GROUND](GROUND.md)。

## 当前执行

原0x50丢金币同时规划钱包扣款与地面金堆；类型／最大堆数由ItemCatalog准备，必要时按上限拆堆。碰撞、世界容量或身份不足时不扣钱包，金堆与人物余额一次提交。普通拾取支持实际可接收量，满额余量留地，不因移除通知单独认定到账。

手动丢金与死亡丢金共用原GetFreeSpaceEx落点；连续丢弃围绕人物坐标偏移`(2,3)`的中心展开，八邻格顺序、碰撞／房间边界及D2MOO转录差异的原1.13c依据见[地面落点](GROUND.md#落地与拾取)。

仓库存取沿原0x4F、原钱包／stashGoldLimit与有效私人箱授权，不能从未打开页面绕过校验。余额与上限相关显示只能使用已知原属性；0x19与绝对余额分别归并，2A服务金额不重复加到钱包。

## 缺口与证据

自然金堆按同区域同队人数分配，整除余数由拾取者接收；每个钱包按自己的等级上限截取，未接收部分保留地面。原版用存活人数作除数，存活少于两人时不向队友分配；其分配循环却检查拾取者死亡模式，因此同区域死亡队员仍可收到份额。保留这个原版分支及有符号余数，不用无符号减法导致溢出。队友余额、拾取者余额与移除／余量新金堆共用一次事件预留和事务提交，背压不产生半笔到账。手动丢金及死亡丢金保留本局归属，不参加队伍分金；该归属只属于地面运行态，不改变D2S。

D2MOO Party::PARTY_ShareGoldDrop提供人数与余数入口；当前1.13c D2Game RVA`0x9C270`、`0x9C436..0x9C496`及容量辅助`0x9BC70`核实队友自己的容量，纠正D2MOO误用拾取者容量的指针；同段确认死亡检查仍用拾取者。原D2Common RVA`0x31940`为等级×10000。原版满钱包、死亡队员与溢出组合已静态核对，尚未录包／运行逐项认证。全部等级／最大金堆、死亡与存取组合、多人争用／异常断线仍未完整验收。钱币不采用自选分堆私有协议。

保存字段及资格由[存档](../../modules/SAVES.md)负责；原服金币协议观察见[联网](../../modules/NETWORK.md#既有有限证据)。管理grant-gold只准备余额，不能代替原版交易／掉落／死亡扣款依据。
