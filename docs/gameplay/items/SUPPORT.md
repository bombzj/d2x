## 数据与入口

- 运行时 MPQ：Weapons、Armor、Misc、ItemTypes、ItemRatio、TreasureClassEx、MagicPrefix／Suffix、RarePrefix／Suffix、UniqueItems、SetItems、Sets、QualityItems、LowQualityItems、Properties、ItemStatCost、NPC、Gamble、DifficultyLevels 和语言 TBL。
- `content/items/item_properties.cpp` 将原属性指令与实例掷值解析成共同统计值，保留原 stat、layer、原值与按等级换算后的效果值。装备、说明和定价共用解析结果；不从界面文字反推效果。
- `content/items/item_descriptions.cpp` 按 ItemStatCost 的说明优先级、函数、正负文本与 TBL 生成说明，合并元素／毒素伤害；商店与背包共用同一提示框。
- `content/items/item_pricing.cpp` 按基础表、词缀／品质费用、ItemStatCost、NPC 倍率形成购买、出售和单件修理报价。尚不能解释的属性计价分支拒绝报价，不按普通价格出售。
- `content/items/item_loot.cpp` 与 `gameplay/loot` 处理 TC、品质和实例；`gameplay/items` 负责数量、持久身份、位置、需求、耐久与事务。UI 只提交购买／修理等命令。

地面放置由 `InventoryService::resolve/checkPlacement` 统一处理，装备／腰带事务草稿沿用同一世界碰撞回调并检查自身草稿物品。依据 D2MOO `Items.cpp`、`ItemMode.cpp`、`D2Collision.cpp`：单格物品，`COLLIDE_MASK_SPAWN`（0x3e01）与源点到候选点的 WALL／DOOR field（0x801），逐圈找最近空格，搜索半径小于 50。怪物和物体掉落保留原 (2,3) 偏移起点，不再先按角色行走网格挪落点；阻挡石头／对象由当前 MPQ `Objects` 各模式占位决定，存活怪物／NPC／佣兵由 `MonStats2.SizeX` 和原单位 presence pattern 决定，玩家用原单位尺寸。已有物品动态查询，拾取／移走即释放格子，不按物品名、背包尺寸或图片包围盒排间距。地面取放的阻隔同样用 WALL／DOOR，避免将可落物但不可站人的格子误判为不可取放。大图像仍可能伸到相邻格，不承诺像素完全不相交；跨 Region 边界搜落点仍未接入。无空位的批量掉落不排队重试、不重抽。

## Jewel、宝石、符文与孔

当前 MPQ 的 jewel 为 `Misc.code=jew`／`ItemTypes.Code=jewl`，继承 `sock`；宝石 `gem` 与符文 `rune` 也继承 `sock`。Jewel 可为魔法、稀有或暗金，嵌入前须鉴定，本身是随机属性物品；宝石和符文的单件镶嵌效果按宿主类别选择 `gems.txt` 的三组属性。Jewel 美术变体与属性不绑定，并可作为 Crafted 材料；依据原表与 [暴雪 jewel 说明](https://classic.battle.net/diablo2exp/items/jewels.shtml)，不能只在“宝石镶嵌”条目下省略 jewel。

| 任务互斥形式 | 原生规则绑定 `j34↔g34`、`bks↔bkd`、`d33↔g33`、`hst↔msf/vip`、`qf2↔qf1/qhr/qey/qbr`；内容层按当前 MPQ 核验相同 quest 身份后准备关系，玩法只读取定义 |
| 事务与失败 | 创建、拾取（含 Cursor）、移动、整件转移、交换及载入库存校验共用 `checkCarryLimit`；不删除重复物品、不消耗材料、不重新掷掉落。死亡容器自身不拒绝脱装，任务拾取会检查其中的原件 |
| 难度／任务资格 | 任务难度来源、完成／领奖限制仍由 `session_loot.cpp` 独立复验；限带关系不会代替这些资格。任务状态查询与物品限带是不同职责 |

这是本项目在库存预览／提交／恢复处统一应用的规则适配；原参考的限带调用主要在拾取与尸体回收，完整零售客户端的储物箱拿放顺序及各种非法档组合尚未验收。D2S v96 字段不变，运行规则指纹新增 `inventory-carry-rules-v2-native-quest-pairs`；原生档若携带重复／互斥任务物品则明确拒绝，不静默删物品或迁移。事件暗金元数据读入不等于其事件掉落／原生档导入已开放。
