# MPQ人口计划与权威出生

更新：2026-10-17。本页维护自然生成任务的目标、进度、后续步骤，以及怪物候选、固定身份、出生与房间调度边界；物件算法细节归[物件专题](../world/OBJECTS.md#自然生成源码边界)，战斗规范见[COMMON](COMMON.md)，按幕覆盖见[怪物目录](README.md)。

原服和自研都由原单位分配消息驱动客户端，客户端不运行人口计划、出生或AI。服务端`population`执行实时密度、已迁入预设及任务／物件出生；`world/population`仅保留工具和未迁入身份的旧规划适配，hosting在调用它之前排除已迁入的DS1源序号，不重复占位或掷数。

## 自然生成工作总览

### 整体目标

按当前MPQ和原版1.13c实际程序，复刻服务端自然怪物、野外宝箱／藏物、陷阱、祭坛／井及必要任务控制物件的生成规则。目标不只是生成数量或画面接近，还包括类型与位置、保护范围、密度与数量预算、生成次序、随机流、初始化、失败重试及房间卸载／恢复。D2MOO用于定位和解释原程序；反编译有差异时以本地同版本原程序证据核实，不照搬空函数或可疑转录。

同种子一致性的条件是相同MPQ、游戏设置、玩家输入、房间激活顺序和事件顺序，不是仅有相同地图seed。应能说明每次选择消费哪条流、消费几次，以及成功、失败、异步等待和恢复分别留下什么状态。不能通过自定义密度上限、传送点避让半径、额外重试或换种子掩盖差异。

地形生成及客户端房间重建的原版对照见[地图](../world/MAPS.md#对照与验证边界)。本文讨论服务端出生、随机消费及单位恢复。

### 工作范围

| 范围 | 本任务处理内容 |
| --- | --- |
| 自然怪物 | 区域候选、难度替换、密度／稀疏、族群／party、冠军／暗金／随从、固定预设、保护区域、实际碰撞和水面等特殊寻位 |
| 自然物件 | ObjGroup概率与顺序、PopulateFn、簇／间距／数量限制、主题、传送点房间规则、祭坛类型及治疗保底、箱锁／陷阱与初始化随机 |
| 关联出生与生命周期 | 箱子怪物、机关控制器、邪恶瓮、任务控制物件及固定怪物出生；房间激活、压缩恢复、地面物品和真实身份分配对后续生成的影响 |
| 必要公共依赖 | 游戏／控制／关卡／房间／单位流，组件池、出生属性／装备、实际占位、帧事件及可靠输出的联合提交 |
| 非本任务扩展 | 佣兵／职业召唤物自身的完整AI、跟随、外观、复活和技能功能；商店／赌博完整经济行为及无关战斗内容由各专题维护，不作为自然生成主线的连续工作 |

佣兵、召唤物及其他消费者只在影响共享游戏流、房间流、组件池、占位或生成事件顺序时核对公共边界。它们自己的单位流多一次投掷，不自动等于自然生成全局错位。此前已做的相关改动保留在对应专题，不回滚，也不计作自然怪物／物件生成完成项；发现专属问题应记入对应专题，不能据此持续扩展本任务。

### 注意事项与验收

- 原参数尽量动态读取当前MPQ，原算法常量与表参数分开；缺资源或证据明确暂缓，不编造地图、怪物参数、物件概率或默认成功结果。
- hosting准备不可变纯值，server持有权威随机与运行状态，gameplay提供纯计算；客户端只读状态并提交命令，不在玩法中读取MPQ、文件、设备或GPU。
- 同时记录随机流所有者、调用位置、上下界、条件和失败分支。固定属性范围、单选范围、空候选等不能一概省略或补一次投掷；原程序决定是否消费。
- 异步准备和输出背压保留当前发生及必要候选；提交复验区域／房间代次、revision、ID游标及共享随机。过期候选不得覆盖新流，也不能静默重掷来伪装恢复。
- 怪物保护区、物件间距和碰撞分别按所属原函数核对，不把“所有生成都避开传送点”当通用规则。中立单位不可替换为敌人；允许的敌怪替身保留真实身份，不认证真实类型行为完成。
- 原有用户及并行改动保留，重构限于本任务所需模块；不回滚此前伙伴改动。存档语义若变化，必须同步格式、校验与[保存边界](../../modules/SAVES.md)，不静默迁移。
- 完成声明应有同版本、相同初始条件及事件序列下的逐随机／生成结果证据，覆盖成功、失败、重试、激活及恢复；管理生成不能代替自然分布证据。未具备对照条件时明确记为未验证，不新增测试脚本、用例或专用程序凑覆盖。
- 验证授权与方法沿[测试指南](../../development/TESTING.md)。本次文档整理不触发构建、游戏、测试或打包；保留“相关实现全部完成后尝试构建和打包”的先后约束。源码核对、编译通过、有限运行与原版一致性分开报告。

## 数据与所有权

Levels的mon／nmon／umon、MonDen、MonUMin／Max，MonStats／MonStats2、MonPreset、SuperUniques、MonPlace和MonUMod决定候选、密度、族群、随从／精英及固定身份。hosting从当前MPQ准备不可变规则、真实spawn key及DS1节点；server/population调度准入，monsters实际安装实体并持有区域组件池与运行态。server不直接读表。

战斗范围、精英准入及限制统一见[第一幕](ACT1.md)与[精英](ELITES.md)。固定表记录不等于当前地图有刷新点，中立单位和不可击杀墙面发射器不混入敌对战斗池。缺规则或无法放置的人口保留暂缓身份，任务清场不能跳过这些单位。

MonStats2.spawnCol决定出生掩码，飞行／Wraith移动掩码不能替代它。原房间Populate、DS1单位／path nodes保留；空间选位、全区域初始化、房间激活与随机消耗仍有项目适配，不能宣称同种子逐单位等价。动态占位由权威服务端处理。

普通难度精英候选按`MONSTERCHOOSE_GetPresetMonsterId`在umon选择后直接返回，不执行PlaceSpawn替换或消耗该替换随机；噩梦／地狱仍走区域稀有度选择及PlaceSpawn。`gameplay/monsters/region_generation`以纯值目录按关卡ID顺序执行NumMon删选、首个RangedSpawn最多20次重抽及组件池投掷。宿主从当前MPQ准备缓存规则，实例与宿主调用同一算法，首次人口准入校验蓝图目录与组件初值。密度机会／稀疏门控使用游戏流，区域选型／精英预算及搜索使用活动房间流，族群、词缀、随从数量和姓名使用实际出生单位流。各阶段保留游标，异步规则准备不重掷、不推进游戏帧；这不代表完整全局初始化交错已经认证。

Levels的mon／nmon／umon现分别读取原25槽，在首个空／未链接MonStats条目处停止，不压缩空洞。Hit39另保留完整mon列表及isSpawn，不借用NumMon选择后的区域人口，也不改读噩梦／地狱的nmon。`nativeLevelSpawnClass`保留先随机索引、再前进一位才检查的顺序；只尝试首个合格类型，放置失败不换类型。

地图准备在房间瓦片完成后，按DRLG_CreateRoomForRoomEx多抽取一次原房间流，再以low／high=666准备独立活动房间种子；后续接缝选瓦片仍使用已前进的原房间流。生成数据只携带不可变初值，运行随机唯一归AreaStore::RoomState，RoomRandomLoan复验区域代次、房间随机revision及期望值。离区卸载清除运行流，重建使旧贷款失效；完整房间重建和原人口／对象对该流的消费顺序尚未迁完。

普通怪物与NPC的出生候选先从全局流创建实际单位种子，再完成组件选择、特殊DoomKnight组件抽样和HP投掷；HP使用单位流。非恶方按一人初始化，恶方人数包含已入场的死亡玩家及当前虚拟人数。组件池候选、Actor、房间登记和全局随机准备完成后一起安装，失败不提前消耗ID或组件池。四种原城镇居民跳过区域组件池。鸟巢／石棺AI的时间起点保留真实准入帧，不延后到首次思考；普通中性敌怪首个AI事件在有客户端可见的相邻房间按出生后2帧安排，无客户端时保留AIdel及非正值15帧回退。客户端换房间先加新相邻房间、再移除旧房间；首位客户端登记重排中性及原特殊家族AI到2帧后，末位离开删除AI／再生事件。拓扑缓存重建保留实际客户端登记，不伪造重入。S1、召唤专用期限及完整全局事件交错尚未闭合。

MonProp从当前MonStats引用、MonProp难度六槽及Properties准备纯值，首个空属性结束。机会0不抽签，非零机会消费单位流；属性函数1／8／17按原范围、首值复用和参数规则消费同一流，固定范围不抽签。普通／NPC及公共召唤属性准入在初始技能后应用独立非扩展列表，保留原物品owner类型；Actor保存已掷列表，属性刷新复用，重新准入才重新掷值。真实类型缓存和允许的敌怪替身回填真实MonProp，不继承替身属性。当前MPQ使用的淡化、速率、压碎、火焰精通、击退、荆棘和致盲已接；其他属性函数明确拒绝，完整属性逐写回调、专用佣兵出生及所有召唤初始化仍未闭合。此段源码未构建运行。

怪物动作开始及逐帧动画推进读取完整原生速率属性，MonProp与装备的攻速／施法速率不再只存在于属性列表；attackrate和other_animrate的原基值100转换成公共速率函数的增量，武器基础速度仍从选中武器投影读取。此处不认证全部模式、双持及召唤组合。

MonEquip的on-init记录由当前表按MonStats.inventory资格、连续类型段、首条oninit、等级门槛和原身体槽位准备。普通准入在MonProp后以PendingContent暂停等待宿主构造真实物品，调度通过公共isDeferred判断内容等待／容量背压；写入准备队列的接口不再声明const。MonEquip、召唤装备及商店共用prepareNativeItem的双种子／品质／生成入口，保留装备与商店各自的孔数和修复策略；选槽、种子、区域组件池和HP抽签由构造与返回校验共用纯算法。真实物品构造规则：选槽消费单位流，单选也抽签；实际物品分配与属性种子消费游戏双流值。返回校验单位／游戏流、物品身份区间、实际选中代码／槽位、等级和属性列表，出生发布才一起提交Actor、装备身份和随机终值。品质降级可合法重置物品nativeSeed，不将其误判为原分配种子不一致。当前血乌的sbw、飞行弯刀的scm均按原品质6构造稀有装备；强制装备绕过需求，不改变原鉴定状态，保留NOSELL和修复耐久。NOSOCKETS保留普通／超强品质的机会抽签但不自然加孔，不拒绝属性提供的孔数；NEVERETH不抽自然无形。近战／飞弹采样同一选中武器属性来源，词缀升级保留该来源。限定暗金按准备时冻结的整局记录生成，装备内及同批后续Actor读取前面已选项，Actor出生复验真实整局基线后登记。物件批次的地面与装备登记先合并再发布，不提前改变自身基线；跨来源生成次序造成的重复选择仍在发布前拒绝，不能认证全部联合生成。特殊物品光环尚不能在此出生通道联合发布时明确暂缓；创建失败副作用、全部装备回调及召唤专用MonEquip仍未闭合，不认证完整装备出生。乌鸦初始化在公共出生属性之后消费实际单位流：普通初始化与公共召唤各调用一次，保留两次投掷，以第二次结果决定环绕方向并缓存，属性重算不重掷。亚马逊召唤MonProp按运行难度准备。敌怪规则移除仅接受固定knock的旧MonProp闸门，统一由出生属性解释器决定支持范围；近战／投射物击退读取实际属性快照，不保留第二份类型布尔缓存。上述源码未构建运行。
