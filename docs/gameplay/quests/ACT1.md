# 第一幕任务

第一幕六项任务的角色进度按难度保存。任务次序为邪恶洞窟、埋骨之地、凯恩的搜寻、遗忘之塔、交易的工具、屠杀的姐妹；玩家仍可提前进入部分区域，进度以实际交谈、交互和击杀事件推进。任务资料始终从运行时 MPQ 读取：`Levels.txt` 决定区域，DS1 与 `Objects.txt` 决定物件，`MonStats.txt`／`SuperUniques.txt` 决定目标身份，`Hireling.txt`、物品表、TBL 和 `a1npc.txt` 决定奖励、图标文字和对话。引擎事件次序参考 `reference/d2moo/source/D2Game/src/QUESTS/ACT1/`。

当前解耦边界：任务身份单独在 `quest/id.hpp`，阶段和旗标仍由权威任务簿拥有；日志 UI 读取 `QuestView`，NPC 菜单／回顾读取 NPC 投影。完成事件在发出时附带该次转换的完成标志，UI 不解释完成阈值。原规则／D2S 位保持，入口及有限实际覆盖见 [NPC／任务基线](../../modules/NPC_QUEST.md)，不视作第一幕全流程验收。

## 代码入口

- `src/gameplay/quest/acts/` 按幕分开规则，QuestModule 登记当前各幕消费者；`src/gameplay/session/session_quests.cpp` 连接 NPC 与死亡事件，凯恩物件、卷轴、恰西灌注和安达利尔结局另分文件。`session_quest_dialogue.cpp` 统一选出任务对白及其可推进的任务；本地适配和交谈命令复用这一选择，其他任务的回顾对白不能遮蔽正在交付的任务。
- `src/content/npc/npc_dialogue.cpp` 从 MPQ 解析任务状态对白；`src/client/local_quest_client.cpp` 准备原日志文字，`src/presentation/hud/quest_panel.cpp` 消费投影与原背景／任务图标，`quest_controller.cpp` 处理手势。Q 或红色 Quest Log 按钮打开，六项任务保持三列两行；选择只切换高亮与下方文字，关闭再打开保留有效选择，有更新时优先选更新项。日志按已解锁幕显示实际任务与页签，第一／二幕各六项、第四幕三项，不由 UI 推算全局编号。插槽与图标分别按原尺寸绘制，外框复用 `panel_frame.cpp`。参考 [OpenDiablo2 的 quest_log.go](https://github.com/OpenDiablo2/OpenDiablo2/blob/master/d2game/d2player/quest_log.go) 和用户原版截图；UI 只读投影。
- `src/persistence/d2s_codec.cpp` 保存三难度任务、各难度 NPC 初见记录、佣兵和奖励点数；格式为原 D2S v96。凯恩致谢及安达利尔死后逐 NPC 反应按 D2MOO 的 GUID 列表语义只保留在本局，不写入角色存档。
- 管道 `quest-status` 读取任务阶段；`quest-panel` 配合 `screenshot` 查看原图面板。所有任务命令仍走正式会话规则。

## 当前核对结果与边界

完成动画核对本地 OpenDiablo2 `quest_log.go::playQuestAnimations/stopPlayedAnimations/Advance`：只有首次由未完成进入当前完成阶段才置待播放状态，普通任务更新不触发。日志隐藏时保留待播放，打开时从第 0 帧开始并选中该任务；按 reference 的 `SetPlayLength(3)` 对整组帧计时，达到第 24 帧停住，不播放进行中 25／未开始 26 帧。播放中关闭日志则结束本次过渡；读档已完成任务、技能重置等重复事件不重播。开始播放时使用当前 MPQ 已确认存在的 `data/global/sfx/cursor/questdone.wav`。完成阶段仍按本项目六项阶段映射（例如邪恶洞窟领取奖励后），不是声称还原全部 D2Client 任务时序。

按钮方块区域由每项 MPQ 的第 25／26 帧像素差异求包围框；原图本身也带拱顶，不能平移整张 72×86 纹理。按住同一任务控件时只在差异区内向左下偏移，底座和金色插槽固定；范围与方向核对用户正常／按下对比图，2 原图像素位移仍是视觉适配，OpenDiablo2 的透明任务点击控件并不提供这个位移算法。鼠标归属与松开激活依据其 `ui_manager.go`。完成序列播放期间不叠加按压裁片。

已在源码修复：石阵误点击不清空已点亮的石头（D2MOO `A1Q4.cpp`）；NPC 对白、自动提示与任务推进共用会话查询。六项内部阶段显式映射原 TBL 键。邪恶洞窟剩余数量包括活怪和待激活人口；进入洞穴后剩 2–5 只用 `qstsa1q14` 加数量，剩 1 只用 `qstsa1q140`，杀光后用 `qstsa1q15`，此时保持进行中图标，回阿卡拉领取技能点后才完成。交还锤子后待灌注用 `qstsa1q32b`。任务图形和外框用 Sky，关闭、金币及重播按钮用 Units；未开始的任务保留暗图标但不能选中。

头顶提示从当前 MPQ 的 `Overlay.txt/npcalert` 读取 DCC、帧数、速率、偏移及透明方式，按 `MonStats2.OverlayHeight` 选高度。当前 NPC 提示直接将原表 `Xoffset=-5` 加到屏幕位置，保留 DCC 自身锚点，不增加按 NPC 名称的硬编码；这是待用户验收的定位适配。OpenDiablo2 的相关偏移实际进入实体坐标再投影，不能作为屏幕像素直接相加的完整依据，见 [资料来源](../../resources/THIRD_PARTY.md)。营地 NPC 共用绘制入口。触发依据为 D2MOO `A1Intro`、`A1Q0` 和各任务 `ActiveFilterCallback`：初见提示仅 Warriv／Akara；任务分配、实际携带任务物品的交付、待领奖与本局未读致谢分别判定。交谈中隐藏提示；没有新的自动对白时，退出商店／字幕不会重新出现菜单。

首次点击直接播放 MPQ 原介绍，按职业选择 Sor/Ama/Bar/Nec/Pal 分支；同次交互有任务消息时播放为第二段独立字幕，而非把两段文字拼在一个滚动窗口中。新角色与阿卡拉交谈先显示首次介绍，关闭后显示邪恶洞窟任务介绍。介绍记录按难度保存。可自动触发的任务对白无需先选 Talk；文字从字幕框底部连续上滚。当前在 NPC 激活、自动对白事件发出时确认任务消息并推进；有首次介绍时，任务段此时仍在队列内，尚未显示。未按逐段显示或声音结束回调确认，本轮不改变任务推进语义。

字幕队列保存每段 NPC 实体、说话者和文字；同次对话逐段推进保留后续队列，显式打开新的介绍／话题／Gossip 或另一个 NPC 的对话会替换旧队列。整次中断共用 `cancelNpcDialogue`，读档、换区、死亡、背包及调试佣兵面板均取消当前段和剩余段，避免旧任务文字出现在另一 NPC 名下。审查修复仅通过编辑器诊断与静态检查，未构建或运行。

NPC 发布任务的可用条件由同一 `assignmentAvailable` 查询提供：按 D2MOO `SeqCallback`，领取洞穴奖励开放卡夏介绍，领取血鸟奖励开放凯恩任务，领取凯恩戒指开放恰西介绍，交还锤子开放安达利尔任务介绍。8 级限制用于锤子的取得／交还，不再代替恰西任务的前置条件。此处是当前单人进度的适配，提前进区或取得任务物品仍可触发对应流程；没有实现多人全局序列状态。
