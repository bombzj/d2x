## 资格、准备与提交

任务状态传播与奖励资格是不同的公共路径。`progressRecipients`按当前任务筛选可推进的本局人物，`shareProgress`冻结玩家／actor并复用已有提交队列；`queueStatus`／`flushStatuses`独立安排原5D状态循环，在指定NPC结束交谈后才向所属幕、满足任务过滤条件的玩家发布。更新个人记录不必立即输出整套28／5D；通知必须由任务回调决定。当前`startQuest`由邪恶洞穴64、血乌81和罗达门特304接取回调共用，不要求组队；尚未领奖且无待领奖资格的同局玩家可获得STARTED，状态通知另限对应幕。死亡／击杀／奖励仍使用下表各任务的原资格，不沿用接取受众。

普通共享进度只提交阶段与指定旗标，技能书待领、奖励对白等里程碑副作用仅在`Goal::primaryGoal`路径执行，不能由接取传播授予。罗达门特接取的共享人物曾错误附带技能书待领位并被D2S校验拒绝，现已在公共队列隔离该副作用；修复后的双方保存及新进程恢复仍待验证。

依据为本地D2MOO的`QUESTS_EventCallback`、`QUESTS_UnitIterate`／`QUESTS_StatusCyclerEx`和A1Q1／A1Q2／A2Q1的ScrollMessage、NpcDeactivate、UpdateQuestStateFlags回调；查西等任务的遍历时机与资格不同，不能按上述三个接取回调推定全部任务已对齐。NPC对白列表变化通过公共NPC刷新路径投影，见[NPC交互](../npc/INTERACTIONS.md)。已核实原版Akara接取对白及关闭后的通知时序，其他任务、已完成／待领奖人物及多难度组合仍有未核实边界。

任务回调成功时冻结直接候选、队伍关系与人物actor；后来入局／组队不追授这一事件。不同任务的候选规则分别实现，不统一套用击杀距离或存活要求；都瑞尔死亡和泰瑞尔开放门是两个独立事件，后者仍可纳入在开放门前抵达巢穴的未完成人物。已完成或已有保存奖励资格的角色不作为新的击杀共享源；尼拉塞克另要求冰之囚已取得奖励资格。

当前同房间／近邻判定调用地图activation布局，近邻由房间边界距离派生；尚未保留原D2Common完整房间邻接身份和跨区域邻接列表，因此边界资格不能宣称逐房间完全一致。管理员生成的怪物不计自然目标；缺失或未准入的人口不能当成已经清场，中立单位不能替换为敌人。

建局角色的已完成／原RewardPending任务关闭本局介绍与新目标资格（原bNoSetState的赫拉迪克法杖除外）；加入者的已保存奖励／通行资格保留。错过本局目标的角色实际拒绝任务接取、奖励和区域自动推进，而不只显示状态12；携带真实马勒斯、黄金鸟、基德宾或古书的原回调例外仍可交付。任务尚未提交但已经冻结的资格不会被投影成无法完成。牛王、囚犯伤亡等特殊事件仍按各幕限制，不将本表等同全部任务共享完成。

内容准备绑定玩家／actor、来源区域及代次、来源GUID、token、库存版本和交谈revision。安装复验入局、存活、区域、等级、实际材料／奖励资格及来源；使用当前人物／库存revision提交。容量不足保留待处理项，提交成功才消费材料／资格和发布结果，不能空发奖励或重复领取。库存版本变动会使旧准备失效；普通人物revision变化仍需按当前语义复验，不能一律取消有效准备。

多人目标按人物事务提交；同一任务可同时排队多个共享阶段，后续对白不会覆盖前一阶段尚未提交的队员。资格绑定actor，连接ID复用不继承旧资格。正常保存退出先归一化交易，并等待本人已接收命令（包括0x58日志已阅）及冻结奖励；TCP/IP房主退出同时等待客人，提交完成才回传存档和05／06／B0。未执行的回执不能被退局直接删除，否则同局Q键不重播而再次加入仍会重播。强制断线后仍保留的actor可继续结算后再导出恢复副本，资格队列本身不写盘，不构成崩溃持久日志。

关闭／重开交谈、换区、死亡或离线使相关未提交准备失效。NPC对白确认仅在领域成功后清除待确认；目的地尚未准备好的NPC任务确认可重开交谈重试原消息，不能把客户端“已发送”当作已发奖。第二幕日志确认有独立的有界等待／固定步重试，见ACT2。NPC旅行允许已接受请求后原客户端关闭交谈，仍复验来源、资格与新交谈身份，见[内核旅行](../../modules/SERVER_SYSTEMS.md#任务与旅行)。

## 原协议与客户端投影

客户端只显示服务端已知的本人资格，不执行任务转换、认定目标、发奖或读取D2S。旧Local任务适配和客户端会话级任务执行器已删除；服务端与客户端不共享隐藏世界真值。

| 方向／消息 | 用途与边界 |
| --- | --- |
| C→S 0x40 | 每局ProtocolReady后一次日志请求 |
| C→S 0x58 | 3字节日志已阅回执，u16为原filter槽0..40；只设置当前人物／难度的UPDATEQUESTLOG（0x1000），重复回执幂等，越界拒绝，不授予任务或奖励。经人物事务提交，由28及D2S原位保留 |
| S→C 0x28／0x29 | 本人私有48项原任务字／本局公共任务字；29来自独立世界标志，入场及目标变化同步，不再复制私人D2S。上局PrimaryGoalDone／CompletedNow按当前1.13c读取规则在slot0..41清除，本局个人目标位只来自冻结资格；旧档待领奖保留CompletedBefore，slot41重置奖励资格保留但旧目标位清除。错过目标的临时CompletedNow只在本局投影 |
| S→C 0x52／0x5D | 入场／40刷新生产52的41个filter槽，任务增量生产5D；50附加进度先于52。5D链编号为nativeSlot减从0起的幕索引，不是面板槽或D2S槽 |
| S→C 0x5E | 原37项介绍／可完成初始化顺序由公共catalog唯一声明；自有客户端按相同映射保留已知可用性，不从未发布的房间状态推断 |
| S→C 0x50 | 原特殊进度：任务号1含洞穴剩余、真墓偏移、囚犯剩余；任务号4为凯恩五柱。不是日志位置 |
| S→C 0x27／0x8A | 对白／NPC提示，0x27保留来源unitType（NPC为1，机关为2）；提示不授权领奖 |
| C→S 0x31／0x38 | 确认实际原stringId／原NPC服务与旅行；请求成功发送不表示任务完成 |
| S→C 0x58、C→S 0x44 | 原NPC加工结果或插杖交互租约、原17字节插杖提交／取消；由对应来源解释 |
| S→C 0x53 | 第二幕日食环境，独立于个人任务字 |

本人原任务事实 → QuestProjectionInput → projectQuestDisplay → QuestView → 共用quest_panel／controller。[catalog.hpp](../../../src/gameplay/quest/catalog.hpp)分别声明内部ID、幕、面板槽、原幕内任务号、图像槽及D2S槽；各幕身份表维护实际映射。第四幕只有三项，不用其他幕的六项布局补槽。

任务药剂、加工和跨幕旅行也从任务领域取得带本局上下文的事实，不用缺少公共标志的裸个人记录覆盖29。自有客户端将私有CompletedNow、状态12及已关闭且无私人奖励资格的5E条目标为无法完成，显示当前MPQ的qstsThankYouComeAgain；条目仍可选中查看原因。旧档待领奖和已完成条目不被公共关闭状态降级。

标题、qstsa／qsta描述、完成文字、newquestlog及原图取当前MPQ。未知细分状态、真墓图案或剩余数保持未知，不从种子、公共字、地图人口或旧单机流程补答案。已完成条目仍可查看，固定显示完成帧24；私人完成记录未设置UPDATEQUESTLOG时才排队动画，包括旧档中完成但尚未看过日志的条目。已阅完成记录不因Q键关闭／重开或任务同步重播；动画按100毫秒帧间隔推进，结束或中途关闭／切幕发送原0x58。首次未知→已知不自行制造任务更新通知，也不吞掉服务端明确发布的未阅完成。私人PrimaryGoalDone未设置的完成条目使用MPQ的qstsprevious，区分本局完成文字。

原版依据：本地D2MOO `PlrMsg::D2GAME_PACKETCALLBACK_Rcv0x58_QuestCompleted_6FC883B0`检查3字节及MAX_QUEST_STATUS，只设置QFLAG_UPDATEQUESTLOG；`D2Constants.h`定义该位为bit12，`D2QuestRecord`读取重置不会清除此位。当前1.13c D2Client.dll（ImageBase `6FAB0000`，SHA256 `DD8BC6025DE921216A97C17F97CD1A50FBB85926E838EC60E13451448836D906`）RVA `1CE00`／`1D56D`按私人bit12选择动画或完成静帧，`1F27A`–`1F367`按100毫秒推进、到帧25设置bit12并发58，`1CA00`在关闭未播完的日志时设置同位并发送58。原D2Common ordinal10174（RVA `2D0F0`）为读取、ordinal10003（RVA `2D0B0`）为设置，不能沿D2MOO旧版ordinal机械定位。两端混合连接及全部任务的完成表现仍需实机核对。

## 核对与后续扩展

先参考master任务纯规则与旧单机执行，再核对当前MPQ及本地D2MOO Quests、D2QuestRecord、各幕回调、ObjMode、SUnitNpc与PlrSave2。D2Common记录解释可共享；D2Game目标认定、世界资格、随机奖励与发奖属于服务端。公共层依据见[参考设计](../../architecture/REFERENCE_DESIGN.md#9-npc怪物任务与物品怎样拆)，来源／许可见[资料来源](../../resources/THIRD_PARTY.md)。

组队修正交叉核对本机1.13c D2Game.dll（ImageBase 6FC20000，SHA256 `24B293B86F95BEA0228826C502EA04737BA21B91CA9832E52AAC4B11FEF14F53`）：召唤者6FCE66B0／6FCE2F10／6FCE2E70、尼拉塞克6FC7B690／6FC77900／6FC77830、马勒斯163分支6FC87000及组队6FC81D40、古代人6FC7EED0、迪亚波罗6FCDC2C0／6FCD9F8F／6FCDA010。D2MOO的召唤者、尼拉塞克、马勒斯存在指向其他任务的交叉引用，不能按函数名机械迁入；上述争议规则以本机1.13c原槽位／分支为依据。

每项扩展需声明个人位／本局位、难度及前置、真实事件身份、材料／奖励事务、保存恢复、原包生产／消费、原版依据和未完成范围。若客户端对原D2GS也缺功能，先核实原协议；有原版依据的修复两端共用，禁止自研专用消息或成功fallback。自研执行结果只在当次交付中说明；队伍、牛王资格与扩展事件的实施顺序归总计划，不在本页另建待办副本。

第二幕多阶段目标、古代人／熔炉／囚犯各分支、已冻结奖励容量背压、强制断线／崩溃、三难度、八人、跨机器与Linux仍缺完整原版对照。完整房间邻接和后三幕剧情／AI缺口按各幕说明保留。
