# 资料片佣兵

佣兵资格、费用、归属、同行、战斗和保存由服务端决定；客户端沿原MCP／D2GS消息显示和操作，不恢复旧本地执行器。当前源码准备第一幕罗格、第二幕沙漠守卫、第三幕铁狼和第五幕野蛮人的真实活动实体；第四幕没有独立佣兵类型。本页维护当前实现、原版依据与缺口，技能归属见[同行者能力](../skills/COMPANIONS.md)。

## 原数据与执行入口

[hireling_content.cpp](../../../src/hosting/hireling_content.cpp)从当前MPQ的Hireling、MonStats／MonStats2、Skills、Missiles、MonSeq、States和AnimData准备身份、难度／等级段、基础成长、技能权重、原动画及装备后的技能和动作速度。技能使用佣兵自身等级、基础技能及佣兵装备贡献；不借用主人技能、精通或装备触发。Battle Command等作用于佣兵自身的临时全技能属性参与准备缓存，生效／到期重算实际技能和被动；刷新保留Battle Orders的生命上限，BO使用装备后基础生命。缺失原数据或程序明确暂缓，不以沉沦魔替代中立佣兵。

[hireling.cpp](../../../src/server/systems/companions/hireling.cpp)负责服务，[hireling_control.cpp](../../../src/server/systems/companions/hireling_control.cpp)负责准备复验、出生、同行、选技和成长。技能动作、弹体、命中与效果分别归skills／missiles／combat／effects，伙伴生命与装备快照归monsters。hosting读取内容；server仅接收纯值规则。替换内容请求带独立token和人物／库存版本，避免与旧佣兵刷新结果串用；雇佣、管理授予和活佣兵入局共用HirelingBirthPublication，准备原生寻位、随机流、装备来源和初始光环。

Fn061按25格以内视线选敌，跟随门槛24、移动主人16、远距归位100；距离使用AiUtil的FullUnitSize逐轴公式，不是10399交互距离。远距跟随按PETAI_PetMove motion1读取主人的20个实际移动位置，最新优先，原PlrModes在平方位移大于45时记录；数据只属当前玩家运行态，不入存档。佣兵专用寻路参数随MoveRequest传给公共nativeUnitPath和原67／68，远距为100、现有近处路径为40，不再套普通怪物的5；原Toward／WallFollow／Straight失败分支见AiThink／MonsterMode，未加接缝扫描或自行传送脱困。WALK／RUN期间保留剩余路径，不在每次AI时钟重启追赶；速度按原基础75及PETAI的60／15修正，装备／状态贡献独立叠加。

普通动态路径在权威和RemoteScene共用16.16 NativePathStep、25Hz方向和实际进入格碰撞，点目标消费最后精确折点，不额外使用浮点停止半径。佣兵步行跨同幕相连区域时按原PATH_RecacheRoomAtCoordIfNeeded转换实际房间归属和区域原点，保留精确位置及剩余路径；距离计算先转换全局坐标，不能比较两区域局部坐标。自然跨界不等于传送；主人真实Teleport、非步行连通旅行及原超100格归位仍走既有同行归位处理。多人敌对关系沿共享Participants，不由UI选敌。

完整Fn061仍有明确边界：近处motion0的DRLGLOGIC坐标列表索引和7个有序偏移点尚未接入，现有近处单位靠近策略仅把真实到达门槛同步为PATH_SetStepNum；非玩家特殊技能运动、动态单位占位及原PetMove归位坐标搜索尚未完整复刻，不把本次桥头修订称为全部佣兵AI与原版相同。

武器伤害使用自身武器／STR或DEX、目标类型增伤和六通道；承伤使用自身防御、格挡、四抗、物理／魔法抗性、减伤／吸收以及状态。装备IAS／FCR／FHR／FBR、技能加成、生命、移动、吸血、压碎、撕裂、冻结／击退和生命击杀恢复已有消费者。佣兵吸血不套玩家难度吸取除数，目标Drain和抗性仍有效；首领伤害比例取DifficultyLevels。撕裂／毒伤保留实际来源和主人归功，佣兵独立击杀按自身经验份额。基础固定点回复叠加装备hpregen；毒／撕裂抑制自然回复，营地毒伤保留一点生命。装备触发技能及装备自带光环仍受公共物品消费者限制，与master相同，不由天然光环入口推定全符文之语支持。

名单使用当前Hireling普通难度首条雇主记录的原TBL名字范围；逐名字消费一次NPCControl种子，零seed合法，再按十次随机起点及环形扫描标记可用候选。普通雇用只改变槽位，全体可用候选耗尽才重建并增加名单代次；异步安装与雇用复验代次／名字／seed，其他玩家雇走某项不使其余项全部失效。成功雇用同笔通知剩余候选；奖励准备捕获共享名单首个可用项，成功后标记同一槽位。耗尽重建在人物事务前准备，事务接受后只交换名单及控制流；首次阿席拉商店在货架抽签后准备名单，与库存通知共同发布。旧内容层独立名单抽签已删除，诊断hirelingRosters可读原始槽位。NPC服务完整初始化时点、奖励消息和完整多人交错仍未闭合。

主人开始DT时不立即杀佣兵；MPQ死亡动画ready时间到达后ownerDied同笔提交死亡记录，进入佣兵自身DT。回城复活和死亡保存等待这一事务完成，背压可延后不可提前。佣兵自身死亡停技能／通道／光环、清恢复状态，本局保留原尸体；复活不再删除后重新出生，按原入口关闭freeze／shatter／recycled状态位，不等同于药剂移除冷状态列表。原复活直接归位主人坐标、完整消息和事件次序仍未闭合。

实际怪物出生种子与名册seed分开：名册seed供Hireling身份／属性规则使用，实际单位种子从游戏流分配，并随人物事务复验和发布。组件复用所属区域的原组件池及十三类型上限，随后按普通难度MonStats等级／生命表保留基础HP投掷，再安装佣兵属性；当前零基础生命也保留单选消费。绑定后按原sub_6FC61270清零组件0／1／5／6／7，不退还之前的随机消费。出生前复验准备结果的佣兵记录、难度、玩家Actor和装备修订。

普通雇用按当前NPC及玩家中心各4顺序搜索；管理授予和活佣兵入局按玩家中心4／6／12搜索，共用原房间出生搜索及碰撞。新雇佣内容准备完成前保留旧记录与实体；成功后联合发布房间／游戏流、新Actor、旧Actor退役、装备删除、人物扣款及成功事实，随后占用名单槽位。无落点时失败事实15与全部搜索房间流一起发布，不扣款、不删除旧佣兵及装备、不占用名单；输出背压不产生部分提交，重试重新准备并复验当前候选。跨区、离局、人物或库存版本过期取消待替换请求。任务奖励仍先提交奖励记录后由公共出生恢复，不据正常雇佣的联合事务认证奖励消息次序。读档无房间构造、NPC完整初始化及首次AI事件仍有缺口，不认证完整佣兵出生。

原D2S v96保存type、名字偏移、seed、经验、死亡位和jf装备，等级按原经验曲线恢复；当前生命没有原字段，活佣兵入局按装备后满生命恢复，死佣兵不生成活动实体。临时AI、位置、光环、装甲、恢复队列和候选不入盘；存档校验及拒绝边界唯一维护于[存档](../../modules/SAVES.md)。
