# 地图物件与交互

PD2专项内容：[城镇服务](../../pd2/TOWN_CLIENT.md)。本页保留原版／公共规则及必要的版本边界。

Objects／ObjGroup／Levels／Shrines及原DS1、COF／DCC提供身份、尺寸、模式／动画、名称、AutoMap及灯光。静态地形物件与原服可交互GUID分开；操作、开门、井水、神坛、宝箱锁／陷阱、掉落和任务效果由所连接的服务端执行；自研实际范围见下文，不把原服支持当作自研已实现。

## 碰撞与靠近

共同Grid保留DT1地形层及独立对象层，按真实SizeX／Y、HasCollision0–7、BlocksLight0–7、BlockMissile等模式字段更新；不按画面石头类别猜阻挡，不覆盖重叠物体／原墙。已核实的静默ENDANIM衔接也更新对象层，后续原服模式仍优先。

交互几何核对D2MOO UNITS_IsObjectInInteractRange／D2Common_10399：原整数子格、对象矩形及外侧条带，OperateRange不当中心圆半径。接近点查询完整行走体积与原射线；范围预览不能证明原服操作成功。

自研服务端的原02／04物件靠近按当前objects运行态GUID查找目标，不再查AreaDefinition预设列表；随机生成和休眠恢复后的木桶使用实际位置、尺寸及对象交互几何，保留每轴50子格的请求边界。行进期间复验目标，撤出或离开可达区域时取消旧路线。02／04只负责靠近，原13才请求操作；13距离不足时由objects绑定人物意图继续靠近，到达后复验并操作，木桶再经skills触发隐藏Kick。依据PlrMsg::Rcv0x02／Rcv0x04／sub_6FC828D0、PlrModes::sub_6FC7F780及ObjMode::OperateFunction05；当前修改仅作源码核对，远距离点击与逐帧衔接仍待运行对照。

客户端02／04不设置movementRequest.interaction；物件路径仍按实际范围／碰撞停步，RemoteControl到达后提交13，只有该操作请求才进入本人木桶KK预测。type2靠近若标成操作，会在远处提前预测KK并以施放衔接中止本地路径。原1.13c D2Client（MD5 `f5860c629d309b8fc1f96174babcf633`）RVA29E80／2AE30先核对物件范围及0x804交互碰撞，2AA40发送02／04并登记待交互；2B090复验后续行。2AC10的type2分支在2ACB3查隐藏技能1，2AD83尝试本地动作，2AD96才构造13。该依据区分靠近与操作，不代表当前所有物件动作及逐帧表现已认证。

## 原服适配

蓝色回城门按当前Objects.Selectable模式及已收到目的地区域开放交互。ObjMode15在服务端检查主人、队伍及任务资格；不能因为创建时中立模式留下的TARGETABLE清位而隐藏已经打开的门。此例外仅用于OperateFn15、原class59和mode1／2且目的地已知的蓝门，不放宽其他物件的目标资格。依据D2MOO `OBJECTS_InitObject`初始Selectable检查及`D2GAME_CreatePortalObject_6FD13DF0`／`OBJECTS_OperateFunction15_Portal`。

RemoteTown从真实物件／目标和原Selectable／TARGETABLE投影资格；SceneController提交靠近／0x13。神坛InteractType结合Shrines.Code与TBL ShrId显示真实名称，不本地授予效果。开箱状态取0x0E，掉落取真实物品通知，传送点取0x63及原服旅行位置；0x77属于玩家交易，不能当开箱回执。

传送点OperateFn23在mode1／2保留点击例外，启动后衔接ON动画／灯光，详见[联网实现](../../modules/NETWORK.md#本批源码修正)；共用模式投影也更新原MPQ对象碰撞，不改副本模式或解锁。

祭坛表现源码补回公共绘制迁移时漏掉的未领取类型图／闪光层及物件COF阴影。真实Objects.SubClass／OperateFn识别祭坛，原服0x51的InteractType经既有shrineStateName映射到当前MPQ States.overlay1／2和Overlay DCC；只在原服mode0显示，mode1开始后移除，角色增益图仍只读原服状态。物件Overlay使用原静态落点及Height1，角色用Height2，secondary层先入队，两层各自按PreDraw排序；不使用物件X／Yoffset移动Overlay。

OperateFn2的非循环OP按D2MOO OBJECTS_OperateFunction02_Shrine所安排的(FrameCnt1+1)/25秒衔接ON，模式动画、Start／帧数及灯光继续读当前MPQ；显示模式与对象碰撞分别投影，不写回原服副本或授予效果。资源解码／COF合成沿用公共实现。另据ObjMode／SCmd解释0x4D物件操作通知：其技能字段实际是操作者GUID，等级字段是祭坛类型；只对玩家／怪物生成施法动作，不清除物件0x0E模式或生成伪施法效果。原服state137及生命祭坛模式／回复参考见[联网](../../modules/NETWORK.md#原服物件与交易观察)；精确Overlay节拍及全部祭坛表现仍待原版对照。

### 自然生成源码边界

自然生成专项的整体目标、当前进度、后续顺序与注意事项集中见[自然生成工作总览](../monsters/POPULATION.md#自然生成工作总览)；本节只维护物件算法和实际限制。主线包括自然箱子／陷阱／祭坛及必要任务物件，不扩展为佣兵或职业召唤物自身功能完善。

`hosting/object_content.cpp`准备ObjGroup／Objects纯值，服务端路径不再调用旧第一幕撒点；`server/systems/objects/population.cpp`使用活动房间随机贷款、ObjectControl候选与同步碰撞，已核对PopulateFn1–9、治疗保底及原主题分派。完整休眠、GUID、初始化交错及全变体仍未闭合。旧`world/object_population.cpp`仍是世界工具的适配路径，不代表服务端原随机顺序。

实例按怪物区域、ObjectControl、NPCControl、QuestControl顺序分出子流，再创建玩家。石柱顺序及日蚀延迟使用任务控制流；NPCControl的佣兵名单和库存消费见[佣兵](../characters/HIRELINGS.md)与[经济](../items/ECONOMY.md)，不代表全局交错完成。物件准入不再按GUID派生种子，而按SUNIT_InitSeed取游戏子流。Init1/2/3/27/34/57/58使用准入候选，金币／灵魂辅助初始化完成后才执行PreOperate及特殊覆盖；宝箱重置后的单位种子供掉落使用。Init8火把固定OPENED，Init14／26火盆固定OPERATING；Init11在OPERATING时安装ENDANIM，Init12中性转OPERATING并安装ENDANIM。特殊箱资格／模式及574–579覆盖位于普通初始化之后，后者用单位流；塔楼特殊箱整体覆盖陷阱3并清锁。宿主只提供有序Shrines目录。原分派空槽保持空操作，但有实际回调的任务控制点、失败分支和初始化交错仍未闭合，未覆盖的分支不能按无操作认证。

当前源码按D2MOO Objects／ObjRgn及本地1.13c核对：传送点房间依据原房间waypoint标记及实际WP预设跳过随机物件；空组槽仍抽概率；组内保留Gore门控；公共物件使用SizeX/Y加六和完整16位碰撞，CreateObject全局坐标保留uint16截断。祭坛按Orientation寻位，井尺寸为两倍加一；成功坐标和数量上限独立登记。治疗保底替换类别及其实际ObjectTxt规则／尺寸，再选择治疗效果，保留既有随机与时钟，不重新初始化。Fn1保留各类别簇／步长，Fn4首桶1/3、后续1/4及最多八只，Fn5保留双重瓮类别抽签与后续成员八只上限，Fn7保留四组坐标；间距读XSpace/YSpace。Fn6只按末次返回值抽class103，Fn9首个成功后停止。未知非零PopulateFn记录到服务端诊断并返回NotImplemented，不发布房间完成状态。

服务端内容准备与客户端加载完成是两个边界。`NativeRealmHost::advance`先安装准备好的地形／权威区域，`travel::System::step`取得真实落点房间、复验碰撞并提交旅行，之后hosting才发布跨幕05／03、房间07和位置15；03是加载目标幕及种子的通知，04才是服务端加载完成。D2MOO `GAME/Level.cpp::LEVEL_ChangeAct`同样先LoadAct、FindActSpawnLocationEx及FreeCoordinates，再05／03；`GAME/Game.cpp::D2GAME_UpdateAllClients_6FC389C0`另以`D2Common_10073`等待当前房间的活动近邻列表完整且每个近邻已置人口初始化位，才发送04，房间休眠恢复也在客户端更新之前执行。

初次入局与跨幕共用`publishLoadComplete`：world核对当前客户端归属及完整原近邻列表已物化，population按本次活动房间creationOrder确认预设／随机人口和休眠恢复已完成，常规房间／单位发布之后才发送一次04。已安装／可见的近邻子集不能冒充完整列表，上一轮房间的人口阶段也不能使本次恢复提前完成；不等待整幕／整区或无关内容队列清空。03的物件种子保存自该局ObjectControl初始化时的low值，初次／晚加入／跨幕一致，不以变化后的控制流或固定0代替，也不为发包另掷随机。客户端将04放入有序地图事件流，处理前序07／定位并确认本人房间已加载后才开放本地地图操作；协议已收04与本地资源已就绪分别检查。原1.13c的双端定点依据见[资料来源](../../resources/THIRD_PARTY.md#原版113c静态与开发对照证据)。客户端地图资源耗时不包含在服务端准备计时内。

客户端只补原版启动通知的等待处理：中性传送点收到0x0E/mode1后结束激活等待，下一次点击才能正常请求菜单；若多人先后点击引起随后0x63到达，只在同一交互代次接受该真实菜单。关闭、移动、换区等代次失效后不重新打开。两种服务端共用此处理，没有自研协议或自行解锁。

物件入场和进入视野统一由publishObjects使用权威初始化后的模式指派；nativeAreaWarps仅指派warp，不再从AreaMetadata发模式0的第二份物件。这样城镇InitFn17／mode2会以真实51模式首次送达，野外中性WP及开门／箱子／神坛也使用同一物件状态出口。旧WP模式1→2的ENDANIM仍静默衔接，不能用额外默认点亮补包掩盖入场基线错误。

城镇传送点按D2MOO ObjRgn::OBJECTS_InitFunction17_Waypoint的OBJMODE_OPENED初始化值指派，不能先发虚构中性基线再只补mode1。个人解锁位、菜单和旅行资格独立处理。新房间中立物件首次入场即使没有模式变化也刷新权威碰撞；原SUNIT_Add／SUNIT_Restore按HasCollision[当前模式]建立占位，避免只有客户端保留障碍。

依据：D2Game ObjMode::OperateFunction23／WAYPOINT、ObjRgn::InitFunction17、PlrMsg::Rcv0x49、SUnitNpc::WARRIV1；D2Common D2Waypoints、DrlgDrlgWarp::GetWaypointRoomExFromLevel、D2Dungeon::FindActSpawnLocationEx及D2Collision::GetFreeCoordinatesImpl。当前MPQ为39个传送点及16种OperateFn23物件；容量112是原布局，不代表新增传送点或解锁后续幕任务。

尚有前置依赖：PvP敌意变更后的10秒禁用规则需要真实敌意时钟；五幕个人任务的城镇解锁已随旅行事务接入，完整组队／特殊旅行边界仍待补。原WAYPOINT到达分支额外发送0x0D/action1、坐标+3的短动作通知，当前仍使用既有TravelFact／0x15位置同步；需先核实原客户端该动作的坐标／路径消费，不能直接追加一个会被当前客户端解释为新权威位置的包。精细房间生命周期与动态拥挤亦未完成一致性认证，不能据本轮源码核对宣称全路径与原服完全相同。调试观察入口见[调试管道](../../development/DEBUG_PIPE.md)。

## 限制与证据

宝箱上锁／钥匙、特殊箱掉落／陷阱、全部神坛效果、特殊任务物件及五幕全部变体未逐项对齐。隐藏控制器、怪物陷阱和火焰物件使用真实原身份，不把中立控制物件替换成敌人。0x51不带原服sparklyChest标志，未核实的独立闪光层暂缓；原箱本体／特殊箱音仍沿当前MPQ。旧session的直接grant-shrine／宝箱生成入口已删除；当前同名管理命令只向自研objects准入真实物件，效果须原0x13操作触发。保留world/chest与content掉落资料供内容准备，不作为客户端结算器。

本地D2MOO Objects／ObjMode／ObjRgn、ItemMode、Items、D2Collision及当前MPQ核对原语义。有限法力神坛、门／传送点／门户观察见[联网记录](../../modules/NETWORK.md#既有有限证据)，地形与生成限制见[地图](MAPS.md)。

## 原服手动观察方法

原服祭坛模式、状态与回复参考见[联网](../../modules/NETWORK.md#原服物件与交易观察)。以下为用户授权运行后的观察方法；不作为已执行记录。

1. 从运行包Play.cmd启动，正常登录建房。先单客户端检查普通箱子、棺材、尸体／石堆、木桶、罐子：左键点击，观察靠近、动作、打开／碎裂及原服实际掉落。停留一秒再观察本体，避免只看中间帧；应保留原打开图或残骸，不持续播放破碎动画。破坏后能否走过按该物件MPQ规则判断，不能要求所有箱子都可穿过。
2. 普通木桶观察原踢击及破碎；爆炸木桶观察爆炸、附近连锁和真实生命变化。上锁箱子使用女巫分别在没有钥匙／带钥匙时操作，观察Locked Chest名称、缺钥匙提示、钥匙消耗及实际打开；刺客有原免钥匙规则，不适合作此观察。
3. 陷阱按正常地图遇到的实例观察：箱子随机飞箭／火焰／毒云／新星、周期地刺或喷火雕像。注意触发声音、弹体出现位置、毒云烟团及原服伤害；随机箱子不保证每次触发或包含每类陷阱，不修改掉落概率来凑样本。
4. 后续区域遇到护甲架、武器架、书架、丛林藏物、受困灵魂及邪恶瓮时，检查真实打开图、灵魂两种结果、声音和原服掉落／生成怪物。原版截图对照应尽量使用同类物件，区域、名称及操作前后画面一起保留。
5. 需要检查同步时，第二实例使用另一个账号加入同房，建房关闭等级差限制（SkillTestSor与NetCombatSor等级不同）。两人来到同一区域且靠近同一物件，一端操作，另一端观察模式／残骸与掉落；离开视野再回来，已打开物件不应重放旧交互。原版客户端与D2X不要同时登录同一账号，否则会互相断开。

出现问题时记录区域、物件名称、操作者／观察者及操作前后截图；声音问题可补简短录屏。独立闪光宝箱层仍暂缓；玩家连锁闪电范围由技能专题维护，环境陷阱93后继跳转虽已接，也未逐项运行认证。
