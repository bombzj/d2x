# D2GS 全面联机开发计划

更新：2026-10-06。本文是联机功能的唯一总计划，替代原“保留离线后端”的接入路线。当前事实以[项目基线](../../BASELINE.md)、[联网模块](../modules/NETWORK.md)及源码为准；下述目标和完成条件不代表已经实现。现已开始 M0 源码改造，并接入 M1 的持续网络服务／诊断与快捷入局；本批按最新授权完成 Windows Release 构建、打包及有限原服冒烟；阶段边界及未验项如下，完整 M1–M12 仍未完成。

## 产品目标与范围

D2X 改为面向既有 PvPGN／D2CS／D2GS 的完整资料片客户端。**放弃单机兼容，所有 UI、输入、世界显示和持久化流程都围绕联机服务。遇到旧单机接口、状态模型或依赖冲突，直接改造或删除，不以保住单机作为限制。** 继续利用已有原生地图、MPQ 解码和原图界面，不另建一套联网 UI。

目标链路为 D2X → PvPGN 账号／频道 → D2CS Realm／角色／房间 → D2GS 游戏；角色持久化由 D2GS 与 D2DBS 完成。客户端不直接访问 D2DBS，不上传本地 D2S，不自行启动 GameSession 来补齐服务端规则。本机参考服也是正常联机部署，不是客户端内置的单机后端。

目标版本以当前 1.13c 原安装、`assets/mpq2` 五个原始 MPQ 和参考服实际协议为基准。覆盖五幕、三难度、七职业、普通／专家角色、非 Ladder／Ladder、完整 PvE 与多人协作／交易／PvP，以及对应局前和局内 UI。Ladder 当前是已知服务阻塞，列入实施范围，不能永久藏在“后续可选项”中。服务未开启的事件按能力明确标识，不伪造结果。

不扩展为自研 D2GS、TCP/IP 房主、开放角色本地上传、经典非资料片、D2R、任意 MOD 或所有补丁通用客户端。官方 Battle.net 特有认证／Warden 不属于已验证的 PvPGN 兼容承诺；遇到要求明确拒绝并说明，不能宣称支持或绕过。与目标服兼容的新配置须先核实协议和数据，不能用宽松认证掩盖版本差异。

### 不可退让的边界

- **普通操作没有暂停模式。** 仅显式开启的测试管道保留 `pause/resume`：冻结客户端表现和界面输入，网络／权威副本／原服继续；恢复时采用最新状态，不能单步或暂停原服。ESC 仅关闭当前面板或显示菜单；死亡时保留原服回城／专家退局流程。菜单、选项、帮助、背包、箱子、方块、商店、赌博、玩家交易、任务、佣兵、对话、聊天输入、加载、失焦和最小化都不能暂停收发、心跳、回包归并或客户端世界时间。UI 可接管输入、取消尚未发送的持续意图，不能冻结服务器状态或动画来模拟暂停。
- 服务端拥有位置与运动结果、资源、伤害、AI、技能结果、物品、金币、任务、佣兵／宠物、死亡、尸体、组队和保存。客户端只发送原生请求、消费可见状态、生成显示效果；任何预测仅限画面，不能修改权威副本。
- UI 只读值视图并提交意图；协议层不读取 MPQ、GPU 或窗口；内容适配层读当前 MPQ 并输出只读定义，纯导航和表现逻辑使用这些定义。不得让界面直接修改远端副本或调用旧本地结算。
- 原图、表、名称、布局、动画和物品属性编码优先从当前 MPQ 动态取得。协议编号、版本结构及已证实算法可以进入代码，游戏参数不能照抄参考表或示例硬编码。
- 缺资源／协议证据的功能明确标为待核实并保持未完成。唯一允许的类型替身是未实现的敌对怪物使用沉沦魔，保留真实身份、GUID、阵营、尺寸及服务端行为；中立 NPC、友军、佣兵／宠物不得冒充敌人。替身不算该类型表现完成。
- 保留 C++20／CMake 的 Windows、Linux 路径。Win32 仅留窗口、凭据、网络或调试等平台适配，不能进入世界、规则或编码模型。
- 保留原始 MPQ、旧压缩包、已有用户存档和 `mvp/`；不提交资源、reference、服务二进制、缓存、截图或角色资料。取消单机兼容不意味着删除用户文件。

当前源码的直接改造点与剩余边界：

- `app/application.cpp` 仅装载 MPQ／平台／渲染目标并进入 `runOnlineFrontend`；`options.*` 不再包含本地角色、人口、地图种子或读写档参数；启动脚本也不再自动构建或传入这些参数。
- `network/realm_session.cpp` 的独立 worker 串行维护传输和副本；公共请求持锁提交，`tick()` 发布客户端快照；后台收包不会改写 UI 正在借用的容器。长加载不再通过 MPQ 回调重入会话。
- `ViewState::capturesWorldInput()` 与 `blocksInput()` 仅表达输入／命中屏蔽；`advanceUi` 不接受 `worldPaused`，普通菜单不调用 `pauseEmitters`。测试暂停只存在前端管道标志，不能冻结原服。
- `SceneView::advance` 等仍查询 `localSession()`；CMake 中表现库仍私有链接 `d2x_session`。应用已移除本地角色前端、调试结算源文件及直接 `d2x_local_client`／`d2x_persistence` 依赖，剩余表现调用链须在 M12 收尾。
- `remote_ui_clients.cpp` 明确拒绝赌博和若干 NPC 服务；`remote_combat.cpp` 与模型仍有限制目标／技能来源。完整联机必须补协议和视图，而不是调用单机代码绕过限制。

### 里程碑与依赖

按用户当前优先级，先收口自己能玩的入局、鼠标走跑／靠近交互、基础施法／拾取与保存重入；聊天、组队等 M4 新功能暂缓。自己游玩的后续批次已接神坛身份／可交互标志、技能快捷键原服保存恢复、原生任务日志和鉴定准备流程；UI鉴定装备、快捷键重入和任务接取／STARTED重入有限验证，完整M3／M5／M6／M7仍未完成。先完成 M0–M3，获得不暂停、能稳定入局／移动的客户端底座；随后按表顺序交付完整调用链。依赖表示所需接口，不能只完成底层就越过同阶段的 UI。没有人力和实际剩余证据前不承诺固定工期。

## 目标架构与状态边界

```text
窗口／输入 → SceneController／局前界面 → 类型化意图
                                            ↓
                            RemoteControl／Inventory／Combat／其他领域协调器
                                            ↓
                         RealmSession → SID／MCP／D2GS → 原服
                                            ↓
                         有序协议事件 → 远端权威副本 → 只读 UI／场景视图
当前 MPQ → 内容／图像／音频目录 → 地图重建、导航、显示预测、SceneView
```

沿用已有 `contracts/online*.hpp`、`client/remote_world.*`、`remote_town.*`、`remote_control.*`、`remote_inventory.*`、`remote_combat.*`、`remote_ui_clients.*` 和 `presentation/remote/remote_scene.*`；新增组队、聊天、交易等接口时按领域拆分，避免把所有状态继续堆进 frontend 或 RemoteTown。现有 IActor／IInventory／ICharacter／INpc／IQuest／IMap 可直接改为适合异步联机的接口，不要求 Local 实现继续编译通过。

需要严格区分四类状态：

| 状态 | 所有者与规则 |
| --- | --- |
| 原服副本 | 网络消费层拥有；仅由已核实回包改变；使用连接／游戏代次、单位 type＋GUID、物品 revision 等防串局 |
| 本地静态数据与地图 | MPQ 内容层／地图缓存拥有；按服提供的种子和有序房间事件重建；不生成权威怪物、物品或任务 |
| 显示状态 | 动画、插值、临时施放效果、光照和音频拥有独立生命周期；不能写回生命、坐标或物品副本 |
| UI／偏好／请求 | 面板、键位、已发送请求及等待状态；收不到确认显示未知／超时，不能先展示结算成功 |

本人私有数据、其他玩家公开数据、尚未分配单位的数据分别处理；未知、已知零值、已删除不能混为同一值。玩家离开视野不等于退局，房间卸载不等于尸体归属消失。场景渲染借用值快照，资源回调不能在容器遍历期间重入修改副本。

请求状态按原协议能力区分排队、已发送、观察到结果、被拒绝、超时结果未知、中断。原协议没有通用 ACK 或客户端事务号，不能自造线上序号和成功回执；本地 sequence 仅作日志及关联。合成、买卖、交易、加点、领奖等非幂等请求在超时／断线后不盲目重发。
