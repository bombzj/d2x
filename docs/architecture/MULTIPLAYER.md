## 实现约束与代码落点

- network 按 SID／MCP／D2GS 独立 framing 和有限缓冲；未知长度拒绝，已核实长度的非关键消息才可保留或跳过，不改原服协议。
- contracts 增加只读远端值、字段可用性与异步状态；client/remote_world 归并包，remote_town 单独绑定 MPQ，RemoteScene 读远端状态并发移动／退出意图。原 SceneController／SceneView 仍服务离线，不复用本地模拟。
- world 复用 DS1／DT1 解码和 MPQ 原目录，地图重建单设入口，不借用本地怪物／任务世界；secondarySeed 不能凭 1.10f 注释认证 1.13c 语义。
- presentation 映射原动作／帧／方向／装备／技能效果，不用本地伤害或 AI 替代回包。先初始化、房间、实体和位置，再扩展物品 0x9C／0x9D 位流。
- 库存预览／NPC 报价只检查已知布局，回包驱动成功；断线停止消费，不回放扣金／领奖。重连取新票、新代次，清理副本和临时地图，不调用离线 restore。
- 未匹配地图明确暂缓，不画近似地图冒充互通；原 DLL 地图辅助器增加平台依赖，仅另行授权后采用。

本地 D2MOO 为 1.10f 的包／DRLG／服务端语义线索，OpenD2 的 TCP/IP 本地 D2S 上传不能照搬封闭 Realm；OpenDiablo2 自身 JSON 协议仅作架构参考。固定版本与许可见 [资料来源](../resources/THIRD_PARTY.md)。目标边界须核对实际 1.13c 原文件，不照搬参考的职业／CheckRevision 常量。

验收使用现有游戏、command、原客户端和参考服，不编写测试程序；按约定仅用户要求时构建／运行／打包。Linux、严格 key 模式、完整包覆盖与长期稳定性未验证。

## 本机部署与验证入口

运行目录为 `D:\Projects\d2x\artifacts\d2gs-local`，下载包、上游源码、局部补丁、二进制、配置和日志均在忽略目录；服务部署阶段没有改动 D2X 游戏代码，未安装 Windows 服务或添加防火墙规则。当前网络底层已接入应用并通过本机有限冒烟，范围见模块基线。

| 组件 | 本机实际采用 |
| --- | --- |
| 账号／Realm／保存 | [PvPGN 1.99.7.2.1 PRO plain 发行包](https://github.com/pvpgn/pvpgn-server/releases/tag/1.99.7.2.1)，文件存储，无外部数据库 |
| D2GS 宿主／引擎 | RElesgoe `3f09bd9`，VS2022 Win32 Debug 编译＋Windows 8 兼容层；引擎使用该仓库的 `lib/d2gelib/d2server.dll` |
| 原版依赖 | 从用户提供的 `D:\Downloads\Diablo II V1.13C` 复制 DLL 与服务所需 MPQ，原安装文件保留；所有 DLL 与 Magic Builder 1.13c 依赖 MD5 匹配。Patch_D2 摘要与其下载清单不同，但与本项目当前 MPQ 相同，引擎已成功加载 |
| 本地适配 | 宿主配置改读 `HKCU\Software\D2X\D2GSReference`；修正上游 Realm 名称读取指针；使用 32 位 `time_t`；管理端口仅绑定回环。差异保存于 `relesgoe-local.patch` |
| 入口 | 账号 `127.0.0.1:6112`，Realm `D2X-Local`／`127.0.0.1:6113`，保存 `127.0.0.1:6114`；D2GS 游戏端口 `4000` 默认监听全部 IPv4，管理端口 `127.0.0.1:8888` |

已记录：引擎完成 MPQ、语言、游戏表、监听与回调初始化，进入消息循环；D2CS 认证 D2GS 并接受 8 个游戏槽位；D2DBS 接受游戏服连接，双方持续心跳。一次正常关闭触发引擎保存收尾；重启过程中曾出现引擎初始化异常退出，再次启动成功，见 `d2gs/D2-261005.txt`，尚未确认原因或启动稳定性。

原版客户端连接使用 `Play-D2GS.bat`，实际调用 `Play-client.ps1`：客户端从用户原有 `D:\Downloads\Diablo II V1.13C.rar` 独立解压到 `client-1.13c/`，启动前检查 `Game.exe` 为 1.0.13.60。入口启动／复用本机组件，备份当前用户的 Diablo II 网关列表与 `BNETIP`，临时将列表设为仅含 `D2X-Local`／`127.0.0.1`，打开窗口模式主菜单；用户手动点击 Battle.net。正常退出后恢复原网关，启动窗口须保持打开；窗口异常关闭时，先退出全部客户端，再运行 `Restore-client-gateway.cmd` 恢复。当前入口要求先关闭其他原版客户端，第二客户端验收入口仍待准备。设置方式依据 [PvPGN 网关安装器](https://github.com/pvpgn/battle.net-gateway-installer/blob/master/install%20gateway.bat)。

原客户端须使用真实网关注册，不能只依赖 `-bn` 参数；旧入口曾连向官方服并自动更新，已修正并由用户确认。当前配置含 D2XP_113C／IX86ver1.mpq，未启用 Diablo II 自动更新；仍允许未知／不匹配版本，不能据认证成功声称严格校验已通过。首轮只验证回环；跨机器需配置客户端可达的 Realm／游戏服地址。

`Start.cmd` 单独启动／复用本目录组件，`Stop.cmd` 先通知 D2GS 保存关闭再结束配套进程，关闭前先让客户端退局并注销。管理凭据只保存在本机忽略目录。运行包 SHA256 及配置差异随本地材料保留。

用户已确认注册账号、创建角色和进入游戏成功；`d2gs.log` 记录资料片／普通难度／softcore／non-ladder 入局、正常离开与 D2DBS 保存成功回执。本机选择 Ladder 会显示 server down，原因尚未确认；原客户端验收须取消 Ladder，D2X 首期只选择非 Ladder 角色、创建非 Ladder 游戏，不开放 Ladder 入口。

剩余验收：联网战斗／拾取并记录金币或物品 → 保存退出 → 用同角色重新入局核对；原客户端双人互通和服务长期稳定性亦待验收。D2X 已有双账号营地互见／移动、退局与新进程角色重入证据；营地移动未改变持久角色字段，不能替代实际玩法变化重入结果。

此宿主含上游 build 03 的规则修正和 World Event 配置，不能宣称与纯原版规则完全一致；当前用于建立网络互通环境。原客户端账号／建角／非 Ladder 入局已验证；D2X 已完成双账号营地入局、移动及角色重入有限冒烟，完整联机玩法仍未接入。
