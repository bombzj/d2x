# 客户端导航结构

本页维护客户端导航所有权、规划入口及限制。策略与命令见[调试AI](../development/DEBUG_AI.md)，验证约定见[测试指南](../development/TESTING.md)。

## 坐标与知识

客户端DynamicPath暴露的是减去半格后的世界脚点。`DebugExplorationMemory::playerCell`调用公共`nativeFeetCell`，统一以`floor(position + 0.5)`还原原生整数脚格，供规划起点、观察路线缓存键、父子抵达判定、传送起点邻域及AI输入坐标使用；不能直接向下取整而把靠墙脚点放进相邻障碍格。局部Grid路径坐标仍按原接口保留半格中心，不重复转换。不同原生脚格之间即使小数距离不足一格也仍是有效中继。

观察记忆使用全球原生子格，储存矩形随实际观察增长；0xffff始终表示未知，矩形边界不推断地图边界。RemoteTown枚举NativeMapSnapshot中已加载并完整发布的碰撞页，不使用绘制帧、小地图探索掩码或Layer作为碰撞获取条件。连续步行区域两侧的已知页共同参与路线与角色占地判断，区域归属仅限制当前探索目标，不裁剪起点。`AutomapSketch`另保存城镇全显／历史自然小地图的真实图元笔画；普通图元选择与地图显示、地标提取共用，城镇DC6布局与渲染共用。结构提示只对已观察通路做较弱的方向排序，不授予可行走边，不从空白填充地面或把笔画直接转换成墙。城镇全显布局将原MPQ对应变体的服务站点关联为固定地标，供NPC方向搜索；地标不证明活单位或碰撞存在。壁画等视觉线索另从即时绘制记录取得，不受小地图刷新阈值延迟。

地形碰撞完整不代表其中单位已经观察。真实07订阅与已加载碰撞页匹配后，将其空间范围记为单位观察证据；相邻预加载碰撞不自动获得此证据，08退订不抹掉已经观察过的范围，也不表示敌人死亡。已观察单位范围与尚未观察范围之间的已知合法通路，同样产生待探方向；目标跨到边界另一侧的合法站位，不按房间中心或覆盖率巡游。两类通路共用同一选择、路线、承诺及暂缓机制；角色占地已验证开口宽度，不再要求多个相邻站位来重复扩大最小宽度。

已走边来自本人确认位置之间的短连续通行采样，纠正／传送／换区不补成步行边。已走边降低回走成本，但未采样边不阻止完整碰撞已证明的合法通行；未知处不能补路。当前动态实体、真实指派和观察地形分别维护，不把退订当成敌人死亡。`observeTerrain`在长期知识之外另建临时执行快照，路线中的站位和移动边提前检查实时占位及原生传送邻接。实时搜索无可执行路线、但结构搜索有路线时返回`ExecutionBlocked`而不耗尽待探方向；实时搜索已经找到的合法待探通路直接保留，历史路线可能需要未驻留的传送落点／房间邻接，不能据此否决用于恢复观察的通路；动态变化后复用后台结果必须逐边复验。混合路线允许短步行后传送，精确中继不使用普通坐标目标的一格到达容差。保留通路的重规划使用该通路的真实站位集合，并同步更新路线终点和抵达目标；不能用旧终点周围的容差把相邻脚点当成已到达。普通坐标目标的规划与抵达统一使用原生整数脚格和同一容差，零容差不扩大为一格。已在合法交互站位时交给子导航检查真实交互资格，不要求再生成一段非空位移。

## 能力与目标

城镇找NPC、清场、入口搜索、庇护所及已知目标返回共用观察模型。目标是有实际接近站位的通路方向，选择考虑路线成本和方向连续性；当前开口前移保留承诺。已知目标不可完整到达时，同一规划器按实际路线成本、目标剩余距离和开口朝向选择带方向的探索。城镇连接及已知传送点同样传递目标方向。父AI和子导航精确到达开口站位后，等Host同格确认及碰撞／单位指派短暂稳定，图元更新不充当碰撞完成回执。受阻方向按局部证据暂缓，任务切换、离区返回和计时到期不能解除，实际证据变化后重新判断。

步行与传送使用同一目标集合。普通门只在步行规划视图中作为可操作通路，开门属于执行。传送落点及受限射线使用另存的当前真实碰撞快照，保留关闭的门和动态占位，未驻留碰撞不授予施法资格；后台选点、缓存复验和即时执行遵守同一约束。具备传送时，涉及开门的路线会用同一规划器再检查无需开门的合法路线，并优先采用后者；只有无法绕过或目标本身处于门碰撞内才保留开门后备。混合路线可先传送到门前合法地面，再把包含开门操作的步行段交给子导航，不能把可开门站位当作已空出的传送落点。普通步行连接的合法站位、归属和跨界线段统一从完整知识碰撞提取；父子导航共用多目标路线，父层可用步行／传送中继，子层只执行当前驻留窗口内的步行段。窗口边缘不等于知识边缘，不能因局部窗口止于接缝就否决已知出口；未知出口保留稳定方向线索，不另用局部连通分量或特定关卡门面中点算法兜底。单位请求范围不证明路线可知；在途中继保留至交还或实际可交互，只有完整观察路线能交接单位接近。父子共用真实交互站位提取，子层缺少观察路线返回needs-observation，父层继续目标方向探索。传送只需要已观察合法落点，不要求中间步行段畅通；Levels.Teleport=2逐跳验0x0804射线，最终输入另验原生房间邻域。房间订阅仍是单位生命周期证据，不是探索对象。

## 局部执行与接敌

地形规划、路段执行、战斗选位和普通技能输入分别有自己的结果：路线存在不代表下一输入已经执行；技能受理不代表位移、伤害或击杀。怪物密度只属于当前指派的局部决策，不写入远处路线成本、知识地形或缓存失效键。

`NavigationState`唯一保存三类局部任务及类型化原导航意图，`ai_route_execution.cpp`负责推进：步行打通当前路段、传送途中一次技能后续行、传送到目标附近后选空挡入战。步行任务暂停已有子行走，按实际移动射线清除阻挡后直接续行；传送任务保留旅行目标，用实际确认的局部位移交接技能／战斗，不能让普通步行和传送同时推进相反的指针。预算到期不冒充目标完成。

局部任务沿动作契约等待已提交技能、职业位移和补弹事务；普通路线子行走不能因遗留战术状态而解锁。闪避独占当前局部移动目标，替换旧撤退／换位；清路失去攻击角度则恢复原路线重新接近。补弹只暂停局部执行，恢复时保留原落点及预算；无后备弹药交回补给仲裁。精确局部传送不搜索远处中继，位移确认与落点交接共用4子格容差。途经攻击后的Resume只作落点去重，跨接近子目标保留，不再占用调度或输入。

`RemoteTown::visitNavigationPresence`是单位原生占地的共同来源，`navigationGrid`与`navigationBlockers`消费同一套怪物大小、宠物、中立、尸体和非实体模式规则。后者逐单位归因真实移动射线，重叠单位也保留各自身份。`DebugAutoWalk`先检查短距离两段绕行；不能容易绕过时提前发布带单位身份的`BlockedStep`，不等走进包围。危险闪避、撤退和换位沿现有战斗执行器，安全评估检查全部实际可见威胁；普通补弹可接管库存输入，这些中断保留旅行意图和局部任务预算。战斗收到受限目标集合与群攻偏好，普通技能入口仍裁决等级、武器、弹药、射程和射线；每次输入前重新检查路径阻挡，不把附近其他敌人升级为清场目标。

`ai_tactics.cpp`在当前已知地面、活动邻房和实际敌人／危险物上选择可停留并攻击的局部传送点，并负责撤退、攻击角度和绕圈候选；选敌与直接攻击／辅助施法分别由战斗策略模块提供，`ai_combat.cpp`保留执行次序。途中调整必须更短且向下一落点前进；战斗入场优先保留已有合格脚点。移动前重新核对站位，真实位移后才交接攻击。没有可用站位不伪造安全或成功，普通通行／战斗继续保留自己的资格与失败边界。三种模式、局部绕行和职业组合尚待实机验收。

## 生命周期与预算

父AI导航、战斗、补给和任务各有唯一状态对象；`ai_lifecycle.cpp`负责所属状态的重置／计时补偿及跨域换区协调，`ai_scheduler.cpp`按既有优先级消费观察并仲裁动作。步骤重置不会清空同局探索记忆，暂停计时不统一延长已提交原生请求的现实期限。类型接口、状态归属、战斗策略拆分及局部交接修正已通过Windows Release构建，运行组合仍待实机验收。

观察记忆按游戏隔离并跨区域保留，不持久化到角色存档。单区储存上限8Mi格，达到限制明确报错。路线作业拥有不可变快照，按起点、区域、知识修订、能力和目标缓存最多64项；换局／换区取消旧作业，退出先取消并等待Worker结束。失去消费者的观察请求在后续帧取消；仅实时占位修订变化时继续等待原请求，完成后逐边复验，不持续追加相同目标的作业。任务／区域路线评分使用独立低优先级估算，固定起点直至完成；未就绪时使用距离和未知段估价，不挂起动作执行，估算不能作为路线可通的证明。只有一个就绪任务条件或保留现有行走目标时不做多分支成本评分。

普通精确执行规划保留既有Complete／Partial／NoRoute／NeedObservation／StartBlocked／Cancelled／ResourceLimited结果。StartUnavailable单独报告起点缺少可用碰撞，不伪装成没有待探方向。探索无可达开口只意味着当前知识下无可执行待探方向，不能宣称整区已清空或任务完成。新观察模型的复杂地图、资源占用和跨帧执行尚待运行验收。

## 计量与解释

`observedPlanPending`仅表示尚未就绪的观察路线；`observedRequests`区分queued／running／ready及请求年龄，`costEstimatePending`单独报告后台成本估算；实际位移、回溯和任务耗时另计。纯算法耗时不等于角色停顿，排队、动作恢复、输入及网络结果需要分别观察。`nativeMapReady`不证明视口资源齐全；绘制确认、地图准备、单位指派和任务状态不可互相替代。
