# 客户端导航结构

本页维护当前客户端导航的数据所有权、规划接口及限制，不保留重构过程、历史性能报告或修复尝试。策略与操作入口见[调试AI](../development/DEBUG_AI.md)，验证约定见[测试指南](../development/TESTING.md)。

| 范围 | 实现 | 边界 |

| 诊断 | 常驻监视与异步写盘、请求时间线、冻结输入分块清单和同源资源工具重放 | 有界容量及丢弃状态必须报告；重放固定输入不认证任务资格、跨帧执行或原版规则完整性 |

## 坐标与知识

地图块按全球原生subtile整数坐标对齐。规划路径为本地格中心，全球脚点等于本地点加coordinateOrigin再减(0.5,0.5)。显示矩形移动不改变全球块身份。观察点输入中的from／hub／排除点为全球脚点，房间执行几何与输出路线为本地坐标。

已加载碰撞和实际探索分开：规划可读取已加载碰撞，不等于严格仅已探索策略。归档只输出实际观察瓦片内已知碰撞；未加载域不作为合法地面，也不写成永久墙。历史地形、当前驻留、真实观察及单位指派是不同事实。

## 能力与目标

Walk、TownWalk、Teleport共用地图与规划接口，由当前可用能力及区域限制选择，不按职业名称硬编码。城镇使用步行约束；传送保留范围、原生房间邻接、落脚碰撞和适用射线规则。

Coverage、PerimeterConnection、InteriorEntrance、Units区分覆盖、外围连接、内部入口和单位搜索。外围偏好仅消费已解析目标连接边界；内部入口不套外围偏好，未知目标不猜隐藏坐标。收益来自当前资格下仍待观察的瓦片；实际覆盖只由视口回调更新。

候选比较结合路径成本、观察收益和AI方向／墙距策略。步行速度与可用施法样本用于时间估计，缺数据退回相对成本；score含策略权重，不能当作预计通关秒数。失败暂缓、到达避重、房间订阅及任务完成分别维护，具体行为和日志见调试AI。

## 生命周期与预算

一个作业固定一个不可变输入，换局／换区取消旧任务；几何变化按结果相关证据复验。退出先取消并等待Worker结束，再释放其依赖。后台协作抢占期间不能跨检查点保留可能被缓存淘汰的迭代器。

Complete、Partial、NoRoute、NeedObservation、StartBlocked、Cancelled及ResourceLimited分别表达结果。无路只针对固定已知域，预算耗尽、未知或取消不能冒充无路。规划域、候选、工作集、持久缓存和诊断队列各有上限；工作集计费不等于进程实际峰值。

## 计量与解释

分别观察意图等待、排队、纯算法、抢占、发布／消费、实际输入和位移回执。算法耗时不能直接相加成角色停顿；动作恢复、交谈、世界等待与地图准备可能重叠。通关效率以相同条件的目标完成时间为主，新增探索、回溯、传送和重复请求作辅助。

nativeMapReady不是整个视口已完整生成的证明。地图事件消费进度、地形准备、实际观察与绘制资源就绪必须分别解释；黑色像素也可能是合法空白。日志字段及观察点暂缓原因不能代替逐瓦片完备性证明。
