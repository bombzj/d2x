# 客户端导航结构

本页维护客户端导航所有权、规划入口及限制。策略与命令见[调试AI](../development/DEBUG_AI.md)，验证约定见[测试指南](../development/TESTING.md)。

## 坐标与知识

客户端DynamicPath暴露的是减去半格后的世界脚点。`DebugExplorationMemory::playerCell`调用公共`nativeFeetCell`，统一以`floor(position + 0.5)`还原原生整数脚格，供规划起点、观察路线缓存键、父子抵达判定、传送起点邻域及AI输入坐标使用；不能直接向下取整而把靠墙脚点放进相邻障碍格。局部Grid路径坐标仍按原接口保留半格中心，不重复转换。不同原生脚格之间即使小数距离不足一格也仍是有效中继。

观察记忆使用全球原生子格，储存矩形随实际观察增长；0xffff始终表示未知，矩形边界不推断地图边界。RemoteTown枚举NativeMapSnapshot中已加载并完整发布的碰撞页，不使用绘制帧、小地图探索掩码或Layer作为碰撞获取条件。连续步行区域两侧的已知页共同参与路线与角色占地判断，区域归属仅限制当前探索目标，不裁剪起点。`AutomapSketch`另保存城镇全显／历史自然小地图的真实图元笔画；普通图元选择与地图显示、地标提取共用，城镇DC6布局与渲染共用。结构提示只对已观察通路做较弱的方向排序，不授予可行走边，不从空白填充地面或把笔画直接转换成墙。城镇全显布局将原MPQ对应变体的服务站点关联为固定地标，供NPC方向搜索；地标不证明活单位或碰撞存在。壁画等视觉线索另从即时绘制记录取得，不受小地图刷新阈值延迟。

单位搜索覆盖仅记录本地原生路径实际进入、且已加载并有真实07订阅的房间。邻房07只证明地形揭示，不能据此取消尚未进入的单位搜索方向；原版LEVEL_AddClient只枚举当时房间链，预设出生由GAME_PopulateRoom等流程另行处理。覆盖是有限核查策略，不证明目标不存在；真实指派随时接管，交互仍以当前单位为准。08退订保留历史覆盖，敌人状态按实际单位消息更新。已核查范围与尚未核查范围之间的已知合法通路，同样产生待探方向；目标跨到边界另一侧的合法站位，不按房间中心或覆盖率巡游。两类通路共用同一选择、路线、承诺及暂缓机制；角色占地已验证开口宽度，不再要求多个相邻站位来重复扩大最小宽度。

已走边来自本人确认位置之间的短连续通行采样，纠正／传送／换区不补成步行边。已走边降低回走成本，但未采样边不阻止完整碰撞已证明的合法通行；未知处不能补路。待探方向耗尽时，能传送的角色可以从孤立落点回到同区域实际确认过、且步行连通范围更大的已知地面；确认过的传送落点同样合格，不要求它带有步行采样边。候选按已获取碰撞选取，每次回跳仍检查当前落点占地、房间邻域、受限射线和技能资格，实际位移后继续原探索。当前动态实体、真实指派和观察地形分别维护，不把退订当成敌人死亡。`observeTerrain`在长期知识之外另建临时执行快照，路线中的站位和移动边只检查地形／物件及原生传送邻接，动态单位占位只在下一执行路段检查。传送规划不能要求远处全部房间现在都已驻留：实时搜索未到目标、但已知地形有结构路线时，从本次可执行搜索树中选择该路线最靠后的可达中继，返回`Partial`（诊断`executable-prefix`）及原目标；中继不代表目标完成。范围核查跨中继保留原目标，普通探索保留原通路，抵达并确认房间观察后续接；已查房间不能取消途经中继。无可执行前段时才返回`ExecutionBlocked`；范围核查先尝试正常开门／步行传送台／合法回跳，仍无路则明确保留现场，只有预期出生目标继续有界观察，不复用空结果无限等待。无路结论还必须先核对客户端已观察的物件碰撞过渡：`RemoteTown::navigationTransitionRemainingMilliseconds`复用物件ENDANIM及MPQ模式碰撞，搜索只在确有尚未到期的碰撞变化时等待，随后随正常碰撞发布重算；不为NPC或区域增加固定延时，此项尚待构建及运行验证。步行规划仍使用实际确认的传送台连接；会传送时不纳入传送台，也不要求跨平台步行连通。此项前段续接尚待构建与实机验证；实时搜索已经找到的合法待探通路直接保留，历史路线可能需要未驻留的传送落点／房间邻接，不能据此否决用于恢复观察的通路；地形／物件和房间驻留变化后复用后台结果必须逐边复验。混合路线允许短步行后传送，精确中继不使用普通坐标目标的一格到达容差。保留通路的重规划使用该通路的真实站位集合，并同步更新路线终点和抵达目标；不能用旧终点周围的容差把相邻脚点当成已到达。普通坐标目标的规划与抵达统一使用原生整数脚格和同一容差，零容差不扩大为一格。已在合法交互站位时交给子导航检查真实交互资格，不要求再生成一段非空位移。

## 能力与目标

城镇传送点与NPC共用配置地标的变体／相对坐标语义。父AI将已核实配置转换为`DebugWalkIntent.searchHint`交给子导航；该值只提供搜索方向，当前真实指派和观察地形继续决定可执行路线。子导航优先使用已观察的传送点位置；目标线索变化时不沿用旧通路承诺。开局读取传送点历史、普通旅行及探索返回共用此入口，不从城镇图片识别坐标，也不在运行时扫描未观察预设取得位置。

城镇找NPC、清场、入口搜索、庇护所及已知目标返回共用观察模型。候选区域搜索在一次区域核查完成后可按配置比较回城／已解锁传送点与直接前往下一目标的代价，复用旅行续接并保留核查状态；传送能力参与两条路线的同一成本模型。事件清场同样使用有限范围观察轮次，优先处理范围内实际敌人，覆盖结束只结束本轮巡视，世界事件仍由真实指派和任务事实确认。目标是有实际接近站位的通路方向，选择考虑路线成本和方向连续性。当前开口前移保留承诺。已知目标不可完整到达时，同一规划器按实际路线成本、目标剩余距离和开口朝向选择带方向的探索。城镇连接及已知传送点同样传递目标方向。同类、同朝向的相连边格归为一条通路。父AI和子导航按本地原生路径确认抵达站位并停步，再以`observationStatus`核对脚点所属房间已加载、实际07订阅、地形发布及既有消息稳定条件；不要求最近服务端位置采样逐格等于计划终点，不扩大精确坐标目标的到达容差。共享入口供目标搜索、在途中继、地标和已知传送台源头重访使用，返回移动、地形待发布、未订阅、消息稳定中或就绪。观察完成只推进核查与路线，不能代替单位指派、交互、击杀或换区事实。证据稳定后暂缓当前通路，通路证据变化后重新判断。图元更新不充当碰撞完成回执。

步行与传送使用同一目标集合。普通门只在步行规划视图中作为可操作通路，开门属于执行。传送目标及受限射线使用当前驻留地形／物件快照，保留关闭的门，不叠加玩家、怪物和伙伴占位，未驻留碰撞不授予施法资格；后台选点、缓存复验和即时执行遵守同一约束。即时选点统一经过TeleportTargets，地形网格按快照缓存；动态单位只影响局部步行与明确的战术安全选择。具备传送时，涉及开门的路线会用同一规划器再检查无需开门的合法路线，并优先采用后者；只有无法绕过或目标本身处于门碰撞内才保留开门后备。混合路线可先传送到门前合法地面，再把包含开门操作的步行段交给子导航，不能把可开门站位当作已空出的传送落点。普通步行连接的合法站位、归属和跨界线段统一从完整知识碰撞提取；父子导航共用多目标路线，父层可用步行／传送中继，子层只执行当前驻留窗口内的步行段。窗口边缘不等于知识边缘，不能因局部窗口止于接缝就否决已知出口；未知出口保留稳定方向线索，不另用局部连通分量或特定关卡门面中点算法兜底。单位请求范围不证明路线可知；在途中继保留至交还或实际可交互，只有完整观察路线能交接单位接近。父子共用真实交互站位提取，子层缺少观察路线返回needs-observation，父层继续目标方向探索。传送只需要已观察合法落点，不要求中间步行段畅通；Levels.Teleport=2逐跳验0x0804射线，最终输入另验原生房间邻域。房间订阅仍是单位生命周期证据，不是探索对象。

已观察路线交接近距单位前，父子共用RemoteTown.nativeInteractionApproach，以实时碰撞预览公共Grid.nativePlayerPath并核对路径终点的实际交互资格；仅在50格请求范围内或只生成墙前截断路径，不授权交接。不能结束本地接近时继续地形路线中继；可以结束时调用普通RemoteControl.interact，不以目标中心的直线可达为前提。客户端沿手动点击的原生寻路接近并自动交互，AI保留其执行归属；实际交互尚未发出而接近停滞15秒时，先在同一子目标内接回地形路线恢复一次，再按既有无进展上限失败。这项交接与恢复尚未构建／实机复验。下一段仍需传送时先执行传送，不能因目标进入请求范围而切成步行；实际换区／菜单／任务结果各自确认。

## 局部执行与接敌

传送距离与射线资格使用原生整数输入域：人物小数显示脚点经`nativeFeetCell`转换，候选落点按实际提交的`floor(landing)`取整；观察规划、`TeleportTargets`即时复验及普通`RemoteCombat`输入保持同一口径。`teleportLanding`不再用小数显示距离重复裁剪路线节点。满配置距离的合法中继不能因显示脚点偏离格中心而被拒；这不增加距离容差，也不改变步行连续路径、房间驻留、地形占地或受限关卡的屏障规则。该坐标修正尚未构建／实机续跑。

城镇和野外坐标步行共用公共Grid.nativePlayerPath处理局部动态绕行，不再枚举固定的单拐点形状；局部目标按整数脚格收敛到18格前视内，遵守原生Straight／AStar范围。只有实际可到目标邻格并产生位移才交给普通坐标移动，不能把被阻挡的截断前缀当作成功；移动中的原生路径拥有后续拐点，结束后再接回长期路线。中立单位只绕行或等待，城镇不进入战斗清路；传送落点仍不检查动态单位占位。旅行入口在已有两次局部恢复之后，同一地区／单位指派连续三轮失败且确认脚点未离开两格邻域时明确失败并记录入口、位置及原因，路线重选不清零；目的地或任务步骤变化才重置这项记录。坐标中继也按同一目标与服务端位置观察累计三轮失败，3秒冷却不清空次数，失败记录目标、位置及子导航原因。失败上限属于AI策略；18格原生后备范围依据D2MOO PathMisc::PATH_Straight_Compute。原生局部绕行和坐标中继上限尚未构建／实机复验。

地形规划、路段执行、战斗选位和普通技能输入分别有自己的结果：路线存在不代表下一输入已经执行；技能受理不代表位移、伤害或击杀。怪物密度只属于当前指派的局部决策，不写入远处路线成本、知识地形或缓存失效键。

`NavigationState`唯一保存三类局部任务及类型化原导航意图，`ai_route_execution.cpp`负责推进：步行打通当前路段、传送途中一次技能后续行、传送到目标附近后选空挡入战。步行任务暂停已有子行走，按实际移动射线清除阻挡后直接续行；传送任务保留旅行目标，用实际确认的局部位移交接技能／战斗，不能让普通步行和传送同时推进相反的指针。预算到期不冒充目标完成。清路归属取决于当前实际执行路段，不取决于角色是否会传送：最后几格先用实时单位碰撞判断可否步行；受阻时能合法传送则交给位移，否则清除该段实际阻挡。传送回包确认实际位移后，routeRelay类型的中继交还父层；落点修正不把请求点记成不可达，也不要求先走回该点。已有后续传送点从实际落点复验距离、活动邻房和屏障后继续，失效才重新规划。最终到达、交互和战斗站位仍各自核实，不能由位移回包替代；短接近不再用附近中继替代终点。

局部任务沿动作契约等待已提交技能、职业位移和补弹事务；普通路线子行走不能因遗留战术状态而解锁。闪避独占当前局部移动目标，替换旧撤退／换位；清路失去攻击角度则恢复原路线重新接近。补弹只暂停局部执行，恢复时保留原落点及预算；无后备弹药交回补给仲裁。精确局部传送不搜索远处中继，位移确认与落点交接共用4子格容差。途经攻击后的Resume只作落点去重，跨接近子目标保留，不再占用调度或输入。

`RemoteTown::visitNavigationPresence`是单位原生占地的共同来源，`navigationGrid`与`navigationBlockers`消费同一套怪物大小、宠物、中立、尸体和非实体模式规则。后者逐单位归因真实移动射线，重叠单位也保留各自身份。`DebugAutoWalk`先检查普通客户端原生局部路径；不能容易绕过时提前发布带单位身份的`BlockedStep`，不等走进包围。危险闪避、撤退和换位沿现有战斗执行器，安全评估检查全部实际可见威胁；普通补弹可接管库存输入，这些中断保留旅行意图和局部任务预算。战斗收到受限目标集合与群攻偏好，普通技能入口仍裁决等级、武器、弹药、射程和射线；每次输入前重新检查路径阻挡，不把附近其他敌人升级为清场目标。

`ai_tactics.cpp`在当前已知地面、活动邻房和实际敌人／危险物上选择可停留并攻击的局部传送点，并负责撤退、攻击角度和绕圈候选；选敌与直接攻击／辅助施法分别由战斗策略模块提供，`ai_combat.cpp`保留执行次序。途中调整必须更短且向下一落点前进；战斗入场优先保留已有合格脚点。移动前重新核对站位，真实位移后才交接攻击。没有可用站位不伪造安全或成功，普通通行／战斗继续保留自己的资格与失败边界。选位与施放共用当前技能的AI距离，技能对象range覆盖全局远程距离；默认冰封球为12子格，其他技能沿原配置，原生飞弹规则不变。三种模式、局部绕行和职业组合尚待实机验收。

停留等待的远程防御在`ai_scheduler.cpp`完成原任务推进或收到后台寻路让出后仲裁，由`ai_defense.cpp::defendWhileWaiting`限定当前实际敌人、半径和攻击射线。默认半径10，可经`combat.waitDefenseRadius`配置；不等待拥挤／掉血，不追击、不改原导航，复用普通技能资格、选择和单次施放。任务续接优先于下一次防御，原生输入和库存事务锁保持。任务合成节点指定城镇，`questCombine`只在城镇执行，材料及配方仍由实际库存和Host确认。此项尚未构建／运行。

## 生命周期与预算

父AI导航、战斗、补给和任务各有唯一状态对象；`ai_lifecycle.cpp`负责所属状态的重置／计时补偿及跨域换区协调，`ai_scheduler.cpp`按既有优先级消费观察并仲裁动作。步骤重置不会清空同局探索记忆，暂停计时不统一延长已提交原生请求的现实期限。既有类型接口、局部交接、实时短步行占位及技能独立距离调整曾通过Windows Release构建；通用目标搜索、规划／传送目标移除单位占位及修正落点续接尚未构建／运行。普通难度单机调试女巫已完成第一幕并进入鲁高因，独立路线与职业组合见[调试导航验收范围](../development/DEBUG_AI.md#待验收调试导航)。

观察记忆按游戏隔离并跨区域保留，不持久化到角色存档。单区储存上限8Mi格，达到限制明确报错。路线作业拥有不可变快照，按起点、区域、知识修订、能力和目标缓存最多64项；换局／换区取消旧作业，退出先取消并等待Worker结束。地图几何修订变化时，`Worker::reset(false)`随路径结果一并清除回调采样的碰撞快照，不能仅凭局部修订号和尺寸复用旧房间／旧原点的掩码；原生发布快照仍按不可变输入身份复用，保留路线在使用时复验。此项缓存失效修复尚待构建及实机复测。失去消费者的观察请求在后续帧取消；单位占位不进入长程作业键；地形／物件修订变化时完成后逐边复验，不持续追加相同目标的作业。任务／区域路线评分使用独立低优先级估算，固定起点直至完成；估算缓存另限16项，区分起点分桶、步行／传送射程及受限区域规则，不挤掉未完成估算以反复排队。结果绑定实际计算的地形修订，仅完整目标路线用于成本；未就绪时使用距离和未知段估价，不挂起动作执行，估算不能作为路线可通的证明。区域旅行带进入方向与观察落点评分，实际入口选择与执行共用`travelLeg`；城镇中转保留原行程历史，补给完成后任务条件在城内重新选择。只有一个就绪任务条件或保留现有行走目标时不做多分支成本评分。

普通精确执行规划保留既有Complete／Partial／NoRoute／NeedObservation／StartBlocked／Cancelled／ResourceLimited结果。StartUnavailable单独报告起点缺少可用碰撞，不伪装成没有待探方向。探索无可达开口只意味着当前知识下无可执行待探方向，不能宣称整区已清空或任务完成。新观察模型的复杂地图、资源占用和跨帧执行尚待运行验收。

## 计量与解释

`observedPlanPending`仅表示尚未就绪的观察路线；`observedRequests`区分queued／running／ready及请求年龄，`costEstimatePending`单独报告后台成本估算；实际位移、回溯和任务耗时另计。纯算法耗时不等于角色停顿，排队、动作恢复、输入及网络结果需要分别观察。`nativeMapReady`不证明视口资源齐全；绘制确认、地图准备、单位指派和任务状态不可互相替代。
