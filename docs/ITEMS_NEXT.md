# 物品系统工作划分

本页保留物品阶段的历史拆分，不代表当前完成状态。当前物品与掉落实施顺序见 [物品补全](ITEM_COMPLETION.md)，全项目能力与缺口见 [项目基线](../BASELINE.md)。

以下项目状态是当时交接记录；当前原版生成及品质展示实例已在新的实施清单中继续推进。全程不编写测试脚本或测试用例。

| --- | --- | --- |
| 1. 统一物品与容器模型 | 原版基础定义、唯一实例/归属、矩形格子、移动/交换、堆叠拆分合并、权限与会话命令 | 已完成 |
| 2. 怪物掉落与拾取 | 单次死亡结算、地面图形/名字、拾取已实现；原版 TC 生成待接入 | 原版生成暂缓；旧权重已删除 |
| 3. 包裹界面 | 原版风格面板和图标、拖拽/交换/自动放置、数量与物品说明 | 已完成 |

## 第 1 项的实际交付

`src/gameplay/items` / `d2x_items` 已实现完整的底层物品与容器操作，独立于 raylib、MPQ 和窗口。

- 从现有经典 1.04 试玩 MPQ 的 `misc.txt`、`weapons.txt`、`armor.txt` 提取 361 条有效物品定义：94 条杂项、175 条武器、92 条护甲。导入原始代码、名称、占格、堆叠上限、耐久、腰带/使用标记和图标路径；不是完整词缀、装备属性或使用效果实现。
- 定义与实例分离；实例具有会话唯一 ID、数量、品质/等级/耐久字段和版本号。当前创建入口生成普通品质；品质生成、词缀和装备生效留给后续扩展。
- 实例位置只有一个权威来源：地面位置或容器格子位置。格子占用、容器内容和按区域查询地面物品都从位置推导，不再保存第二份物品副本或独立占格表。
- 矩形占格、边界和重叠限制，按行优先自动找空位；移动、双方交换、拆分、合并和底层数量消耗。交换会校验双方的新占格，失败不改变原状态。
- 版本号拒绝过期命令；所有者、存活状态、区域/距离、储物箱访问授权和腰带物品限制统一校验。
- 会话初始化玩家的空容器：包裹 10×4、基础腰带 4×1、按 MPQ `inventory.txt` 当前模式建立私人储物箱（资料片 6×8，经典 6×4）。容器/物品与角色战斗状态分开管理，旅行和 `R` 不会重新创建玩家容器。
- `MoveItem`、`SwapItems`、`SplitStack`、`MergeStacks` 已接入固定步会话命令；成功发出 `ItemChange`，失败发出 `InventoryRejected`，界面可显示错误文字。

本项没有新增物品面板、掉落、药剂使用效果或装备切换。容器初始为空，现有角色外观仍由原来的 COF/DCC 配置决定。当前只完成 Windows 编译、正常启动和定义/容器初始化检查，没有编写或运行专用交易测试程序。

底层接口和不变量见 [物品与容器模型](ITEM_MODEL.md)。

## 第 2 项的实际交付：掉落到入包

`GameSession` 在固定步结束、表现层读取事件之前收集 `EnemyDied`，交给独立的 `LootSystem` 结算。先复制死亡事件再发布物品事件，避免事件数组扩容使引用失效。系统记录已结算的死者 ID，即使重复传入死亡事件也不会再次掉落或推进随机数。

本轮完成：

- 21 种普通品质掉落：四种基础生命/法力药剂、回复药剂、两种卷轴、钥匙、箭矢/弩矢、四种基础武器、五种基础护甲、戒指和项链。沉沦魔与僵尸使用不同权重；20% 不掉落，其余掉落一件，其中 20% 再掉一件。钥匙和弹药有随机数量。
- 显式 SplitMix64 随机数流及无偏整数取样；默认种子为十进制 `210`，可用 `--seed <无符号64位十进制整数>` 指定。相同种子、相同死亡类型/顺序产生相同掉落序列。旅行和 `R` 不重置随机数。
- 死亡位置附近的可行走地面投放，不能隔墙散落；创建入口仍为可信玩法调用。地面物品只存在于 `InventoryState`，以区域 ID 查询，不向 `AreaState` 复制物品。
- 经典 DC6 落地动画、静止帧、名称与数量、名称避让和鼠标高亮。新掉落名称短暂显示，悬停显示单件，按住 `Alt` 显示屏幕内名称。图形与墙体、角色共用深度排序。
- 左键点击名称或物品，自动寻路至近处拾取。检查版本号、当前区域、存活状态、1.8 子格距离与无障碍直线；不可达时给出提示。移动、攻击、施法、交互、死亡和旅行会取消旧拾取目标。
- 自动填入包裹中的兼容堆叠，再给余量寻找完整空矩形。先验证全部容量和目标版本，再一次性提交；空间不足时既不减少地面数量，也不部分增加已有堆叠。界面显示拾取结果、失败原因和包裹占格数。
- 旅行保留各区掉落，`R` 保留地面物品与已有库存，只重生怪物并分配新的怪物 ID；旧尸体不会重复结算。所有状态仍只存在于当前会话。
- 361 条定义补齐原表 `flippyfile` 路径，精简 MPQ 新增当前 21 种物品对应的 39 个不同 DC6 图形资源；包括后续包裹界面需要的图标。启动预加载活动掉落池，重新导入资源时自动收录这些文件。

当前权重是本项目的入门战斗规则，尚未复刻原版完整 TreasureClass、金币钱包、魔法/稀有词缀、MF 或难度掉落。药剂的使用效果在第 4 项实现；包裹整理与丢弃界面已由第 3 项接通。占格计数表示面积，零散空格不一定能放下大物品。

本轮完成 Windows 编译、原始素材加载和更新后的单个精简 MPQ 独立启动/截图检查。没有编写测试脚本、测试用例或专用交易测试程序；Linux 尚未实际编译运行，交互式掉落拾取未做自动化验证。

## 第 3 项的实际交付：包裹界面

- `I` 或 HUD 的包裹计数打开/关闭右侧面板；采用试玩版 `invchar.dc6` 的原版石框和包裹格子，显示现有 21 种掉落物品的原版图标。打开面板时停止旧的行走/拾取目标，并把人物视野移至左半屏；世界继续运行，`P` 仍负责暂停。
- 10×4 占格、悬停/选中高亮、堆叠数量角标；详情区读取真实名称、品质、分类、数量/上限、尺寸、耐久、等级和腰带适用标记，不生成尚未实现的装备词缀或属性。
- 按住左键拖动、松开放置；记录实际抓取格，长武器与护甲不会跳到错误的锚点。绿色/红色预览来自与正式提交共用的校验入口，交换同时显示双方目标占格。
- 拖至空格移动；拖至另一物品提交双方交换；同类型可堆叠物品默认提交合并，目标满时拒绝，未能合入的余量留在来源。按住 `Ctrl` 拖动可明确要求交换堆叠。
- `AUTO PLACE` 或 `Shift` 点击将选中物品放入第一个完整空矩形；拖到自动放置按钮也可使用。它只移动这一件物品，不会隐式重排其他物品。
- `SPLIT` 打开数量选择，按钮、滚轮或左右键调整，`Enter` 确认；新堆叠自动找空位，没有空间时源数量不变。`DROP` 或拖到面板左侧的世界区域，将物品放至角色脚边的有效地面，之后仍可拾取。
- 右键或 `Esc` 取消手势，关闭/暂停/切图/失焦同样取消；拖动只保留 ID、版本和抓取偏移，不移出来源格。提交后等待会话的成功/失败事件，阻止连续点击重复提交；无变化操作也有完成回执。死亡关闭面板。
- 面板、弹窗与拖动期间的输入不会穿透到地图攻击或施法；HUD 上释放拖动物品只取消，不会误点技能。`--inventory` 支持启动时直接打开包裹。

底层新增 `InventoryService::preview` 和 `GameSession::previewInventory`，显示预览与提交时都使用同一组业务校验。地面移动同时校验区域、距离、可行走性与无障碍直线。面板状态、布局/拖放意图、控制器和绘制分开，未把物品规则放入绘制代码。

Windows 编译与更新后的单个精简 MPQ 启动/包裹截图检查已通过。没有编写测试脚本、测试用例或专用交易程序；实际拖拽流程未进行自动化验证，Linux 尚未实际编译运行。操作和代码入口见 [包裹界面](INVENTORY_UI.md)。装备穿戴、腰带操作、物品效果与储物箱面板仍属于后续工作。

## 第 4 项的实际交付：腰带与物品使用

- 4／8／12／16 格容量、五种基础腰带掉落和穿脱，缩容先完整规划溢出物品入包，无空间则全部保持原状。
- 同类列优先自动入带，四列快捷饮药，展开行、包裹右键饮药，跨容器拖动／交换和 Shift 整理，饮用后同列向下补位。
- 13 种药剂的持续／即时恢复和耐力效果，固定步结算、数量消耗、药效队列以及死亡／治疗清理；初始四瓶生命药剂和两张卷轴取自原始野蛮人初始消耗品记录。
- 掉落池扩展为 34 种，新增物品的落地动画、图标均来自现有 MPQ。恢复完整包裹装备区域，使用原版腰带格、空槽、按钮、生命／法力球、野蛮人技能图标及音效。
- 1～4 改为饮药，F5～F10 为技能，B 展开腰带；帮助、暂停和旅行菜单隔离使用命令。

本项使用 Windows 构建、普通启动、资源加载和截图检查，未编写测试脚本、用例或专用交易程序。药水恢复时长、混合等级排队和耐力增强属于明确说明的模拟规则，未宣称经典 1.04 逐帧等价；卷轴效果、词缀、防御属性、雇佣兵尚未实现。操作、资源来源和实现边界见 [腰带与物品使用](BELT_AND_CONSUMABLES.md)。

以上第 1～3 项为各轮交付时的历史记录；当前操作以第 4 项和最新使用说明为准。

## 第 5 项当前交付：私人储物箱

原版资料片 `tradestash.dc6` 面板、MPQ 6×8 容器、自动走近授权、包裹／箱子拖放与原子整件转移已经接通。拆分目标跟随来源容器，离开范围／死亡／旅行／重置／关闭都会撤销访问，库存继续保留。

本轮按职责整理了场景组装、交互协调、通用容器网格、共用绘制和整件转移计划。没有复制一套专用箱子交易规则，没有增加箱子界面副本或临时“鼠标持有物品”库存。代码入口见 [私人储物箱](STORAGE.md)。

按最新要求，不用自定义位置和掉落权重补齐地图箱子。当前四张地图无原生可掉落箱子，但源 MPQ 有箱子图形和旧版 TreasureClass 条目；原生分布及完整掉落执行链仍需接入，不能宣称仅换一个大 MPQ 即已完成。该子项暂缓，原版内容／版本条件明确后再继续；本轮未把第 5 项整体标为完成。文件清单和寻找方法见 [MPQ 资源](MPQ_RESOURCES.md)。

Windows 构建、普通启动及真实寻路到箱子／打开面板的截图检查已完成。未编写测试脚本、测试用例或专用交易程序；存取交互未做自动化验证，Linux 尚未实际构建运行。

## 第 6 项与本轮数据纠正

已完成值快照、版本化二进制格式、内容指纹、状态与引用校验、临时文件替换及备份；F11 保存、Ctrl+F11 读取，支持 `--save/--load`。保留各区战斗、物品、容器、药效、ID 与结算状态；读档不恢复 UI 手势或储物箱授权。见 [存档说明](SAVES.md)。

同时移除静态物品目录，直接读取 MPQ 的 361 条物品定义、410 条怪物数据、95 条 TreasureClass；补齐基础装备参数和原字段查询。1.04 的 TC 格式与资料片不同，旧模拟权重已经删除，怪物生成掉落暂缓。见 [原版数据说明](ITEM_DATA.md)。

下一阶段先明确采用经典 1.04 还是完整 LoD 的版本规则，再接原版掉落执行链、金币和物品品质；如相应资料仍不足，可先推进已有 MPQ 能完整支持的内容，不能重新编造掉率。装备属性生效、词缀及原生地图箱子应分别作为后续交付范围。

## 后续共同约束

后续已接入 [MPQ 怪物生成](MONSTER_POPULATION.md)、部分原版迷宫／户外生成及双向出口，当前范围见 [第一幕地图](ACT1_MAPS.md)。TreasureClassEx 执行仍待实现；掉落请求携带真实怪物身份，不能按替身选择掉落池。

- 不以自制素材、随意布置物件或未经核实的规则替代缺失的原版内容；不足时标为未实现并记录资源／规则缺口。
- UI 只读取状态、持有 ID/版本号和提交命令；拖拽时不提前清空来源格。
- 自动放置、显式交换和合并是不同操作，不能因为命中目标格就隐式删除或覆盖物品。
- 腰带与储物箱复用当前容器规则；药剂使用由会话验证权限与效果，再提交消耗和玩法效果，界面不得直接修改库存或生命。
- 私人储物箱是玩家所有的容器，地图箱子是世界对象，两者状态不能混用。
- 存档保存物品实例、位置、容器、玩家容器 ID、战斗/区域状态、ID 分配游标和随机数状态；不保存 GPU 指针。
